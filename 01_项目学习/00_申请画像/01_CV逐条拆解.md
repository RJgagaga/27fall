# CV 逐条拆解：每一句话到底做了什么、会被怎么追问

> **一句话定位**：把英文 CV 当作"面试大纲"，对每个板块、每条 bullet 回答四个问题：这句话实际做了什么？里面有哪些技术名词？面试官会怎么追问？去哪份文档学？

**本章学完你能……**

- 对 CV 上任何一条 bullet，用中文 30 秒讲清"做了什么"，并说出其中每个技术名词的含义；
- 预判每条 bullet 至少 3 个英文追问，并知道答案该从哪篇文档找；
- 讲清 Education、Awards、Skills 三个板块各自能撑起什么、不能撑起什么；
- 分清哪些话 CV 已经"锁死"（必须一致），哪些细节需要你补全（`【待你补全】`）。

**前置知识**：已读 [总入口 README](../README.md)。

**使用方法**：每个 bullet 的格式固定为——原文（来自 CV）→ 这句话在做什么 → 技术名词（逐个一句话）→ 英文追问（带中文要点）→ 对应文档。追问后面带"回答方向"，只写**有依据的事实**，没依据的写成 `【待你补全】`。

## 0. CV 抬头与整体定位

CV 抬头：**Robotics Algorithms · Motion Control · Autonomous Navigation**（机器人算法 · 运动控制 · 自主导航）。

这三个词是你对面试官的"承诺"：

| 抬头词 | 面试官的预期 | 最能支撑它的项目 |
|---|---|---|
| Robotics Algorithms | 你懂建模、估计、规划、优化，不只是调库 | P1（LQR 分析）、P5（EKF/Hybrid-A*/TEB/MPC）、P2（约束 IK） |
| Motion Control | PID、状态反馈、前馈、饱和、实时 | P1、P7、P3、P2 |
| Autonomous Navigation | 定位—规划—跟踪完整链路 | P5 |

注意 CV 没有写 "Machine Learning" 作抬头。机器学习只落在 P4（YOLOv5/RKNN、LangGraph）。这与 PS 里"承认机器学习经验以实践为主"一致，详见 [02_PS与推荐信主线](./02_PS与推荐信主线.md)。

CV 的排列顺序是：Education → Awards → Internships（时间倒序：P6、P2、P1）→ Projects（P7、P5、P3、P4）→ Skills。面试官通常会先从最新的 P6 或最有岗位相关性的 P1/P7 开始问。

### 1.4 Education 的可能追问

1. **"Your major is Computer Science. Why are you applying to a robotics programme?"**（你是 CS 专业，为什么申请机器人？）
   回答方向：从 CV 抬头和七个项目的主线出发——硬件实际验证的控制、导航、操作，再说明想补系统理论。详见 [PS 主线](./02_PS与推荐信主线.md)。
2. **"You ranked 6 of 156. What did you do beyond the coursework?"**
   回答方向：RoboMaster、实验室项目、三段实习。不要说没有依据的"发表论文"之类。
3. **"Tell me about the control courses you took. What was the hardest concept?"**
   回答方向：选一个你真懂的（如 LQR 的权重含义或状态空间可控性），用 P1 的经验落地。
4. **"Your IELTS is 6.5. Are you comfortable studying in English?"**
   回答方向：承认当前水平，说明已有的英文使用（读文档、写英文 CV/PS、本次面试准备）。不夸大。

## 3. Internships

CV 中实习按时间倒序：P6（在职）→ P2 → P1。下面按 CV 顺序拆解。

### 3.1 P6 — Shenzhen Kaihong Digital Industry Development Co., Ltd. — Robotics Platform Intern（Jun 2026 – Present）

**Overview（CV）**：device abstraction and motion coordination on the M-Robots OpenHarmony multi-robot platform; independently developed and integrated device abstraction, state management, distributed coordination and the safe-execution chain.

**一句话理解**：在深开鸿的 M-Robots 多机器人平台（跑在 OpenHarmony 上）上，把"各种传感器/执行器/控制器"变成统一接口，把状态变成可信一致的状态，把多设备的发现、同步、任务下发通过 M-DDS 串起来，并让任务计划必须过一条安全链才能真正动机器人。

**统一的名词表**（P6 三条 bullet 共用）

| 名词 | 一句话解释 |
|---|---|
| OpenHarmony | 开源的分布式操作系统，面向多设备互联；这里是机器人平台的操作系统层 |
| M-Robots | 深开鸿的多机器人平台（本 CV 里的项目平台名） |
| M-DDS | 平台上的 DDS（Data Distribution Service，数据分发服务）类通信中间件，支持发布/订阅 |
| ROS/ROS2 | 机器人操作系统（Robot Operating System），提供节点、话题、服务等通信模型 |
| capability model（能力模型） | 把设备能做什么（如"可输出速度""可读 IMU"）抽象成标准描述的一种建模方式 |
| device abstraction（设备抽象） | 屏蔽硬件差异，给上层提供统一接口 |
| coordinate frame（坐标系） | 位姿的参考系，如 map、odom、base_link |
| validity check（有效性检查） | 判断一条数据是否可信（时间戳是否过期、数值是否在范围、传感器是否报错等） |
| action-proposal → policy-check → execution → state-feedback | 任务计划先提案，经策略检查，才执行，执行后用状态反馈确认 |

#### P6-1 Unified motion interface

> built a unified capability model for sensors, actuators and controllers using C++ on OpenHarmony and mapped ROS/ROS2 motion commands to low-level drivers, enabling motion-control code reuse across hardware.

- **做了什么**：用 C++ 在 OpenHarmony 上定义了一套"能力模型"，让传感器、执行器、控制器都用统一描述；把 ROS/ROS2 的运动指令（例如速度指令）映射到底层驱动，使同一份运动控制代码能跑在不同硬件上。
- **技术名词**：见上表；另需理解"driver（驱动）"= 与具体硬件通信的底层代码；"motion command（运动指令）"= 如 `Twist` 速度命令。
- **英文追问**：
  1. "What exactly is a capability model? Can you give an example of one capability?"（能力模型到底是什么？举个能力的例子。）
  2. "How did you map a ROS2 velocity command to a low-level driver? What happens if two robots have different wheel layouts?"（怎么把 ROS2 速度命令映射到驱动？轮子布局不同怎么办？）
  3. "Why did you write it in C++ rather than use ROS2 nodes directly?"（为什么用 C++ 而不直接用 ROS2 节点？）
  4. "How did you prove the motion-control code was actually reusable across hardware?"（怎么证明代码确实跨硬件复用？）
- **回答方向**：先讲问题（不同硬件接口不同导致控制代码要重写），再讲抽象（统一能力描述 + 命令映射），最后讲验证。具体接口名、测试过的硬件种类 `【待你补全：能力模型的字段/接口名；验证过的硬件型号数量】`。
- **对应文档**：[P6 README](../01_项目课程/P6_深开鸿M-Robots平台软件/README.md)、[P6 英文口述](../01_项目课程/P6_深开鸿M-Robots平台软件/99_英文面试口述与深挖问答.md)；基础：[ROS1/ROS2 核心概念](../02_基础知识/09_机器人软件/04_ROS1_ROS2核心概念.md)、[OpenHarmony/Hi3861/RK3588 平台基础](../02_基础知识/08_嵌入式与通信/06_OpenHarmony_Hi3861_RK3588平台基础.md)、[现代 C++](../02_基础知识/09_机器人软件/02_C++现代特性与工程实践.md)；八股：[ROS 与机器人软件八股](../03_八股知识/03_机器人学/05_ROS与机器人软件八股.md)、[C++ 八股](../03_八股知识/01_计算机基础/05_C++八股.md)。

#### P6-2 Robot state management

> standardised timestamps, coordinate frames and validity checks across multi-source perception and actuator feedback, giving the motion-control and task layers a consistent, trusted robot state.

- **做了什么**：对来自不同传感器和执行器反馈的数据，统一时间戳、统一坐标系、统一有效性判断，向运动控制层和任务层提供"一致且可信"的机器人状态。
- **技术名词**：timestamp（时间戳，数据产生时刻）；time synchronisation（时间同步）；frame transform（坐标变换，如 TF）；staleness（数据陈旧）；consistent state（同一时刻的各分量互相匹配的状态快照）。
- **英文追问**：
  1. "What kinds of inconsistency did you actually see — timing, frames, or something else?"（实际见到哪类不一致？）
  2. "How do you decide a sensor reading is invalid? What is your policy when it is?"（怎么判定无效？无效后怎么处理？）
  3. "Why does state inconsistency matter for control? Give a concrete failure."（状态不一致为何影响控制？举具体失效。）
  4. "How is this related to the pose jumps you mentioned in your navigation project?"（和 P5 的位姿跳变有什么关系？）
- **回答方向**：把 P5 的"定位漂移/位姿跳变"、P7 的"状态不一致导致平衡异常"联起来，是你的三处共同经验；具体判据阈值 `【待你补全】`。
- **对应文档**：[P6 README](../01_项目课程/P6_深开鸿M-Robots平台软件/README.md)；基础：[时间同步_坐标系一致性与数据有效性](../02_基础知识/05_状态估计/06_时间同步_坐标系一致性与数据有效性.md)、[URDF_TF_坐标系实践](../02_基础知识/09_机器人软件/07_URDF_TF_坐标系实践.md)；八股：[状态估计与 SLAM 八股](../03_八股知识/03_机器人学/03_状态估计与SLAM八股.md)。

#### P6-3 Coordination and safe execution

> implemented device discovery, capability registration, state synchronisation and task dispatch over M-DDS, and gated task plans through an action-proposal, policy-check, execution and state-feedback chain.

- **做了什么**：设备发现（新设备上线被识别）、能力注册（设备登记自己能做什么）、状态同步、任务分发，全部走 M-DDS；任务计划不是直接发给机器人，而是依次经过动作提案、策略检查、执行、状态反馈四步。
- **技术名词**：DDS / pub-sub（发布—订阅）；QoS（服务质量，如可靠性、时延）；discovery（发现）；dispatch（任务分发）；policy check（策略检查，如是否越界/超限/与当前状态冲突）。
- **英文追问**：
  1. "Walk me through the four steps of the safe-execution chain. What does the policy check actually verify?"（四步链路是什么？策略检查具体检查什么？）
  2. "What happens if the policy check rejects a proposal? Who is told?"（被拒后怎么办？通知谁？）
  3. "Why did you use publish-subscribe? What are the trade-offs versus a direct service call?"（为什么用发布订阅？对比服务调用有何取舍？）

#### P3-3 Chassis power control

> allocated body velocity to four Mecanum wheels, estimated power demand from real-time power and buffer-energy feedback and scaled wheel speeds, keeping the chassis manoeuvrable under power limits.

- **做了什么**：把车体速度指令分配到四个麦轮；用实时功率和缓冲能量反馈估计功率需求，按比例缩放轮速，保持在功率限制下仍可机动。
- **技术名词**：Mecanum inverse kinematics（麦轮逆解：$v_i$ 由 $v_x,v_y,\omega$ 线性组合）；power limit（裁判系统规定的功率上限）；power model（典型做法：功率 ≈ 力矩×转速 + 铜损 + 静态损耗）；scaling（等比例缩放轮速目标以保持运动方向）。
- **英文追问**：
  1. "Write the inverse kinematics of a Mecanum chassis."（麦轮逆解。）
  2. "Why scale all four wheels by the same factor instead of clipping each?"（为何整体缩放而非各自限幅？——保持运动方向不变。）
  3. "How did you estimate power demand from feedback?"（如何估算功率需求？）
  4. "What happens when the buffer energy runs out?"（缓冲能量耗尽怎么办？）
- **回答方向**：`【待你补全：功率模型形式与参数获取方式；缩放策略；缓冲能量阈值逻辑】`。
- **对应文档**：基础：[差速_麦克纳姆_全向轮与车辆运动学](../02_基础知识/02_力学与建模/04_差速_麦克纳姆_全向轮与车辆运动学.md)、[电机_编码器_驱动与力矩控制](../02_基础知识/08_嵌入式与通信/05_电机_编码器_驱动与力矩控制.md)、[FreeRTOS 实时系统](../02_基础知识/08_嵌入式与通信/02_FreeRTOS实时系统.md)、[CAN_FDCAN 与电机通信](../02_基础知识/08_嵌入式与通信/03_CAN_FDCAN与电机通信.md)。

### 4.4 P4 — OpenHarmony Smart Gardening System（May 2024 – Aug 2024）

**Overview（CV）**：edge-vision perception, agent decision-making and autonomous irrigation on OpenHarmony and RK3588; independently built the full loop from visual observation and decision to device-side execution.

## 本章要点速记

1. CV 抬头 "Robotics Algorithms · Motion Control · Autonomous Navigation" 是你对面试官的承诺；机器学习不在抬头里。
2. Education 的六门课是"低成本高风险"提问点，尤其是两门控制课。
3. 奖项：RoboMaster 全国总决赛三等奖、南部赛区二等奖；高校联盟赛 3V3 二等奖；华为 ICT 编程（OpenHarmony）省赛一等奖、国赛三等奖；校级两项二等奖。说奖项时注意团队属性。
4. P1 中 LQR 是**分析工具与模型参考**，部署的是级联 PID，别说反。
5. P7 的"异常归因三件套"：状态不一致、力矩限幅、触地切换，要准备真实案例。
6. P5 的"定位跳变根因"：时间、坐标系、运动方向不一致。

8. P4 是唯一的机器学习项目，要诚实地说"实践为主，想补理论"。
