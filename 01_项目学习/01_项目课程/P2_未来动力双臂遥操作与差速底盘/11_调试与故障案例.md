## 0. 方法论与通用日志清单

### 0.1 分层定位

所有故障先回答一个问题：**问题出在哪一层？** 分层顺序（自上而下）：算法层（目标对不对）→ ROS 层（消息有没有、对不对）→ 驱动层（映射、钳位、打包）→ 总线层（帧有没有、字段对不对）→ 电机层（电机有没有动、反馈对不对）。定位技巧是**在层与层之间的箭头上取样**，找到“上一层正确、下一层错误”的那个箭头，故障就在这两层之间。

### 0.2 每次实验必记的四类量

目标、实际、误差、约束触发。缺任何一类，事后复盘都会是猜测。

### 0.3 通用日志清单

| 线 | 必记字段 |
|---|---|
| VR | 原始 pose、转换后 pose、触发键状态、起点位姿、目标位姿、关节角 $q$、关节速度 $\dot q$、$\sigma_{min}$、QP 状态、目标年龄 |
| 主从 | 主臂关节角 / 速度、$g(q)$、MIT 五字段（$q_d,\dot q_d,K_p,K_d,\tau_{ff}$）、回读力矩、循环周期（实测） |
| 底盘 | 模式、目标轮速 / 反馈轮速（带符号）、里程计 $(x,y,\text{yaw})$、时间戳、`/cmd_vel` 年龄 |
| 总线 | `candump` 带时间差、错误计数（`ip -s link`）、回包缺失计数 |

**周期必须用实测时间戳**，不要用配置值——配置的 200 Hz 与实际 120 Hz 的差别，会让所有基于 $dt$ 的结论失真（见 [03 章 dt 提示](./03_MuJoCo与Mink入门.md)）。

### 0.4 复现与回归

每个修好的故障，都留一个“**复现条件 + 通过判据**”：例如案例 4 的复现是“把右臂缓慢伸向工作空间边缘”，通过判据是“$\max|\dot q|$ 不超过 2.5 rad/s”。下次改参数后跑一遍，不通过就不合入。这一习惯在 [20 工程化实践](./20_工程化实践_频率周期与问题解决.md) 里展开。

## 案例 1：按下触发键机械臂跳变【典型情形】

- **现象**：按下 VR 触发键的瞬间，手臂冲向很远的位置，或明显一抖。
- **可能原因（按概率）**：①目标用了**绝对**手柄位置，没有“目标 = 起点 + 缩放位移”；②起点保存的是旧的末端位姿（保存发生在 IK 更新之前，或用了上一次松开时的值）；③按键边沿检测失败（持续按下被当成每帧重新按下，起点被每帧覆盖，导致目标一直等于当前，随后松动）；④坐标映射 $R_a$ 错（见案例 2）使位移被放大成大角度。
- **定位**：在“按下”那一帧打印 $p_d$（目标）和 $p_{r0}$（起点），二者应当几乎相等（位移为零）。再看接下来几帧 $p_d-p_{r0}$ 是否随手柄位移线性增长。
- **处理**：目标 $=p_{r0}+s\,R_a(p_v-p_{v0})$；起点取当前正运动学结果；加**目标速率限幅**（本项目取值：线速度 ≤0.5 m/s，100 Hz 下单步 ≤5 mm），即使起点出错，手臂也只是缓慢走过去而不是跳变；触发键用滞回（0.9 按下 / 0.7 松开）。
- **验证**：按下 10 次，每次打印第一帧 $|p_d-p_{r0}|<10^{-3}$ m；故意在按键瞬间摇晃手柄，手臂仍平滑跟随。
- **防复发**：单元测试“按下首帧目标等于起点”；起点保存与目标计算放在同一个函数里，不允许分开。
- **面试怎么说**："A classic one is the arm jumping when the clutch is pressed. I check that the first-frame target equals the start pose, and I rate-limit the target so a wrong start pose cannot make the arm leap." （典型问题；检查首帧目标等于起点，并对目标限速。）

## 案例 2：前后左右错位或镜像【典型情形】

- **现象**：手柄向前，末端向侧面；或左右反向（镜像）。
- **原因**：$R_a$ 的行列写反（用了转置），或 $\det R_a=-1$（引入了镜像）。轴映射矩阵不是随便写的 3 个 $\pm1$：必须是**旋转矩阵**（正交、行列式 $+1$）。
- **定位**：单轴小幅度测试：只向前推 5 cm，看末端是否沿基座 $x$ 向前；再只向左，看是否沿 $y$；再只向上。三次测试能唯一确定 $R_a$ 的三列。同时断言 `np.allclose(Ra @ Ra.T, np.eye(3))` 且 `np.linalg.det(Ra) > 0`。
- **处理**：重建 $R_a$。本项目取值（README 自查表 #2）：XR 的 $-z$ 前、$-x$ 左、$y$ 上 → 基座 $x$ 前、$y$ 左、$z$ 上，$\det=+1$。方法是：写出“XR 的每个轴在基座系下的方向”，作为矩阵的**列**。
- **验证**：三个单轴测试全部符合；再做一个斜方向（前+左）测试，末端沿 45° 方向。
- **防复发**：把三个单轴测试写成启动自检脚本，每次换设备 / 换软件版本都跑一遍。
- **面试怎么说**："If the mapping is a transpose, a single-axis test exposes it in seconds, and I assert orthonormality and determinant plus one at startup." （转置映射，单轴测试几秒钟暴露，并在启动时断言正交且行列式 +1。）

## 案例 3：转手柄时夹爪绕自身轴滚转【典型情形】

- **现象**：绕竖直轴转手柄，夹爪却绕自己的轴滚动，而不是跟着手柄绕竖直轴转。
- **原因**：旋转增量用了**右乘**。$R_d=R_{r0}\,\Delta R'$ 是在夹爪自己的坐标系里叠加旋转；而操作者想要的是“在基座系里转”，应当**左乘**：$R_d=(R_a\,\Delta R\,R_a^T)\,R_{r0}$。
- **定位**：把夹爪朝前水平放置，绕竖直轴转手柄 30°，看夹爪指向：左乘时夹爪水平转 30°；右乘时，只有当夹爪的自身轴恰好竖直才一致，其他姿态会错。
- **处理**：改为左乘，并对 $\Delta R$ 做相似变换 $R_a\Delta R\,R_a^T$，把 VR 系下的旋转表达到基座系里。
- **验证**：在三个不同初始姿态下重复测试，行为一致。
- **防复发**：写旋转更新的数值测试：给定 $R_{r0}$、$\Delta R$，对比解析结果。
- **面试怎么说**："Left multiplication rotates about fixed base axes; right multiplication rotates about the gripper's own axes, which feels like the gripper is rolling." （左乘绕基座固定轴，右乘绕夹爪自身轴。）

## 案例 4：接近伸直时关节暴冲【真实经历】

- **现象**：操作者把手柄推向远处，手臂接近完全伸直时，某个关节（多数是肩部 / 肘部）突然高速转动，并带来明显抖动。
- **可能原因（按概率）**：①末端雅可比最小奇异值 $\sigma_{min}\to0$，逆映射增益 $\sim1/\sigma$ 放大，微小目标位移变成大关节速度；②阻尼不足（QP 里 `lm_damping` 偏小）或速度约束没有生效；③目标本身超出可达空间，求解器在边界上反复“挣扎”；④循环周期抖动，积分步长不一致放大了速度。
- **定位**：日志里并排画 $\sigma_{min}$ 与 $\max|\dot q|$：在本项目的日志里，二者的变化同步出现——$\sigma_{min}$ 低于约 0.05 时，关节速度才出现尖峰，高于这个值时不出现（README 自查表 #5、99 章问答 32）。再看是哪一个关节速度最大：伸直时肘关节接近 0。
- **处理**：三层同时用：①QP 里加 Levenberg–Marquardt 阻尼（`lm_damping=0.05`，学习笔记核对值）并显式传入全局 `damping=1e-3`；②关节速度约束（J1–4 取 2.5 rad/s，J5–7 取 4 rad/s），写在目标端与驱动节点；③目标限速 0.5 m/s，并在 $\sigma_{min}<0.05$ 时进一步降低目标速率（把目标位移乘以一个 0–1 的比例）。注意：**阻尼不是限位**，它只抑制放大，不保证不越界，硬限位另有（见案例 5 与 [05 章](./05_约束与限位.md)）。
- **验证**：重复“缓慢伸向边界”的动作 20 次，$\max|\dot q|\le2.5$ rad/s（J1–4），伸直附近末端轨迹平滑；对比修复前后同一动作的速度曲线。
- **防复发**：日志常驻 $\sigma_{min}$；回归脚本里包含“伸向边界”这一用例；任何调整阻尼、权重、限位的改动都必须重跑它。
- **面试怎么说**："The arm sped up near full extension. The log showed the smallest singular value dropping below about 0.05 exactly when joint speed spiked, so I added damping and joint speed limits and slowed the target near singular poses." （伸直时关节暴冲；日志显示最小奇异值低于约 0.05 时速度尖峰，所以加阻尼、速度约束并在奇异附近降低目标速度。）

## 案例 5：IK 不动也不报错【典型情形】

- **现象**：操作者在动，机械臂纹丝不动，日志也没有报错。
- **可能原因（按概率）**：①QP 求解失败被捕获后“返回当前 $q$”，下游当作新目标继续发，手臂“保持”；②触发键没有超过阈值（0.9），所以参考没有被建立；③下游使用了旧目标（目标年龄过大但没有保护）；④求解成功但解为零速度（约束互相冲突，如目标在关节限位外）。
- **定位**：在 IK 里**记录失败计数和目标年龄**；打印触发键原始值；检查目标是否落在可达空间内（用正运动学的包围盒）。
- **处理**：失败计数达到阈值（本项目取 3 次连续）就告警；持续失败（>10 次）转入“保持并提示”或停机；不要把“保持”当作安全状态（上游死了，保持也是错的）。
- **验证**：人为构造一个不可达目标，应在 3 个周期内告警，而不是静默。
- **防复发**：所有“异常时返回默认值”的代码路径都必须带计数与日志。
- **面试怎么说**："Returning the current configuration on a failed solve is not a safe stop; I count failures and escalate to a hold-and-alarm or stop." （失败返回当前构型不是安全停机；我计数并升级为保持告警或停机。）

## 案例 6：四元数偶发翻转【典型情形】

- **现象**：旋转姿态偶尔突然翻转 180° 或抖一下，之后恢复。
- **原因**：①$q$ 与 $-q$ 表示同一姿态，线性融合（低通滤波）时两者符号相反会相消；②四元数顺序（xyzw 与 wxyz）在不同库之间混用。
- **定位**：打印相邻帧四元数的点积：点积接近 $-1$ 说明符号翻转；检查范数是否偏离 1。
- **处理**：融合前统一半球（`if dot(q, q_prev) < 0: q = -q`）；显式写一个顺序转换函数，别在代码里散落索引。
- **验证**：构造相邻帧符号相反但姿态相同的输入，滤波输出应保持稳定。
- **防复发**：约定“系统内部一律用 xyzw，进出库时转换”，并在转换函数上写注释和单元测试。
- **面试怎么说**："Quaternions double-cover rotations, so before blending I flip the sign if the dot product is negative." （四元数双覆盖，融合前若点积为负就翻符号。）

## 案例 7：主臂越拖越重【典型情形】

- **现象**：松手后手臂不是悬停，而是加速下掉；或者往上推时变得“更重”。
- **原因**：重力补偿**符号反**。符号可能错在任一层：URDF 关节轴方向、编码器正方向、电机正方向、关节映射。
- **定位**：水平摆臂，**单关节**只发 $g(q)$ 的那一个分量，观察是掉下去还是飘上去；对比回读力矩与指令方向。逐个关节做，一次一个，从末端往根部。
- **处理**：在映射层乘 $-1$；确认正确后，补偿比例从 0.5 逐步升到 1.0，并保证最后一个关节留 10%–20% 的余量（`gravity_comp_ratio` 第 7 项取 0.8，README 自查表 #8）。
- **验证**：手臂在 5 个不同姿态下都能悬停不动，松手后 5 s 内漂移 <2°。
- **防复发**：把符号测试做成启动检查；URDF、电机、映射的正方向写进一张表。
- **面试怎么说**："If the arm gets heavier when you let go, the sign is wrong. I test one joint at a time with only the gravity term." （越松越重说明符号反；逐关节只发重力项测试。）

## 案例 8：主臂啸叫 / 自激【典型情形】

- **现象**：主臂在某些姿态发出高频啸叫或持续震颤。
- **原因**：纯力矩模式 + 延迟 + 模型误差形成的正反馈；科氏力 / 摩擦补偿增益过大；速度噪声被放大。
- **定位**：画关节速度的频谱，找出震颤频率；临时关掉科氏和摩擦补偿（源码里的 `CORIOLIS_GAIN=0.1`、`FRICTION_GAIN=0.3` 只是缩放，设 0 即关）。
- **处理**：加小 $K_d$（右臂 `[0.5,0.5,0.1,0.1,0.1,0.2,0.2]`，源码注释里提到右臂关节 2 曾需要更大的 $K_d$ 才稳定）；提高循环频率；对速度做一阶低通（`dq_alpha`）；降低补偿比例。
- **验证**：自由悬停与缓慢拖动时无啸叫，频谱中不再有尖峰。
- **防复发**：新增补偿项时，从 0 开始逐步加大，每一步观察 1 分钟。
- **面试怎么说**："Pure torque control with delay and model error can oscillate. I added small damping and low-pass filtered the velocity." （纯力矩 + 延迟 + 模型误差会震荡；加小阻尼并对速度低通。）

## 案例 9：从臂下垂与滞后【典型情形】

- **现象**：从臂跟随主臂时，静止后比主臂低一点；运动时总落后一拍。
- **原因**：①从臂没有重力前馈，稳态偏差 $e\approx g/K_p$（例：$3.4/300\approx0.6^\circ$；$K_p=50$ 时 $3.9^\circ$）；②没有速度前馈，匀速滞后 $\approx K_d\omega/K_p$；③通信与电机延迟 $D$ 造成滞后 $\omega D$。
- **定位**：画主从关节角叠加曲线，静止段看常值偏差（重力），运动段看相位差（延迟与速度前馈）。
- **处理**：本项目从臂 $K_p=[50,50,50,50,10,10,10]$，$K_d=[1.2,1.2,1.2,1.2,0.3,0.2,0.3]$，带速度前馈（`vel` 取主臂速度并低通），不带重力前馈（`torque=0`），稳态误差通过较高的 $K_p$ 控制在 0.02 rad 以内；可选：加 $g(q)$ 前馈。
- **验证**：稳态误差 <0.02 rad，运动中滞后约 3 个控制周期（100 Hz 下约 30 ms）。
- **防复发**：跟踪误差（RMS 约 0.01 rad）作为回归指标，增益变更前后各测一次。
- **面试怎么说**："Without gravity feed-forward the steady error is roughly gravity torque over Kp, and without velocity feed-forward the lag is roughly Kd times speed over Kp." （无重力前馈稳态误差约 g/Kp；无速度前馈滞后约 Kd·ω/Kp。）

## 案例 10：力矩符号翻转（打包不钳位）【读码发现 + 单测复现】

- **现象**：指令力矩超出量程时，关节猛地向反方向动。
- **原因**：v1 的 `_pack_mit` 不钳位，12 位力矩字段回绕。DM4310 上 $+11$ N·m：$\lfloor21/20\times4095\rfloor=4299$，取模 $4299-4096=203$，解码得 $203/4095\times20-10=-9.0$ N·m——**符号翻转**。
- **定位**：对打包函数做**越界单测**：输入 $\pm11$、$\pm100$ N·m，检查解码值；看日志里指令力矩是否超过量程。
- **处理**：打包前钳位到量程（v2 的 `_pack` 已经这样做，`XArmcontroller_v2.py` 第 159–181 行）；上层也限幅。这是团队的驱动封装，我读码发现并用单测确认，不是我写的修复。
- **验证**：越界输入时输出饱和在 $\pm$ 量程。
- **防复发**：任何定点编码函数都必须有“越界 / 边界 / 符号”三个单测。
- **面试怎么说**："Out-of-range inputs to a fixed-point packer can wrap and flip the sign, so always clamp before quantising and unit-test the boundaries." （定点编码越界会回绕翻符号；先钳位再量化并测边界。）

## 案例 11：底盘直行跑偏 / 里程计转角偏【真实经历】

- **现象**：给定直行，车逐渐向一侧偏，2 m 的横向偏移达到十几厘米量级；原地转一圈，里程计显示的角度不是 360°。
- **可能原因（按概率）**：①左右**轮径 / 参数不一致**（轮半径、减速比、标定系数）；②左右符号约定不一致（镜像轮）；③PID 增益或限幅左右不同；④地面打滑、轮胎磨损；⑤轮距常量不准，转角比例错（固件里 `L=0.375`、`×0.5` 的含义要核对）。
- **定位**：①把左右目标设成相等，读两侧反馈，看是否相等（排除指令侧问题）；②直线跑 5 m，量实际距离与里程计距离的比，得到轮半径修正；③原地转 10 圈，量实际角度与里程计角度的比，得到轮距修正；④左右互换轮的位置，看偏向是否跟着轮走（定位到某只轮）。
- **处理**：修正轮半径与轮距（本项目标定值：轮半径 0.13 m、轮距 0.75 m，各重复 3 次取均值）；检查符号链（09 章 11.3）；左右 PID 增益统一。结果：2 m 直行横向偏移 <5 cm；5 m 往返距离误差约 2%；原地转 10 圈累积航向误差约 30°。
- **验证**：每次改参数后重复“2 m 直行 + 原地转 10 圈”两个测试，记录偏移与角度；变化超过阈值就回滚。
- **防复发**：标定值写入配置文件而不是散落在代码里；每次换轮胎 / 电池重做标定；长期改进是融合 IMU 的 yaw。
- **面试怎么说**："The base drifted sideways. I fed equal targets to both wheels and compared the feedback, then calibrated the wheel radius with a straight run and the wheelbase with in-place turns, and the sideways drift over two metres dropped below five centimetres." （底盘跑偏：左右目标相等看反馈，用直线标定轮半径、原地转标定轮距，2 m 偏移降到 5 cm 以内。）

## 案例 12：自动模式失联车不停【读码发现】

- **现象**：自动模式下上位机断开（或崩溃），车继续按最后的速度前进。
- **原因**：`rc_flag` 从未被写入，`host_online` 一路加到 5000 后停，判据 `> 5000` 永不成立（09 章隐患 1）；另外 AUTO 分支向 FDCAN1 发送未初始化的 `tx_data`（隐患 2）。
- **定位**：断开上位机，观察 `host_online` 与 `chassis.spd_input`；用调试器看 `can_spd_input.rc_flag` 是否变化。
- **处理**：（固件侧建议，由团队决定）在 0x050 回调更新心跳，判据改 `>=`；初始化缓冲区；删除误发。**我实际做的**是上位机侧：`/cmd_vel` 超过 300 ms 无更新则发零速（0x050 全零），把风险在不改固件的前提下兜住。
- **验证**：自动模式下拔掉上位机 CAN 线，车应在约 300 ms 内停下（用上位机 timeout）；固件修复后再验证 500 ms 内由板子自己停。
- **防复发**：任何看门狗必须有“被喂狗 → 状态更新”和“超时 → 动作”两个单测；评审时问“这个标志位在哪里被写”。
- **面试怎么说**："I found while reading the firmware that the host heartbeat flag is never updated, so I did not rely on it; I added a velocity command timeout on the host side. This was a code-reading finding, not a failure on the robot." （读码发现心跳标志从未更新，所以不依赖它，在上位机侧加了速度命令超时；这是读码发现而非机器人上的故障。）

## 案例 13：里程计突变【读码发现】

- **现象**：长时间运行后，上位机看到的 x 或 y 突然从很大的正数跳到很大的负数。
- **原因**：x/y 以 `int16` 毫米上报（×1000），超过 ±32.767 m 回绕（09 章隐患 4）。
- **定位**：画 x 随时间曲线，看跳变点是否恰好在 ±32767 mm；检查上位机解码是否按有符号 int16。
- **处理**：上位机侧**展开回绕**（相邻两帧差超过 32768 就加减 65536），或改协议位宽 / 单位（cm，或 4 字节）；周期性复位里程计原点。
- **验证**：构造 40 m 直线，里程计曲线连续。
- **防复发**：协议文档里写明量程；每个字段做“最大值是否会溢出”的评审。
- **面试怎么说**："The odometry is packed as 16-bit millimetres, so it wraps at about 32 metres; I unwrap it on the host." （里程计 16 位毫米，约 32 m 回绕；上位机展开回绕。）

## 案例 14：总线收不到反馈 / 间歇断连【真实经历】

- **现象**：`recv_all` 经常超时（10 ms），关节状态不更新；或者运行一段时间后某条臂突然不响应，重新插拔后恢复。
- **可能原因（按概率）**：①物理连接：接头松动、线缆屏蔽层接触不良、**终端电阻缺失或多装**（空载量 CAN_H–CAN_L 应约 60 Ω）；②波特率不一致；③电机未使能或已被自动失能（总线静默约 1 s）；④ID 冲突或过滤器没放行回包 ID（0x11–0x18、0x581/0x583）；⑤上位机适配器 / 驱动问题（USB 供电不足）。
- **定位**：①`ip -details -statistics link show can0`：看 `bus-error`、`error-warn`、`restarts` 计数；②`candump can0 -td`：有没有回包、间隔是否均匀；③关电量电阻（约 60 Ω）；④单独接一个电机，逐个排除；⑤轻轻晃动接头，看错误计数是否跳升——现场就是靠这一步找到接触不良的接头。
- **处理**：重做接头 / 换线，保证两端各一个 120 Ω 终端电阻；统一 1 Mbit/s；使能后立刻读回包确认；硬件节点里**回包缺失 >3 个周期告警、>10 个周期失能**整条臂，避免带着坏数据继续控制。
- **验证**：连续运行 30 分钟，错误计数不增，回包缺失 0 次。
- **防复发**：上电自检（逐个电机读回包）；接线表与终端电阻位置写进维护文档；接头用锁扣或热熔胶固定。
- **面试怎么说**："Intermittent bus loss turned out to be a loose connector. I checked the error counters, measured the termination resistance, and wiggled the connectors while watching the counters. After fixing it, I made the driver disable the arm if replies went missing for ten cycles." （间歇断连最后是接头松；查错误计数、量终端电阻、边晃接头边看计数；修好后让驱动在回包缺失十个周期时失能。）

## 15. 面试问答（6 个）

**Q1. Tell me about a time a robot behaved unexpectedly.**

> Near full arm extension one joint suddenly sped up. I plotted the smallest singular value of the Jacobian next to the maximum joint speed and saw the spikes only when it dropped below about 0.05. So the cause was the near-singular amplification, not noise. I added damping, joint speed limits and slowed the target near that region, then repeated the stretching motion twenty times and checked that joint speed stayed within limits.

中文：伸直时关节突然加速；把雅可比最小奇异值与最大关节速度并排画，奇异值低于约 0.05 时才出现尖峰，所以是近奇异放大；加阻尼、速度约束、降低目标速度，并重复 20 次验证。

- *L2：Why not just clip the joint speed?* Clipping after the solve changes the direction of motion and makes the end effector drift; it is better to put the bound inside the optimisation and also keep damping. *（求解后再裁剪会改变运动方向、使末端漂移；应把约束放在优化内部并保留阻尼。）*
- *L3：How do you know damping did not hide a different problem?* I kept the singular value in the log and compared tracking error with and without damping on the same motion; the residual increased only slightly near singular poses. *（日志里保留奇异值，同一动作对比有无阻尼的跟踪误差，仅在奇异附近略增。）*

**Q2. How do you debug a fault that could be in the algorithm, the ROS layer or the hardware?**

> I localise by layer: check the target on the ROS topic, then the CAN frame fields, then the encoder feedback. The fault is between the first pair of layers where the data stops being right. For example, if the target on the topic is correct but the joint moves the wrong way, the sign is in the driver mapping.

中文：按层定位：话题上的目标 → CAN 帧字段 → 编码器反馈；故障在数据开始出错的两层之间。

**Q3. Describe a bug you found by reading code rather than by testing.**

> In the base firmware, the zero-speed rule for a lost host depended on a flag that was never updated, so it could never fire. I did not change the vendor framework, but I added a command timeout on the ROS side that sets zero speed after 300 milliseconds, and I listed the issue for the team.

中文：底盘固件里“上位机失联就零速”依赖一个从未更新的标志，永远不会触发；我没改团队框架，但在 ROS 侧加了 300 ms 超时零速，并把问题记给团队。

**Q4. How do you make sure a fix does not break something else?**

> Every fixed fault gets a reproduction step and a pass criterion, for instance stretching the arm to the boundary with joint speed under 2.5 radians per second. I rerun these after any change to damping, weights or limits.

中文：每个修复保留复现步骤和通过判据（如伸向边界关节速度 <2.5 rad/s），改阻尼 / 权重 / 限位后重跑。

**Q5. A wheel base drifts sideways. What do you do?**

> First give both wheels equal targets and compare the feedback to separate command problems from physical ones. Then calibrate the wheel radius with a five-metre straight run and the wheelbase with ten in-place turns, and check the sign convention of the mirrored wheel. Afterwards the drift over two metres was under five centimetres.

中文：先给两轮相同目标比较反馈，区分指令问题与物理问题；用 5 m 直线标定轮半径、10 圈原地转标定轮距，检查镜像轮符号；之后 2 m 偏移 <5 cm。

**Q6. What would you change to make debugging easier next time?**

> I would log measured loop periods, the target age and the smallest singular value by default, record a rosbag for every real-hardware run, and keep the calibration values in a versioned config file instead of the code.

中文：默认记录实测循环周期、目标年龄、最小奇异值；每次真机运行录 rosbag；标定值放进有版本的配置文件。

### 要点速记

1. 先分层再定位：算法 → ROS → 驱动 → 总线 → 电机；在箭头上取样。
2. 每次实验记四类量：目标、实际、误差、约束触发；周期用实测。
3. “保持”不等于“安全”；失败要计数、告警、升级。
4. 打包前钳位；定点编码测越界 / 边界 / 符号。
5. 左乘是基座系旋转；$R_a$ 必须正交且 $\det=+1$。
6. 重力补偿符号用“单关节只发重力项”测。
7. 看门狗要问“标志位在哪里被写”；读码发现不等于我的贡献。
