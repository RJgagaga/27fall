## 1. 问题：怎么知道土壤"够不够湿"

灌溉控制是反馈控制：**被控量**是土壤湿度，**执行器**是水泵，**传感器**是土壤湿度探头。控制器需要一个能和阈值比较的数。探头给的是模拟电压，MCU 的 ADC 把它变成整数计数（count）。从"计数"到"我们愿意拿来比阈值的湿度数"，中间有三步：

```text
物理量(土壤含水) → 探头电压(V) → ADC计数(整数) → 标定映射 → 湿度%(0..100) → 与阈值比较
```

每一步都会引入误差：探头非线性、温度/盐分/接触不良、ADC 量化与噪声、标定点选择。理解这些，才能回答"这个 55 到底有多可信"。

## 2. 土壤湿度探头的原理

| 类型 | 原理 | 输出趋势 | 优点 | 缺点 |
|---|---|---|---|---|
| 电阻式 | 两根金属探针测土壤电阻；越湿电阻越小 | 常见接成分压，越湿输出电压越高或越低取决于接法 | 便宜 | 电解腐蚀快、受盐分影响大 |
| 电容式 | 土壤介电常数随含水量变化，改变振荡频率/电压 | 常见模块**越湿输出电压越低** | 不直接接触金属、寿命长 | 仍受温度、土壤类型、插入深度影响 |

此前对源码的阅读线索显示湿度公式的斜率为**负**（$-0.05$）：ADC 计数越大越"干"，这与常见电容式模块"越湿电压越低"一致。**你实际使用的探头型号、输出趋势属于实机细节**，见 README 自查表。

> **注意**：探头给出的是"介电常数/电阻的某个函数"，不是体积含水量（VWC, m³/m³）。要得到真实 VWC 需要用已知含水量的土样做标定，且不同土壤、不同密实度的标定曲线不同。

## 3. ADC 基础：分辨率、参考电压、LSB

### 3.1 符号与单位

| 符号 | 含义 | 单位 |
|---|---|---|
| $N$ | ADC 位数 | bit |
| $V_{\text{ref}}$ | 满量程输入电压（参考） | V |
| $\text{count}$ | ADC 输出整数 | 无 |
| LSB | 最低有效位对应的电压步长 | V |

### 3.2 公式

$$\text{LSB} = \frac{V_{\text{ref}}}{2^{N}},\qquad V_{\text{in}} \approx \text{count}\times \text{LSB}$$

### 3.3 手算（教学示例：12 位、满量程 3.3 V）

$$\text{LSB}=\frac{3.3}{4096}=0.8057\ \text{mV}$$

$$\text{count}=2000 \Rightarrow V_{\text{in}} = 2000\times 0.8057\ \text{mV}=1.611\ \text{V}$$

> **注意**：Hi3861 的 ADC 实际位数、输入量程、衰减/偏置配置请以数据手册和你的代码为准（有的配置下输入范围远小于 3.3 V）。**【待你补全：ADC 通道、位数、参考电压、采样配置】**。本节只用来讲清楚公式。

### 3.4 量化误差与分辨率

ADC 的量化误差最大 $\pm 0.5$ LSB。后面标定斜率 $|a| = 0.05$ %/count，所以 1 个计数 = 0.05 个湿度百分点；±10 计数的噪声 = ±0.5 个百分点——与滞回带宽度（9 个百分点，见第 04 章）相比很小，这是阈值带设计时要核对的一件事。

## 4. 标定：从计数到湿度百分比

### 4.1 两点标定的推导

**目标**：找到线性函数 $m = a\cdot x + b$，其中 $x$ 为 ADC 计数，$m$ 为湿度百分比。

选两个参考点：
- 干点：探头放在空气中（或完全干的土），读数 $x_d$，定义 $m=0$；
- 湿点：探头放入水中（或饱和土），读数 $x_w$，定义 $m=100$。

联立：

$$0 = a x_d + b,\qquad 100 = a x_w + b$$

相减：$100 = a(x_w - x_d)$，所以

$$a = \frac{100}{x_w - x_d},\qquad b = -a\,x_d = \frac{100\,x_d}{x_d - x_w}$$

对于"越湿计数越小"的探头：$x_w < x_d$，所以 $a<0$。

### 4.2 教学算例

教学数值：$x_d = 2900$，$x_w = 1000$。

$$a=\frac{100}{1000-2900}=-0.05263,\qquad b = 0.05263\times 2900 = 152.63$$

检验：$x=2900$：$-0.05263\times 2900+152.63 = 0$ ✓；$x=1000$：$-52.63+152.63=100$ ✓。

任意读数 $x=2000$：$m = -0.05263\times 2000+152.63=47.37$。

### 4.3 笔记中记录的系数的含义（推算）

此前对源码的阅读记录的映射为：

$$m = -0.05\cdot \text{ADC} + 147.52,\qquad m\leftarrow \text{clip}(m, 0, 100)$$

由两点标定公式反推（**推算**，不是你测得的参考点）：

- 斜率 $a=-0.05 \Rightarrow x_w - x_d = 100/(-0.05) = -2000$，即干/湿参考相差 2000 计数；
- 截距 $b = 147.52 = -a x_d = 0.05\, x_d \Rightarrow x_d = 2950.4$，于是 $x_w = 950.4$。

也就是说，这条线假定 **计数约 950 对应 100%，约 2950 对应 0%**。你可以拿它来核对：你当时测的干/湿读数是不是接近这两个值？**【待你补全：当时的标定方法与参考读数】**。

### 4.4 clip 的含义

湿度结果 $m<0$ 或 $>100$ 没有物理意义，所以截到 $[0,100]$。**但 clip 会掩盖故障**：探头断线时 ADC 常顶到某个极端值，映射出的 $m$ 可能被截成 0（"极干"），自动逻辑看到 0 就会开泵——见第 7 节。

### 4.5 "56%" 是什么

56 是**这条标定曲线上的 56**，不是"土壤含水 56%"。换探头、换土、换插入深度，同一个土壤状态的"湿度%"会变。面试里说：

> "The percentage is a calibrated relative index. It is good enough for a threshold controller on one probe and one pot, but it is not volumetric water content."

## 5. 手算：整数截断与边界

### 5.1 浮点公式 vs 整数公式

在没有浮点单元或想省代码的 MCU 上，常用**定点（整数）**写法。把系数乘 100：

$$m_{100} = -5\cdot \text{ADC} + 14752 \quad(\text{单位 }0.01\%)$$

$$m = \left\lfloor \frac{m_{100}}{100}\right\rfloor\ (\text{正数时整数除法即向零截断})$$

**手算**：ADC = 2000：$m_{100} = -10000+14752=4752$，$m=47$（与浮点 47.52 截断一致）。

| ADC | 浮点 $m$ | 截断后整数 $m$ |
|---|---|---|
| 1500 | $-75+147.52=72.52$ | 72 |
| 1600 | $-80+147.52=67.52$ | 67 |
| 1650 | $-82.5+147.52=65.02$ | **65** |
| 1700 | $-85+147.52=62.52$ | 62 |
| 1800 | $-90+147.52=57.52$ | 57 |
| 1850 | $-92.5+147.52=55.02$ | 55 |
| 1900 | $-95+147.52=52.52$ | 52 |
| 2000 | $-100+147.52=47.52$ | 47 |
| 2200 | $-110+147.52=37.52$ | 37 |
| 2700 | $-135+147.52=12.52$ | 12 |
| 2950 | $-147.5+147.52=0.02$ | 0 |

### 5.2 阈值边界上的"整数陷阱"

假设状态机用**严格不等号**，停止条件是 $m>65$，且 $m$ 是整数：

- ADC = 1650 → 浮点 65.02 > 65 → 若用浮点会**关泵**；
- 但整数截断后 $m=65$，$65>65$ 为假 → **不关泵，继续保持**。

也就是说**截断位置决定了阈值实际落在哪个 ADC 值**：浮点比较时 ADC ≤ 1650 就会关泵（$m>65 \iff x<1650.4$），而整数（截断）比较时要到 $m\ge 66$ 才关。对应的计数为：

$$m\ge 66 \iff -0.05x+147.52\ge 66 \iff x\le 1630.4$$

所以 ADC ≤ 1630 才关（1631 时 $m=65.97\to 65$ 不关）。**教训**：阈值比较发生在浮点还是整数、截断还是四舍五入，会让实际切换点漂移 1 个百分点（≈20 计数）。你的系统用的是哪种【待你补全】，面试时可以主动说"I'm aware of this boundary effect"。

## 6. 噪声与滤波

### 6.1 噪声来源

- 电源纹波、Wi-Fi 发射瞬间的电源跌落（Hi3861 是 Wi-Fi SoC，发射时电流脉冲大，ADC 参考也可能被扰动）；
- 探头接触不良、线缆过长、土壤中水分的微小波动；
- ADC 量化。

### 6.2 常见滤波

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 平均 | N 次求均值 | 简单，压随机噪声 | 对离群点敏感 |
| 中位数 | N 次取中位数 | 抗离群点 | 稍多一点排序代码 |
| 滑动平均 | 窗口滑动 | 平滑输出 | 引入滞后 |
| 一阶低通 | $y_k=\alpha x_k+(1-\alpha)y_{k-1}$ | 代码极短 | 需要选 $\alpha$ |

### 6.3 手算：一个离群点如何导致误开泵

教学数据：真实土壤读数约 1790（$m=58$ 左右，处于滞回带内，泵本应保持现状）。某次采样，5 个样本里有 1 个被干扰成 2400：

样本 = [1790, 1792, 1789, 2400, 1791]

- **均值**：$(1790+1792+1789+2400+1791)/5 = 9562/5 = 1912.4$；$m = -0.05\times 1912.4+147.52 = 51.9 \to 51$。**51 < 56 → 触发开泵！**
- **中位数**：排序 [1789, 1790, 1791, 1792, 2400]，中位数 1791；$m = 147.52-89.55 = 57.97\to 57$，在带内，不触发。

结论：**单个离群点就能让均值滤波的结果越过启动阈值**，而中位数不会。这也是"滤波 + 滞回"要同时使用的原因：滞回处理的是读数在阈值附近的小抖动，滤波处理的是尖峰。

### 6.4 滞后与采样周期

滤波会引入延迟：窗口 N 次、周期 T，则平均滞后约 $(N-1)T/2$。土壤响应很慢（分钟级），所以几秒的滞后没有关系；但如果你把采样周期拉得很长（比如 10 分钟），则要考虑"开泵后读数要多久才反映"，否则会出现**过冲**（泵一直开着，直到下一次采样才发现已经太湿）。采样周期与最长开泵时间要匹配设计。**【待你补全：你的采样周期、滤波方式、是否有最长开泵时间】**

## 7. 传感失效策略

### 7.1 为什么必须有

控制器信任一个数字去驱动执行器；传感器一旦出错，**错误的数字会变成物理动作**。对泵来说，最危险的失效是：

| 失效 | 典型表现 | 如果不处理 |
|---|---|---|
| 探头断线/脱落 | ADC 顶到极端值（取决于电路：接近 0 或满量程） | 映射成极干 → 自动持续开泵 → **淹盆** |
| 探头短路/进水 | 读数接近"极湿" | 永不浇水 → 植物干死 |
| 卡死 | 数值长时间完全不变 | 控制器以为土壤没变 |
| 偶发尖峰 | 单次异常值 | 误触发（见 6.3） |
| ADC 配置/电源问题 | 读数整体漂移 | 阈值整体偏移 |

此前对源码的静态阅读中，笔记记录的失败条件包含"传感断线读假干"，且**未记录到显式的新鲜度/失效分支**——所以你可以诚实地说"the original firmware is a threshold controller; I analysed its failure modes and here is how I would harden it"。下面是**典型加固做法（推荐方案，非你已实现的事实）**。

### 7.2 检查清单

1. **有效范围检查**：先校验**原始 ADC**（而不是 clip 之后的湿度）是否落在探头的物理合理范围内。

$$x \in [x_{\min}^{\text{valid}},\; x_{\max}^{\text{valid}}]$$

   例如由标定点 $x_w\approx 950$、$x_d\approx 2950$ 各留 ±300 的余量（教学数值）：有效范围 [650, 3250]。超出 → 判为**无效读数**，不要 clip 成 0 或 100。

2. **变化率检查**：土壤湿度不会在 1 秒内变化 30 个百分点。

$$\left|\frac{m_k-m_{k-1}}{T}\right| \le r_{\max}\quad(\text{教学取 } r_{\max}=5\ \%/\text{s})$$

   违反 → 丢弃该样本，用前值，并计数；连续 K 次违反 → 判传感故障。

3. **卡死检测**：连续很长时间 ADC 完全相同（含噪声时不可能完全相同）→ 怀疑卡死/冻结。

4. **新鲜度**：每个读数带采样时刻；控制器只使用"够新"的读数；超过 $T_{\text{stale}}$ 视为无效。

5. **交叉验证（服务端）**：服务端看到"湿度 12%、泵已开 10 分钟、湿度仍为 12%"，应判断为"泵无效/探头坏/水箱空"，发告警（见第 11、13 章）。

### 7.3 失效时的安全动作

必须明确：**无效读数时，泵应处于哪种状态？**

| 策略 | 做法 | 适用 |
|---|---|---|
| 关泵优先（fail-safe off） | 读数无效 → 关泵 + 告警 + 等待人工 | 盆栽、怕淹、水量可控 |
| 保持现状 + 超时关 | 读数无效 → 保持当前，但最长再运行 $T$ 秒后强制关 | 防止中途丢读数就断水 |
| 定时兜底浇水 | 读数长期无效 → 按固定节律少量浇 | 农业场景，需另评估 |

对于盆栽，通常推荐"关泵 + 告警"，并配合**最长连续开泵时间**与**最短停泵间隔**（防止任何单点故障造成无限浇水）。这些是硬件级保护，不依赖传感器。

### 7.4 状态流转

```text
            读到有效数据
     ┌───────────────────────────┐
     ▼                           │
  [VALID] ──连续 K 次无效/超时──▶ [INVALID/ALARM]
     ▲                           │
     └──── 连续 M 次有效 ─────────┘   （迟滞，避免在边界来回切）
```

INVALID 状态下：关泵、上报 `sensor_state=invalid`、等待恢复或人工；恢复条件也用"连续 M 次有效"，同样是一种滞回思想。

## 8. 教学示例代码

> 以下为**教学示例，非项目源码**；API 名称为示意，实际以 OpenHarmony Hi3861 SDK 为准。

```c
#include <stdint.h>
#include <stdbool.h>

#define ADC_VALID_MIN   650     /* 教学数值：由标定点留余量 */
#define ADC_VALID_MAX  3250
#define WINDOW            5

/* 定点标定：m100 = -5*adc + 14752  (单位 0.01 %) */
static int16_t adc_to_moisture(uint16_t adc)
{
    int32_t m100 = -5 * (int32_t)adc + 14752;
    int32_t m = m100 / 100;          /* 正数时向零截断 */
    if (m < 0)   m = 0;
    if (m > 100) m = 100;
    return (int16_t)m;
}

/* 中位数滤波：5 点插入排序 */
static uint16_t median5(const uint16_t s[WINDOW])
{
    uint16_t a[WINDOW];
    for (int i = 0; i < WINDOW; i++) a[i] = s[i];
    for (int i = 1; i < WINDOW; i++) {
        uint16_t k = a[i]; int j = i - 1;
        while (j >= 0 && a[j] > k) { a[j+1] = a[j]; j--; }
        a[j+1] = k;
    }
    return a[WINDOW / 2];
}

typedef struct { bool valid; int16_t moisture; } Reading;

/* 先验范围，再标定；无效读数不 clip */
static Reading read_moisture(const uint16_t samples[WINDOW])
{
    uint16_t x = median5(samples);
    Reading r = { .valid = false, .moisture = 0 };
    if (x < ADC_VALID_MIN || x > ADC_VALID_MAX) return r;
    r.valid = true;
    r.moisture = adc_to_moisture(x);
    return r;
}
```

自测这段代码（手算）：样本 [1790,1792,1789,2400,1791] → 中位数 1791 → `m100 = -8955 + 14752 = 5797` → `m = 57`，`valid = true`。样本全为 3300（断线顶到高位）→ 中位数 3300 > 3250 → `valid = false`（而不是被 clip 成"0% 极干"）。

- "我实现了完整的传感失效诊断"（除非你确实做了）；
- "湿度精度是 x%"（没有参考测量就没有精度数）。

**可以说**：
- 我知道映射是标定后的线性近似，知道 clip 会掩盖断线，知道阈值边界上的整数效应；
- 如果有更多时间，我会加范围检查、变化率检查和最长开泵时间。

## 10. 常见错误与故障现象

| 现象 | 可能原因 | 如何定位 |
|---|---|---|
| 泵一直开 | 探头断线读成"极干"；阈值写反；GPIO 极性理解反（见第 04 章） | 串口打印原始 ADC、$m$、状态；拔探头对比 |
| 泵从不开 | 探头短路读成"极湿"；标定斜率符号错 | 手指蘸水/干探头看读数方向 |
| 读数跳 | 供电噪声、接触不良、未滤波 | 示波器/连续打印；加中位数 |
| 同一盆换土后阈值不准 | 标定对象变了 | 重新两点标定 |
| 开泵后读数几分钟才变 | 土壤响应慢，采样/滞后不匹配 | 记录开泵时间与读数曲线 |
| 阈值附近"差一个" | 取整/截断/比较符边界 | 用 5.2 节的表核对 |

## 11. 面试怎么问、怎么答

**Q1. How does the Hi3861 get the soil moisture value?**

> "The probe outputs an analog voltage that changes with soil moisture. The Hi3861's ADC converts it to a count, and I map the count to a 0–100 index with a linear calibration, using a dry reference and a wet reference. I clip the result to the valid range. The percentage is a calibrated index for this probe and this soil, not volumetric water content."

（译：探头输出随湿度变化的模拟电压；ADC 变成计数；再用干/湿参考点做线性标定映射为 0–100 指数并截到合法范围。百分比是针对该探头与土壤的标定指数，不是体积含水量。）

追问：**How did you choose the calibration points?**
> "I used a dry reading and a wet reading as the two endpoints and solved the linear map. 【补全：你的干/湿参考与读数】. I'd want to validate it against a reference measurement, for example by weighing soil samples."

追问：**What are the weaknesses of this approach?**
> "It's a single linear map, so it ignores soil type, temperature and salinity. Clipping can hide a disconnected probe, because an open circuit can look like very dry soil. For a more robust version I'd check the raw ADC against a valid range, add a rate-of-change check, and keep a maximum pump run time as a hardware-level backstop."

**Q2. How do you know the sensor is wrong?**

> "I check the raw reading against a physically plausible range before calibration, check that the value doesn't change faster than soil can, and look for a frozen value. When the reading is invalid, the safe action is to stop the pump and raise an alarm, rather than clipping the value and acting on it."

**Q3. Why filter, and why median instead of mean?**

> "A single spike in a five-sample window can drag the mean across the start threshold. For example, four readings near 1790 and one 2400 give a mean that maps to about 51 percent, which would start the pump, while the median stays around 57 and doesn't. Median filtering is cheap and robust to outliers."

**Q4. Does the percentage mean the pump should run when it's below 56?**

> "56 is a threshold on my calibrated index, chosen for this setup. It's a configuration value, not a universal soil threshold. It would have to be re-tuned for a different plant or probe."

**Q5（陷阱题）. What's your sensor accuracy?**

> "I haven't characterised it against a reference instrument, so I wouldn't quote an accuracy figure. What I can tell you is the resolution of the mapping, about 0.05 percentage points per ADC count, and that the noise I observed was small compared with the 9-point hysteresis band." — 只有当你确实观察过噪声时才能说后半句；否则只说前半句。

## 本章要点速记

1. 链路：物理湿度 → 探头电压 → ADC 计数 → 标定映射 → 湿度指数 → 阈值比较。
2. $\text{LSB}=V_{\text{ref}}/2^N$；本项目斜率 0.05 %/count，1 计数 = 0.05 个百分点。
3. 两点标定：$a=100/(x_w-x_d)$，$b=-a x_d$；笔记系数反推干/湿点约 2950/950（推算）。
4. 百分比是标定后的指数，不是体积含水量；56 是该曲线上的值。
5. 整数截断会让切换点漂移约 1 个百分点（≈20 计数）。
6. 单个离群点可使均值越过启动阈值，中位数不会。
7. clip 会掩盖断线；应先检查原始 ADC 的有效范围。
8. 传感失效时安全动作是关泵+告警，并配最长开泵时间等硬件级保护。

## 自测题

1. 12 位、3.3 V 的 ADC，计数 3000 对应多少伏？
2. 由 $x_d=2800$、$x_w=900$ 推出 $a$、$b$，并计算 $x=1850$ 的湿度。
3. 用笔记系数，ADC = 1750 的整数湿度是多少？它与 56、65 的关系？
4. 解释为什么 clip 会让断线的探头引起持续开泵。
5. 列出三种传感失效检测手段，并说明各自能抓到什么故障。

**参考答案**：
1. $3000\times 0.8057\text{ mV}=2.417$ V。
2. $a=100/(900-2800)=-0.05263$；$b=0.05263\times 2800=147.37$；$m=-97.37+147.37=50.0$。
3. $-87.5+147.52=60.02\to 60$；位于 56–65 带内，状态保持。
4. 断线读成极端高计数，映射为负数被 clip 成 0（极干），自动逻辑一直满足"<56 开泵"。
5. 范围检查（断线/短路）、变化率检查（尖峰/接触不良）、卡死检测（冻结/ADC 故障）。
