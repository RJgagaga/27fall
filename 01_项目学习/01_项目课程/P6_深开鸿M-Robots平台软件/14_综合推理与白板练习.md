## 1. 手算题

**W1（差速）** $r=0.1$ m，$L=0.5$ m，$v=0.4$ m/s，$\omega_z=-0.8$ rad/s。求 $\omega_L,\omega_R$。
答：$v_L=0.4-(-0.8)(0.5)/2=0.6$，$v_R=0.4-0.2=0.2$；$\omega_L=6$，$\omega_R=2$ rad/s。

**W2（阿克曼）** $L_w=0.8$，$v_x=1.0$，$\omega_z=0.5$。
答：$\tan\delta=0.4$，$\delta\approx21.8^\circ$。若 $\delta_{max}=20^\circ$，则 $\omega_{z,max}=v_x\tan20^\circ/L_w=0.364/0.8=0.455$ rad/s，需钳位。

**W3（麦轮）** $r=0.05$，$l_x+l_y=0.35$，$v_x=0$，$v_y=0.2$，$\omega_z=0$。
答：$\omega_{fl}=-4,\ \omega_{fr}=4,\ \omega_{rl}=4,\ \omega_{rr}=-4$ rad/s（纯横移，对角同号）。

**W4（NTP）** $t_1=50.000,t_2=50.040,t_3=50.042,t_4=50.030$。
答：$\delta=0.030-0.002=0.028$；$\theta=(0.040+0.012)/2=0.026$ s；不确定度 $\le0.014$ s。

**W5（坐标）** $T^{map}_{odom}$：平移 $(1,0)$，偏航 $180^\circ$；base 在 odom 为 $(2,1)$，偏航 0。base 在 map？
答：$R(180^\circ)(2,1)=(-2,-1)$，加 $(1,0)$ → $(-1,-1)$，偏航 $180^\circ$。

**W6（看门狗）** $v_{max}=0.6$，$a_{brake}=1.2$，$d_{safe}=0.4$。求 $T_{cmd}$ 上限。
答：制动距离 $0.36/2.4=0.15$；剩余 $0.25$；$T_{cmd}\le0.25/0.6\approx0.417$ s。

**W7（陈旧上限）** 反馈周期 20 ms，$k=3$，回路延迟预算 50 ms。
答：$kT=60$ ms，取小 → 50 ms。

**W8（带宽）** 12 台设备，30 Hz，负载 250 B，开销 60 B。
答：$12\times30\times310=111{,}600$ B/s ≈ 0.89 Mbit/s。

**W9（累积风险）** $p=0.2\%$，$n=300$。
答：$1-0.998^{300}\approx1-0.548=45.2\%$。

## 2. 接口设计题

**W10 设计一个能力注册表（C++ 接口草图）**

```cpp
struct DeviceRecord {
  std::string device_id;
  DeviceKind kind;
  std::vector<CapabilityDescriptor> caps;
  int schema_version;
  int64_t registered_ns;
  Health health;
};

class IRegistry {
 public:
  virtual ~IRegistry() = default;
  virtual Status Register(const DeviceRecord& rec) = 0;     // validates; rejects duplicates
  virtual Status Update(const std::string& id, const DeviceRecord& rec) = 0;
  virtual Status Unregister(const std::string& id) = 0;     // idempotent
  virtual std::vector<DeviceRecord> Find(const std::string& capability_id) const = 0;
  virtual std::optional<DeviceRecord> Get(const std::string& id) const = 0;
};
```
要点：校验（重复 id、版本、范围合理）、认证、线程安全、变化通知、注销幂等。字段为教学设计。

**W11 设计策略引擎的数据模型**：规则是纯函数 `(Proposal&, Context) -> RuleResult`；引擎持有有序规则；输出 Decision + trace + 策略版本；上限来自能力描述。可参考 [08 章第 13 节](./08_安全执行链.md) 的可编译实现。

## 3. QoS 选型题

**W12** 为下列 Topic 选 QoS（教学答案）：

| Topic | Reliability | Durability | History | 其他 | 理由 |
|---|---|---|---|---|---|
| 高频底盘状态 | BEST_EFFORT | VOLATILE | KEEP_LAST 1 | Deadline 2×周期 | 旧值无价值 |
| 设备能力记录 | RELIABLE | TRANSIENT_LOCAL | KEEP_LAST 1 | key=device_id | 晚到者要最新 |
| 设备公告/存活 | RELIABLE | TRANSIENT_LOCAL | KEEP_LAST 1 | Liveliness lease | 掉线检测 |
| 任务命令 | RELIABLE | VOLATILE 或谨慎 TRANSIENT_LOCAL | KEEP_ALL 或深度 N | Lifespan | 不可丢，但防重放 |
| 任务回执 | RELIABLE | VOLATILE | KEEP_LAST N | | 阶段回报 |
| 急停广播 | RELIABLE | TRANSIENT_LOCAL | KEEP_LAST 1 | 最高优先级 | 晚到者也须知 |（急停主路径仍应独立于 DDS）

## 4. 幂等执行器（可编译）

> 教学示例，已用 g++ -std=c++17 编译运行：同一 id 重发 3 次只执行 1 次。

```cpp
#include <cstdint>
#include <iostream>
#include <string>
#include <unordered_map>

enum class Outcome { Completed, Failed, Rejected };
struct Result { Outcome outcome; std::string detail; };

class IdempotentExecutor {
 public:
  explicit IdempotentExecutor(int64_t window_ns) : window_ns_(window_ns) {}

  template <typename Fn>
  Result Submit(const std::string& id, int64_t now_ns, int64_t valid_until_ns, Fn&& do_it) {
    Evict(now_ns);
    auto it = done_.find(id);
    if (it != done_.end()) { ++duplicates_; return it->second.result; }  // replay stored result
    if (now_ns > valid_until_ns) return {Outcome::Rejected, "expired"};
    Result r = do_it();                       // side effect once per id
    done_[id] = {r, now_ns};
    return r;
  }
  int duplicates() const { return duplicates_; }

 private:
  struct Entry { Result result; int64_t stored_ns; };
  void Evict(int64_t now_ns) {
    for (auto it = done_.begin(); it != done_.end();)
      it = (now_ns - it->second.stored_ns > window_ns_) ? done_.erase(it) : std::next(it);
  }
  int64_t window_ns_;
  std::unordered_map<std::string, Entry> done_;
  int duplicates_ = 0;
};
```
输出示例：`executed=1 duplicates=2`；过期提案 → `expired`。局限：去重表在内存，重启会丢；窗口应覆盖提案有效期；需持久化才能跨重启（`【待你补全：实际去重方式】`）。

## 5. 时序图练习

画出下列场景（答案要点）：

1. **设备上线到可接任务**：公告 → 能力注册（校验）→ 状态首帧 Valid → 标 Active。
2. **一次被修改的提案**：提案 → 规则链（限幅 Modify）→ 凭据 → 执行 → 回执含"被修改项"。
3. **回执丢失重发**：见 [08 章 11.2](./08_安全执行链.md) 图。
4. **上层崩溃**：设定值过期 → 看门狗 → 受控减速 → 回执 Aborted → 恢复需确认。
5. **传感器掉线**：驱动返回错误 → 状态 Stale → 分级降级 → 策略拒绝依赖它的提案。

## 6. 情景推理（what if）

| # | 情景 | 推理要点 |
|---|---|---|
| S1 | 两个调度器同时给同一机器人下任务 | 所有权/串行裁决；优先级；冲突拒绝并给原因 |
| S2 | 状态服务重启 3 秒 | 状态变 Stale；提案拒绝依赖状态者；stop 仍允许；恢复后重新同步 |
| S3 | 时钟被校时回拨 200 ms | 单调时钟不受影响；跨设备戳标记同步异常 |
| S4 | 新增一种底盘 | 写适配器 + 声明能力 + 过契约测试 + 配置符号表；上层不改 |
| S5 | 规则变更后拒绝率翻倍 | 回放旧流量对比；影子模式；回滚 |
| S6 | 订阅端收不到状态 | 查 QoS 兼容、domain/partition、类型、防火墙 |
| S7 | AI 规划器反复提交被拒提案 | 速率限制、结构化原因、重复上限后升级给人 |
| S8 | 校验器宕机 | 默认拒绝；stop 允许；执行端凭据过期；告警 |
| S9 | 20 台同时上电发现很慢 | 单播对等/发现服务器、错开启动、分区 |
| S10 | 要把平台用于带人的场景 | 提高风险等级：更严规则、人确认、独立硬件安全、重新评审——不能仅靠软件链 |
