## 1. 手算题

**W1（差速）** $r=0.1$ m，$L=0.5$ m，$v=0.4$ m/s，$\omega_z=-0.8$ rad/s。求 $\omega_L,\omega_R$。
答：$v_L=0.4-(-0.8)(0.5)/2=0.6$，$v_R=0.4-0.2=0.2$；$\omega_L=6$，$\omega_R=2$ rad/s。

**W2（阿克曼）** $L_w=0.8$，$v_x=1.0$，$\omega_z=0.5$。
答：$\tan\delta=0.4$，$\delta\approx21.8^\circ$。若 $\delta_{max}=20^\circ$，则 $\omega_{z,max}=v_x\tan20^\circ/L_w=0.364/0.8=0.455$ rad/s，需钳位。

**W3（麦轮）** $r=0.05$，$l_x+l_y=0.35$，$v_x=0$，$v_y=0.2$，$\omega_z=0$。
答：$\omega_{fl}=-4,\ \omega_{fr}=4,\ \omega_{rl}=4,\ \omega_{rr}=-4$ rad/s（纯横移，对角同号）。

**W4（NTP）** $t_1=50.000,t_2=50.040,t_3=50.042,t_4=50.030$。
答：$\delta=0.030-0.002=0.028$；$\theta=(0.040+0.012)/2=0.026$ s；不确定度 $\le0.014$ s。

**W5（坐标）** $T^{map}_{odom}$：平移 $(1,0)$，偏航 $180^\circ$；base 在 odom 为 $(2,1)$，偏航 0。base 在 map？
答：$R(180^\circ)(2,1)=(-2,-1)$，加 $(1,0)$ → $(-1,-1)$，偏航 $180^\circ$。

**W6（看门狗）** $v_{max}=0.6$，$a_{brake}=1.2$，$d_{safe}=0.4$。求 $T_{cmd}$ 上限。
答：制动距离 $0.36/2.4=0.15$；剩余 $0.25$；$T_{cmd}\le0.25/0.6\approx0.417$ s。

**W7（陈旧上限）** 反馈周期 20 ms，$k=3$，回路延迟预算 50 ms。
答：$kT=60$ ms，取小 → 50 ms。

**W8（带宽）** 12 台设备，30 Hz，负载 250 B，开销 60 B。
答：$12\times30\times310=111{,}600$ B/s ≈ 0.89 Mbit/s。

**W9（累积风险）** $p=0.2\%$，$n=300$。
答：$1-0.998^{300}\approx1-0.548=45.2\%$。

struct DeviceRecord {
  std::string device_id;
  DeviceKind kind;
  std::vector<CapabilityDescriptor> caps;

class IRegistry {
 public:
  virtual ~IRegistry() = default;

  virtual Status Update(const std::string& id, const DeviceRecord& rec) = 0;

## 4. 幂等执行器（可编译）

> 教学示例，已用 g++ -std=c++17 编译运行：同一 id 重发 3 次只执行 1 次。

```cpp
#include <cstdint>
#include <iostream>
#include <string>
#include <unordered_map>

enum class Outcome { Completed, Failed, Rejected };
struct Result { Outcome outcome; std::string detail; };

class IdempotentExecutor {
 public:
  explicit IdempotentExecutor(int64_t window_ns) : window_ns_(window_ns) {}

  template <typename Fn>
  Result Submit(const std::string& id, int64_t now_ns, int64_t valid_until_ns, Fn&& do_it) {
    Evict(now_ns);
    auto it = done_.find(id);
    if (it != done_.end()) { ++duplicates_; return it->second.result; }  // replay stored result
    if (now_ns > valid_until_ns) return {Outcome::Rejected, "expired"};
    Result r = do_it();                       // side effect once per id
    done_[id] = {r, now_ns};
    return r;
  }
  int duplicates() const { return duplicates_; }

 private:
  struct Entry { Result result; int64_t stored_ns; };
  void Evict(int64_t now_ns) {
    for (auto it = done_.begin(); it != done_.end();)
      it = (now_ns - it->second.stored_ns > window_ns_) ? done_.erase(it) : std::next(it);
  }
  int64_t window_ns_;
  std::unordered_map<std::string, Entry> done_;
  int duplicates_ = 0;
};
```
输出示例：`executed=1 duplicates=2`；过期提案 → `expired`。局限：去重表在内存，重启会丢；窗口应覆盖提案有效期。本项目口径：去重表每 5 s 快照到本地文件，进程重启后先静默一个有效期窗口再接新提案。

## 6.5 情景推理详解：把"要点"展开成完整回答

上一节的表格是要点。面试官真正想看的是你能不能把要点串成一段有逻辑的推理。下面选三个最容易被追问的情景，按"问题—符号与前提—推导—手算—在本项目里怎么用—常见错误—面试问答—自测"的顺序展开。

### 6.5.1 情景 S2：状态服务重启 3 秒

**它要解决什么问题。** 状态管理器是"机器人当前什么样"的唯一出口。它一旦停了，所有依赖状态的判断（任务层选机器人、策略校验的新鲜度规则、运动控制的反馈）都会失去输入。面试官想看的是：你有没有想过"下游此刻看到什么、做什么"，而不是只说"重启就好了"。

**符号与前提。** 设状态发布周期 $T=50$ ms（20 Hz），新鲜度上限 $T_{max}=3T=150$ ms（本项目口径：约 3 个周期）；服务停止时刻 $t_0$，恢复时刻 $t_0+3$ s。

**推导。**

1. 服务停止后，下游收到的最后一条状态年龄随时间增长：$age(t)=t-t_0+age_0$。
2. 当 $age>T_{max}$，也就是停止后约 100–150 ms，下游把状态判为 Stale。
3. 策略校验的"状态新鲜度"规则对依赖状态的提案回 `E_STALE`，不依赖状态的提案（例如 stop）照常放行；这是"stop 永远允许"原则的直接体现。
4. 运动控制层仍在执行已下发的、带有效期的设定值；设定值有效期通常很短（本项目取值约 200 ms），到期后看门狗触发受控减速。所以 3 秒停机期间机器人**不会盲目地继续跑**。
5. 恢复后，状态管理器先做一次完整同步（读取各适配器最新快照），首帧 Valid 之后才对外宣告 ready；任务层看到 ready 才重新派发。不自动续跑旧任务。

**手算。** 停机 3 s、速度 0.8 m/s：若没有有效期与看门狗，机器人会沿原方向多走 $0.8\times3=2.4$ m；有看门狗时，约 200 ms 后开始以 1.0 m/s² 减速，总位移约 $0.8\times0.2+0.8^2/(2\times1.0)=0.16+0.32=0.48$ m。差距 5 倍，这就是"带有效期的设定值"的价值。

**在本项目里怎么用。** 05 章的陈旧检测、07 章的设定值契约、08 章的新鲜度规则、15 章的 readiness 都在这个情景里同时出场，是一个很好的"串讲"题。

**常见错误。**

- 只说"重启后恢复"，不说停机期间机器人在做什么。
- 说"状态服务不会挂"。任何组件都要假设会挂。
- 恢复后直接续跑旧任务：旧任务的前提（位置、环境）可能已经变了。

**面试问答。**

> **Q**: What happens to a moving robot if the state service restarts for three seconds?
>
> **A**: The last state goes stale after about three publish periods, so the policy layer rejects proposals that depend on fresh state, but stop is still allowed. The setpoint the motion layer holds has a short validity, around 200 ms in our design, so the watchdog brings the robot to a controlled stop. After the restart, the state manager resyncs, publishes a valid first frame, and only then does the task layer dispatch again. I don't resume the old task automatically.
>
> 译：状态约 3 个周期后判陈旧，策略层拒绝依赖新鲜状态的提案但允许 stop；运动层的设定值有效期很短（我们设计约 200 ms），看门狗让机器人受控停车；重启后先重新同步、首帧 Valid 后任务层才重新派发，不自动续跑旧任务。

追问方向：为什么不让机器人在状态丢失时继续跑？→ 因为所有安全判断（距离、速度上限）都依赖状态，不能在"盲飞"时假设一切正常。

### 6.5.2 情景 S1：两个调度器同时给同一机器人下任务

**问题。** 多个提案来源（任务调度器、操作员控制台）同时指向同一台机器人，如果两者都被执行，机器人会在两个目标之间抖动，更糟的是动作互相覆盖。

**前提。** 每台机器人同一时刻只有一个任务所有者（owner），优先级高者可抢占，急停永远最高。提案带 `priority` 与 `seq`。

**推导。**

1. 提案 A（优先级 5）先到达，所有权为空 → 授予 A，状态 EXECUTING。
2. 提案 B（优先级 5）后到达，所有权已被 A 持有，且优先级不高于 A → 回 REJECTED，原因码 E_LIMIT 的冲突子类（本项目写作 `E_LIMIT:OWNED`），并带上当前 owner 的 proposal_id，方便对方决定等待还是放弃。
3. 若 B 的优先级为 9（例如操作员接管）→ 抢占：先向 A 回 ABORTED，机器人受控停车，再授予 B；整个过程在审计日志里是一对有序记录。
4. 急停：不经过所有权判断，直接放行并清除 owner。

**手算。** 设两个来源各以 1 Hz 发提案，竞争窗口为 1 s，且不加所有权：每秒两条命令交替，机器人每 0.5 s 换一次目标。若线速度 0.8 m/s，则每次换向前的位移约 0.4 m，足以撞上障碍。所有权把"并发冲突"变成"有序拒绝"。

**常见错误。** 用"最后到达者胜"来裁决（会让低优先级任务抢掉高优先级）；把裁决放在调度器里而不是执行侧（调度器之间无法互相看到）；不告诉被拒方原因，导致其无限重试。

**面试问答。**

> **Q**: How do you handle two schedulers dispatching to the same robot?
>
> **A**: Each robot has a single task owner at a time. A second proposal is rejected with the current owner's ID unless it has higher priority, in which case the first task is aborted cleanly and the second takes over. Emergency stop bypasses ownership. The arbitration lives on the execution side, because the schedulers can't see each other.
>
> 译：每台机器人同一时刻只有一个任务所有者；后到提案除非优先级更高否则被拒并告知当前所有者；更高优先级则先受控中止前者再接管；急停绕过所有权；裁决放在执行侧，因为调度器彼此看不见。

### 6.5.3 情景 S8：校验器宕机

**问题。** 策略校验是"唯一通道"上的门；门坏了，应该开还是关？

**推导。**

1. 默认拒绝（fail-closed）：校验服务不可用时，执行网关拿不到新的票据，所以所有需要票据的命令都被拒绝。
2. 已发出的票据有效期很短（运动类约 2 s），过期后自动失效，已经在执行的动作到期被看门狗收口。
3. stop 与急停不依赖校验服务：执行网关对它们走本地快速通道，因为"停下来"在任何情况下都是安全方向。
4. 告警：网关在连续 3 次请求超时后上报健康状态 Fault，任务层不再向该机器人派任务。
5. 恢复：校验服务重启后加载同一版本的策略（日志里可以核对策略版本号），先通过自检用例再开放。

**手算。** 设票据有效期 2 s，校验器宕机发生在票据签发后 0.5 s，则机器人最多再带着旧票据运行 1.5 s；这 1.5 s 内的动作是已被批准的、范围内的，风险有界。若有效期设为 60 s，风险窗口就是 60 s，这就是"短时票据"的意义。

**常见错误。** 为了"可用性"在校验器宕机时放行（fail-open）；把 stop 也挡在校验后面，导致宕机时停不下来。

**面试问答。**

> **Q**: What does the robot do if the policy checker is down?
>
> **A**: It fails closed. Without a fresh ticket the gateway rejects new commands, tickets already issued expire within about two seconds, and stop is handled locally, so the robot always can stop. The gateway reports a fault so the scheduler stops assigning tasks to it.
>
> 译：失败即关闭：没有新票据网关拒绝新命令，已发票据约 2 s 内过期，stop 在本地处理，机器人始终能停；网关上报故障，调度器不再派任务。

自测：为什么"短时票据"同时降低了校验器宕机与票据泄漏两种风险？（要点：两者的风险窗口都被票据有效期限制。）

## 6.6 白板作答流程与计时

白板题的失败多数不是不会，而是没有结构。给自己一个固定节奏，10 分钟题可以这样用：

| 分钟 | 做什么 | 说什么 |
|---|---|---|
| 0–1 | 复述问题、确认约束 | "So the goal is ...; the constraints are ...; may I assume ...?" |
| 1–3 | 画最小框图：谁发、谁收、谁裁决 | 先画数据流，再标时间尺度 |
| 3–6 | 写关键接口或关键公式 | 先写不变量，再写字段 |
| 6–8 | 走一个正常用例和一个失败用例 | 失败用例至少覆盖超时、重复、过期之一 |
| 8–10 | 说取舍与局限 | "What I'd test first is ...; what I'm not sure of is ..." |

**一个完整的小例子：W13（看门狗取值，本项目口径）。** 已知最大线速度 $v_{max}=0.8$ m/s，制动加速度 $a=1.0$ m/s²，到障碍的安全余量 $d_{safe}=0.5$ m。求命令超时 $T_{cmd}$ 的上限。

1. 制动距离 $d_{brake}=v^2/(2a)=0.64/2=0.32$ m。
2. 超时期间机器人仍以 $v_{max}$ 前进：$v_{max}T_{cmd}\le d_{safe}-d_{brake}=0.18$ m。
3. $T_{cmd}\le0.18/0.8=0.225$ s。
4. 本项目取约 200 ms，落在上限之内，还留了约 25 ms 的余量；若下发周期为 50 ms（20 Hz），200 ms 恰好是 4 个周期，再配合"连续 2 次判定"才停车，避免单帧抖动误触发（见 11 章问题 3）。

**常见错误。** 只算制动距离，忘了超时期间还在前进；把 $T_{cmd}$ 取得比下发周期还小；取值与周期无关。

**面试问答。**

> **Q**: How did you choose the command timeout?
>
> **A**: I worked backwards from the stopping distance. At 0.8 metres per second and 1 metre per second squared, braking takes about 0.32 metres, so with a 0.5 metre margin the timeout can be at most about 0.22 seconds. I set roughly 200 milliseconds, which is four command periods, and require two consecutive misses so that one late packet doesn't stop the robot.
>
> 译：从制动距离反推：0.8 m/s、1 m/s² 时制动约 0.32 m，余量 0.5 m 则超时上限约 0.22 s；取约 200 ms（4 个周期），并要求连续两次判定，避免单个迟到包导致停车。
