# P6 深开鸿 M-Robots 平台软件：设备抽象、状态管理、分布式协同与安全执行链

> 一句话定位：CV 中 Shenzhen Kaihong Digital Industry Development Co., Ltd. 的在职实习（Robotics Platform Intern，2026.06 至今）。你在 M-Robots OpenHarmony 异构多机器人协同平台上，独立开发并集成了 **设备抽象、状态管理、分布式协同、安全执行链**。其中 "action-proposal → policy-check → execution → state-feedback" 链是你 PS 的开篇钩子，面试必问。

> **重要说明**：本项目的源码目录不作参考，文档只依据 CV、PS 和通用工程知识。所以：CV 写了的是**事实**；其余是"这类系统的典型设计"，面试里用 *typically / in a design like this* 措辞；专有细节统一采用"实机细节自查表"中的设计取值口径（具体但属设计级描述）。

## 1. 一页纸：P6 是什么

**CV 原意（可直接用 "I"）**

| 线 | 做了什么 |
|---|---|
| 统一运动接口 | 在 OpenHarmony 上用 C++ 为传感器、执行器、控制器建立统一能力模型；把 ROS/ROS2 运动指令映射到底层驱动；运动控制代码可跨硬件复用 |
| 机器人状态管理 | 统一多源感知与执行器反馈的时间戳、坐标系、有效性检查，向运动控制层与任务层提供一致、可信的状态 |
| 协同与安全执行 | 在 M-DDS 上实现设备发现、能力注册、状态同步、任务分发；任务计划经"动作提案 → 策略校验 → 控制执行 → 状态回传"链才能进入物理执行 |

**一句话讲法（英文）**

> I work on the M-Robots multi-robot platform on OpenHarmony: a unified C++ capability model so ROS and ROS2 motion commands drive different hardware, standardised timestamps, frames and validity for a trusted robot state, and discovery, registration and task dispatch over M-DDS — with every task plan gated through a proposal, policy-check, execution and feedback chain.

**数据流一图**

```text
任务层 / 调度 / AI 规划
   │ 动作提案（结构化、带身份与有效期）
   ▼
策略校验 ◀──────── 可信状态（时间/坐标/有效性已标准化）
   │ 接受 / 修改 / 拒绝(原因码)
   ▼
运动接口（统一能力模型）◀── ROS/ROS2 命令映射
   │
   ▼
驱动适配器 → 底层驱动 → 硬件
   │
   └──── 反馈 → 状态管理 → 回传（M-DDS）→ 任务层
```
