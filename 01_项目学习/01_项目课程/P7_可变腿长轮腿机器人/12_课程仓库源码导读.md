# 课程仓库源码导读（StackForce 大轮足，公开课程代码）

> **一句话定位**：本地副本在 `项目源码/轮腿小车/gaint_bipedal_wheeled_robot-master/课程代码/`。它是同款参考实现（ESP32-S3 + Arduino + PlatformIO），**不是你的 STM32H7 实机代码**；可作"真实代码证据"和"结构参照"，不得说成你写的。本章逐课说明它做了什么、怎么读、和 CV 里的项目差在哪里。

**本章学完你能：**
1. 按"控制输出怎样变成电机命令"的主线，读懂第四到第十一课每一课的关键文件；
2. 说出课程代码与 CV 项目在主控、状态数、输出数、估计、VMC、离地、软件结构上的八项差异；
3. 把课程里的一段代码对应到本教材的某一章，并说明在 STM32H7 工程里怎样改写；
4. 面试时区分"课程里有的"与"我做的"，不会说错话；
5. 指出课程代码里的几处易误导点（例如写死常数、注释与实现不一致）。

## 1. 它要解决什么问题

读公开课程代码有三个用途，也有一个风险：

- **用途一：看真实实现长什么样**。例如五连杆正解的几何写法、MIT 帧的位打包、LQR 增益多项式怎样烧进固件。这些细节教材里的公式给不出；
- **用途二：用真实代码给教学数值做旁证**。例如杆长 $L_1=L_4=150$ mm、$L_2=L_3=250$ mm、$L_5=108$ mm，轮半径 0.07 m；
- **用途三：对照自己的实现，找出可能的漏洞**。例如课程没有数据过期检查，你自己的实现必须有；
- **风险**：把课程代码说成自己写的，或把课程里的结构（四状态、单输出）说成自己项目的结构（六状态、双输出）。面试官只要追问一步就会发现。

所以本章的结构是：**每一课先说它是什么，再说和 CV 的差异**。

建议的使用方式是三遍：第一遍只看第 2 节的总表，建立"课程是什么、项目是什么"的边界；第二遍按第 3 节的顺序，每课只打开表中列出的关键文件，找到"控制输出变成电机命令"那几行；第三遍带着第 5.5 节的八个问题读第十一课，并在草稿纸上画出一张数据流图。读完以后，你应当能不看代码讲清：一个遥控速度指令，是怎样经过几次变换，最后变成四个关节力矩和两个轮矩的。这个讲述能力比记住某个常数重要得多，因为面试官关心的是你对结构的理解，而不是某个数字。

## 2. 符号与定位：课程 vs CV 项目总表

| 项 | 课程仓库（公开） | 你的项目（CV，面试按此说） |
|---|---|---|
| 主控 | ESP32-S3 + Arduino + PlatformIO，TWAI 1 Mbps | STM32H7 + FreeRTOS + FDCAN |
| LQR 状态 | 四状态（俯仰、俯仰角速度、位置、速度，对应轮控制式里的 K1–K4；位置增益 K3 置 0） | 六状态 $[\theta,\dot\theta,x,\dot x,\phi,\dot\phi]$ |
| LQR 输出 | 单输出（轮矩） | 双输出：轮毂矩 $T$ 与髋矩 $T_p$ |
| 增益调度 | 按腿高 $y$（mm）二次多项式拟合 | 按腿长 $L_0$ 三次多项式，12 个增益 × 4 = 48 系数 |
| VMC | 第十一课：笛卡尔 $(F_x,F_y)$；第九课：极坐标 | 虚拟腿长/姿态，$F$ 与 $T_p$ 经雅可比转置到关节 |
| 状态估计 | 轮速平均，无融合，姿态为 MPU6050 互补滤波 | IMU + 轮速 + 关节反馈构造状态，速度卡尔曼融合 |
| 离地检测 / 防劈叉 | 无 | 离地切换（CV）；本项目有支撑力判据、差模 PD |
| 软件结构 | 单线程 `loop()` + 一个 IMU 任务，CAN 每次收一帧 | FreeRTOS 多任务，FDCAN 中断接收，快照与过期检测 |
| 周期 | `SEND_INTERVAL=1` ms 仅是发送门槛 | 控制 500 Hz，IMU 1 kHz |
| 安全 | 无过期检查、无 DLC 检查、无失联保护 | 有（[10](./10_STM32H7_FreeRTOS_FDCAN软件结构.md)） |

The balance algorithm and tuning on our robot were my work."

### 3.1 第四课：关节电机控制（MIT 模式）

**读什么：** 四个渐进例子。2-1 只发纯力矩 0.2（`pos=vel=kp=kd=0`），电机像一个受力矩驱动的飞轮；2-2 加 pos 与 `kp=35`，变成位置弹簧；2-3 再加 kd，抑制振荡；2-4 `kp=0.5, kd=0.05`，做柔顺。**抓住的概念**：MIT 模式下电机内部实现 $\tau=k_p(p_d-p)+k_d(v_d-v)+\tau_{ff}$，上层只要填这五个字段。

**和 CV 的关系：** CV 项目也用 MIT 风格力矩帧（力矩模式，kp=kd=0）。编码范围不同（课程 tor ±18，本项目 ±10）。

### 3.2 第五课：运动学正逆解

**读什么：** `Kinematics.cpp` 的 FK（两圆交点）与 IK；MATLAB 脚本 `forwardKinematics.m`、`inverseKinematics.m` 以及动画。注意坐标：$y$ 向下为正，腿高就是 B 点纵坐标；FK 取固定解支。

**和 CV 的关系：** CV 写"闭链运动学算虚拟腿长与姿态"，与此同源。本教材 [02](./02_五连杆闭链运动学.md) 的手算数值 $B=(54,298.1)$ mm 就用的这组杆长。

### 3.3 第六课：用 PID 实现变腿高自稳定

**读什么：** 平衡由串级 PID 完成：速度环→目标俯仰角→角度/陀螺 PD→轮矩；PID 增益按高度线性插值；IK 控制腿高（位置模式）。`Pid/pid.cpp` 用 Tustin 积分，积分限幅为 `limit/3`，输出斜率限制 `output_ramp`，自带抗积分饱和。

**和 CV 的关系：** 这是 LQR 之前的版本。CV 的项目用 LQR + VMC，不是串级 PID。所以第六课的 PID 不能说成"我的平衡控制"，但可以说"我对比过串级 PID 与 LQR 的差异"（若确实做过；否则不要说）。

### 3.4 第八课：LQR 原理

**读什么：** `wheel_control.m` 建立四状态模型，调用 `lqr()` 得 K。注意课程 MATLAB 的 $B$ 矩阵末项与直接消元差一个符号（本教材第 4 章已核对）。

**和 CV 的关系：** CV 是六状态双输出，课程是四状态单输出。本教材用六状态模型，并由脚本一验证。

### 3.5 第九课：LQR 实机部署

**读什么：** `LQRfitting.m` 对不同腿高解 LQR、对每个增益元素做二次拟合，生成 C 数组；`robot.cpp` 里 `calVMC_*` 是极坐标 VMC（沿腿的力 + 切向力矩）。**易误导点**：`wheel_control` 实际用的是写死常数，多项式函数并未被调用；`F = 48.755 / cos(thetaRight1) + yError` 里的常数 48.755 源码未说明来源，是实机标定出来的。

**和 CV 的关系：** CV 的增益调度是"按腿长调度"，本项目用三次多项式和 48 个系数。

### 3.6 第十课与第十一课：VMC 与完整实现

**读什么：** 第十课 `calJacobian.m` 用符号推导雅可比；第十一课是最完整的一课：笛卡尔 VMC（$\tau=J^\top F/1000$）、力矩模式（腿关节 `pos=vel=kp=kd=0` 只填 `tor`）、横滚补偿、TWAI 收发。

轮控制（第十一课）：

```text
-(K1*pitch*π/180 + K2*gyroY*π/180 + K3*position + K4*vel) - 0.3*steering - 0.1*forwardBackward
```

其中 $K$ 由腿高 $y$ 的二次多项式给出，$K_3=0$（位置增益置 0）。VMC 参数：`kpHeight=0.3`、`kdHeight=0.06`、`fG=25`、`kpX=0.4`、`kdX=0.05`。横滚补偿：外环 `rollKp=1.5`，内环陀螺阻尼 `gyroKp=0.13`，`roll_EH` 限幅 ±80、低通 0.8，右腿加、左腿减。

**和 CV 的关系：** 第十一课没有离地检测，没有防劈叉，没有真正的状态融合。

## 4. 真实结构与事实（均可在源码核对）

- 杆长 $L_1=L_4=150$，$L_2=L_3=250$，$L_5=108$ mm；$y$ 向下；腿高 140–290 mm（十一课遥控）；
- 轮：半径 0.07 m（`radius`），`speed_limit=3`；轮电机经预编译库 `SF_Motor`，目标单位未知；
- 轮控制（十一课）：见上式；
- 九课 `wheel_control` 实际用写死常数，多项式函数未调用；
- VMC（十一课）：$\tau=J^\top F/1000$；
- 周期：`SEND_INTERVAL=1` ms 是发送门槛而非实测频率；IMU 任务无延时循环，创建时固定核 1（注释写核 0）；`twai_transmit` 超时 1000 ms（注释写 1 ms）；
- 单线程 `loop()` 加一个 IMU 任务；CAN 每次只收一帧；
- 姿态：MPU6050 互补滤波 `angle = 0.98*(angle + gyro*dt) + 0.02*accAngle`；
- 速度：`vel = −((motor1_vel*r + motor2_vel*r)/2)`，只是轮速平均；
- 位置：`position += v*dt`，用 `micros()` 算 dt，限幅 ±0.1 m。

## 5. 从课程代码迁移到 STM32H7 工程的改写点

这一节是**典型迁移思路**，说明你的实机结构为何与课程不同，也可作面试时解释"为什么这样设计"。

| 课程写法 | 问题 | STM32H7 工程的改写 |
|---|---|---|
| `loop()` 里顺序执行读、算、发 | 周期靠 `micros()` 比较，抖动大 | FreeRTOS 固定周期任务 `vTaskDelayUntil`，实测抖动 |
| 先发上次的力矩 | 多一拍延迟 | 同周期"读—算—发" |
| 每次只收一帧 CAN | 反馈慢于命令，易旧数据 | RX 中断收全部帧，带时间戳 |
| 轮速平均当速度 | 与腿运动、打滑耦合 | 腿速度修正 + 加速度卡尔曼融合 |
| 四状态，位置增益 0 | 位置会漂移 | 六状态，位置项保留小增益，限幅复位 |
| 单输出轮矩 | 俯仰靠轮矩承担 | 双输出：$T$ 与 $T_p$，经 VMC 到关节 |
| 腿高二次多项式 | 区间小、阶数低 | 三次、48 系数、clamp |
| 无离地检测 | 颠簸/起跳后失控 | 支撑力判据、模式切换 |
| 无安全检查 | 断线即失控 | 过期检测、限幅报警、看门狗 |

## 5.5 读任何一课代码时的八个问题

为了避免"读了很多文件却不知道系统怎么跑"，每读一课都带着下面八个问题，并把答案记成一页笔记。这也是面试时讲"我怎样读陌生代码"的素材。

1. **入口在哪里？** `main.cpp` 的 `setup()` 初始化了什么（串口、CAN、IMU、电机使能），`loop()` 每一圈做什么；
2. **有几个并发单元？** 课程里只有 `loop()` 和一个 IMU 任务，没有多任务划分；
3. **控制量从哪来到哪去？** 从遥控（PPM）→ 目标速度/高度 → 控制律 → 电机力矩或位置 → CAN 帧；沿这条链写下每一步的变量名与单位；
4. **单位是什么？** 腿高用毫米还是米，角度用度还是弧度，力矩单位是否经过除以 1000。课程里 $\tau=J^\top F/1000$ 就是单位换算；
5. **哪些常数是写死的？** 例如 `fG=25`、`kpHeight=0.3`、`0.3*steering`；这些通常是实机标定值，不是公式算出来的；
6. **哪里有限幅？** 看每个输出前的 `constrain`，限幅值是多少；
7. **注释和代码是否一致？** 例如核编号、超时时间；不一致时以代码为准；
8. **缺什么？** 过期检测、失联保护、离地检测、状态融合——这些缺口正是你自己的工程需要补的部分。

做完八问以后，再去对照本教材相应章节，问自己："如果我把它改成六状态双输出，哪几行要变？" 能答出来，说明读懂了。

## 深入专题：迁移实战——把课程的 `loop()` 改写成一个 RTOS 控制周期

第 5 节列出了改写点，这一节给一个可对照的"改写前后"骨架，帮助你在面试里讲清楚"课程是怎么做的、我的工程怎么做、为什么"。两段代码都是教学示例，不是任何项目的源码。

### A. 课程风格（单线程，顺序执行）

```cpp
// 教学示例：课程风格的主循环（简化）
void loop() {
  readCANOnce();                  // 只收一帧，反馈可能是旧的
  if (micros() - last >= SEND_INTERVAL_US) {   // 发送门槛，不是实测周期
    last = micros();
    computeControl();            // 用上一圈读到的数据
    sendTorqueToMotors();        // 发的是"这一圈算出来、下一圈才到电机"的力矩
  }
  handleRemote();                // 遥控解析
}
```

它的问题不是"写得不好"，而是**时序不确定**：每圈耗时随遥控解析和串口打印变化；CAN 一次只收一帧，6 个电机轮流更新，某个电机的反馈可能是好几圈之前的；读、算、发之间没有明确的时间顺序，延迟无法预算。

### B. STM32H7 风格（固定周期，快照，先读后算再发）

```c
// 教学示例：FreeRTOS 控制任务（简化）
void ControlTask(void *arg) {
  TickType_t last = xTaskGetTickCount();
  for (;;) {
    vTaskDelayUntil(&last, pdMS_TO_TICKS(2));        // 固定 2 ms
    RobotSnapshot_t s;
    taskENTER_CRITICAL(); s = g_shared; taskEXIT_CRITICAL();   // 一次性快照
    if (!snapshot_valid(&s)) { send_zero_torque(); continue; } // 过期则降级
    State6 x = estimate(&s);          // 运动学 + 估计 -> 六状态
    Mode m  = contact_logic(&s, &x);  // 着地 / 腾空 / 恢复
    Cmd u   = lqr_vmc_leg(&x, m);     // LQR + 腿长 PID + VMC
    clamp_and_count(&u);              // 限幅，并统计触发次数
    fdcan_send_all(&u);               // 两路总线入发送队列
  }
}
```

对照 A，要注意三点变化：（1）`vTaskDelayUntil` 锚定在上一次唤醒时刻，不是"等待 2 ms"，所以不会累积漂移；（2）快照让整个周期用同一份数据；（3）读、算、发在同一个周期里，延迟可以预算（见 [20](./20_工程化实践_频率周期与问题解决.md)）。

### C. 四状态到六状态：增益对照表

| 项 | 课程（四状态，单输出） | 本项目（六状态，双输出） |
|---|---|---|
| 状态 | $[\phi,\dot\phi,x,\dot x]$ | $[\theta,\dot\theta,x,\dot x,\phi,\dot\phi]$ |
| 增益矩阵形状 | $1\times4$，其中位置增益置 0 | $2\times6$，共 12 个增益 |
| 需要调度的量 | 4 个（实际 3 个有效） | 12 个，每个 4 个系数共 48 个 |
| 控制输出 | 轮矩 | 轮矩 $T$ 与髋矩 $T_p$ |
| 腿的作用 | 视为固定杆或简化 | 腿角 $\theta$ 是状态，腿长是调度变量 |
| 增益拟合变量 | 腿高 $y$（mm） | 虚拟腿长 $L_0$（m） |

课程中把位置增益 $K_3$ 置 0，意味着不抑制位置漂移，只做速度和姿态控制；本项目保留位置项并限幅复位，是为了在静止时不漂（案例 A）。

### D. "我用了哪些公开资料"的边界与说法

| 内容 | 来源 | 面试怎么说 |
|---|---|---|
| 五连杆几何与雅可比 | 课程 + 自己推导核对 | "I derived and checked it myself; the public course has the same geometry." |
| MIT 电机帧格式 | 课程 + 电机手册 | "The frame format is the motor vendor's protocol; I implemented the packing on STM32H7." |
| 四状态 LQR 的结构 | 课程 | "A reference for the structure only; ours had six states and two outputs." |
| 增益调度、VMC 映射、离地切换、安全保护 | 自己的工程 | "This was my part." |
| 参数整定 | 自己的实车 | "Tuned on our robot." |

原则：公开代码可以说"学过、参考过"，不说"这是我写的"；被追问到具体行，就老实说"我读过这一课的实现，但我们的版本是…"。

## 补充：课程代码里值得借鉴与不值得借鉴的写法

**值得借鉴。** 第一，函数命名把物理意义写在名字里（如把前后电机力矩分开命名）；第二，把可调参数（`kpHeight`、`steering`）集中放在顶部，便于整定；第三，MIT 帧打包函数独立成库，便于测试；第四，把遥控输入先映射成目标高度、目标速度，再进入控制律，而不是直接改电机命令。

**不值得借鉴。** 第一，用写死常数代替多项式调用（第九课），代码里留着未调用的函数，容易让人误以为用了；第二，注释与代码不一致（核编号、超时），读者会被误导；第三，缺少限幅报警与过期检查，出现问题时没有任何线索；第四，用 `micros()` 比较代替真正的周期任务，抖动无法测。

**怎么把它变成面试素材。** 讲"读公开代码的经验"时，可以说："I used it as a reference, but I rewrote the timing and safety parts, because the public version had no stale-data check and its loop period was not guaranteed." 这句话既承认了参考，又指出了你的增量。（中文：我把它当参考，但时序和安全部分重写了，因为公开版本没有数据过期检查，循环周期也没有保证。）

**读不懂时怎么办。** 先找输入输出：把一课代码里所有 `Serial.print` 打开，对着波形反推公式；不要先抠每一行，先抠"一个控制周期的数据流"。

## 补充：从课程代码里能拿到的"证据"和不能拿到的

能拿到的：杆长与几何尺寸（可核对）；MIT 帧的位分配和量化范围；轮控制律的结构与四个增益的符号；遥控映射和几个调参常数的量级。不能拿到的：六状态模型、增益调度的六状态数值、离地检测、状态融合、FreeRTOS 结构、FDCAN 配置、实车整定结果——这些都来自本项目自己的工作，在课程仓库里找不到对应文件。面试里如果对方追问"你怎么证明这是你做的"，可以讲细节：为什么选 500 Hz、为什么取 8 个周期做去抖、怎样用日志定位案例 A，这些细节是读公开代码得不到的。反过来，被问课程代码的具体行为时，要老实说"我读过，但我们的版本不同"，不要凭印象编。

**一个自检方法。** 讲任何一个设计取值前，先问自己两个问题：这个数字在课程代码里有吗？如果没有，我能说出它是怎么来的吗？两个答案都是"否"，说明这一块还没有真正掌握，需要回到对应章节再过一遍。

## 6. 常见错误

| 错误 | 为什么错 |
|---|---|
| 说"我用了第九课的 LQR 增益" | 课程是四状态单输出，实机是六状态双输出，增益不可通用 |
| 说"我写了 MIT 帧驱动"而没说明范围 | 你要能说出本项目范围（±12.5/±30/±10），否则像是背课程的 |
| 把 `SEND_INTERVAL=1` 当作 1 kHz 控制 | 它只是发送门槛 |
| 把注释当事实 | 课程里多处注释与实现不一致（核、超时） |
| 把"腿高 mm"与"腿长 m"混用 | 课程调度变量是腿高 $y$（mm），本项目是腿长 $L_0$（m） |

## 7. 面试怎么问、怎么答

**Q1. Did you use an open-source course code for the robot?**
> I read the public course code of a similar platform as a reference, especially for the five-bar kinematics and the motor frame format. Our robot used a different controller: an STM32H7 with FreeRTOS and FDCAN, six states and two outputs. The balance and tuning work was mine.

**Q2. What is different between your controller and a typical open-source one?**
> The open-source version I studied uses four states with the position gain set to zero and a single wheel output, and it schedules by leg height with a quadratic fit. Mine uses six states, outputs both wheel torque and hip torque, and schedules by leg length with cubic polynomials.

**Q3. Does the course code detect ground contact?**
> No. That is a gap I handled myself with a support-force estimate, hysteresis and debouncing.

**Q4. Which part of the open-source code was most useful to you?**
> The kinematics and the Jacobian derivation, because they let me check my own numbers, and the motor frame packing, to cross-check my encoding.

## 要点速记

1. 课程 = ESP32-S3 + Arduino，四状态单输出，参考实现。
2. 项目 = STM32H7 + FreeRTOS + FDCAN，六状态双输出。
3. 课程调度按腿高（二次），项目按腿长（三次，48 系数）。
4. 课程无离地、无防劈叉、无融合、无安全保护。
5. 第九课写死常数；第十一课 $K_3=0$。
6. 注释与实现不一致的几处要小心。
7. 课程可以做旁证，不能说成自己写的。
