## 1. RAII

### 1.1 它要解决什么问题

资源（内存、文件、锁、套接字、设备句柄）都要"获取 → 使用 → 释放"。手写 `open … close` 的问题：中间任何一个 `return`、异常、`break` 都可能漏掉释放，造成泄漏或死锁。**RAII（Resource Acquisition Is Initialization）**：把资源的生命周期绑定到**对象的生命周期**——构造函数获取资源，析构函数释放资源；对象离开作用域，C++ 保证析构函数被调用（正常返回、`return`、异常都一样）。

### 1.2 例子

```cpp
// 教学示例
class CanSocket {
public:
    explicit CanSocket(const char* ifname) {
        fd_ = ::socket(PF_CAN, SOCK_RAW, CAN_RAW);
        if (fd_ < 0) throw std::runtime_error("socket");
        // bind 到 ifname ...
    }
    ~CanSocket() { if (fd_ >= 0) ::close(fd_); }

    CanSocket(const CanSocket&) = delete;             // 禁止拷贝：fd 不能被两个对象各 close 一次
    CanSocket& operator=(const CanSocket&) = delete;
    CanSocket(CanSocket&& o) noexcept : fd_(o.fd_) { o.fd_ = -1; }   // 允许转移所有权
    CanSocket& operator=(CanSocket&& o) noexcept {
        if (this != &o) { if (fd_ >= 0) ::close(fd_); fd_ = o.fd_; o.fd_ = -1; }
        return *this;
    }
    int fd() const { return fd_; }
private:
    int fd_ = -1;
};

void send_cmd() {
    CanSocket s("can0");            // 获取
    // ... 任何位置 return 或抛异常，s 的析构都会关闭 fd
}
```

标准库里的 RAII：`std::lock_guard`（锁）、`std::unique_ptr`（内存）、`std::fstream`（文件）、`std::vector`（动态数组）、`std::thread`（需 join）。

### 1.3 零法则 / 三法则 / 五法则

- **零法则**：能不自己写析构/拷贝/移动，就不写——用标准库成员（`vector`、`unique_ptr`）让编译器自动生成正确版本；
- **三法则（C++03）**：只要自定义了析构、拷贝构造、拷贝赋值**之一**，通常三个都要自定义；
- **五法则（C++11）**：再加上移动构造、移动赋值。像上面 `CanSocket` 这种管理原始资源的类，要么全写（五个），要么 `delete` 拷贝只留移动。

## 2. 智能指针

### 2.1 三种

| 类型 | 所有权 | 开销 | 用途 |
|---|---|---|---|
| `std::unique_ptr<T>` | **独占**，不可拷贝，可移动 | 与裸指针几乎相同 | 默认选择 |
| `std::shared_ptr<T>` | **共享**，引用计数 | 控制块 + 原子计数 | 真正多方共享 |
| `std::weak_ptr<T>` | 不拥有，观察 `shared_ptr` | 小 | 打破循环、缓存、观察者 |

创建：`std::make_unique<T>(args...)`、`std::make_shared<T>(args...)`（一次分配，异常安全）。裸指针/引用用于"**不拥有**"的借用，不要在函数签名里为了借用而传 `shared_ptr`。

### 2.2 引用计数手追

```cpp
auto a = std::make_shared<Motor>();   // use_count = 1
auto b = a;                           // 2    （拷贝，计数 +1）
{
    auto c = b;                       // 3
}                                     // c 析构：2
a.reset();                            // 1
b.reset();                            // 0 -> Motor 被销毁
```

`use_count` 的增减是原子的，所以多线程里**不同的 `shared_ptr` 对象**指向同一个对象是安全的；但**同一个 `shared_ptr` 对象**被多线程同时读写（赋值）不是线程安全的，且指向的对象本身的读写仍需自己同步。

### 2.3 循环引用与 weak_ptr

```cpp
struct B;
struct A { std::shared_ptr<B> b; };
struct B { std::shared_ptr<A> a; };    // A 与 B 互相持有 shared_ptr
// a->b = b; b->a = a;  离开作用域后：两个计数都是 1，永不为 0 -> 内存泄漏
```

**手算**：A 的计数 = 栈上变量 a 的 1 + B 内 `a` 成员的 1 = 2；B 同理。栈变量销毁后各剩 1（被对方持有），谁也不会降到 0。**解决**：其中一方改为 `std::weak_ptr`（不增加计数），使用时 `if (auto sp = wp.lock()) { ... }` 临时提升。典型场景：子节点指向父节点用 weak_ptr；回调持有对象用 weak_ptr 防止悬空。

### 2.4 在 ROS2/机器人代码里

ROS2 的 `rclcpp::Node` 通常用 `shared_ptr`（`std::make_shared<MyNode>()` 交给 executor）；订阅回调里的消息指针（`const Msg::SharedPtr` 或 `ConstSharedPtr`）也是共享所有权。设备对象在平台中心注册表里常用 `shared_ptr` 或 `unique_ptr` + 引用借用。

## 3. 移动语义

### 3.1 要解决什么问题

拷贝大对象（`vector<double>` 有 1 万个元素）很贵，但很多时候原对象马上就要销毁了（函数返回的临时对象），拷贝纯属浪费。**移动**：把资源（堆内存指针）"偷"过来，原对象留下一个有效但空的状态。

### 3.2 左值与右值

- **左值（lvalue）**：有名字、能取地址的对象（`x`、`vec[0]`）；
- **右值（rvalue）**：临时值/即将消亡（`f()` 的返回值、字面量、`std::move(x)` 的结果）；
- 右值引用 `T&&` 能绑定右值；重载 `T(T&&)`（移动构造）和 `operator=(T&&)`（移动赋值）来"偷"资源；
- `std::move(x)` **本身不移动任何东西**，只是把 `x` 转换为右值引用，让重载解析选中移动版本；之后 `x` 处于"有效但未指定"的状态，不要再依赖其值（除了赋新值或销毁）。

### 3.3 手算：vector 的搬运

```cpp
std::vector<std::string> v;
v.push_back("abc");                  // 字面量构造临时 string，移动进 v
std::string s = "motor";
v.push_back(s);                      // s 是左值：拷贝
v.push_back(std::move(s));           // 移动：s 变空
```

`vector` 扩容（容量不够时分配新内存，把旧元素搬过去）：**如果元素的移动构造声明了 `noexcept`，`vector` 才会用移动；否则为了强异常安全会用拷贝**。所以自定义类的移动构造要写 `noexcept`（见 1.2 的例子）。

**扩容次数手算**（容量翻倍策略，初始容量 0，1→2→4→8→16）：连续 `push_back` 9 个元素：

| 第几次 | 容量够吗 | 动作 | 搬运元素数 |
|---|---|---|---|
| 1 | 否 | 分配容量 1 | 0 |
| 2 | 否 | 容量 2 | 1 |
| 3 | 否 | 容量 4 | 2 |
| 4 | 是 | – | 0 |
| 5 | 否 | 容量 8 | 4 |
| 6–8 | 是 | – | 0 |
| 9 | 否 | 容量 16 | 8 |

总搬运 = 1 + 2 + 4 + 8 = 15 < 2×9 = 18 → **均摊 O(1)**。已知大小时 `reserve(n)` 一次分配，搬运为 0。

### 3.4 返回值优化

`return local;` 编译器通常做 **RVO/NRVO**（直接在调用者位置构造，零拷贝零移动；C++17 起对纯右值是强制的）。**不要写 `return std::move(local);`**，它会阻止 NRVO，反而更慢。

### 3.5 完美转发（了解）

模板里 `template<class T> void wrap(T&& arg) { f(std::forward<T>(arg)); }`：保持实参的左/右值性质转发，`make_unique/make_shared/emplace_back` 就是这么实现的。`emplace_back(args...)` 直接在容器内存里构造，省一次临时对象。

## 4. 模板基础

### 4.1 它要解决什么问题

同样的算法/容器要对多种类型工作（`float` 和 `double` 的滤波器、不同大小的缓冲），复制粘贴会重复且难维护。**模板**在**编译期**按需生成针对具体类型的代码（实例化），零运行时开销。

### 4.2 函数模板与类模板

```cpp
template <typename T>
T clamp_value(T x, T lo, T hi) { return x < lo ? lo : (x > hi ? hi : x); }
// 使用：clamp_value(2.5f, 0.f, 1.f) 推导 T = float

// 固定容量环形缓冲：无动态分配，嵌入式友好（教学示例）
template <typename T, std::size_t N>
class RingBuffer {
    static_assert(N > 0, "capacity must be positive");
public:
    bool push(const T& v) {
        if (size_ == N) return false;                 // 满：由调用者决定丢弃策略
        buf_[(head_ + size_) % N] = v; ++size_; return true;
    }
    bool pop(T& out) {
        if (size_ == 0) return false;
        out = buf_[head_]; head_ = (head_ + 1) % N; --size_; return true;
    }
    std::size_t size() const { return size_; }
private:
    std::array<T, N> buf_{};
    std::size_t head_ = 0, size_ = 0;
};
RingBuffer<float, 8> q;      // 实例化：一个容量 8 的 float 缓冲
```

**手追**（N = 3）：push(1),push(2),push(3) → 满，size=3；push(4) 返回 false；pop 得 1，head=1，size=2；push(5)：写入位置 (1+2)%3 = 0，覆盖原来 1 的位置，size=3；此时顺序为 2,3,5 ✓。

### 4.3 要点

- 模板定义通常放在**头文件**（编译器实例化时需要看到定义）；
- 类型推导：函数模板可自动推导；类模板 C++17 起有 CTAD（`std::pair p{1, 2.0};`）；
- 错误信息很长，是常见痛点；C++20 的 **concepts**（`template<std::floating_point T>`）能给出更清晰的约束；
- 模板代码膨胀：每种实例化生成一份代码，嵌入式要关注 Flash 占用；
- 模板特化、SFINAE 等是进阶内容，面试通常考到"理解实例化与编译期多态"即可。

## 5. STL 容器与复杂度

### 5.1 速查表

| 容器 | 底层 | 随机访问 | 尾部插入 | 中间插入/删除 | 查找 | 备注 |
|---|---|---|---|---|---|---|
| `std::array<T,N>` | 栈上数组 | O(1) | – | – | O(n) | 固定大小，无动态分配 |
| `std::vector<T>` | 连续动态数组 | O(1) | 均摊 O(1) | O(n) | O(n)（有序时二分 O(log n)） | **默认首选**，缓存友好 |
| `std::deque<T>` | 分段数组 | O(1) | 两端 O(1) | O(n) | O(n) | 队列 |
| `std::list<T>` | 双向链表 | O(n) | O(1) | O(1)（已有迭代器） | O(n) | 缓存差，很少用 |
| `std::map<K,V>` | 红黑树 | – | – | O(log n) | O(log n) | 有序，键需可比较 |
| `std::unordered_map<K,V>` | 哈希表 | – | – | 均摊 O(1)，最坏 O(n) | 均摊 O(1) | 无序 |
| `std::priority_queue<T>` | 堆（vector） | – | push O(log n) | pop O(log n) | top O(1) | A* 的 open list |
| `std::set<K>` / `unordered_set<K>` | 树 / 哈希 | – | – | O(log n) / O(1) | 同左 | 去重 |

### 5.2 选择原则与缓存

- 默认 `vector`：连续内存，对 CPU 缓存友好，小规模下**常数因子**远小于链表/树；
- 查找频繁 → `unordered_map`；需要有序遍历/范围查询 → `map`；
- 需要稳定指针/引用（元素地址不变）→ `list`/`map`（`vector` 扩容会使所有迭代器/指针失效）；
- 实时回路里避免在循环中使 `vector` 扩容、`unordered_map` 重哈希（耗时不确定）——先 `reserve`。

### 5.3 手算：迭代器失效

```cpp
std::vector<int> v{1,2,3};          // size 3, capacity 3
int* p = &v[0];
v.push_back(4);                     // 容量不足 -> 重新分配 -> p 悬空！
// *p 为未定义行为
```

### 5.4 算法库

`std::sort`（O(n log n)，introsort）、`std::find`、`std::accumulate`、`std::transform`、`std::lower_bound`（有序区间二分，O(log n)）。配合 lambda 使用：

```cpp
std::sort(waypoints.begin(), waypoints.end(),
          [](const Pose& a, const Pose& b){ return a.t < b.t; });
```

## 6. lambda

### 6.1 语法与捕获

```cpp
auto f = [captures](params) mutable -> ret { body };
```

| 捕获 | 含义 |
|---|---|
| `[]` | 不捕获 |
| `[=]` | 按值捕获用到的所有外部变量（拷贝） |
| `[&]` | 按引用捕获 |
| `[x, &y]` | x 按值，y 按引用 |
| `[this]` | 捕获当前对象指针 |
| `[p = std::move(ptr)]` | C++14 初始化捕获，可移动入 lambda |

按值捕获的变量在 lambda 内默认是 `const`（要修改需 `mutable`，修改的是 lambda 内部的拷贝）。

### 6.2 悬空引用陷阱（机器人回调常见）

```cpp
std::function<void()> make_cb() {
    int count = 0;
    return [&count]() { ++count; };    // 返回后 count 已销毁 -> 悬空引用，UB
}
```

当 lambda 的**生命周期超过**捕获的局部变量（异步回调、线程、定时器、ROS2 订阅回调）时，必须按值捕获，或捕获 `shared_ptr`/`weak_ptr`。捕获 `this` 的回调，如果对象先被销毁，回调再被触发就悬空——用 `weak_ptr` 保护。

### 6.3 用途

STL 算法的谓词、线程入口、ROS2 回调（`create_subscription<Msg>("topic", 10, [this](const Msg::SharedPtr m){ ... })`）、定时器回调、一次性初始化任务。lambda 本质是**编译器生成的匿名函数对象类**；赋给 `auto` 零开销，存入 `std::function` 有类型擦除开销（可能堆分配）。

## 7. constexpr

### 7.1 概念

- `const`：运行期不可修改（值可能在运行期才确定）；
- `constexpr`：值/函数**可以在编译期求值**；若参数是编译期常量，则编译期计算，结果直接嵌入代码。C++14 起 `constexpr` 函数可含循环、局部变量；C++20 有 `consteval`（必须编译期）。

### 7.2 例：编译期生成 CRC 查表

```cpp
// 教学示例：CRC-8，多项式 0x07
constexpr std::array<uint8_t, 256> make_crc8_table() {
    std::array<uint8_t, 256> t{};
    for (int i = 0; i < 256; ++i) {
        uint8_t c = static_cast<uint8_t>(i);
        for (int b = 0; b < 8; ++b)
            c = (c & 0x80) ? static_cast<uint8_t>((c << 1) ^ 0x07) : static_cast<uint8_t>(c << 1);
        t[i] = c;
    }
    return t;
}
constexpr auto kCrc8Table = make_crc8_table();     // 编译期完成，放 Flash/.rodata
static_assert(kCrc8Table[0x01] == 0x07, "table check");   // 编译期自检
```

好处：运行期零计算；表放只读段，不占 RAM（嵌入式关键）；`static_assert` 在编译期发现错误。同理可在编译期算：滤波器系数、`sin` 查表、`1u << bits` 的掩码、单位换算常数。参考 [UART 章 CRC](../08_嵌入式与通信/04_UART_SPI_I2C_以太网_TCP.md) 中 CRC8(0x01 对应表项) = 0x07。

### 7.3 常用相关

`constexpr` 变量代替宏：`constexpr double kPi = 3.14159265358979;`（有类型、有作用域）。`inline constexpr`（C++17）用于头文件里的全局常量。`static_assert(sizeof(Frame) == 12)` 检查协议结构体大小。

## 8. 多线程：thread、mutex、atomic、condition_variable

### 8.1 std::thread

```cpp
std::thread t([]{ /* 工作 */ });
t.join();           // 等待结束（必须在 t 析构前 join 或 detach，否则 std::terminate）
```

用 `std::jthread`（C++20）可自动 join。线程数不要无限制，上限看核数与任务类型。

### 8.2 数据竞争（data race）手追

```cpp
int counter = 0;
void work() { for (int i = 0; i < 100000; ++i) ++counter; }
// 两个线程同时跑 work()
```

`++counter` 并非原子，它是三步：**load → add → store**。交错执行：

| 步 | 线程 A | 线程 B | counter |
|---|---|---|---|
| 1 | load → 5 | | 5 |
| 2 | | load → 5 | 5 |
| 3 | add → 6 | | 5 |
| 4 | | add → 6 | 5 |
| 5 | store 6 | | 6 |
| 6 | | store 6 | 6 |

两次自增只加了 1。所以最终结果会在 100000 到 200000 之间随机——并且这在 C++ 里属于**未定义行为**。

### 8.3 三种修复

1. **mutex**：

```cpp
std::mutex m;
void work() { for (int i = 0; i < 100000; ++i) { std::lock_guard<std::mutex> lk(m); ++counter; } }
```

`lock_guard`/`unique_lock`/`scoped_lock` 是 RAII 锁，离开作用域自动解锁。多把锁一起拿用 `std::scoped_lock lk(m1, m2);`（内部避免死锁）。

2. **atomic**：`std::atomic<int> counter{0}; counter.fetch_add(1);`（硬件原子指令，更轻，适合单个变量/标志位/计数器）；
3. **无共享**：每个线程用自己的局部计数，最后再合并。

### 8.4 atomic 与内存序（概念）

`std::atomic` 默认 `memory_order_seq_cst`（最强、最易理解）。常见使用：

- **标志位**（线程退出请求 `std::atomic<bool> stop{false}`）；
- **发布—获取（release/acquire）**：生产者先写数据，再用 `store(release)` 设置就绪标志；消费者用 `load(acquire)` 看到标志后，一定能看到之前写入的数据。`relaxed` 只保证原子性，不保证顺序，适合纯计数统计。
- **原子不是万能**：多个字段要一致更新（如姿态四元数的 4 个分量）需要锁或双缓冲，不是给每个字段各加 atomic（会"撕裂"，与 [FreeRTOS 章 4.8](../08_嵌入式与通信/02_FreeRTOS实时系统.md) 的快照问题相同）。

### 8.5 condition_variable：生产者—消费者

**问题**：消费者线程不应忙等（浪费 CPU），而是睡眠等待"有数据"的通知。

```cpp
std::mutex m;
std::condition_variable cv;
std::queue<Cmd> q;
bool done = false;

void producer(Cmd c) {
    { std::lock_guard<std::mutex> lk(m); q.push(c); }
    cv.notify_one();
}
void consumer() {
    for (;;) {
        std::unique_lock<std::mutex> lk(m);
        cv.wait(lk, [&]{ return !q.empty() || done; });   // 带谓词：防虚假唤醒
        if (q.empty() && done) return;
        Cmd c = q.front(); q.pop();
        lk.unlock();                    // 先解锁再处理，缩短持锁时间
        handle(c);
    }
}
```

要点：(1) `wait` 内部先**原子地解锁并睡眠**，唤醒后重新加锁；(2) 必须用**谓词（while 循环）**，因为存在虚假唤醒（spurious wakeup）和"通知先于等待"的丢失唤醒；(3) 共享状态（队列、done）的修改要在同一把互斥量保护下进行；(4) 处理耗时工作要在锁外。

### 8.6 死锁

线程 A 持有锁 1 等锁 2，线程 B 持有锁 2 等锁 1 → 永久等待。四个必要条件：互斥、占有并等待、不可抢占、循环等待。预防：**统一加锁顺序**、用 `std::scoped_lock` 一次获取多把锁、缩小临界区、避免持锁调用外部回调。

### 8.7 "最新值邮箱"（与嵌入式对应）

```cpp
template <typename T>
class Latest {
public:
    void set(const T& v) { std::lock_guard<std::mutex> lk(m_); v_ = v; stamp_ = Clock::now(); }
    bool get(T& out, std::chrono::milliseconds max_age) const {
        std::lock_guard<std::mutex> lk(m_);
        if (Clock::now() - stamp_ > max_age) return false;   // 过期
        out = v_; return true;
    }
private:
    using Clock = std::chrono::steady_clock;
    mutable std::mutex m_; T v_{}; Clock::time_point stamp_{};
};
```

读到的是一份**一致的整体快照**，并带"新鲜度"判断。这与 [CAN 章](../08_嵌入式与通信/03_CAN_FDCAN与电机通信.md) 的 `last_seen` 和 P6 "validity checks" 的思想一致。时间用 `steady_clock`（单调，不受系统时间调整影响），不要用 `system_clock` 测间隔。

## 9. CMake

### 9.1 它要解决什么问题

C++ 工程有大量源文件、依赖库、编译选项，手写命令不可维护。**CMake** 是跨平台的构建系统生成器：你描述"目标（target）及其依赖"，它生成 Makefile/Ninja 工程；ROS2 的 `ament_cmake` 基于它。

### 9.2 最小工程

```cmake
cmake_minimum_required(VERSION 3.16)
project(robot_ctrl LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)     # 生成 compile_commands.json，给 clangd 用

add_library(device_core src/device.cpp src/can_device.cpp)
target_include_directories(device_core PUBLIC include)
target_compile_options(device_core PRIVATE -Wall -Wextra -Wpedantic)

find_package(Threads REQUIRED)
target_link_libraries(device_core PUBLIC Threads::Threads)

add_executable(ctrl_node src/main.cpp)
target_link_libraries(ctrl_node PRIVATE device_core)

enable_testing()
add_subdirectory(tests)
```

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build
```

### 9.3 可见性 PUBLIC / PRIVATE / INTERFACE

以 `target_link_libraries(A PUBLIC B)` 为例：

- **PRIVATE**：A 自己用到 B，使用 A 的人不需要知道 B；
- **PUBLIC**：A 用到 B，并且 A 的头文件里也暴露了 B，使用 A 的目标也需要 B；
- **INTERFACE**：A 自己不用 B，但使用 A 的目标要用 B（header-only 库）。

依赖会沿 PUBLIC/INTERFACE 传递，所以不要滥用 PUBLIC。

### 9.4 构建类型与交叉编译

`Debug`（`-O0 -g`）、`Release`（`-O3 -DNDEBUG`）、`RelWithDebInfo`。注意 `NDEBUG` 会让 `assert` 失效——**别把必须执行的逻辑写在 `assert(...)` 里**。控制代码的性能测试一定要 Release。交叉编译用工具链文件，见 [平台基础章 8 节](../08_嵌入式与通信/06_OpenHarmony_Hi3861_RK3588平台基础.md)。OpenHarmony 使用 GN + Ninja 的 `BUILD.gn`，概念类似（目标、依赖、源文件），只是语法不同。

### 9.5 常见错误

- 头文件改了不重新编译：依赖没声明；
- 链接顺序/未定义引用：忘记 `target_link_libraries`；
- 多处定义：头文件里定义了非 inline 的函数/变量；
- 不同目标用了不同 C++ 标准或 ABI（`_GLIBCXX_USE_CXX11_ABI`）。

## 10. 嵌入式 C++ 注意点

### 10.1 为什么要有取舍

MCU 的 Flash/RAM 小、要求确定性（见 [FreeRTOS 章](../08_嵌入式与通信/02_FreeRTOS实时系统.md)）。C++ 的某些特性带来**隐藏的开销或不确定性**。

| 特性 | 嵌入式常见态度 | 原因 |
|---|---|---|
| 异常 | 常关闭 `-fno-exceptions` | 异常表占 Flash，抛出时间不确定，栈展开复杂 |
| RTTI（`dynamic_cast`、`typeid`） | 常关闭 `-fno-rtti` | 占 Flash |
| 动态分配（`new`/`malloc`） | 初始化阶段允许，运行期避免 | 碎片化、耗时不确定、可能失败 |
| STL 容器 | 谨慎：`std::array` 可以；`vector/map/string` 会动态分配 | 可用 ETL 等嵌入式容器库，或自定义固定容量容器 |
| 虚函数 | 可以用 | 每对象 +1 个指针，调用多一次间接跳转，开销很小且确定 |
| iostream | 避免 | 体积巨大 |
| 全局对象构造 | 谨慎 | 构造顺序跨文件不确定，需 `__libc_init_array` 启动代码调用（见 [STM32 章 2](../08_嵌入式与通信/01_STM32_时钟_GPIO_中断_DMA.md)） |
| 模板 | 好用，但注意代码膨胀 | |
| `constexpr` | 强烈推荐 | 编译期计算，放 Flash |

### 10.2 常用技巧

- **静态分配**：缓冲与对象用全局/静态存储，或在启动阶段一次性分配；`std::array`、固定容量环形缓冲（见 4.2）；
- **`extern "C"`**：中断服务函数、HAL 回调、C 库接口需要 C 链接，避免 C++ 名字改编：

```cpp
extern "C" void USART1_IRQHandler(void) { /* 调用 C++ 对象的方法 */ }
```

- **placement new**：在预留好的静态缓冲上构造对象：`new (buf) Motor(id);` 而不用堆；
- **`volatile` 与寄存器**：外设寄存器访问用 `volatile`；`volatile` 不提供线程安全；
- **`static_assert`** 检查结构体大小、对齐、位宽；
- **`noexcept`** 标注不会抛异常的函数，帮助优化；
- **ISR 中不调用可能分配内存或阻塞的 C++ 库函数**。

### 10.3 手算：结构体布局

```cpp
struct A { char a; int b; char c; };     // 偏移：a=0, (填充 3) b=4, c=8, (尾填充 3) -> sizeof = 12
struct B { int b; char a; char c; };     // b=0, a=4, c=5, (尾填充 2) -> sizeof = 8
struct __attribute__((packed)) P { char a; int b; char c; };   // sizeof = 6，但 b 未对齐
```

对齐规则：每个成员对齐到其自身大小的倍数，结构体大小是最大对齐数的倍数。重新排列成员（大的在前）可省空间。`packed` 省空间但未对齐访问在某些 Cortex-M（如 M0）上会 HardFault，且访问变慢——协议解析建议用 `memcpy` 逐字段拷贝（见 [UART 章 9](../08_嵌入式与通信/04_UART_SPI_I2C_以太网_TCP.md)）。

## 11. 接口抽象与多态（对应 P6 统一设备抽象）

> 说明：下面是"这类系统常见的做法"的教学设计，帮助你理解并讲清"如何用 C++ 做统一设备能力模型"。示例中的类名与层次是教学命名，不是 P6 的源码。P6 的设计思路与此一致：能力分 Sensor / Actuator / Controller 三类，每个能力带 id、type、unit、frame、limits、timeout_ms 等字段，状态数据带时间戳、坐标系与有效性标志，设备启动后经"公告—能力注册"流程登记（字段与流程见 [P6 第 03 章](../../01_项目课程/P6_深开鸿M-Robots平台软件/03_统一能力模型与设备抽象.md)）。

### 11.1 它要解决什么问题

机器人平台上有不同厂商、不同总线的设备：CAN 电机、串口 IMU、网络相机……上层运动控制代码如果直接调用各设备的私有接口，换一个硬件就要重写。**统一抽象**：定义一个"能力接口"，各设备实现它，上层只面向接口编程（依赖倒置）。

### 11.2 设计

```cpp
// 教学示例
struct JointState { double pos, vel, effort; std::chrono::steady_clock::time_point stamp; bool valid; };

class IActuator {                       // 抽象接口：纯虚函数
public:
    virtual ~IActuator() = default;     // 虚析构：通过基类指针 delete 才安全
    virtual bool enable() = 0;
    virtual void disable() = 0;
    virtual bool set_torque(double nm) = 0;                  // 统一力矩接口，单位 N·m（输出轴）
    virtual bool set_position(double rad, double kp, double kd, double ff = 0) = 0;
    virtual JointState read() const = 0;
};

class CanMotor final : public IActuator {   // 具体驱动：协议细节封装在内部
public:
    CanMotor(CanBus& bus, uint8_t id, MotorParams p);
    bool set_torque(double nm) override;    // 内部：限幅 -> 单位换算(减速比/力矩常数) -> 打包 -> 发 CAN
    JointState read() const override;       // 内部：返回最近反馈 + 时间戳 + valid
    // ...
};

class MockMotor final : public IActuator { /* 单元测试用：不接硬件，可注入故障 */ };
```

上层只有：

```cpp
void control_step(IActuator& left, IActuator& right) {
    auto s = left.read();
    if (!s.valid) { /* 安全策略 */ }
    left.set_torque(u_left);              // 不关心是 CAN 电机还是别的
}
```

### 11.3 注册表 / 工厂：运行时选择具体实现

```cpp
using Maker = std::function<std::unique_ptr<IActuator>(const Config&)>;
class Registry {
public:
    static Registry& instance();
    void add(const std::string& type, Maker m) { makers_[type] = std::move(m); }
    std::unique_ptr<IActuator> create(const std::string& type, const Config& c) const {
        auto it = makers_.find(type);
        return it == makers_.end() ? nullptr : it->second(c);   // 未注册的类型返回空，由调用者处理
    }
private:
    std::unordered_map<std::string, Maker> makers_;
};
```

配置文件里写 `type: can_motor`，启动时按类型创建对象——**换硬件只改配置和新增一个实现类**，上层代码不变。这就是"实现运动控制代码在不同硬件上复用"的典型机制。ROS/ROS2 的运动指令（如 `cmd_vel`、`JointTrajectory`、`ros2_control` 的接口）到底层驱动的映射，就是在抽象层之上再加一层适配（把消息里的速度、位置转换成对 `IActuator` 的调用，并做限幅与单位统一）。

### 11.4 虚函数机制与开销（手算）

编译器为含虚函数的类生成一张**虚函数表（vtable）**，每个对象头部多一个**虚表指针（vptr）**。调用 `p->set_torque(x)`：读 `p->vptr` → 取表中第 k 项函数地址 → 间接调用。

**手算（64 位）**：

```cpp
struct Plain { int x; };                       // sizeof = 4
struct WithVirtual { virtual void f(); int x; };// vptr 8 字节 + int 4 字节 + 尾填充 4 = 16
```

每个对象多 8 字节（32 位 MCU 上多 4 字节）；每次虚调用比直接调用多一次内存读取和一个间接跳转，大约几个周期，且无法内联。对 1 kHz 的控制回路完全可以忽略；极热的内层循环（如每个采样点调用）才需要用模板/CRTP（编译期多态）代替。

**对象切片**：`void f(Base b)` 按值传递派生对象会切掉派生部分，多态必须通过**指针或引用**。

**组合优于继承**：接口继承用于"是一种能力"；复用实现优先用成员组合。

### 11.5 状态管理的接口配合

结合 CV 里 P6 的 "standardised timestamps, coordinate frames and validity checks"：`read()` 返回的不是一个裸 `double`，而是带**时间戳、坐标系/单位、有效位**的状态结构体——上层据此做新鲜度与一致性判断（见 [时间同步、坐标系一致性与数据有效性](../05_状态估计/06_时间同步_坐标系一致性与数据有效性.md)）。把"有效性"编码进类型，比靠约定更不容易出错。

### 11.6 可测试性

接口使你可以注入 `MockMotor`：模拟超时、返回非法值、力矩饱和，在没有硬件的情况下对控制逻辑与安全链做单元测试。这是抽象带来的工程价值之一。

## 12. 常见错误 / 边界 / 故障现象

| 现象 | 原因 |
|---|---|
| 偶发崩溃/段错误 | 悬空指针/引用（lambda 捕获、`vector` 扩容后的指针）；use-after-free |
| 内存缓慢增长 | `shared_ptr` 循环引用；容器无限增长 |
| 程序卡死 | 死锁；`condition_variable` 没谓词导致丢失唤醒；线程没 join |
| 数值偶尔错乱 | 数据竞争；多字段未同步 |
| 性能差 | Debug 构建；频繁拷贝（该传 `const&` 或移动）；`std::function` 在热路径；`unordered_map` 在循环里 rehash |
| `std::terminate` | 线程析构前没 join/detach；异常逃出 `noexcept` 函数 |
| 链接错误 | 忘链接库；头文件里定义非 inline 函数 |
| 嵌入式 Flash 爆 | 引入 iostream/异常/大模板实例化 |
| 回调时对象已销毁 | 捕获 `this` 但没有生命周期保护 |

调试工具：`-Wall -Wextra -fsanitize=address,undefined`（内存和未定义行为）、`-fsanitize=thread`（数据竞争）、`valgrind`、`gdb`/`lldb`、`clang-tidy`。

## 13. 面试怎么问、怎么答

**Q1. What is RAII and why does it matter in robot software?**

> RAII ties a resource's lifetime to an object's lifetime: the constructor acquires it, the destructor releases it. In robot code, that covers locks, sockets, CAN handles and memory, so an early return or an exception can't leave a mutex locked or a device open. I prefer standard wrappers like unique_ptr and lock_guard, and follow the rule of zero where I can.

**Q2. When do you use unique_ptr versus shared_ptr?**

> unique_ptr by default, since ownership is clear and it costs nothing. shared_ptr only when several owners truly share lifetime, such as a ROS node handed to an executor. I use weak_ptr to break cycles, like a child that refers to a parent, or in callbacks that may outlive an object.

**Q3. How do you protect shared robot state between threads?**

> For a single flag or counter I use std::atomic. For a state made of several fields, like pose plus timestamp, I use a mutex around a whole snapshot, or double buffering, so readers never see a half-updated state. For waiting I use a condition variable with a predicate, not busy-waiting. I also keep critical sections short and avoid calling out while holding a lock.

追问：memory_order 懂吗？（release/acquire 发布数据；relaxed 仅计数）；死锁如何避免？（统一顺序、scoped_lock）。

**Q4. How did you design the unified device abstraction on the platform?**

> The idea was an interface for each capability, such as a sensor, an actuator or a controller, with the hardware-specific parts hidden in driver classes. The upper motion-control code depends only on the interface and works with data that carries a timestamp, a frame and a validity flag. ROS or ROS2 commands are adapted to the interface, which then maps them to the low-level driver. This lets the same control code run on different hardware, and I can test it with mock devices.

P6 里对应的设计是：能力模型分 Sensor / Actuator / Controller 三类，适配器把 CAN、串口等硬件细节藏在驱动类里，上层只依赖接口；状态数据统一带 stamp、frame_id、validity；测试上用假设备（mock）做单元测试，并对每个适配器跑同一套契约用例（含运动学往返）。这是设计级描述，细节见 P6 第 03 章。

**Q5. Why might you avoid exceptions or dynamic allocation in embedded C++?**

> Exceptions increase code size and have non-deterministic timing; dynamic allocation can fragment memory and take unpredictable time or fail. In real-time loops I allocate everything at start-up, use fixed-capacity containers, and handle errors with return codes.

## 本章要点速记

1. RAII：构造获取、析构释放；管理资源的类要么五法则、要么 delete 拷贝留移动、要么零法则；
2. `unique_ptr` 默认，`shared_ptr` 共享，`weak_ptr` 破循环；`make_unique/make_shared`；
3. `std::move` 只是转换为右值引用；移动构造要 `noexcept`，`vector` 才会用移动；不要 `return std::move(local)`；
4. `vector` 扩容翻倍，均摊 O(1)，9 次 push 搬运 15 次；已知大小用 `reserve`；
5. 模板在编译期实例化，零运行时开销，注意代码膨胀；
6. 容器默认 `vector`；`unordered_map` 查找 O(1) 均摊；`map` 有序 O(log n)；
7. lambda 超出局部变量生命周期就按值捕获；`this` 回调用 `weak_ptr` 保护；
8. `constexpr` 在编译期算表，`static_assert` 自检，放 Flash 不占 RAM；
9. 数据竞争：`++` 是 load/add/store；用 mutex/atomic/无共享；cv 必须带谓词；统一加锁顺序防死锁；
10. CMake：目标 + `target_link_libraries`，PRIVATE/PUBLIC/INTERFACE，Release 构建测性能；
11. 嵌入式 C++：无异常、无运行期动态分配、`extern "C"` 的 ISR、`std::array`、静态分配；
12. 接口 + 驱动 + 注册工厂 = 同一份控制代码跨硬件复用；虚调用开销小；状态带时间戳与有效位。

## 自测题

1. `struct S { char a; double b; char c; };` 在 64 位下 `sizeof` 多少？怎么重排最省？（要点：a 0，b 8，c 16，尾填充 → 24；重排 `double b; char a; char c;` → 16。）
2. `a = make_shared<X>(); b = a; c = b; b.reset();` 此时 `use_count`？（要点：3 → b 重置后 2。）
3. `push_back` 17 个元素（容量 1,2,4,8,16,32 翻倍），总搬运多少次？（要点：1+2+4+8+16 = 31 < 2×17。）
4. 说出下面代码的错误：`std::thread t(f);` 后函数直接返回。（要点：未 join/detach，析构时 `std::terminate`。）
5. 写出 `cv.wait` 需要谓词的两个原因。（要点：虚假唤醒；通知先于等待导致丢失唤醒——谓词读到共享状态已变。）
6. `target_link_libraries(core PUBLIC fmt)` 与 `PRIVATE fmt` 对使用 core 的 app 有什么不同？（要点：PUBLIC 会让 app 也获得 fmt 的包含路径和链接；PRIVATE 不会。）
7. 为什么抽象基类需要虚析构函数？（要点：通过基类指针 delete 派生对象时才会调用派生析构函数，否则泄漏/未定义行为。）
