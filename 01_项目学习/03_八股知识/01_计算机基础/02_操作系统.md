## 一、进程与线程

### Q1 进程和线程的区别？（Process vs thread）
**优先级：★★★**

**答案要点**
- 进程（process）是资源分配单位：独立虚拟地址空间、文件描述符表、信号处理等。线程（thread）是 CPU 调度单位：共享所属进程的地址空间、堆、全局变量、文件描述符，各自有独立的栈、寄存器、程序计数器和线程局部存储。
- 创建与切换开销：线程切换不需要换页表、不刷 TLB（同进程内），比进程切换便宜。
- 通信：进程间需要 IPC（管道、共享内存、消息队列、socket）；线程间直接读写共享内存，但必须同步。
- 隔离：一个进程崩溃不影响其他进程；一个线程崩溃（如段错误）会拖垮整个进程。
- ROS：每个节点常是一个进程；节点内回调线程共享内存。

**English short answer**
A process owns its own address space and resources, while threads inside a process share the address space, heap and file descriptors but have their own stacks and registers. Threads are cheaper to create and switch, and they communicate through shared memory, but they need synchronization. Processes are better isolated, so a crash in one does not take down the others.

**追问方向**：进程切换要保存什么；协程是什么；为什么线程栈独立。

### Q2 进程的状态与转换？（Process states）
**优先级：★★**

**答案要点**：新建 → 就绪（ready）⇄ 运行（running）→ 阻塞（waiting）→ 就绪 → 终止。就绪到运行由调度器选中；运行到就绪是时间片用完或被抢占；运行到阻塞是等待 IO/锁/事件；阻塞到就绪是事件到来。僵尸进程（zombie）：子进程已退出，父进程没 `wait`，PCB 残留；孤儿进程被 init 收养。

```text
 new -> ready <-> running -> terminated
          ^          |
          |          v
          +------ blocked
```

**English short answer**
A process moves between ready, running and blocked. A scheduler picks a ready process to run; it returns to ready when preempted or its time slice ends, and goes to blocked when it waits for IO or a lock. A zombie is a finished child whose parent has not collected its exit status yet.

**追问方向**：僵尸进程如何清理（wait / SIGCHLD）；FreeRTOS 任务状态。

### Q3 fork 做了什么？写时复制（COW）是什么？（fork and copy-on-write）
**优先级：★★★**

**答案要点**：`fork()` 创建子进程，返回两次：父进程得到子 pid，子进程得到 0。现代内核不立即复制内存，而是让父子共享物理页并标记只读，任一方写入时触发缺页异常，内核才复制该页，这就是写时复制。`fork` 后常跟 `exec` 加载新程序，COW 避免了无谓拷贝。

```c
pid_t pid = fork();
if (pid == 0) { execlp("ls", "ls", NULL); _exit(127); }
else waitpid(pid, NULL, 0);
```

**English short answer**
fork creates a child process that is a copy of the parent. It returns the child pid in the parent and zero in the child. Modern kernels use copy-on-write: parent and child share physical pages marked read-only, and a page is copied only when someone writes to it. That makes fork followed by exec cheap.

**追问方向**：vfork；多线程程序 fork 的陷阱；exec 做了什么。

### Q4 线程切换（上下文切换）开销在哪里？（Context switch cost）
**优先级：★★★**

**答案要点**：直接开销：保存/恢复寄存器、栈指针、PC，进入内核。间接开销：缓存和 TLB 失效（进程切换更重）、流水线冲刷。频繁切换使吞吐下降。所以实时控制环中减少线程数、避免不必要的阻塞。FreeRTOS 在 Cortex-M 上通过 PendSV 完成切换，只保存任务的核心寄存器。

**English short answer**
A context switch saves the registers and stack pointer of the current thread and restores another one. The direct cost is small, but the indirect cost from cold caches and TLB flushes can be large, especially across processes. That is why I avoid creating too many threads in a control system.

**追问方向**：用户态线程/协程切换为何更快；PendSV。

### Q5 进程间通信（IPC）有哪些方式？（IPC mechanisms）
**优先级：★★★**

| 方式 | 特点 |
|---|---|
| 管道 pipe / 命名管道 FIFO | 字节流、单向，简单 |
| 消息队列 | 带类型的消息，内核缓冲 |
| 共享内存 | 最快（零拷贝），需自己同步 |
| 信号量 | 同步而非传数据 |
| 信号 signal | 异步通知 |
| socket | 可跨机器，Unix domain socket 本机高效 |

**答案要点**：共享内存最快，因为数据不经过内核拷贝；但要配信号量或互斥量。ROS2 同机进程通信可经 DDS 共享内存传输；跨机用 UDP/TCP。

**English short answer**
Common IPC mechanisms are pipes, message queues, shared memory, semaphores, signals and sockets. Shared memory is the fastest because there is no copy through the kernel, but you have to synchronize access yourself. Sockets work across machines, which is how most robot middleware talks over the network.

**追问方向**：管道的阻塞行为；DDS 共享内存传输；见 [Linux_Git_编译构建八股](./08_Linux_Git_编译构建八股.md)。

### Q6 用户态线程、内核态线程、协程的区别？（User vs kernel threads, coroutines）
**优先级：★★**

**答案要点**：内核线程由 OS 调度，可利用多核，阻塞系统调用只阻塞自己。用户态线程由库调度，切换快，但一个阻塞调用可能阻塞整个进程（N:1 模型）。协程是用户态协作式调度的轻量执行单元，主动让出（yield/await），切换只需保存少量寄存器，适合 IO 密集；不能自动利用多核。见 [Python八股](./06_Python八股.md) 的 asyncio。

**English short answer**
Kernel threads are scheduled by the OS and can run on multiple cores. User-level threads and coroutines are scheduled in user space, which makes switching much cheaper, but they cooperate by yielding explicitly and do not use multiple cores by themselves. Coroutines are great for IO-bound work.

**追问方向**：Go goroutine 模型 M:N；协程栈。

## 二、调度

### Q7 常见调度算法有哪些？（CPU scheduling algorithms）
**优先级：★★★**

**答案要点**
- FCFS：简单，护航效应（convoy effect）。
- SJF/SRTF：平均等待时间最短（可证明最优），但需预测运行时间，易饥饿。
- 时间片轮转 RR：公平，响应好；时间片过小切换开销大，过大退化为 FCFS。
- 优先级调度：高优先级先跑，低优先级可能饥饿，用老化（aging）缓解。
- 多级反馈队列 MLFQ：新进程高优先级短时间片，用完时间片降级，兼顾交互与批处理。
- Linux CFS：按虚拟运行时间 vruntime 公平，用红黑树取最小 vruntime。

**English short answer**
First-come-first-served is simple but suffers from the convoy effect. Shortest job first minimizes average waiting time but needs run-time prediction and can starve long jobs. Round robin gives fairness with time slices. Real systems use multilevel feedback queues or Linux CFS, which picks the task with the smallest virtual runtime from a red-black tree.

**追问方向**：周转时间/响应时间/吞吐量的定义；多核调度负载均衡。

### Q8 抢占式与非抢占式调度？（Preemptive vs non-preemptive）
**优先级：★★**

**答案要点**：抢占式：高优先级就绪或时间片到时，内核可强行剥夺 CPU（需要定时器中断驱动），响应快，需要处理共享数据竞争。非抢占式（协作式）：任务主动让出，简单但一个任务不放手系统就卡住。实时系统（FreeRTOS 默认）使用基于优先级的抢占式调度，同优先级任务时间片轮转。

**English short answer**
In preemptive scheduling the kernel can take the CPU away from a running task when a higher priority task becomes ready or its time slice ends. In cooperative scheduling tasks must yield by themselves. RTOSes like FreeRTOS are priority-based and preemptive, which gives bounded response for high priority tasks.

**追问方向**：FreeRTOS tick；临界区关中断。

### Q9 什么是优先级反转？如何解决？（Priority inversion）
**优先级：★★★**

**答案要点**：低优先级任务 L 持有锁，高优先级 H 等待该锁被阻塞，此时中优先级 M 抢占 L 运行，导致 H 实际被 M 压住。1997 年火星探路者（Mars Pathfinder）事故是经典案例。解决：优先级继承（L 临时继承 H 的优先级）、优先级天花板协议、避免共享锁。FreeRTOS 的互斥量（mutex）带优先级继承，二值信号量没有。详见 [并发多线程与实时系统八股](./07_并发多线程与实时系统八股.md)。

**English short answer**
Priority inversion happens when a low priority task holds a lock needed by a high priority task, and a medium priority task preempts the low one, so the high priority task is effectively delayed by the medium one. The fix is priority inheritance, where the lock holder temporarily runs at the waiter's priority, or a priority ceiling protocol. FreeRTOS mutexes support inheritance, while binary semaphores do not.

**追问方向**：继承的局限（不能解决死锁）；天花板协议。

### Q10 实时调度算法 RM 与 EDF？（Rate-monotonic and EDF）
**优先级：★★**

**答案要点**
- RM（速率单调）：周期越短优先级越高，固定优先级。可调度的充分条件 $U=\sum C_i/T_i \le n(2^{1/n}-1)$，$n\to\infty$ 时约 69.3%；必要条件 $U\le1$。
- EDF（最早截止期优先）：动态优先级，单核理想条件下 $U\le 1$ 即可调度。
- 例（教学示例）：两任务 $C_1=1,T_1=4$；$C_2=2,T_2=6$，$U=0.25+0.333=0.583<0.828$，RM 可调度。

**English short answer**
Rate-monotonic scheduling gives higher fixed priority to tasks with shorter periods, and it is guaranteed to work if CPU utilization is below about 69 percent for many tasks. Earliest deadline first uses dynamic priorities based on the nearest deadline and can reach 100 percent utilization on one core in theory. In practice most RTOS applications use RM-style fixed priorities.

**追问方向**：WCET；抖动；对应 P3/P7 的任务优先级设计思路（典型做法：控制环高优先级，通信低）。

## 三、内存管理

### Q11 虚拟内存是什么？为什么需要？（Virtual memory）
**优先级：★★★**

**答案要点**：每个进程看到连续的私有虚拟地址空间，由 MMU 通过页表映射到物理内存。作用：①隔离与保护；②地址空间可大于物理内存（换出到磁盘）；③简化链接与加载；④共享（共享库、COW）；⑤按需分页（demand paging）。代价：地址翻译开销，缺页异常处理慢。嵌入式 MCU（如 STM32F4）多无 MMU，只有可选 MPU 做区域保护。

**English short answer**
Virtual memory gives every process its own contiguous address space, which the MMU maps to physical memory through page tables. It provides isolation, lets programs use more memory than physically installed through swapping, and allows sharing and demand paging. Small microcontrollers usually have no MMU, only an optional memory protection unit.

**追问方向**：MMU 与 MPU；mmap；overcommit。

### Q12 分页与分段？页表如何工作？（Paging and segmentation）
**优先级：★★★**

**答案要点**
- 分页：虚拟地址分为页号 + 页内偏移，物理内存分为同样大小的页框。页表项记录页框号及有效、读写、脏位等标志。无外部碎片，有内部碎片。
- 例（教学示例）：32 位地址、4KB 页，偏移 12 位，页号 20 位，单级页表 $2^{20}$ 项 × 4B = 4MB/进程，太大，故用多级页表（x86-64 四级），只为用到的区域建表。
- 分段：按逻辑模块，有外部碎片。现代系统以分页为主。
- 大页（huge page）减少 TLB 压力。

**English short answer**
With paging, a virtual address is split into a page number and an offset. The page table maps the page number to a physical frame. Multi-level page tables save memory because only used regions need tables. Paging has no external fragmentation, only a little internal fragmentation inside the last page.

**追问方向**：多级页表为何省空间；反向页表。

### Q13 TLB 是什么？命中率如何影响性能？（TLB）
**优先级：★★★**

**答案要点**：TLB（Translation Lookaside Buffer）是缓存最近页表项的小而快的硬件缓存。命中时一次翻译近乎零开销，未命中需遍历页表（多次内存访问）。有效访问时间 $EAT = h\cdot t_{tlb}+(1-h)(t_{tlb}+k\cdot t_{mem})$，$k$ 为页表级数。进程切换要刷 TLB（或用 ASID 标记免刷）。大页、局部性好的访问可提高命中率。

**English short answer**
The TLB is a small hardware cache of recent virtual-to-physical translations. On a hit, translation is almost free; on a miss the hardware has to walk the page table, which costs several memory accesses. Good locality and huge pages improve the hit rate, and context switches may flush it unless entries are tagged with an address-space ID.

**追问方向**：为什么线程切换比进程切换轻；TLB shootdown。

### Q14 缺页异常（page fault）处理流程？（Page fault）
**优先级：★★★**

**答案要点**：访问的页不在内存（或权限不符）→ MMU 触发异常 → 内核检查地址是否合法（非法则 SIGSEGV）→ 找空闲页框，没有则按置换算法选牺牲页（脏页需写回）→ 从磁盘读入 → 更新页表 → 重新执行指令。分 minor（页在内存只需映射，如 COW、首次访问零页）和 major（需要磁盘 IO）。

**English short answer**
When a program touches a page that is not mapped, the MMU raises a page fault. The kernel checks that the address is valid, finds a free frame or evicts one, loads the page from disk if needed, updates the page table and restarts the instruction. If the address is illegal the process gets a segmentation fault.

**追问方向**：抖动（thrashing）；工作集；mlock 在实时系统中的作用。

### Q15 页面置换算法？（Page replacement）
**优先级：★★**

**答案要点**：OPT（理论最优，需知未来）；FIFO（有 Belady 异常，增加页框反而缺页增多）；LRU（近似最优，实现代价高，常用近似：Clock/二次机会算法，用访问位）；LFU。例（教学示例）：访问序列 1,2,3,1,4，3 个页框，LRU 在访问 4 时淘汰 2。

**English short answer**
OPT is the theoretical best but needs future knowledge. FIFO is simple but can show Belady's anomaly. LRU approximates OPT using recency, and real systems use cheap approximations like the clock algorithm with reference bits.

**追问方向**：LRU 的实现（见 DS 章 LRU 缓存）。

### Q16 内部碎片与外部碎片？malloc 如何管理堆？（Fragmentation and malloc）
**优先级：★★**

**答案要点**：内部碎片：分配块内未用部分（分页、对齐）。外部碎片：空闲块分散，总量够但不连续（分段、变长分配）。malloc：小块从堆（brk）按大小类的空闲链表分配，大块用 mmap；释放后合并相邻空闲块。嵌入式避免 malloc：碎片和不确定延迟，用静态分配或内存池（固定大小块，$O(1)$ 分配释放，无外部碎片）。

**English short answer**
Internal fragmentation is wasted space inside an allocated block, and external fragmentation is free memory scattered in pieces too small to use. malloc keeps free lists by size and uses mmap for big requests. In embedded systems I prefer static allocation or memory pools because they have constant time and no external fragmentation.

**追问方向**：jemalloc/tcmalloc；伙伴系统（buddy）与 slab。

### Q17 进程的内存布局？（Process memory layout）
**优先级：★★★**

```text
高地址  +-----------------+
        | 内核空间        |
        +-----------------+
        | 栈 stack  (向下)|
        |       ...       |
        | 堆 heap   (向上)|
        +-----------------+
        | .bss  未初始化  |
        | .data 已初始化  |
        | .text 代码/常量 |
低地址  +-----------------+
```

**答案要点**：栈存局部变量、返回地址，自动管理，大小有限（Linux 默认约 8MB，`ulimit -s`）；堆由程序员管理；`.bss` 在文件中不占空间，加载时清零。嵌入式 MCU 的 SRAM 同理：`.data` 从 Flash 拷贝到 RAM，`.bss` 清零，堆栈大小在链接脚本/启动文件配置。详见 [C语言与嵌入式八股](./04_C语言与嵌入式八股.md)。

**English short answer**
A process has code, initialized data, uninitialized data called bss, the heap growing upward, and the stack growing downward. Locals and return addresses live on the stack, and the heap is for dynamic allocation. On a microcontroller the layout is similar, but initialized data is copied from flash to RAM at startup.

**追问方向**：栈溢出后果；ASLR。

### Q18 内存映射 mmap 的用途？（mmap）
**优先级：★★**

**答案要点**：把文件或设备映射到进程地址空间，读写如访问内存，由缺页机制按需加载。用途：加载共享库、大文件处理、进程间共享内存（MAP_SHARED）、分配大块匿名内存、嵌入式 Linux 里访问设备寄存器（映射 `/dev/mem`）。零拷贝减少 `read` 的内核到用户拷贝。

**English short answer**
mmap maps a file or device into the process address space so you can access it like memory, and pages are loaded on demand. It is used for shared libraries, large files, shared memory between processes, and accessing hardware registers on embedded Linux.

**追问方向**：mmap 与 read 的性能对比；page cache。

## 四、文件系统与 IO

### Q19 Linux 文件系统的核心概念：inode、目录项、硬链接软链接？（inode, links）
**优先级：★★★**

**答案要点**：inode 保存文件元数据（大小、权限、时间、数据块指针），不含文件名；目录是"文件名 → inode 号"的映射表。硬链接：多个名字指向同一 inode，引用计数减到 0 才真正删除，不能跨文件系统、不能指向目录。软链接（符号链接）：存放目标路径的特殊文件，可跨文件系统，目标删除后悬空。

**English short answer**
An inode stores a file's metadata and block pointers but not its name; directories map names to inode numbers. A hard link is another name for the same inode, and the data is freed only when the link count reaches zero. A symbolic link is a small file that stores a path, so it can cross file systems and can dangle.

**追问方向**：`rm` 一个正在被打开的文件会怎样；ln 命令。

### Q20 文件描述符是什么？（File descriptor）
**优先级：★★★**

**答案要点**：进程级整数索引，指向内核的"打开文件表"项。0/1/2 是标准输入/输出/错误。socket、管道、设备都以 fd 表示（"一切皆文件"）。`dup2` 重定向；`fork` 后子进程继承 fd；`close-on-exec`。fd 泄漏会耗尽上限（`ulimit -n`）。

**English short answer**
A file descriptor is a small integer that indexes into a per-process table pointing to an open file object in the kernel. Files, pipes, sockets and devices are all accessed through descriptors, which is the Unix everything-is-a-file idea. Forgetting to close them leaks descriptors until you hit the limit.

**追问方向**：dup2 原理；重定向实现。

### Q21 阻塞/非阻塞、同步/异步 IO 的区别？（Blocking, non-blocking, sync, async IO）
**优先级：★★★**

**答案要点**：阻塞：调用在数据未就绪时挂起。非阻塞：立即返回 EAGAIN。IO 多路复用：用一个线程监听多个 fd（select/poll/epoll）。同步 IO：数据拷贝阶段调用者仍被阻塞（含 IO 多路复用）；异步 IO（POSIX AIO、io_uring）：内核完成拷贝后通知。五种模型：阻塞、非阻塞、多路复用、信号驱动、异步。

**English short answer**
Blocking IO suspends the caller until data is ready; non-blocking IO returns immediately with an error if nothing is available. IO multiplexing, like epoll, lets one thread wait on many descriptors. In truly asynchronous IO, the kernel also performs the data copy and notifies you afterwards.

**追问方向**：Reactor vs Proactor；见 [计算机网络](./03_计算机网络.md)。

### Q22 select、poll、epoll 的区别？（select/poll/epoll）
**优先级：★★★**

**答案要点**
- select：fd_set 位图，上限 1024，每次调用把整个集合拷到内核并线性扫描 $O(n)$。
- poll：用数组，无 1024 限制，仍是 $O(n)$ 扫描。
- epoll：内核维护红黑树存兴趣集，就绪事件放就绪链表，`epoll_wait` 只返回就绪的 fd，复杂度 $O(\text{就绪数})$；支持水平触发（LT）和边缘触发（ET）。ET 必须配非阻塞 IO 且一次读尽。

**English short answer**
select and poll scan all descriptors on every call, so they cost O(n), and select is limited to 1024 descriptors. epoll keeps the interest set in the kernel and returns only the ready descriptors, so it scales to many connections. It supports level-triggered and edge-triggered modes; with edge-triggered mode you must read until EAGAIN.

**追问方向**：LT 与 ET；惊群。

### Q23 DMA 是什么？零拷贝（zero-copy）？（DMA and zero-copy）
**优先级：★★**

**答案要点**：DMA 让外设直接读写内存，不占用 CPU 搬运数据，传输完成后用中断通知。零拷贝（sendfile）：文件到 socket 不经用户态缓冲，减少两次拷贝和上下文切换。嵌入式 DMA 的 cache 一致性问题见 [C语言与嵌入式八股](./04_C语言与嵌入式八股.md)。

**English short answer**
DMA lets a peripheral move data to or from memory without the CPU copying every byte; the CPU only gets an interrupt when the transfer is done. Zero-copy techniques like sendfile avoid copying data between kernel and user buffers.

**追问方向**：DMA 与 cache 一致性；STM32 UART DMA 空闲中断（典型做法）。

## 五、同步与死锁

### Q24 什么是竞态条件和临界区？（Race condition, critical section）
**优先级：★★★**

**答案要点**：多个执行流在没有同步的情况下访问共享数据，结果取决于时序，即竞态条件。临界区是访问共享资源的那段代码，需满足互斥、空闲让进、有限等待、让权等待。经典例子：`counter++` 实际是 load-add-store 三步，不是原子的。

**English short answer**
A race condition occurs when two threads access shared data without synchronization and the result depends on timing. Even counter plus plus is three steps: load, add and store, so two threads can overwrite each other. The code that touches shared data is a critical section and must be protected by a mutual exclusion mechanism.

**追问方向**：原子变量；Peterson 算法。

### Q25 互斥锁、自旋锁、信号量、条件变量的区别？（Mutex, spinlock, semaphore, condition variable）
**优先级：★★★**

**答案要点**
- 互斥锁 mutex：拿不到锁就睡眠（让出 CPU），有所有权（谁加谁解）。适合临界区较长。
- 自旋锁 spinlock：忙等循环，不切换上下文，适合临界区极短且多核；单核上自旋无意义。中断上下文只能用自旋锁（不能睡眠）。
- 信号量 semaphore：计数器 + P/V（wait/post）操作，用于资源计数或信号通知，无所有权。二值信号量可用于任务与中断同步。
- 条件变量：等待某条件成立，必须与互斥锁配合，用 `while` 检查谓词防止虚假唤醒（spurious wakeup）。

```cpp
std::unique_lock<std::mutex> lk(m);
cv.wait(lk, []{ return !q.empty(); });
```

**English short answer**
A mutex puts a waiting thread to sleep and has an owner. A spinlock busy-waits and is only good for very short critical sections on multi-core systems. A semaphore is a counter used for resource counting or signaling, with no owner. A condition variable lets a thread wait for a predicate and must be used with a mutex and a while loop to handle spurious wakeups.

**追问方向**：读写锁；递归锁；信号量可用于中断。

### Q26 死锁的四个必要条件和处理方法？（Deadlock conditions）
**优先级：★★★**

**答案要点**
- 四条件（Coffman）：①互斥；②占有并等待（hold and wait）；③不可剥夺；④循环等待。打破任一条即可避免。
- 预防：一次性申请所有资源（破坏②）、允许抢占（破坏③）、按全局顺序加锁（破坏④，最常用）。
- 避免：银行家算法（需要知道最大需求，实际少用）。
- 检测与恢复：资源分配图找环，杀进程/回滚。
- 工程做法：固定加锁顺序、`std::scoped_lock` 同时锁多个、`try_lock` 加超时、减小锁粒度。

**English short answer**
Deadlock needs four conditions at once: mutual exclusion, hold and wait, no preemption, and circular wait. Breaking any one prevents it. In practice the most common fix is a global lock ordering, or locking several mutexes at once with std::scoped_lock. Timeouts with try_lock help detect and recover.

**追问方向**：写出一个死锁例子；活锁与饥饿的区别；银行家算法。

### Q27 生产者—消费者问题怎么用信号量解决？（Producer-consumer with semaphores）
**优先级：★★★**

**答案要点**：三个量：`empty`（空槽数，初值 N）、`full`（已用数，初值 0）、`mutex`（保护缓冲区）。生产者 `P(empty); P(mutex); put; V(mutex); V(full)`；消费者 `P(full); P(mutex); get; V(mutex); V(empty)`。**两个 P 的顺序不能反**，先 P(mutex) 再 P(empty) 可能死锁。C++ 版本见 [并发多线程与实时系统八股](./07_并发多线程与实时系统八股.md)。

**English short answer**
I use two counting semaphores, one for empty slots and one for filled slots, plus a mutex protecting the buffer. The producer waits on empty slots, locks, inserts, unlocks and signals full; the consumer does the reverse. The order of waiting on the semaphore and the mutex matters, otherwise it can deadlock.

**追问方向**：读者—写者；哲学家就餐。

### Q28 读者—写者问题与读写锁？（Readers-writers lock）
**优先级：★★**

**答案要点**：允许多个读者并发，写者独占。读者优先可能饿死写者，写者优先则反之。`std::shared_mutex`/`pthread_rwlock`。读多写少的配置/地图数据适用；写频繁时读写锁开销比 mutex 大。

**English short answer**
A readers-writer lock allows many readers at once but only one writer, and writers exclude readers. It helps with read-heavy data, but depending on the policy it can starve either readers or writers.

**追问方向**：RCU；seqlock。

### Q29 内存屏障和 CAS 是什么？（Memory barrier and CAS）
**优先级：★★**

**答案要点**：CPU 和编译器会重排指令，内存屏障限制重排顺序。CAS（compare-and-swap）原子地"若值等于期望则替换"，是无锁结构基础，存在 ABA 问题（用版本号解决）。详见 [并发多线程与实时系统八股](./07_并发多线程与实时系统八股.md)。

**English short answer**
Compilers and CPUs may reorder memory operations, so memory barriers enforce ordering. Compare-and-swap atomically replaces a value only if it still equals the expected one, and it is the building block of lock-free algorithms. A classic pitfall is the ABA problem.

**追问方向**：acquire/release；volatile 不等于原子。

## 六、系统调用、中断与实时性

### Q30 系统调用是什么？用户态和内核态如何切换？（System call, user/kernel mode）
**优先级：★★★**

**答案要点**：用户程序不能直接访问硬件，必须通过系统调用请求内核服务（open/read/write/fork/mmap）。流程：库函数把调用号放入寄存器 → 执行 `syscall`/`svc`/`int 0x80` 陷入指令 → CPU 切换到内核态、跳到内核入口 → 内核按调用号分发处理 → 返回用户态。开销来自模式切换和参数检查，故 `printf` 会缓冲、批量 `write`。`strace` 可观察。

**English short answer**
A system call is how a user program asks the kernel to do privileged work, like reading a file. The library puts the call number in a register and executes a trap instruction; the CPU switches to kernel mode, runs the handler, and returns. Because the switch has a cost, libraries buffer output and batch operations.

**追问方向**：vDSO；`strace` 的用法；glibc 封装。

### Q31 中断的处理流程与上半部/下半部？（Interrupt handling）
**优先级：★★★**

**答案要点**：硬件拉起中断线 → CPU 保存现场、查中断向量表跳转 ISR → 执行 → 恢复现场返回。ISR 要短：不能阻塞、不能睡眠、不做耗时操作。Linux 分上半部（硬中断，快速确认硬件）与下半部（softirq/tasklet/workqueue，做耗时处理）。RTOS：ISR 里只调用以 `FromISR` 结尾的 API（如 FreeRTOS `xQueueSendFromISR`），唤醒任务后处理。嵌入式见 [C语言与嵌入式八股](./04_C语言与嵌入式八股.md)。

**English short answer**
When an interrupt fires, the CPU saves its context, looks up the handler in the vector table and runs the interrupt service routine, then restores the context. The handler must be short and must not block. Heavy work is deferred to a task or a bottom-half mechanism. In an RTOS I only call the FromISR versions of the APIs inside an ISR.

**追问方向**：中断嵌套与优先级；中断延迟；Cortex-M NVIC。

### Q32 中断与异常、陷阱的区别？（Interrupt vs exception vs trap）
**优先级：★★**

**答案要点**：中断：外部异步事件（定时器、外设）。异常：指令执行中同步产生（缺页、除零、非法指令）。陷阱（trap）：有意触发（系统调用、断点）。三者都通过向量表转入内核/处理函数。MCU 里 HardFault 通常由非法内存访问、未对齐访问、栈溢出引起。

**English short answer**
Interrupts are asynchronous events from hardware, exceptions are synchronous faults raised by an instruction such as a page fault or division by zero, and traps are deliberate, like system calls. On a Cortex-M a HardFault often means an invalid memory access or a stack overflow.

**追问方向**：如何调试 HardFault。

### Q33 实时操作系统（RTOS）与通用 OS 的区别？（RTOS vs general-purpose OS）
**优先级：★★★**

**答案要点**：RTOS 追求**可预测性**（determinism）而不是平均吞吐：有界的中断延迟与调度延迟、基于优先级抢占、简单内核、小占用。硬实时：错过截止期即失败（如电机控制环）；软实时：偶尔超期可接受（如视频）。Linux 默认非实时，可用 PREEMPT_RT 补丁、`SCHED_FIFO`、`mlockall`、CPU 亲和性提升实时性。控制闭环的周期抖动（jitter）是核心指标。相关嵌入式项目 P3、P7 使用 FreeRTOS，参见 [FreeRTOS实时系统](../../02_基础知识/08_嵌入式与通信/02_FreeRTOS实时系统.md)。

**English short answer**
A general-purpose OS optimizes average throughput and fairness, while an RTOS optimizes predictability: bounded interrupt and scheduling latency with priority-based preemption. In hard real-time systems, such as motor control loops, missing a deadline is a failure. Linux can be made more real-time with the PREEMPT_RT patch, real-time scheduling classes and locked memory.

**追问方向**：SCHED_FIFO；抖动测量；Linux + MCU 的分工（高层规划在 Linux，底层闭环在 MCU，这是常见架构）。

### Q34 FreeRTOS 的任务调度与关键机制？（FreeRTOS basics）
**优先级：★★★**

**答案要点**：固定优先级抢占 + 同优先级时间片轮转；Tick 中断（常见 1 kHz）触发调度；任务状态 Running/Ready/Blocked/Suspended；同步原语：队列、信号量、互斥量、事件组、任务通知；`vTaskDelayUntil` 保证固定周期（`vTaskDelay` 是相对延时，会累积漂移）；每个任务独立栈，栈溢出需开启检测。

```c
// 教学示例：固定周期控制任务
void ctrl_task(void *arg){
    TickType_t last = xTaskGetTickCount();
    for(;;){
        control_step();
        vTaskDelayUntil(&last, pdMS_TO_TICKS(2)); // 教学示例周期
    }
}
```

**English short answer**
FreeRTOS uses fixed-priority preemptive scheduling with round-robin among equal priorities, driven by a periodic tick interrupt. Tasks communicate through queues, semaphores, mutexes, event groups and task notifications. For a fixed-period control loop I use vTaskDelayUntil rather than vTaskDelay so the period does not drift.

**追问方向**：栈大小如何确定；configMAX_SYSCALL_INTERRUPT_PRIORITY 的意义。

### Q35 什么是抖动（jitter）与最坏执行时间（WCET）？（Jitter and WCET）
**优先级：★★**

**答案要点**：抖动：实际周期与理想周期的偏差，来源：中断抢占、调度延迟、缓存未命中、总线竞争、日志打印。WCET：任务最坏执行时间，是可调度性分析输入。降低抖动：提高控制任务优先级、禁止在控制环里 malloc/printf、使用硬件定时器触发、DMA、绑定核。**具体数值需实测，不可想当然。**

**English short answer**
Jitter is the variation of the actual period around the intended one, caused by interrupts, scheduling delay, cache misses or slow operations such as logging. WCET is the worst-case execution time of a task, used in schedulability analysis. To reduce jitter I keep the control task at high priority and avoid allocation and printing inside the loop.

**追问方向**：如何测量（GPIO 翻转 + 示波器、DWT 周期计数器）。

### Q36 看门狗（watchdog）是什么？（Watchdog）
**优先级：★★**

**答案要点**：独立计时器，需要软件周期性"喂狗"，超时则复位系统，防止程序跑飞/死锁。独立看门狗 IWDG 用内部低速时钟；窗口看门狗 WWDG 要求在窗口内喂狗。设计要点：不要在定时器中断里无条件喂狗（会掩盖主循环卡死），应由各任务汇报心跳后统一喂。属于机器人安全回路的一环。

**English short answer**
A watchdog is a hardware timer that resets the system if software does not refresh it in time, so it recovers from hangs. A good design feeds it only after all critical tasks have reported healthy, not from a timer interrupt that would hide a stuck main loop.

**追问方向**：故障安全状态；上电自检。

### Q37 栈溢出、堆溢出有什么区别？怎么发现？（Stack overflow vs heap overflow）
**优先级：★★**

**答案要点**：栈溢出：递归过深或大局部数组，覆盖相邻内存；RTOS 任务栈小，更易发生。堆溢出：越界写堆块覆盖元数据。检测：栈填充魔数（watermark）、`uxTaskGetStackHighWaterMark`、MPU 保护页、AddressSanitizer、Valgrind。避免：大数组用静态或堆、避免递归。

**English short answer**
A stack overflow comes from deep recursion or large local arrays and overwrites adjacent memory, which is a common failure in small RTOS task stacks. A heap overflow is writing past an allocated block. I detect them with stack watermarks, a memory protection unit and tools like AddressSanitizer on the PC.

**追问方向**：栈溢出攻击；金丝雀值。

### Q38 Linux 启动流程和嵌入式 Linux 的组成？（Boot process）
**优先级：★**

**答案要点**：上电 → BootROM → Bootloader（U-Boot）→ 加载内核与设备树 → 内核初始化驱动 → 挂载根文件系统 → init/systemd 启动服务。RK3588 这类 SoC 板子典型是 U-Boot + Linux 内核 + rootfs。设备树描述硬件资源。

**English short answer**
After power-on, the boot ROM loads a bootloader such as U-Boot, which loads the kernel and device tree. The kernel initializes drivers, mounts the root file system, and starts the init process, which launches services.

**追问方向**：设备树作用；驱动模型。

### Q39 内核态与用户态的权限，驱动程序在哪里？（Drivers and privilege levels）
**优先级：★**

**答案要点**：驱动运行在内核态（可作为模块 `.ko` 加载），通过字符设备/块设备接口暴露为 `/dev/*`，用户程序通过 `open/read/write/ioctl` 访问。SocketCAN 把 CAN 总线表现为网络接口，ROS 节点通过 socket 收发 CAN 帧（典型做法）。

**English short answer**
Drivers run in kernel mode and expose devices as files under /dev, which user programs access with open, read, write and ioctl. For example, Linux SocketCAN presents a CAN bus as a network interface that applications use through sockets.

**追问方向**：用户态驱动；ioctl 设计。

### Q40 进程调度中的 "Linux 实时优先级与 nice 值" 如何配置？（nice and real-time priorities）
**优先级：★**

**答案要点**：普通进程 `SCHED_OTHER`（CFS），nice -20..19 影响权重；实时策略 `SCHED_FIFO`/`SCHED_RR`，优先级 1..99，高于任何普通进程。`chrt -f 80 ./ctrl` 设置；需要权限，设置不当会饿死系统服务，应留出核心给内核线程。

**English short answer**
Normal Linux processes use the CFS scheduler with nice values to adjust weight. Real-time policies SCHED_FIFO and SCHED_RR have priorities from 1 to 99 and always preempt normal tasks. I would use them for a control loop but carefully, because a runaway real-time thread can starve the system.

**追问方向**：CPU 亲和性 `taskset`；cgroups。

## 本章要点速记
1. 进程是资源单位，线程是调度单位；线程共享地址空间、独立栈。
2. fork + COW：写时才复制页。
3. 虚拟内存 = 隔离 + 大地址空间 + 共享；TLB 缓存页表项；缺页异常分 minor / major。
4. 死锁四条件：互斥、占有等待、不可剥夺、循环等待；最实用的预防是统一加锁顺序。
5. mutex 睡眠、spinlock 忙等、信号量计数、条件变量配 while 谓词。
6. 优先级反转用优先级继承解决（Mars Pathfinder 案例）。
7. epoll 只返回就绪 fd，优于 select/poll。
8. ISR 要短、不阻塞；RTOS 中用 FromISR API。
9. RTOS 追求可预测性与低抖动，而非平均性能。
