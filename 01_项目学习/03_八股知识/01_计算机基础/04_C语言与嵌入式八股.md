## 一、指针与声明

### Q1 指针是什么？指针和数组的区别？（Pointer vs array）
**优先级：★★★**

**答案要点**
- 指针是存放地址的变量，大小取决于平台（32 位 MCU 为 4 字节）。数组名在大多数表达式中**退化**为首元素指针，但数组不是指针：`sizeof(arr)` 是整个数组大小，`sizeof(p)` 是指针大小；数组名不能被赋值；`&arr` 是指向整个数组的指针，类型不同。
- 函数参数 `void f(int a[10])` 实际是 `int *a`，`sizeof` 在函数内得不到长度，所以必须另传长度。
- 指针运算按所指类型大小缩放：`p+1` 前进 `sizeof(*p)` 字节。

```c
int a[5];
int *p = a;
printf("%zu %zu\n", sizeof(a), sizeof(p)); // 20 4/8 (典型)
```

**English short answer**
A pointer is a variable that holds an address. An array name usually decays to a pointer to its first element, but an array is not a pointer: sizeof gives the whole array size, and you cannot assign to an array name. When an array is passed to a function it decays, so the function needs a separate length parameter.

**追问方向**：`a[i]` 与 `*(a+i)` 等价性；`i[a]` 为什么合法；指向数组的指针。

### Q2 如何读懂复杂声明：`int *p[10]`、`int (*p)[10]`、`int (*f)(int)`？（Complex declarations）
**优先级：★★★**

**答案要点**：由内向外、右左法则。`int *p[10]`：p 是含 10 个元素的数组，元素是 `int*`。`int (*p)[10]`：p 是指针，指向含 10 个 int 的数组。`int (*f)(int)`：f 是指向"接受 int 返回 int 的函数"的指针。`int *f(int)`：f 是函数，返回 `int*`。读不清时用 `typedef` 拆解。

```c
typedef int (*op_fn)(int, int);   // 函数指针类型
op_fn table[2] = { add, sub };
```

**English short answer**
I read declarations inside-out using the right-left rule. For example int star p of ten is an array of ten pointers to int, while int open-paren star p close-paren of ten is a pointer to an array of ten ints. Typedef helps keep function pointer declarations readable.

**追问方向**：函数指针数组；`signal` 的声明。

### Q3 `const` 的各种位置分别是什么意思？（const placement）
**优先级：★★★**

**答案要点**
- `const int *p` / `int const *p`：指向常量的指针，不能通过 p 改值，但 p 可指向别处。
- `int *const p`：常量指针，p 本身不可改，但可改所指的值。
- `const int *const p`：都不能改。
- 口诀：看 `*` 的左右，`const` 修饰靠近它的那一部分。
- 嵌入式用途：`const` 全局变量可放入 Flash（.rodata）节省 RAM；函数参数 `const uint8_t *buf` 表示只读，让编译器检查；`volatile const` 用于只读硬件寄存器。

**English short answer**
If const is on the left of the star, the data is read-only; if it is on the right, the pointer itself is fixed. So const int star p is a pointer to constant data, and int star const p is a constant pointer. In embedded code, const globals can live in flash and save RAM, and const parameters document and enforce read-only access.

**追问方向**：`volatile const` 合法吗（合法，如状态寄存器）；C++ `constexpr`。

### Q4 野指针、空指针、悬垂指针、内存泄漏有什么区别？（Dangling, null, wild pointers）
**优先级：★★★**

**答案要点**：空指针：值为 NULL，解引用是未定义行为（UB）。野指针：未初始化，值随机。悬垂指针：所指对象已释放或超出作用域（返回局部变量地址是经典错误）。内存泄漏：分配后不再引用也不释放。防范：声明即初始化为 NULL；`free` 后置 NULL；不返回局部变量地址；嵌入式尽量静态分配；工具：Valgrind、AddressSanitizer。

**English short answer**
A null pointer holds zero, a wild pointer is uninitialized, and a dangling pointer refers to memory that was freed or went out of scope, such as the address of a local variable returned from a function. A leak is memory that is no longer reachable but never freed. I initialize pointers, set them to NULL after free, and run sanitizers on the PC build.

**追问方向**：double free；use-after-free。

### Q5 `malloc/free` 与 `new/delete` 区别？嵌入式为什么少用 malloc？（malloc vs new）
**优先级：★★**

**答案要点**：`malloc` 只分配字节，返回 `void*`，不调用构造；`new` 分配并构造，失败抛异常。`malloc(0)` 行为实现相关。嵌入式少用：①碎片导致长时间运行后分配失败；②耗时不确定，影响实时性；③线程安全需要锁；④失败处理麻烦。替代：静态数组、对象池、FreeRTOS `heap_4` 等有界分配器，以及 `pvPortMalloc`。

**English short answer**
malloc only allocates raw bytes, while new also runs the constructor. In embedded systems I avoid malloc at runtime because of fragmentation, unpredictable timing and thread-safety cost. I prefer static buffers and memory pools, and when I need dynamic allocation I allocate once at startup.

**追问方向**：内存池实现；FreeRTOS heap_1~5。

### Q6 `sizeof` 与 `strlen` 的区别？（sizeof vs strlen）
**优先级：★★**

**答案要点**：`sizeof` 是编译期运算符，返回类型/对象所占字节（含 `\0`）；`strlen` 是运行期函数，数到 `\0` 前的字符数。`char s[]="abc"`：`sizeof`=4，`strlen`=3。`sizeof` 一个指针得到指针宽度，不是所指数据长度。

**English short answer**
sizeof is evaluated at compile time and returns the object's size in bytes, including the terminating zero for a string literal array; strlen runs at run time and counts characters up to but not including the terminator.

**追问方向**：`strncpy` 为什么不安全；`snprintf`。

## 二、volatile、编译器与优化

### Q7 `volatile` 的作用是什么？什么时候必须用？（volatile）
**优先级：★★★**

**答案要点**
- 告诉编译器：该变量可能被程序之外的因素改变（硬件、ISR、其他线程），**每次访问都必须真正从内存读写，不得缓存到寄存器、不得优化掉、不得重排 volatile 访问之间的顺序**（只保证 volatile 访问彼此之间的顺序）。
- 三种典型用法：①内存映射的硬件寄存器；②在 ISR 和主循环间共享的标志；③多线程中被其他线程修改（注意：这不是正确的线程同步方式）。
- 反例（没有 volatile）：

```c
// 教学示例
int flag = 0;               // 在 ISR 中被置 1
void main_loop(void){
    while (!flag) { }       // -O2 下编译器可能把 flag 读到寄存器，变成死循环
}
// 正确：volatile int flag;
```

- **volatile 不等于原子**：`counter++` 是读-改-写，即使 volatile 也可能被中断打断。多字节变量在 8/16 位 MCU 上读到一半被中断改写（撕裂）。32 位 Cortex-M 对对齐的 32 位读写通常是原子的，但读-改-写不是。
- **volatile 也不提供内存屏障**：不保证多核之间/缓存的可见性与 CPU 重排顺序，需要 `atomic` 或屏障。

**English short answer**
volatile tells the compiler a variable may change outside the normal program flow, for example a hardware register or a flag set in an interrupt, so every access must really read or write memory and cannot be optimized away. It is not atomic, though: an increment on a volatile variable is still a read-modify-write that an interrupt can split, and it gives no ordering guarantee between cores. For shared counters I use atomics or disable interrupts briefly.

**追问方向**：volatile 与 C++ `std::atomic` 的区别；`volatile` 指针 `volatile uint32_t *reg`；编译器重排。

### Q8 一个参数可以既是 `const` 又是 `volatile` 吗？一个指针可以是 `volatile` 吗？（const volatile）
**优先级：★★**

**答案要点**：可以。`const volatile uint32_t *status` 表示程序不能写它，但硬件可能改变它（只读状态寄存器）。指针本身 `volatile`：`int *volatile p`，指针值可能被意外改变。最常见是 `volatile uint32_t *` 指向寄存器。

**English short answer**
Yes. A const volatile object cannot be modified by the program, but the hardware may change it, such as a read-only status register. A pointer can also be volatile, but the usual case is a pointer to volatile data.

**追问方向**：访问寄存器的宏写法 `#define REG (*(volatile uint32_t*)0x40021000)`。

### Q9 编译器优化会带来哪些嵌入式坑？（Optimization pitfalls）
**优先级：★★**

**答案要点**：优化可能：删除"无副作用"的空延时循环；缓存非 volatile 变量；重排读写；内联函数。表现为"-O0 正常，-O2 出错"。排查：先检查 volatile、未定义行为（有符号溢出、未初始化、越界）、对齐、时序依赖。延时不要靠空循环，使用硬件定时器或 DWT 计数器。

**English short answer**
Optimization can remove empty delay loops, cache non-volatile variables in registers and reorder operations, so a program that works at O0 may fail at O2. When that happens I first suspect missing volatile and undefined behaviour such as signed overflow or uninitialized data.

**追问方向**：未定义行为举例；`-fno-strict-aliasing`。

## 三、位操作与数据表示

### Q10 如何设置、清除、翻转、读取某一位？（Bit manipulation）
**优先级：★★★**

```c
#define SET_BIT(r, n)    ((r) |=  (1u << (n)))
#define CLR_BIT(r, n)    ((r) &= ~(1u << (n)))
#define TOGGLE_BIT(r, n) ((r) ^=  (1u << (n)))
#define READ_BIT(r, n)   (((r) >> (n)) & 1u)

// 修改多位字段：先清掩码再写值
reg = (reg & ~(0x7u << 4)) | ((val & 0x7u) << 4);
```

**答案要点**：用无符号字面量 `1u`，避免对有符号数移位的未定义行为；修改字段时先 `& ~mask` 再 `|` 新值；寄存器读-改-写注意可能被中断打断（用位带别名区或 BSRR 之类的原子置位寄存器）。

**English short answer**
To set a bit I OR with one shifted left by n, to clear I AND with the inverted mask, to toggle I XOR, and to read I shift and mask. I use unsigned constants to avoid undefined behaviour. For multi-bit fields I clear the mask first and then OR in the new value.

**追问方向**：位域（bit-field）为什么不可移植；统计 1 的个数。

### Q11 大端与小端？怎么判断？（Endianness）
**优先级：★★★**

**答案要点**：小端低字节在低地址（ARM Cortex-M、x86）。大端高字节在低地址（网络字节序、部分协议）。判断：

```c
uint16_t x = 0x0102;
uint8_t *p = (uint8_t*)&x;
int little = (p[0] == 0x02);
```

影响：跨平台二进制通信、解析传感器数据（如 IMU 输出的 16 位数据高低字节顺序）、直接 `memcpy` 结构体到总线。解决：按协议显式移位拼装 `(hi<<8)|lo`。见 [计算机网络](./03_计算机网络.md) 字节序。

**English short answer**
Little-endian stores the least significant byte at the lowest address; ARM Cortex-M and x86 are little-endian. I can detect it by casting the address of a 16-bit value to a byte pointer and checking the first byte. When parsing sensor or CAN data I assemble values explicitly with shifts, so the code does not depend on the platform.

**追问方向**：`htons`；联合体判断。

### Q12 结构体对齐与填充？（Struct alignment and padding）
**优先级：★★★**

**答案要点**：编译器让每个成员按其自身对齐要求（通常等于自身大小）放置，结构体总大小对齐到最大成员对齐的倍数。例（教学示例，32 位 ARM）：

```c
struct A { uint8_t a; uint32_t b; uint8_t c; };   // 偏移 0, 4, 8 ; sizeof = 12
struct B { uint32_t b; uint8_t a; uint8_t c; };   // 偏移 0, 4, 5 ; sizeof = 8
```

重排成员从大到小可省空间。`__attribute__((packed))` 取消填充，但访问未对齐成员在某些 Cortex-M（M0）上触发 HardFault，M3/M4 以上默认允许但变慢，且取成员地址传给函数有风险。通信结构体首选显式序列化。

**English short answer**
The compiler aligns each member to its natural boundary and pads the struct so its total size is a multiple of the largest alignment. Ordering members from large to small reduces padding. Packing removes padding but can cause slow or even faulting unaligned accesses, so for communication I serialize fields explicitly.

**追问方向**：`offsetof`；位域；`alignas`。

### Q13 整型提升与有符号/无符号混用的坑？（Integer promotion pitfalls）
**优先级：★★**

**答案要点**：小于 int 的类型运算前提升为 int；有符号与无符号比较时有符号被转为无符号。经典坑：`uint8_t a=200,b=100; if (a+b > 255)` 为真（提升为 int）；`int x=-1; unsigned y=1; x<y` 为假。`uint32_t` 减法：`a - b` 在 `a<b` 时回绕成巨大正数——用作定时器差值时反而正确（回绕安全），但用于比较大小时错误。浮点数与整数的比较、`float` 默认提升到 `double` 也注意（嵌入式无 FPU 双精度很慢；Cortex-M4F 只有单精度 FPU，字面量加 `f`）。

**English short answer**
Types smaller than int are promoted to int before arithmetic, and when signed and unsigned values are compared the signed value converts to unsigned, which can make minus one larger than one. Unsigned subtraction wraps around, which is actually convenient for tick counters but a bug when used for ordering. On Cortex-M4 with a single-precision FPU I write float literals with an f suffix to avoid slow double math.

**追问方向**：定时器溢出安全比较写法 `(int32_t)(now - deadline) >= 0`。

### Q14 浮点数的精度问题？为什么不能直接用 `==` 比较？（Floating point comparison）
**优先级：★★**

**答案要点**：IEEE 754：float 24 位尾数（约 7 位十进制有效数字），double 53 位。十进制 0.1 无法精确表示。比较用容差 `fabs(a-b) < eps`。累加大量小数会丢精度（大数吃小数），用 Kahan 求和或双精度。控制器中积分项长期累加、四元数归一化需要注意。定点数在无 FPU 的 MCU 上常用。

**English short answer**
Floating point numbers cannot represent most decimals exactly, so I never compare them with equality but check whether the difference is below a tolerance. Adding a small number to a large one loses precision, which matters for long-running integrators and sums.

**追问方向**：NaN 比较；定点数 Q 格式。

## 四、内存布局与栈

### Q15 嵌入式程序的内存布局与启动过程？（Memory layout and startup）
**优先级：★★★**

```text
Flash:  .isr_vector | .text | .rodata | .data 的初值(LMA)
RAM  :  .data(VMA)  | .bss  | heap ->        <- stack
```

**答案要点**：复位后 CPU 从向量表取初始 SP 和复位向量；启动代码 `Reset_Handler`：①把 `.data` 初值从 Flash 拷到 RAM；②把 `.bss` 清零；③初始化时钟/库（`SystemInit`）；④调用 `main`。所以"未初始化的全局变量为 0"、"局部变量不会自动清零"。链接脚本（.ld）决定各段位置，Flash/RAM 大小在其中声明。栈向下增长，堆向上，二者在 RAM 中相向，溢出会相撞。

**English short answer**
After reset the CPU loads the initial stack pointer and jumps to the reset handler. The startup code copies initialized data from flash to RAM, zeroes the bss section, sets up the clock and then calls main. That is why uninitialized globals are zero but local variables are not. The linker script decides where each section is placed.

**追问方向**：把函数放到 RAM/CCM（加速）；`.noinit` 段。

### Q16 栈和堆的区别？局部变量放在哪？（Stack vs heap）
**优先级：★★★**

**答案要点**：栈由编译器自动管理，LIFO，速度快，大小固定且小，存局部变量、参数、返回地址；堆由程序员管理，大小灵活，慢，有碎片。栈上返回地址被覆盖是经典漏洞。RTOS 每个任务有独立栈，主栈（MSP）用于中断，任务栈（PSP）用于任务，Cortex-M 有双栈指针。

**English short answer**
The stack is managed automatically in last-in first-out order, is fast, and holds locals and return addresses, but it is small. The heap is managed manually, is flexible but slower and can fragment. In an RTOS every task has its own stack, so I size each one carefully.

**追问方向**：Cortex-M MSP/PSP；栈帧布局。

### Q17 栈溢出怎么发生？怎么检测、估算栈大小？（Stack overflow）
**优先级：★★★**

**答案要点**
- 原因：大局部数组（如 `char buf[1024]` 放在小栈任务）、深递归、`printf` 浮点格式化占栈大、中断嵌套。
- 后果：覆盖相邻任务栈或全局变量，现象怪异（偶发 HardFault、变量被改写）。
- 检测：FreeRTOS `configCHECK_FOR_STACK_OVERFLOW` 1/2（栈尾魔数填充 0xA5）与钩子 `vApplicationStackOverflowHook`；`uxTaskGetStackHighWaterMark` 查看历史最小剩余；编译器 `-fstack-usage`；MPU 设置栈保护区。
- 估算：静态分析最深调用链 + 中断压栈（Cortex-M 异常入栈 8 个字，共 32 字节，带 FPU 上下文更多）+ 余量；运行期压测后根据 high-water mark 留余量。

**English short answer**
Stack overflow comes from large local arrays, deep recursion or heavy library calls such as printf with floats in a small task stack. It overwrites neighbouring memory and shows up as random faults. I detect it with FreeRTOS stack checking, the high water mark API and sometimes an MPU guard region, and I size stacks from the deepest call path plus interrupt frames and some margin.

**追问方向**：HardFault 如何定位（读栈里的 PC、LR）；递归改迭代。

### Q18 `static` 关键字的作用？（static）
**优先级：★★★**

**答案要点**：①函数内局部 `static`：生命周期为整个程序，只初始化一次，存放在 `.data/.bss`，不在栈上（注意：多线程调用该函数有数据竞争，函数不可重入）。②文件作用域 `static`：限制符号在本文件可见（内部链接），避免命名冲突。③C++ 类中的 static 成员。可重入性：使用 static/全局状态的函数不是可重入的，在 ISR 和任务同时调用时有风险。

**English short answer**
A static local variable lives for the whole program and is initialized once, but it makes the function non-reentrant. A static global or function has internal linkage, so it is visible only inside its file. This is useful for encapsulation and avoiding name clashes.

**追问方向**：可重入 vs 线程安全；`printf` 能否在 ISR 中调用。

### Q19 `extern`、头文件保护、`#include` 的原理？（extern, include guards）
**优先级：★★**

**答案要点**：`extern` 声明变量在别处定义；头文件只放声明，不放定义（否则多重定义链接错误）。`#ifndef X_H / #define X_H / #endif` 或 `#pragma once` 防止重复包含。C++ 调用 C 函数需 `extern "C"` 避免名字改编（mangling）。

**English short answer**
extern declares a variable or function defined in another translation unit. Headers should contain declarations only, protected by include guards to avoid duplicate inclusion. When C++ code calls C functions, I wrap the declarations in extern "C" to prevent name mangling.

**追问方向**：编译与链接过程；见 [Linux_Git_编译构建八股](./08_Linux_Git_编译构建八股.md)。

## 五、函数指针、宏与代码风格

### Q20 函数指针的用法和嵌入式场景？（Function pointers）
**优先级：★★★**

**答案要点**：函数指针存放函数入口，用于回调、状态机表、驱动抽象（类似 C 版"虚函数"）。典型：中断回调注册、命令解析表、策略切换。

```c
// 教学示例：用函数指针表实现简单状态机
typedef enum { ST_IDLE, ST_RUN, ST_ERR, ST_NUM } state_t;
typedef state_t (*state_fn)(void);
static state_t do_idle(void){ return ST_RUN; }
static state_t do_run(void){  return ST_RUN; }
static state_t do_err(void){  return ST_ERR; }
static const state_fn table[ST_NUM] = { do_idle, do_run, do_err };
void step(state_t *s){ *s = table[*s](); }
```

用函数指针前先检查是否为 NULL，调用空指针会 HardFault。

**English short answer**
A function pointer holds the address of a function, which lets me implement callbacks, driver interfaces and table-driven state machines in C. For example I can keep an array of state handler functions and call the one indexed by the current state. I always check for NULL before calling, since a null function pointer causes a hard fault.

**追问方向**：回调中的 `void *ctx` 参数；C++ `std::function`。

### Q21 宏的陷阱？宏和内联函数怎么选？（Macro pitfalls）
**优先级：★★★**

**答案要点**
- 参数求值多次：`#define MAX(a,b) ((a)>(b)?(a):(b))`，`MAX(i++, j)` 会让 `i` 自增两次。
- 运算符优先级：宏参数和整体都要加括号：`#define SQ(x) ((x)*(x))`。
- 多语句宏要用 `do { ... } while(0)` 以便后接分号、在 if/else 中不出错。
- 没有类型检查，调试困难。
- 优先用 `static inline` 函数、`enum`、`const`、`constexpr`。宏仍适用于条件编译、字符串化 `#`、拼接 `##`、日志文件行号。

```c
#define SAFE_FREE(p) do { free(p); (p) = NULL; } while (0)
```

**English short answer**
Macro arguments are textually substituted, so they can be evaluated multiple times, for example MAX of i plus plus. I parenthesize every parameter, wrap multi-statement macros in do-while-zero, and prefer static inline functions or constants because they are type-checked. Macros remain useful for conditional compilation and logging with file and line.

**追问方向**：`#` 与 `##`；可变参数宏；`typeof` 实现安全 MAX。

### Q22 `#define` 与 `typedef` 的区别？（define vs typedef）
**优先级：★★**

**答案要点**：`#define` 是预处理文本替换：`#define PINT int*` 后 `PINT a,b;` 得到 `int *a, b;`（b 不是指针）。`typedef int* pint; pint a,b;` 两个都是指针。`typedef` 是类型别名，有作用域，编译器处理。

**English short answer**
define is textual replacement by the preprocessor, so a pointer type macro can silently apply only to the first variable in a declaration. typedef creates a real type alias handled by the compiler, so both variables get the same type.

**追问方向**：`using`（C++）。

### Q23 `inline` 在 C 里怎么用？`static inline` 为何常见？（inline）
**优先级：★**

**答案要点**：`inline` 是对编译器的建议。C99 中非 static 的 inline 需要在某个 .c 文件提供外部定义，容易出链接问题，所以头文件里习惯写 `static inline`。内联消除调用开销，但增大代码体积；中断中的小函数适合。

**English short answer**
inline suggests the compiler expand a function in place to avoid call overhead. In C headers I use static inline so each file gets its own copy and there are no linker problems. It trades code size for speed.

**追问方向**：`__attribute__((always_inline))`。

## 六、中断与 DMA

### Q24 中断服务函数（ISR）的编写规则？（ISR rules）
**优先级：★★★**

**答案要点**
1. **短**：只做必要的事（读状态、清中断标志、置标志/发信号），长任务交给主循环/任务。
2. **不阻塞**：不能调用会睡眠/等待的函数（互斥量、`vTaskDelay`、长时间 `HAL_Delay`）。
3. **不用不可重入函数**：`printf`、`malloc`、浮点格式化（有静态缓冲、锁、占栈大）。
4. **清中断标志**：否则退出后立即再次进入。
5. **共享变量用 `volatile`**，多字节数据使用原子或临界区保护。
6. **RTOS**：只调用 `...FromISR` API，并处理 `xHigherPriorityTaskWoken`，退出时 `portYIELD_FROM_ISR`；中断优先级不能高于 `configMAX_SYSCALL_INTERRUPT_PRIORITY`，否则调用内核 API 会出错。
7. **执行时间有界**，评估对其他中断的延迟。
8. ISR 无参数无返回值。

```c
// 教学示例：FreeRTOS 中 UART 接收中断通知任务
void USART1_IRQHandler(void){
    BaseType_t woken = pdFALSE;
    if (uart_rx_flag()) {
        uint8_t b = uart_read_byte();           // 读数据会清标志
        xQueueSendFromISR(rx_q, &b, &woken);
    }
    portYIELD_FROM_ISR(woken);
}
```

**English short answer**
An ISR should be short and non-blocking. It reads the status, clears the interrupt flag, passes data or a signal to a task, and returns. I do not call printf, malloc or any blocking function inside it. Variables shared with the main code are volatile and protected against tearing, and with FreeRTOS I only use the FromISR API functions and yield at the end if a higher priority task was woken.

**追问方向**：为什么不能在 ISR 里 printf；中断优先级与 NVIC 分组；中断延迟。

### Q25 如何在 ISR 与主循环之间安全地共享数据？（Sharing data with ISR）
**优先级：★★★**

**答案要点**：①单字节/对齐的 32 位标志：`volatile` 足够；②多字节结构体：短暂关中断或使用临界区，或使用"双缓冲 + 序号/版本检查"（seqlock 思路）；③流数据：环形缓冲（单生产者单消费者，只有 head 或 tail 被一方修改，可无锁，但需保证写内容先于写指针的顺序，必要时加内存屏障）；④RTOS：队列、任务通知。避免在临界区中做耗时操作。

**English short answer**
For a simple aligned flag, a volatile variable is enough. For multi-word data I either briefly disable interrupts, or use double buffering with a sequence check. For streams I use a single-producer single-consumer ring buffer, where the ISR only moves the head and the main code only moves the tail. In an RTOS I would use queues or task notifications.

**追问方向**：临界区实现；ABA；内存序。

### Q26 中断延迟由哪些因素决定？NVIC 优先级怎么理解？（Interrupt latency and NVIC）
**优先级：★★**

**答案要点**：延迟 = 硬件响应（Cortex-M 约十几个周期压栈）+ 当前被更高/同级中断或关中断临界区占用的时间 + 向量跳转。NVIC 优先级数值**越小越高**；分组决定抢占优先级与子优先级位数；高抢占优先级可打断低的（嵌套）。FreeRTOS 要求把使用内核 API 的中断设为不高于阈值的优先级，且使用 NVIC 优先级分组为"全抢占位"（`NVIC_PriorityGroup_4`）。

**English short answer**
Interrupt latency is the hardware response time plus any delay caused by higher priority interrupts or code with interrupts disabled. On Cortex-M a lower number means higher priority. With FreeRTOS, any interrupt that calls kernel APIs must have a priority at or below the configured maximum syscall priority.

**追问方向**：Tail-chaining；关键临界区缩短。

### Q27 DMA 的原理、使用场景与注意点？（DMA）
**优先级：★★★**

**答案要点**：DMA 控制器在外设与内存之间搬运数据，CPU 只配置源/目的/长度并响应完成/半完成中断。场景：ADC 连续采样、UART/SPI 收发、定时器触发的数据。模式：单次、循环（circular）。常见组合：UART 接收 DMA + 空闲中断（IDLE）处理不定长帧。注意：①缓冲区生命周期和对齐；②完成前不要修改缓冲；③多个主设备争抢总线；④**cache 一致性**（见下题）。

**English short answer**
DMA lets a controller move data between a peripheral and memory without CPU involvement; the CPU only configures it and handles completion interrupts. It is used for ADC sampling and UART or SPI streams, often in circular mode. UART reception with DMA and an idle-line interrupt is a common way to receive variable-length frames. On cores with a data cache I must handle cache coherency.

**追问方向**：半传输中断；DMA 与 CPU 争总线；双缓冲。

### Q28 DMA 与 cache 一致性问题是什么？（DMA and cache coherency）
**优先级：★★★**

**答案要点**
- 有 D-Cache 的内核（如 Cortex-M7，STM32H7）：CPU 通过 cache 读写，DMA 直接读写 SRAM。出现两类错误：
  1. **DMA 写、CPU 读**（接收）：cache 里可能有旧数据，CPU 读到过期值。→ 读之前对该缓冲区做 **invalidate**（`SCB_InvalidateDCache_by_Addr`）。
  2. **CPU 写、DMA 读**（发送）：新数据还在 cache（write-back）里，没写回 SRAM，DMA 读到旧值。→ 启动 DMA 前做 **clean**（`SCB_CleanDCache_by_Addr`）。
- 解决方案：①缓冲区放入配置为 non-cacheable 的 MPU 区域；②使用不带 cache 的 RAM（如 TCM、部分 SRAM）；③手动 clean/invalidate，缓冲区按 cache 行（32 字节）对齐和取整大小，否则 invalidate 会误伤相邻变量。
- Cortex-M4（P3 使用的 STM32F407）没有 D-Cache，所以不存在此问题；Cortex-M7（STM32H7，P7 使用）有，是 H7 上"DMA 数据偶发错误"的常见原因。我们在 P7 的 FDCAN/DMA 链路上的做法是：本项目通常取"DMA 缓冲区放在不可缓存区域（MPU 配置为 non-cacheable）或在使用前后做 cache clean/invalidate"二选一，并让缓冲区按 32 字节对齐；CAN 收发数据量小，更常见的是用 FDCAN 自带的 Rx FIFO 与中断读取，规避 cache 问题。English: "On the H7 I keep DMA buffers in a non-cacheable region or clean and invalidate the cache around transfers, and align buffers to the cache line."（在 H7 上，DMA 缓冲区放不可缓存区，或在传输前后清理/失效 cache，并按缓存行对齐。）

**English short answer**
On a core with a data cache, such as a Cortex-M7, the CPU reads through the cache but DMA accesses RAM directly. For a receive buffer written by DMA I must invalidate the cache lines before the CPU reads, and for a transmit buffer written by the CPU I must clean the cache before starting DMA. Alternatively I put DMA buffers in a non-cacheable memory region. Buffers should be cache-line aligned so the maintenance does not affect neighbouring data. Cortex-M4 has no data cache, so this issue does not arise there.

**追问方向**：write-through 与 write-back；MPU 配置；为什么对齐 32 字节。

### Q29 轮询、中断、DMA 三种 IO 方式的取舍？（Polling vs interrupt vs DMA）
**优先级：★★**

**答案要点**：轮询：简单、延迟可预测但占 CPU；中断：事件驱动，高效，但有上下文开销，高频中断会拖垮 CPU；DMA：大批量/高速数据，CPU 开销最小，需处理一致性和完成通知。选择：低速偶发用中断；高速连续用 DMA；极低延迟小数据可轮询。

**English short answer**
Polling is simple and predictable but wastes CPU time, interrupts are event driven but have per-event overhead, and DMA is best for large or continuous transfers because the CPU is almost uninvolved. I pick based on data rate and latency needs.

**追问方向**：中断风暴；UART 高波特率的做法。

## 七、嵌入式常见问题

### Q30 什么是可重入函数？线程安全？（Reentrancy）
**优先级：★★★**

**答案要点**：可重入：函数可被中断后再次调用而不出错——不使用静态/全局可变状态，不调用不可重入函数，只用参数和局部变量。线程安全：多线程同时调用结果正确（可通过加锁实现，但加锁的函数在被中断打断的同一线程里重入会死锁，所以不等于可重入）。标准库的 `strtok`、`rand`、`printf`（取决于实现）、`malloc` 通常不可在 ISR 中使用；`strtok_r`、`rand_r` 是可重入版本。

**English short answer**
A reentrant function can be interrupted and called again safely, which means it uses only its arguments and local variables and no shared mutable state. Thread safe means concurrent calls from several threads are correct, often through locking, but a lock-based function is not necessarily reentrant from an interrupt. That is why library functions like strtok are not allowed in ISRs.

**追问方向**：`errno` 的线程局部化；`_r` 后缀函数。

### Q31 `strcpy/memcpy/memmove` 的区别和安全问题？（String and memory functions）
**优先级：★★**

**答案要点**：`strcpy` 到 `\0` 为止，目标不够大会缓冲区溢出，应用 `strncpy`（注意可能不加 `\0`）或 `snprintf`/`strlcpy`。`memcpy` 按字节数拷贝，源目标重叠是未定义行为；`memmove` 处理重叠。`memset` 对整型数组只适合置 0/-1（按字节填充）。`memcmp` 不能直接比较含填充字节的结构体。

**English short answer**
strcpy copies until the terminator and can overflow the destination, so I use bounded functions. memcpy has undefined behaviour if the regions overlap, while memmove handles overlap. memset fills bytes, so it is only reliable for zero or minus one on integer arrays.

**追问方向**：自己实现 `memcpy`；对齐优化。

### Q32 `printf` 在嵌入式中有哪些坑？（printf in embedded）
**优先级：★★**

**答案要点**：占用大量 Flash 与栈（尤其 `%f`）；阻塞（串口慢速发送）会破坏实时性；ISR 里不可用；需重定向 `_write` 到串口；newlib-nano 默认不支持浮点格式，需链接选项。调试替代：环形日志缓冲 + 低优先级任务异步输出、SWO/RTT、DMA 发送。

**English short answer**
printf uses a lot of flash and stack, especially with float formatting, and blocking on a slow UART can destroy timing in a control loop. I never call it from an ISR. Better is to write into a ring buffer and let a low priority task or DMA send the log.

**追问方向**：如何测量控制环耗时而不影响时序（GPIO + 示波器）。

### Q33 Flash 与 RAM 的区别？程序存储在哪里？（Flash vs RAM）
**优先级：★★**

**答案要点**：Flash 非易失，读快写慢且需擦除（按扇区），寿命有限（约 $10^4$–$10^5$ 次擦写量级，具体看手册）；RAM 易失，读写快。代码、`.rodata`、`.data` 初值在 Flash；变量、栈、堆在 RAM。参数存储：片上 Flash 扇区或 EEPROM 仿真，写入时要考虑掉电保护与磨损均衡。

**English short answer**
Flash is non-volatile but slow to write and must be erased in sectors with limited endurance; RAM is volatile and fast. Code and constants live in flash, and variables, stack and heap live in RAM. For storing parameters I write rarely and protect against power loss.

**追问方向**：Bootloader 与 OTA 升级；双备份。

### Q34 CAN 通信的基本特点？（CAN basics）
**优先级：★★★**

**答案要点**：差分总线，多主，基于标识符（ID）的**非破坏性仲裁**（ID 小优先级高）；经典 CAN 一帧最多 8 字节数据，CAN FD 最多 64 字节且数据段可更高速率（FDCAN 为 STM32 上的 CAN FD 控制器）；有 CRC、ACK、位填充、错误帧、错误计数与总线关闭（bus-off）；终端电阻 120Ω 两端。机器人电机驱动常用 CAN。详见 [CAN_FDCAN与电机通信](../../02_基础知识/11_嵌入式与通信/03_CAN_FDCAN与电机通信.md)。

**English short answer**
CAN is a differential multi-master bus where messages carry an identifier and bus access is decided by non-destructive arbitration: the lower ID wins. Classic CAN carries up to eight data bytes per frame, and CAN FD up to 64 with a faster data phase. It has built-in CRC, acknowledgement and error handling, and is widely used for motor drivers in robots.

**追问方向**：为什么要 120 欧终端电阻；bus-off 恢复。

### Q35 UART、SPI、I2C 的区别？（UART vs SPI vs I2C）
**优先级：★★★**

| 项 | UART | SPI | I2C |
|---|---|---|---|
| 线数 | 2（TX/RX） | 4（SCK/MOSI/MISO/CS） | 2（SDA/SCL） |
| 同步 | 异步，需约定波特率 | 同步，主机出时钟 | 同步 |
| 拓扑 | 点对点 | 一主多从，片选 | 多主多从，地址 |
| 速度 | 中 | 高（几十 MHz） | 较低（100k/400k/1M） |
| 场景 | 调试口、GPS、遥控接收 | IMU、Flash、显示 | 温湿度、EEPROM |

**English short answer**
UART is asynchronous point-to-point with two wires and an agreed baud rate. SPI is synchronous and fast with a clock, data lines and a chip select per slave. I2C needs only two wires and addresses devices on a shared bus, but it is slower. IMUs are commonly connected over SPI for speed.

**追问方向**：I2C 上拉电阻；总线挂死恢复。

### Q36 嵌入式代码如何做防御性设计？（Defensive design）
**优先级：★★**

**答案要点**：输入校验与限幅（输出饱和限制）；超时机制而不是无限等待；看门狗；断言（调试版）；错误码一层层返回；状态机明确的初始化/运行/故障/恢复状态；上电自检；失联保护。与 P1 的"状态初始化、输出限幅、倒地恢复保护"、P6 的"安全执行链"思想一致（CV 描述）。

**English short answer**
I validate inputs, clamp outputs, use timeouts instead of waiting forever, add a watchdog and structure the program as an explicit state machine with fault and recovery states. In my robot work this appears as output limiting and safeguards around the control loop.

**追问方向**：fail-safe；断言策略。

### Q37 大端、对齐、volatile 都考虑过后，如何设计跨平台的通信结构体？（Portable message structs）
**优先级：★★**

**答案要点**：不要直接传结构体内存。①规定字节序（常用小端，因 MCU 与 PC 多为小端）；②使用固定宽度类型 `uint16_t`；③手工序列化/反序列化函数或 Protobuf/nanopb；④加版本号与 CRC；⑤`static_assert(sizeof(x)==N)` 检查布局。

```c
static inline void put_u16_le(uint8_t *p, uint16_t v){ p[0]=v&0xFF; p[1]=v>>8; }
static inline uint16_t get_u16_le(const uint8_t *p){ return (uint16_t)(p[0] | (p[1]<<8)); }
```

**English short answer**
I avoid sending raw structs. I fix the byte order, use fixed-width types, write explicit serialization functions and add a version and a CRC. That way the format does not depend on compiler padding or the CPU architecture.

**追问方向**：Protobuf/nanopb；浮点数传输（IEEE 754 的 4 字节）。

### Q38 `restrict`、`__attribute__`、内联汇编等进阶关键字会问吗？（Advanced keywords）
**优先级：★**

**答案要点**：`restrict` 承诺指针不别名，利于优化；`__attribute__((section(".ccmram")))` 放特定段；`weak` 弱符号允许用户覆盖（HAL 回调就是弱函数）；`naked`/内联汇编用于上下文切换、读 PC/LR。

**English short answer**
restrict promises that pointers do not alias, enabling better optimization. Weak symbols let the user override default handlers, which is how HAL callbacks work. Section attributes place variables in specific memory such as fast RAM.

**追问方向**：HAL 回调覆盖机制。

## 本章要点速记
1. 数组名退化为指针，但数组不是指针；`const` 看 `*` 的位置。
2. `volatile` 防优化、用于寄存器/ISR 共享；不等于原子，不是内存屏障。
3. 位操作：`|= 1u<<n`、`&= ~`、`^=`；改字段先清掩码。
4. 启动过程：拷贝 `.data`、清零 `.bss`、跳 `main`。
5. 栈溢出看 high-water mark，并留余量；避免大局部数组。
6. 结构体对齐按成员大小，总大小对齐到最大成员；通信用显式序列化。
7. ISR 短、不阻塞、清标志、RTOS 用 FromISR。
8. DMA + cache：接收前 invalidate，发送前 clean（M7）；M4 无 D-Cache。
9. 宏要加括号，多语句用 do-while(0)；优先 `static inline`。
