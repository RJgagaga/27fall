## 一、RAII 与资源管理

### Q1 什么是 RAII？为什么重要？（RAII）
**优先级：★★★**

**答案要点**
- Resource Acquisition Is Initialization：在构造函数中获取资源，在析构函数中释放；对象生命周期结束（含异常导致的栈展开）时，析构自动被调用，资源一定释放。
- 解决的问题：手动 `new/delete`、`lock/unlock`、`open/close` 在提前返回、异常路径中容易遗漏。
- 典型例子：`std::unique_ptr`、`std::lock_guard`、`std::fstream`、`std::vector`。
- 自己写：

```cpp
class FileGuard {
    FILE* f_;
public:
    explicit FileGuard(const char* p) : f_(std::fopen(p, "r")) {
        if (!f_) throw std::runtime_error("open failed");
    }
    ~FileGuard() { if (f_) std::fclose(f_); }
    FileGuard(const FileGuard&) = delete;            // 资源独占，禁止拷贝
    FileGuard& operator=(const FileGuard&) = delete;
    FILE* get() const { return f_; }
};
```
- 机器人场景：电机使能/失能、串口句柄、互斥锁都用 RAII 包装，保证异常时电机能被安全失能（典型做法）。

**English short answer**
RAII means a resource is acquired in a constructor and released in the destructor, so its lifetime is tied to an object's scope. Because destructors run on every exit path, including exceptions, resources are never leaked. Smart pointers, lock guards and standard containers are all RAII types. I like it for hardware handles as well, so that a device is always released safely.

**追问方向**：构造函数里抛异常会怎样（析构不会被调用，已构造成员会被析构）；三/五/零法则。

### Q2 三法则 / 五法则 / 零法则？（Rule of three/five/zero）
**优先级：★★★**

**答案要点**：若类需要自定义析构、拷贝构造、拷贝赋值之一（通常因为管理资源），往往三个都需要（三法则）。C++11 加入移动构造与移动赋值，成为五法则。零法则：尽量让成员都是 RAII 类型（`vector`、`unique_ptr`），不写任何特殊成员函数，由编译器生成正确版本。`= default`/`= delete` 显式声明意图。

**English short answer**
If a class needs a custom destructor, copy constructor or copy assignment, it usually needs all three; with move semantics it becomes the rule of five. The rule of zero is the best advice: build your class from members that already manage themselves, like vector and unique_ptr, so you write none of them.

**追问方向**：为什么拷贝赋值要处理自赋值；copy-and-swap。

### Q3 深拷贝与浅拷贝？（Deep vs shallow copy）
**优先级：★★★**

**答案要点**：默认拷贝构造逐成员拷贝，对裸指针成员只拷贝地址（浅拷贝），两个对象指向同一块内存，析构时 double free。深拷贝为新对象分配独立资源并复制内容。使用 `vector` 或智能指针可避免手写。

**English short answer**
The default copy copies pointer members by address, so two objects share the same memory and both free it, causing a double free. A deep copy allocates new memory and copies the contents. With a vector or smart pointer member this problem disappears.

**追问方向**：copy-on-write；shared_ptr 的拷贝是浅还是深。

## 二、智能指针

### Q4 `unique_ptr`、`shared_ptr`、`weak_ptr` 的区别与使用场景？（Smart pointers）
**优先级：★★★**

**答案要点**
- `unique_ptr`：独占所有权，不可拷贝，可移动；零额外开销（默认删除器时与裸指针同大小）。**默认首选**。
- `shared_ptr`：共享所有权，引用计数，计数变化是原子操作；对象与控制块；拷贝复制计数，最后一个销毁时释放对象。
- `weak_ptr`：不增加强引用计数，用于打破循环引用、观察者；`lock()` 获取临时的 `shared_ptr`。
- 创建：优先 `make_unique`、`make_shared`（`make_shared` 一次分配对象和控制块，更快更异常安全）。
- 机器人里：节点/传感器对象的所有权用 `unique_ptr`；回调需要延长对象生命周期或在多线程间共享时用 `shared_ptr`；订阅者持有 `weak_ptr` 防止回调访问已销毁对象。

```cpp
auto a = std::make_unique<Sensor>();
auto b = std::make_shared<Map>();
std::weak_ptr<Map> w = b;
if (auto s = w.lock()) s->query();
```

**English short answer**
unique_ptr is exclusive ownership with no overhead and is my default. shared_ptr uses reference counting for shared ownership, and weak_ptr observes an object without keeping it alive, which breaks reference cycles. I create them with make_unique and make_shared. In callbacks I often capture a weak_ptr to avoid using an object that has been destroyed.

**追问方向**：shared_ptr 线程安全性（控制块线程安全，指向对象的访问不是）；`enable_shared_from_this`。

### Q5 shared_ptr 的循环引用怎么发生，怎么解决？（Cyclic reference）
**优先级：★★★**

**答案要点**：A 持有 `shared_ptr<B>`，B 持有 `shared_ptr<A>`，引用计数永远不为 0，析构不会被调用，内存泄漏。解决：其中一方改用 `weak_ptr`（通常是"子指向父"、"观察者"这类非拥有关系）。

```cpp
struct B;
struct A { std::shared_ptr<B> b; };
struct B { std::weak_ptr<A> a; };  // 打破环
```

**English short answer**
If two objects hold shared_ptrs to each other, their reference counts never drop to zero and neither is destroyed. The fix is to make one direction a weak_ptr, usually the back-reference from child to parent.

**追问方向**：如何检测泄漏（ASan LeakSanitizer）。

### Q6 `shared_ptr` 的内部结构与大小？（shared_ptr internals）
**优先级：★★**

**答案要点**：`shared_ptr` 持有两个指针：指向对象与指向控制块（强计数、弱计数、删除器、分配器）。大小为 2 个指针。引用计数用原子增减（有开销）。`make_shared` 将对象与控制块放在同一次分配里；缺点是对象内存要等弱引用都消失才能释放。用裸指针构造多个 `shared_ptr` 会产生多个控制块导致 double free。

**English short answer**
A shared_ptr holds a pointer to the object and a pointer to a control block with the strong and weak reference counts and the deleter. The counts are atomic, which has a small cost. You must never create two shared_ptrs from the same raw pointer, since they would have separate control blocks and double free.

**追问方向**：自定义删除器；`shared_ptr<void>`。

### Q7 什么时候用裸指针/引用？（Raw pointers and references）
**优先级：★★**

**答案要点**：不拥有对象的观察/参数传递用引用或裸指针（可空）；拥有用智能指针。函数参数：只读小对象传值，只读大对象 `const T&`，要修改用 `T&`，转移所有权用 `unique_ptr<T>` 传值，共享所有权才传 `shared_ptr`。

**English short answer**
A raw pointer or reference is fine when it only observes an object and does not own it. For ownership I use smart pointers. In function parameters I pass small types by value, large read-only types by const reference, and transfer ownership with a unique_ptr by value.

**追问方向**：`std::span`；`string_view` 的悬垂问题。

## 三、多态与虚函数

### Q8 虚函数是怎么实现的？vtable 和 vptr？（Virtual function mechanism）
**优先级：★★★**

**答案要点**
- 每个含虚函数的类有一张**虚函数表 vtable**（类级别，存放虚函数地址，通常在只读数据区），每个对象有一个隐藏指针 **vptr** 指向其类的 vtable（通常位于对象起始处，构造时设置）。
- 调用 `p->f()`：通过 `p->vptr` 找到 vtable，取第 i 项函数地址，间接调用——**动态绑定**。代价：一次间接寻址、难以内联、对象多一个指针。
- 多重继承有多个 vptr；虚继承有 vbptr。

```text
 Derived 对象              Derived 的 vtable
 +--------+               +---------------------+
 | vptr  -+-------------> | &Derived::f         |
 | 成员... |              | &Derived::~Derived  |
 +--------+               +---------------------+
```

**English short answer**
Each class with virtual functions has a vtable, which is a table of function pointers, and each object holds a hidden vptr pointing to its class's vtable. A virtual call loads the vptr, indexes the table and calls the function through that pointer. This enables runtime polymorphism at the cost of an extra indirection and an extra pointer per object.

**追问方向**：构造函数里调用虚函数会怎样；纯虚函数；虚函数表何时建立。

### Q9 为什么基类析构函数应该是虚函数？（Virtual destructor）
**优先级：★★★**

**答案要点**：通过基类指针 `delete` 派生类对象时，如果析构非虚，只调用基类析构，派生类部分的资源泄漏（未定义行为）。基类是多态用途就声明 `virtual ~Base() = default;`。纯虚析构必须提供定义。非多态基类不必付虚表代价。

```cpp
struct Base { virtual ~Base() = default; virtual void run() = 0; };
struct Motor : Base { ~Motor() override { /* disable output */ } void run() override {} };
std::unique_ptr<Base> m = std::make_unique<Motor>(); // 析构正确调用 Motor 的
```

**English short answer**
If you delete a derived object through a base pointer and the base destructor is not virtual, only the base destructor runs, so the derived part leaks and the behaviour is undefined. Any class meant for polymorphic use should have a virtual destructor.

**追问方向**：`final`/`override` 的作用；纯虚函数可以有实现吗（可以）。

### Q10 重载、重写（覆盖）、隐藏的区别？（Overload, override, hide）
**优先级：★★★**

**答案要点**：重载：同一作用域内函数名相同，参数不同，编译期选择。重写（override）：派生类提供与基类虚函数同签名的实现，运行期选择；用 `override` 关键字让编译器检查。隐藏：派生类同名函数（参数不同也算）隐藏基类同名函数；`using Base::f;` 引入。返回类型协变（covariant）允许返回派生类指针/引用。

**English short answer**
Overloading is choosing among functions with the same name but different parameters at compile time. Overriding is a derived class replacing a virtual function, resolved at run time, and I always mark it with override so the compiler catches signature mistakes. A same-named function in a derived class hides base versions unless I bring them in with a using declaration.

**追问方向**：默认参数与虚函数（默认参数静态绑定）。

### Q11 静态多态与动态多态？CRTP？（Static vs dynamic polymorphism）
**优先级：★★**

**答案要点**：动态：虚函数，运行期，灵活，有间接调用开销。静态：模板/重载，编译期，可内联，无运行开销但代码膨胀、编译慢。CRTP：`struct D : Base<D>`，基类通过 `static_cast<D*>(this)` 调用派生实现。控制环内高频调用的小接口（如滤波器）适合静态多态；插件式、运行时切换的设备抽象适合虚接口。

**English short answer**
Dynamic polymorphism uses virtual functions and resolves calls at run time, which is flexible but adds an indirect call. Static polymorphism uses templates, so calls are resolved at compile time and can be inlined. For hot loops I choose templates; for runtime-pluggable device interfaces I choose virtual interfaces.

**追问方向**：concepts；`std::variant` + `visit`。

### Q12 抽象类与接口怎么写？对象切片是什么？（Abstract classes and slicing）
**优先级：★★**

**答案要点**：含纯虚函数 `= 0` 的类是抽象类，不能实例化，作为接口。对象切片：把派生类对象按值赋给基类对象时，派生部分被截掉，多态丢失。容器中存多态对象要存指针（`vector<unique_ptr<Base>>`）。

**English short answer**
A class with a pure virtual function is abstract and acts as an interface. Object slicing happens when a derived object is copied into a base-class value: the derived part is lost, along with polymorphic behaviour. Polymorphic objects in containers must therefore be stored by pointer.

**追问方向**：为什么不能在构造函数里多态。

### Q13 构造与析构的调用顺序？（Construction and destruction order）
**优先级：★★★**

**答案要点**：构造：先基类（按继承声明顺序，虚基类最先），再成员（按**声明顺序**，不是初始化列表的顺序），最后派生类构造函数体。析构完全相反。构造/析构函数内调用虚函数不会下沉到派生类（此时派生部分尚未构造/已析构）。全局/静态对象跨翻译单元的初始化顺序不确定（static initialization order fiasco），用函数内局部静态变量（线程安全的懒初始化）规避。

**English short answer**
Construction goes base classes first, then members in the order they are declared, not the order in the initializer list, and finally the constructor body. Destruction is the exact reverse. Virtual calls inside constructors and destructors do not reach the derived override, because that part of the object does not exist at that moment.

**追问方向**：成员初始化列表的必要性（引用、const、无默认构造的成员）；单例的线程安全。

## 四、移动语义与模板

### Q14 左值、右值、右值引用？（lvalue, rvalue, rvalue reference）
**优先级：★★★**

**答案要点**：左值：有名字、可取地址的持久对象。右值：临时对象/即将销毁的值。`T&&` 右值引用只能绑定右值；`std::move(x)` 只是把 `x` 强转为右值引用（不移动任何东西），真正的"窃取资源"发生在移动构造/赋值函数里。C++11 值类别细分：lvalue、prvalue、xvalue。具名的右值引用变量本身是左值。

**English short answer**
An lvalue has a name and an address, while an rvalue is a temporary that is about to disappear. An rvalue reference binds to rvalues. std::move does not move anything by itself, it just casts to an rvalue reference so that the move constructor can be selected, and that constructor steals the resources.

**追问方向**：xvalue；返回局部变量时是否要 `std::move`（不要，会阻碍 RVO）。

### Q15 移动语义解决什么问题？怎么写移动构造？（Move semantics）
**优先级：★★★**

**答案要点**：避免不必要的深拷贝：临时对象或不再使用的对象，其内部资源可以直接"过户"。移动后源对象处于有效但未指定的状态（通常置空）。移动构造应标记 `noexcept`，否则 `vector` 扩容时为强异常安全会退回到拷贝。

```cpp
class Buffer {
    size_t n_; float* p_;
public:
    Buffer(Buffer&& o) noexcept : n_(o.n_), p_(o.p_) { o.n_ = 0; o.p_ = nullptr; }
    Buffer& operator=(Buffer&& o) noexcept {
        if (this != &o) { delete[] p_; n_ = o.n_; p_ = o.p_; o.n_ = 0; o.p_ = nullptr; }
        return *this;
    }
    ~Buffer() { delete[] p_; }
};
```
例：一次传递大点云（`std::vector<Point>`）给另一线程时，用 `std::move` 避免拷贝，源对象之后不应再使用。

**English short answer**
Move semantics lets an object transfer ownership of its internal resources instead of copying them, which is much cheaper for things like large vectors or point clouds. The moved-from object stays valid but unspecified. I mark move operations noexcept, otherwise containers like vector fall back to copying when they reallocate.

**追问方向**：RVO / 拷贝省略；`std::move` 后能否继续使用。

### Q16 完美转发与万能引用？（Perfect forwarding, forwarding references）
**优先级：★★★**

**答案要点**：模板参数 `T&&`（`T` 需被推导）是**转发引用**，既能绑左值也能绑右值：传左值时 `T` 推导为 `X&`，引用折叠 `X& &&` → `X&`；传右值时 `T` 为 `X`。`std::forward<T>(arg)` 按原来的值类别转发，保证左值仍当左值、右值仍当右值，避免多余拷贝。用于工厂函数、`emplace_back`、`make_unique`。

```cpp
template <class T, class... Args>
std::unique_ptr<T> my_make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
```
引用折叠规则：只要有一个是左值引用，结果就是左值引用。

**English short answer**
In a template, a parameter written as T double-ampersand with a deduced T is a forwarding reference that binds to both lvalues and rvalues. std::forward passes the argument on with its original value category, so lvalues stay lvalues and rvalues stay rvalues. This is how make_unique and emplace_back forward constructor arguments without extra copies.

**追问方向**：引用折叠；`auto&&`；何时 `move` 何时 `forward`。

### Q17 `emplace_back` 与 `push_back`？（emplace vs push）
**优先级：★★**

**答案要点**：`push_back(x)` 接受已构造对象（拷贝/移动进容器）；`emplace_back(args...)` 在容器内存里原地构造，省一次临时对象。对已有对象差异不大；显式（`explicit`）构造函数用 `emplace_back` 可通过但 `push_back` 不行，注意类型安全。

**English short answer**
push_back takes an existing object and copies or moves it in, while emplace_back constructs the element in place from constructor arguments, saving a temporary. With an already built object there is little difference.

**追问方向**：`vector<unique_ptr>` 的 emplace。

### Q18 模板基础：函数模板、类模板、特化、SFINAE？（Templates）
**优先级：★★★**

**答案要点**
- 模板在编译期按实参实例化，每个类型生成一份代码（代码膨胀）；定义通常放头文件，因为实例化需看到完整定义。
- 特化：全特化与偏特化（仅类模板可偏特化；函数模板用重载）。
- SFINAE：替换失败不是错误，在重载解析中被丢弃，用于按类型启用函数；C++20 `concepts` 更清晰；C++17 `if constexpr` 编译期分支。
- 可变参数模板：`template<class... Ts>`，折叠表达式。
- 类型萃取：`std::is_integral`、`std::enable_if`。

```cpp
template <class T>
T clamp_val(T v, T lo, T hi) { return v < lo ? lo : (v > hi ? hi : v); }

template <class T>
auto to_num(T v) {
    if constexpr (std::is_floating_point_v<T>) return v;
    else return static_cast<double>(v);
}
```

**English short answer**
Templates are instantiated at compile time for each set of type arguments, so they give zero runtime overhead but may bloat code, and their definitions usually live in headers. SFINAE and C++20 concepts constrain which types a template accepts, and if constexpr selects code paths at compile time. A typical robotics use is a generic filter or math function working for float and double.

**追问方向**：模板与宏的区别；显式实例化；编译错误信息过长的处理。

### Q19 `auto`、`decltype`、`constexpr`、`using` 的现代用法？（Modern keywords）
**优先级：★★**

**答案要点**：`auto` 推导类型（去掉引用和顶层 const，需 `auto&`/`const auto&` 保留）；`decltype(expr)` 取表达式精确类型；`constexpr` 编译期求值，用于常量表与查表（如 sin 表）；`using` 取代 `typedef`，支持模板别名；范围 for、结构化绑定 `auto [a,b]`；`nullptr` 取代 `NULL`；`enum class` 强类型枚举。

**English short answer**
auto deduces types, decltype gives the exact type of an expression, constexpr evaluates at compile time, and using supports template aliases. I also prefer nullptr over NULL and enum class over plain enums for type safety.

**追问方向**：`auto` 与引用折叠；`constinit`。

### Q20 lambda 表达式与捕获？（Lambda captures）
**优先级：★★★**

**答案要点**：`[捕获](参数){体}`。值捕获 `[=]` 拷贝，引用捕获 `[&]`。**悬垂引用陷阱**：异步回调或线程中以引用捕获局部变量，函数返回后它已销毁。`[this]` 捕获当前对象指针，对象销毁后回调仍执行则出错——可捕获 `shared_from_this` 或 `weak_ptr`。lambda 是编译器生成的匿名函数对象，`mutable` 允许修改值捕获的副本；`std::function` 类型擦除有额外开销，高频路径用模板参数。

**English short answer**
A lambda is an anonymous function object that can capture variables by value or by reference. The common bug is capturing a local by reference in an asynchronous callback, so it dangles after the function returns. When capturing this in a callback I make sure the object outlives it, or capture a weak_ptr. std::function adds overhead, so in hot paths I use a template parameter.

**追问方向**：lambda 的底层实现；泛型 lambda。

## 五、STL 容器

### Q21 `vector` 的实现、扩容和迭代器失效？（std::vector）
**优先级：★★★**

**答案要点**：三个指针：begin、end、end_of_storage，连续内存。`push_back` 容量不足时分配新内存（常见 2× 或 1.5×），移动/拷贝元素，释放旧内存，均摊 $O(1)$。迭代器失效：扩容使全部失效；`insert/erase` 使修改点之后的失效；`erase` 返回下一个有效迭代器。`reserve` 预留容量，`shrink_to_fit` 请求缩减；`clear` 不释放容量。`vector<bool>` 是特化的位压缩容器，`operator[]` 返回代理对象，易踩坑。

**English short answer**
A vector keeps a contiguous block with three pointers for begin, end and capacity end. When it is full it allocates a bigger block, moves the elements and frees the old one, so push_back is amortized constant time. Reallocation invalidates all iterators and references, so I reserve when the size is known.

**追问方向**：`resize` vs `reserve`；`vector<bool>`。

### Q22 `map`、`unordered_map`、`set` 的底层实现与复杂度？（Associative containers）
**优先级：★★★**

| 容器 | 实现 | 查找/插入/删除 | 有序 | 备注 |
|---|---|---|---|---|
| map / set | 红黑树 | $O(\log n)$ | 是 | 迭代器稳定，范围查询 |
| unordered_map / set | 哈希表（拉链） | 平均 $O(1)$，最坏 $O(n)$ | 否 | rehash 使迭代器失效 |
| vector | 动态数组 | 查 $O(1)$ 尾插均摊 $O(1)$ | — | 中间插入 $O(n)$ |
| list | 双向链表 | 已知位置 $O(1)$ | — | 缓存不友好 |
| deque | 分段数组 | 两端 $O(1)$ | — | 随机访问 $O(1)$ |
| priority_queue | 堆（vector） | push/pop $O(\log n)$ | — | 无迭代器 |

**答案要点**：`map::operator[]` 会在键不存在时插入默认值（读取请用 `find`/`at`/`contains`）。自定义键需要比较器或 `hash` 与 `==`。小规模数据时排序 `vector` + 二分常比 `map` 快（缓存局部性）。

**English short answer**
map and set are usually red-black trees with logarithmic operations and sorted order. unordered_map and unordered_set are hash tables with average constant time but no ordering. Remember that map's operator square-bracket inserts a default element if the key is missing, so for lookups I use find or at.

**追问方向**：哈希冲突与负载因子；有序 vs 无序的选择。

### Q23 `deque`、`list`、`array`、`stack/queue` 如何选择？（Choosing containers）
**优先级：★★**

**答案要点**：默认 `vector`。两端增删用 `deque`（也是 `std::queue` 默认底层）；需要稳定迭代器和 $O(1)$ 中间插入用 `list`/`forward_list`（少见）；大小固定用 `std::array`（栈上，无堆分配，适合嵌入式/实时）。`stack/queue/priority_queue` 是适配器。

**English short answer**
I start with vector. For queues with insertion at both ends I use deque, and for fixed-size data I use std::array, which lives on the stack with no heap allocation. List is rarely the best choice because of poor cache locality.

**追问方向**：`deque` 内部结构；`array` 与 C 数组区别。

### Q24 迭代器失效规则总结？（Iterator invalidation）
**优先级：★★★**

**答案要点**：`vector`：扩容全失效，插入点之后失效；`deque`：中间插入全失效，两端插入使迭代器失效但引用仍有效；`list`/`map`：仅被删除元素的迭代器失效；`unordered_*`：rehash 时迭代器失效，指针/引用仍有效。循环中删除：`it = c.erase(it)`；不要在范围 for 中修改容器结构。

```cpp
for (auto it = m.begin(); it != m.end();) {
    if (cond(it->second)) it = m.erase(it); else ++it;
}
```

**English short answer**
For a vector, reallocation invalidates everything and an insert or erase invalidates iterators from that point on. For list and map only the erased element is affected. When erasing in a loop I use the iterator returned by erase, and I never change the container structure inside a range-based for loop.

**追问方向**：erase-remove 惯用法；C++20 `std::erase_if`。

### Q25 `string` 的实现：SSO 与拷贝？（std::string SSO）
**优先级：★★**

**答案要点**：多数实现用小字符串优化（SSO）：短字符串（约 15–22 字节，随实现而异）直接存在对象内部，无堆分配；长字符串堆分配。旧 COW 实现已因多线程问题被 C++11 禁止。`string_view`（C++17）是非拥有的只读视图，不拷贝，但需保证底层字符串存活。

**English short answer**
Most standard libraries use small string optimization: short strings are stored inside the string object itself without heap allocation, and longer ones go on the heap. string_view is a non-owning read-only view, cheap to pass, but it must not outlive the underlying data.

**追问方向**：`c_str()` 悬垂；`std::to_string` 性能。

### Q26 自定义排序与比较器要注意什么？（Comparators）
**优先级：★★**

**答案要点**：比较器必须满足**严格弱序**：`comp(a,a)==false`、传递性、反对称。写成 `<=` 会导致未定义行为/崩溃。`priority_queue` 默认大顶堆，写小顶堆要用 `greater`。

```cpp
std::priority_queue<std::pair<double,int>,
                    std::vector<std::pair<double,int>>,
                    std::greater<>> open;   // 小顶堆，A* open list
```

**English short answer**
A comparator must define a strict weak ordering. Using less-or-equal breaks that and can crash sort. The default priority_queue is a max-heap, so for A star's open list I pass greater to get a min-heap.

**追问方向**：`sort` 的实现（introsort）；稳定排序 `stable_sort`。

## 六、内存模型与对象生命周期

### Q27 `const` 成员函数与 `mutable`？（const member functions, mutable）
**优先级：★★★**

**答案要点**：`const` 成员函数承诺不修改对象的逻辑状态（`this` 为 `const T*`），可被 const 对象调用。`mutable` 成员即使在 const 函数里也能修改：典型用途是缓存、互斥量、引用计数、统计计数——不属于"逻辑状态"的东西。const 正确性：能 const 就 const。

```cpp
class Map {
    mutable std::mutex m_;
    std::vector<int> data_;
public:
    int get(size_t i) const { std::lock_guard<std::mutex> g(m_); return data_[i]; }
};
```

**English short answer**
A const member function promises not to change the object's logical state, so it can be called on const objects. mutable members, such as a mutex or a cache, can still be modified inside it because they are not part of the logical state. Const correctness makes interfaces self-documenting and thread-friendly.

**追问方向**：`const` 重载；bitwise const vs logical const。

### Q28 栈对象与堆对象的生命周期？临时对象与引用延长？（Object lifetime）
**优先级：★★★**

**答案要点**：自动存储（栈）：作用域结束析构；动态存储（堆）：`delete` 析构；静态存储：程序结束析构。临时对象在完整表达式结束时销毁；`const T&` 绑定到临时对象会延长其生命周期到引用作用域结束，但返回这样的引用或存入成员不延长。**不要返回局部变量的引用/指针**。`string_view` 指向临时字符串是常见悬垂。

```cpp
const std::string& bad() { std::string s = "x"; return s; } // 悬垂引用 UB
```

**English short answer**
Automatic objects are destroyed at the end of their scope, dynamic ones when deleted, and static ones at program exit. Temporaries die at the end of the full expression, although binding one to a const reference extends its life to the reference's scope. Returning a reference to a local variable is a classic dangling bug.

**追问方向**：RVO / NRVO；C++17 保证的拷贝省略。

### Q29 C++ 内存模型与 `std::atomic`？（C++ memory model）
**优先级：★★★**

**答案要点**：C++11 起有标准内存模型：数据竞争（对同一非原子变量并发读写且至少一个写）是**未定义行为**。`std::atomic<T>` 提供原子读改写和内存序：`relaxed`（只保证原子性）、`acquire/release`（形成同步关系：release 之前的写对 acquire 之后的读可见）、`seq_cst`（默认，全局全序，最强也最慢）。`volatile` 不是线程同步工具。详细见 [并发多线程与实时系统八股](./07_并发多线程与实时系统八股.md)。

```cpp
std::atomic<bool> ready{false};
int payload;
// 生产者
payload = 42; ready.store(true, std::memory_order_release);
// 消费者
while (!ready.load(std::memory_order_acquire)) {}
use(payload);   // 保证看到 42
```

**English short answer**
The C++ memory model says a data race on a non-atomic variable is undefined behaviour. std::atomic gives atomic operations with selectable memory orders: relaxed gives atomicity only, release and acquire establish a happens-before relation between a writer and a reader, and seq_cst is the strongest and the default. volatile is not a synchronization tool in C++.

**追问方向**：acquire-release 例子；CAS；false sharing。

### Q30 内存对齐、`alignof`、`placement new`、内存池？（Alignment, placement new）
**优先级：★★**

**答案要点**：`alignof(T)`/`alignas(N)`。SIMD（如 Eigen 的向量化）需要 16/32 字节对齐，Eigen 固定大小类型放入 `std::vector` 需 `aligned_allocator`（或 C++17 自动对齐）。`placement new`：在已有内存上构造对象 `new (buf) T(args)`，需手动调用析构；配合预分配池实现实时系统的无堆分配。

**English short answer**
Some types and SIMD operations need specific alignment, which I control with alignas. Placement new constructs an object in memory I already own, which lets me build a pool allocator and avoid heap allocation in real-time paths. I must call the destructor explicitly.

**追问方向**：Eigen 对齐问题；PMR allocator。

## 七、异常安全与其他

### Q31 C++ 异常机制与异常安全保证？（Exception safety）
**优先级：★★★**

**答案要点**：`throw` 抛出，栈展开（stack unwinding）时依次析构局部对象，这正是 RAII 能保证资源释放的原因。四个级别：①无保证；②基本保证（无泄漏、不变量保持）；③强保证（失败则回滚到调用前状态，如 copy-and-swap）；④不抛保证（`noexcept`，析构、swap、移动应如此）。**析构函数不要抛异常**（栈展开期间再抛会 `terminate`）。嵌入式/实时常禁用异常（`-fno-exceptions`），因代码体积和时间不可预测，改用错误码或 `std::optional`/`expected` 风格。

**English short answer**
When an exception is thrown, the runtime unwinds the stack and calls destructors of local objects, which is why RAII releases resources correctly. Functions can offer the basic guarantee of no leaks, the strong guarantee of rollback, or the no-throw guarantee. Destructors should never throw. In embedded and real-time code, exceptions are often disabled in favour of error codes or optional-style return types.

**追问方向**：`noexcept` 的作用；copy-and-swap；异常的开销。

### Q32 `new` 失败会怎样？`operator new` 重载？（new failure）
**优先级：★**

**答案要点**：默认抛 `std::bad_alloc`；`new (std::nothrow)` 返回 nullptr；可 `set_new_handler`。嵌入式可重载全局 `operator new` 指向 RTOS 堆（如 `pvPortMalloc`）。`new[]` 要配 `delete[]`，混用是未定义行为。

**English short answer**
By default new throws bad_alloc, and the nothrow form returns a null pointer. On an RTOS I may overload operator new to use the RTOS heap. Memory from new[] must be released with delete[].

**追问方向**：`malloc` 与 `new` 能否混用（不能）。

### Q33 `explicit`、`default/delete`、`override/final` 各有什么用？（Specifiers）
**优先级：★★**

**答案要点**：`explicit` 禁止单参数构造函数的隐式转换（避免 `Foo f = 3;` 意外）；`= default` 让编译器生成；`= delete` 禁用函数（禁止拷贝、禁止某重载）；`override` 让编译器检查确实重写了虚函数；`final` 禁止进一步重写/继承。

**English short answer**
explicit blocks implicit conversions through single-argument constructors, delete disables a function such as copying, override makes the compiler verify that I really overrode a virtual function, and final prevents further overriding or inheritance.

**追问方向**：隐式转换的坑。

### Q34 `std::function` 与函数指针、`std::bind` 的区别？（std::function）
**优先级：★★**

**答案要点**：函数指针只能指向普通函数（无状态）；`std::function` 类型擦除，可存任何可调用对象（lambda、函数对象、成员函数绑定），有堆分配可能和间接调用开销；`std::bind` 在现代 C++ 中基本被 lambda 取代。回调接口：高频用模板参数，低频或需要存储时用 `std::function`。

**English short answer**
A function pointer can only hold a plain function, while std::function can store any callable, including lambdas with captured state, via type erasure, at a cost of possible heap allocation and an indirect call. I prefer lambdas to std::bind.

**追问方向**：小对象优化；成员函数指针。

### Q35 C++ 中的类型转换有哪几种？（Casts）
**优先级：★★**

**答案要点**：`static_cast`（编译期相关类型转换）、`dynamic_cast`（带 RTTI 的向下转型，失败返回 nullptr/抛 `bad_cast`，需要多态类型）、`const_cast`（去 const，修改真正的 const 对象是 UB）、`reinterpret_cast`（位模式重新解释，如指针转整数）。避免 C 风格转换。`dynamic_cast` 有运行开销，嵌入式常禁用 RTTI。

**English short answer**
static_cast is for ordinary compile-time conversions, dynamic_cast does a checked downcast using run-time type information, const_cast removes constness, and reinterpret_cast reinterprets raw bits. I avoid C-style casts because they hide which kind of conversion is happening.

**追问方向**：类型双关（type punning）合法做法 `memcpy`/`bit_cast`。

### Q36 线程安全的单例怎么写？（Thread-safe singleton）
**优先级：★★**

**答案要点**：C++11 保证函数内局部静态变量初始化线程安全（magic statics）：

```cpp
class Config {
public:
    static Config& instance() { static Config c; return c; }
    Config(const Config&) = delete; Config& operator=(const Config&) = delete;
private:
    Config() = default;
};
```
双检锁需要 `atomic` 才正确。单例使测试困难、隐式依赖，慎用；可考虑依赖注入。

**English short answer**
Since C++11 a function-local static is initialized in a thread-safe way, so the simplest correct singleton is a static local inside an instance function with the copy operations deleted. Double-checked locking is easy to get wrong without atomics. I use singletons sparingly because they hide dependencies.

**追问方向**：静态析构顺序问题。

### Q37 `std::optional`、`variant`、`any`、`expected` 的用途？（Vocabulary types）
**优先级：★**

**答案要点**：`optional<T>` 表示"可能没有值"（取代魔法返回值）；`variant<A,B>` 类型安全联合体，配合 `std::visit`；`any` 类型擦除容器；`expected<T,E>`（C++23）承载值或错误，适合无异常环境。机器人中传感器读数"可能无效"用 optional 表示状态有效性（与 P6 里"有效性检查"思想一致）。

**English short answer**
optional represents a value that may be absent, variant is a type-safe union, and expected carries either a result or an error. In robot code, optional is a clean way to represent a sensor reading that may be invalid.

**追问方向**：variant 的内存布局。

### Q38 C++ 编译与链接常见错误：ODR、undefined reference？（ODR, linking errors）
**优先级：★★**

**答案要点**：ODR（单一定义规则）：非内联函数/变量在整个程序只能有一个定义；头文件中定义非 inline 函数被多个 cpp 包含会 "multiple definition"。`undefined reference`：声明有、定义没链接上（缺库、顺序、`extern "C"`、模板定义放在了 cpp）。C++17 `inline` 变量。详见 [Linux_Git_编译构建八股](./08_Linux_Git_编译构建八股.md)。

**English short answer**
The One Definition Rule says a non-inline function or variable can be defined only once in the whole program, so defining one in a header included by several files causes multiple definition errors. An undefined reference means the declaration was found but the definition was not linked, often a missing library or a template defined in a source file.

**追问方向**：静态库顺序；`-Wl,--no-as-needed`。

### Q39 多线程中 `std::thread`、`mutex`、`condition_variable` 的 RAII 用法？（Threading primitives）
**优先级：★★★**

**答案要点**：`std::thread` 析构时若仍 joinable 会 `terminate`，必须 `join/detach`（C++20 `jthread` 自动 join）；`lock_guard`/`unique_lock`/`scoped_lock` 管理锁；`condition_variable::wait` 用谓词防虚假唤醒。详见 [并发多线程与实时系统八股](./07_并发多线程与实时系统八股.md)。

**English short answer**
A std::thread that is still joinable when destroyed calls terminate, so I always join it, or use std::jthread in C++20. I manage mutexes with lock_guard or scoped_lock, and I always wait on a condition variable with a predicate.

**追问方向**：`async` 与 `thread`；线程池。

### Q40 说说你在 C++ 项目里怎么避免内存问题和提升可维护性？（Practical engineering answer）
**优先级：★★**

**答案要点**：这是行为+技术混合题。框架：①默认值语义和 RAII，不手写 `new/delete`；②`unique_ptr` 表达所有权；③接口用 `const&`、`span`；④`-Wall -Wextra`，开启 ASan/UBSan/TSan 在 PC 上跑测试；⑤小接口、依赖注入便于仿真替换；⑥高频路径避免动态分配。结合 P6：统一能力模型使控制代码可跨硬件复用，正是接口抽象的价值（CV 描述）。具体用过哪些工具 `【待你补全：你实际用过的 sanitizer/clang-tidy/单元测试】`。

**English short answer**
I rely on RAII and smart pointers instead of manual memory management, pass objects by const reference, and compile with strict warnings. On the PC I run sanitizers for memory and thread errors. For hardware work I put devices behind small interfaces so the same control code can be reused and tested against simulation, and I avoid dynamic allocation in hot paths.

**追问方向**：如何调试 segfault；core dump + gdb。

## 本章要点速记
1. RAII：构造获取、析构释放，异常安全的基石。
2. 默认 `unique_ptr`；共享才用 `shared_ptr`；环用 `weak_ptr`；用 `make_*` 创建。
3. 虚函数 = vptr + vtable；多态基类析构必须 virtual。
4. 构造顺序：基类 → 成员（声明顺序）→ 本类；析构相反。
5. `std::move` 只是强转；移动构造要 `noexcept`；转发引用 + `std::forward` = 完美转发。
6. map 红黑树 $O(\log n)$，unordered_map 哈希平均 $O(1)$；vector 扩容使迭代器失效。
7. `mutable` 用于不属于逻辑状态的成员（锁、缓存）。
8. 数据竞争是 UB；原子 + 内存序，`volatile` 不是同步。
9. 析构函数不抛异常；嵌入式常禁异常，用错误码。
