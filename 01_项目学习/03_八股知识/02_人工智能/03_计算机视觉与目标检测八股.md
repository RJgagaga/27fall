## 一、检测任务基础

### Q1. 目标检测与分类、分割的区别 ★★★
**答案要点**
分类：整图一个标签；检测：输出每个目标的类别 + 框 $(x,y,w,h)$ + 置信度；语义分割：每个像素一个类别，不区分实例；实例分割：区分同类不同个体；全景分割：二者合一。检测需要解决：目标数量不定、尺度变化大、定位与分类两个任务联合学习。

**English short answer**
> Classification gives one label per image. Detection outputs a bounding box, a class and a confidence for every object, and the number of objects varies. Semantic segmentation labels every pixel but doesn't separate instances, while instance segmentation does. Detection must handle scale variation and balance localization with classification.

**追问方向**：为什么输出数量不定是难点？（需要密集预测+NMS，或集合预测如 DETR）

### Q2. 一阶段 vs 两阶段检测器 ★★★
**答案要点**
两阶段（R-CNN 系列）：先生成候选区域（region proposal），再对每个候选分类与精修框；精度高，速度较慢。一阶段（YOLO、SSD、RetinaNet）：在特征图上密集预测，直接输出类别和框；快、结构简单，早期精度略低（原因之一是前景背景极不平衡，由 Focal Loss 缓解）。现在两者精度差距已很小，边缘部署多选一阶段。

**English short answer**
> Two-stage detectors first propose regions and then classify and refine each one, which is accurate but slower. One-stage detectors predict boxes and classes densely over the feature map in a single pass, so they're faster and simpler to deploy. The accuracy gap has narrowed a lot, and on edge devices one-stage models like YOLO are the usual choice.

**追问方向**：为什么一阶段早期精度低？（正负样本极不平衡）

### Q3. Anchor 的作用与设计 ★★★
**答案要点**
Anchor（先验框）是在每个特征图位置预设的一组不同尺度和宽高比的参考框，网络预测相对 anchor 的偏移，把"回归任意框"变成"回归小修正"，降低学习难度、便于多尺度。设计：用 k-means 在训练集真实框的宽高上聚类（距离用 $1-\mathrm{IoU}$），得到 $k$ 个 anchor（YOLOv5 默认每尺度 3 个共 9 个，并有 AutoAnchor 在训练前检查召回，不够则重聚类）。缺点：超参多、与数据集相关、正负样本极不平衡、增加预测数量。

**English short answer**
> Anchors are predefined boxes of different sizes and aspect ratios at each location, and the network predicts offsets from them, which makes regression easier. Good anchors are chosen by k-means clustering on the ground-truth box sizes, using one minus IoU as the distance. The downsides are extra hyperparameters, dataset dependence, and many negative samples.

**追问方向**：anchor-free 怎么避开这些？（见 Q24）

### Q4. 边框回归的参数化 ★★★
**答案要点**
Faster R-CNN 的偏移编码（相对 anchor $(x_a,y_a,w_a,h_a)$）：
$$t_x=\frac{x-x_a}{w_a},\ t_y=\frac{y-y_a}{h_a},\ t_w=\ln\frac{w}{w_a},\ t_h=\ln\frac{h}{h_a}$$
对数编码保证宽高为正并使尺度不变。YOLOv5 的解码（与 v3/v4 不同，为避免 $e^{t}$ 数值不稳并扩大中心可偏移范围）：
$$b_x=(2\sigma(t_x)-0.5)+c_x,\ b_y=(2\sigma(t_y)-0.5)+c_y,\ b_w=p_w(2\sigma(t_w))^2,\ b_h=p_h(2\sigma(t_h))^2$$
中心偏移在 $[-0.5,1.5]$ 个格子内（可由邻近格子负责），宽高限制在 anchor 的 $[0,4]$ 倍，避免指数爆炸。

**English short answer**
> The network predicts offsets relative to an anchor: the center shift normalized by anchor size, and the log ratio of width and height. YOLOv5 changed the decoding to sigmoid-based formulas, so the center can move up to one and a half cells and the size is limited to four times the anchor, which is more stable than the exponential form.

**追问方向**：为什么用 log 而不是直接回归宽高？

### Q5. 检测网络的整体结构：Backbone-Neck-Head ★★★
**答案要点**
Backbone：提取多尺度特征（CSPDarknet、ResNet）；Neck：融合多尺度特征（FPN/PAN/BiFPN）；Head：每个尺度预测分类、框、置信度（objectness）。输出张量形状（YOLOv5，每尺度）：$B\times(A\cdot(5+C))\times H\times W$，其中 $A$ 为 anchor 数，$5=(x,y,w,h,obj)$，$C$ 为类别数。示例（教学示例）：3 anchors、80 类 → 通道数 $3\times85=255$。

**English short answer**
> A detector has a backbone that extracts features, a neck that fuses features from different scales, and a head that predicts at each scale. For YOLOv5 each head outputs, per anchor, four box values, an objectness score, and the class scores. With three anchors and eighty classes, that's 255 channels.

**追问方向**：为什么要多尺度输出？（大/中/小目标分别在 P5/P4/P3 层预测）

### Q6. 感受野与下采样倍数对检测的意义 ★★
**答案要点**
YOLOv5 输出步长 8、16、32（P3/P4/P5）。输入 $640\times640$ 时特征图为 $80\times80,40\times40,20\times20$。步长 8 的层分辨率高、语义弱，负责小目标；步长 32 的层感受野大，负责大目标。目标小于步长数倍时特征图上信息极少，小目标难检。

**English short answer**
> YOLOv5 predicts at strides 8, 16 and 32. For a 640 input those are 80 by 80, 40 by 40 and 20 by 20 grids. High-resolution layers handle small objects, and low-resolution layers with large receptive fields handle big ones.

**追问方向**：输入分辨率翻倍，计算量如何变？（平方）

## 二、IoU 家族与 NMS

### Q7. IoU 的定义与计算 ★★★
**答案要点**
$$IoU=\frac{|A\cap B|}{|A\cup B|}=\frac{|A\cap B|}{|A|+|B|-|A\cap B|}$$
手算（教学示例）：框 A $=(0,0,4,4)$，框 B $=(2,2,6,6)$（左上、右下坐标）。交集：宽 $\min(4,6)-\max(0,2)=2$，高 $2$，面积 4；各自面积 16；并集 $16+16-4=28$；$IoU=4/28\approx0.143$。代码要点：交集宽高需 `clamp(min=0)`，避免无交集时变为负数相乘为正。

**English short answer**
> IoU is the area of intersection divided by the area of union of two boxes. For two boxes of area sixteen overlapping in a two by two region, the intersection is four and the union is twenty-eight, so IoU is about 0.14. In code I clamp the intersection width and height at zero.

**追问方向**：IoU 作为损失的缺点？（不重叠时为 0，无梯度；不反映距离与形状）

### Q8. GIoU、DIoU、CIoU ★★★
**答案要点**
- GIoU：加入最小外接框 $C$：$GIoU=IoU-\dfrac{|C\setminus(A\cup B)|}{|C|}$，不重叠时也有梯度；缺点：包含时退化为 IoU，收敛慢。
- DIoU：加入中心点距离惩罚：$DIoU=IoU-\dfrac{\rho^2(b,b^{gt})}{c^2}$，$\rho$ 为中心欧氏距离，$c$ 为最小外接框对角线长，直接最小化中心距离，收敛更快。
- CIoU：再加长宽比一致性：
$$CIoU=IoU-\frac{\rho^2}{c^2}-\alpha v,\quad v=\frac{4}{\pi^2}\Big(\arctan\frac{w^{gt}}{h^{gt}}-\arctan\frac{w}{h}\Big)^2,\quad\alpha=\frac{v}{(1-IoU)+v}$$
损失 $L=1-CIoU$。YOLOv5 默认使用 CIoU 作为框回归损失（代码中 `bbox_iou(..., CIoU=True)`）。
手算 DIoU 惩罚（教学示例）：同上 A、B，中心 $(2,2)$ 与 $(4,4)$，$\rho^2=8$；外接框 $(0,0,6,6)$，$c^2=72$；惩罚 $8/72\approx0.111$，$DIoU\approx0.143-0.111=0.032$。

**English short answer**
> IoU gives no gradient when boxes don't overlap. GIoU adds a penalty based on the smallest enclosing box. DIoU adds the normalized distance between box centers, so it converges faster. CIoU further adds an aspect-ratio consistency term. YOLOv5 uses CIoU loss for box regression.

**追问方向**：CIoU 的长宽比项有什么缺陷？（只表达比例，不分别约束宽高；后续有 EIoU、SIoU、WIoU）

### Q9. NMS（非极大值抑制）算法 ★★★
**答案要点**
同一目标会被多个相邻 anchor/格子重复检出，NMS 去重。步骤（按类别分别做）：(1) 滤掉置信度低于阈值的框；(2) 按分数降序；(3) 取最高分框加入结果，计算它与其余框的 IoU，删除 IoU 大于阈值（常用 0.45–0.7）的框；(4) 对剩余重复直到为空。复杂度最坏 $O(n^2)$。实现常用"类别偏移技巧"（把框坐标加上 `class_id * 大数`）一次完成多类别 NMS。
手算（教学示例）：分数 0.9/0.8/0.7，框1与框2 IoU=0.6，框1与框3 IoU=0.1，阈值 0.5：保留框1，框2被删，框3保留。

**English short answer**
> NMS removes duplicate detections. I sort boxes by score, keep the best one, drop every remaining box whose IoU with it exceeds a threshold, and repeat. It's done per class. The threshold is a trade-off: too low removes true neighbors in crowded scenes, too high leaves duplicates.

**追问方向**：NMS 的时间复杂度？为什么部署时 NMS 常放在 CPU 后处理？

### Q10. NMS 的变体：Soft-NMS、DIoU-NMS、WBF ★★
**答案要点**
Soft-NMS：不直接删除，而是衰减重叠框的分数，如 $s_i\leftarrow s_ie^{-IoU^2/\sigma}$，缓解密集目标被误删。DIoU-NMS：用 DIoU 代替 IoU 判断，考虑中心距离，对遮挤更友好（YOLOv4 使用）。WBF：把重叠框按置信度加权融合，常用于集成/竞赛。Class-agnostic NMS 跨类别抑制。端到端检测器（DETR）通过匈牙利匹配训练，推理无需 NMS。

**English short answer**
> Soft-NMS decays the scores of overlapping boxes instead of deleting them, which helps in crowds. DIoU-NMS uses center distance in the suppression criterion. Weighted box fusion averages overlapping boxes, mostly for ensembles. DETR-style models avoid NMS altogether through set-based training.

**追问方向**：为什么 DETR 不需要 NMS？

### Q11. IoU 阈值与正负样本定义 ★★
**答案要点**
两阶段检测：IoU>0.5 为正、<0.5（或 0.1–0.5）为负。Cascade R-CNN 级联提高 IoU 阈值逐步精修。YOLOv5 不用 IoU 做硬匹配而用宽高比阈值（Q36）。IoU 阈值越高，定位越准但正样本越少。

**English short answer**
> In classic two-stage detectors, proposals with IoU above 0.5 are positives. Raising the threshold gives more precise boxes but fewer positives, and Cascade R-CNN solves that by refining in stages with increasing thresholds.

**追问方向**：COCO 为什么对 IoU 阈值 0.5:0.95 求平均？

### Q12. 代码题：向量化 IoU 与 NMS（要点）★★★
**答案要点**
```python
# 教学示例，非项目源码
import numpy as np
def nms(boxes, scores, thr):
    x1,y1,x2,y2 = boxes.T
    areas = (x2-x1)*(y2-y1)
    order = scores.argsort()[::-1]
    keep = []
    while order.size:
        i = order[0]; keep.append(i)
        xx1 = np.maximum(x1[i], x1[order[1:]])
        yy1 = np.maximum(y1[i], y1[order[1:]])
        xx2 = np.minimum(x2[i], x2[order[1:]])
        yy2 = np.minimum(y2[i], y2[order[1:]])
        inter = np.maximum(0, xx2-xx1) * np.maximum(0, yy2-yy1)
        iou = inter / (areas[i] + areas[order[1:]] - inter)
        order = order[1:][iou <= thr]
    return keep
```
要点：用 `np.maximum(0, ...)` 防负交集；坐标定义（含不含 +1）要统一；多类别要按类别分别做。

**English short answer**
> I sort by score, take the top box, compute IoU with all the rest in a vectorized way, and keep only those with IoU below the threshold. The tricky parts are clamping the intersection at zero and doing it per class.

**追问方向**：如何用 GPU 批量做 NMS？（`torchvision.ops.batched_nms`）

### Q13. 置信度的构成：objectness × class probability ★★
**答案要点**
YOLOv5 的最终分数 = objectness（框内是否有目标，训练目标是预测框与真值的 IoU）× 类别概率。训练 objectness 目标可用 IoU 作为软标签，使置信度反映定位质量。检测的置信度阈值与 NMS 阈值是后处理的两个关键超参，影响 Precision/Recall 权衡。

**English short answer**
> The final score is the objectness times the class probability. In YOLOv5 the objectness target can be the IoU between the predicted and ground-truth box, so the confidence reflects localization quality. The confidence threshold and NMS threshold control the precision-recall trade-off.

**追问方向**：为什么部署时置信度阈值不能随便取？（见 P4 的"带置信度的观测"）

## 三、评价指标 mAP

### Q14. AP 与 mAP 的计算流程 ★★★
**答案要点**
对每个类别：(1) 所有预测按置信度降序；(2) 每个预测与未被匹配的真值按 IoU≥阈值（如 0.5）判 TP，否则 FP（重复检测的第二个也是 FP）；漏掉的真值是 FN；(3) 逐位置累积得到 Precision 和 Recall；(4) 对 PR 曲线取包络（precision 取右侧最大值使单调）后求面积，得 AP；(5) 对所有类别求平均得 mAP。
手算（教学示例）：某类 3 个真值，4 个预测按分数排序，TP/FP 依次为 TP、FP、TP、TP。累积：
| 排名 | 判定 | 累积TP | 累积FP | Precision | Recall |
|---|---|---|---|---|---|
| 1 | TP | 1 | 0 | 1.00 | 0.33 |
| 2 | FP | 1 | 1 | 0.50 | 0.33 |
| 3 | TP | 2 | 1 | 0.67 | 0.67 |
| 4 | TP | 3 | 1 | 0.75 | 1.00 |
包络后 precision：召回 0–0.33 取 1.0，0.33–0.67 取 0.75（右侧最大），0.67–1.0 取 0.75。AP $=0.33\times1.0+0.33\times0.75+0.33\times0.75\approx0.83$。

**English short answer**
> For each class I sort predictions by confidence, mark each as true positive if it matches an unmatched ground truth with IoU above the threshold and otherwise a false positive, and compute the cumulative precision and recall. AP is the area under the precision-recall curve after making precision monotonic. mAP is the mean over classes.

**追问方向**：重复检测怎么算？没有检出的真值进哪里？

### Q15. mAP@0.5 与 mAP@0.5:0.95 ★★★
**答案要点**
mAP@0.5：IoU 阈值 0.5；COCO 主指标 mAP@[.5:.95]：阈值从 0.5 到 0.95、步长 0.05 共 10 个，各算 AP 后平均，更看重定位精度。另有 AP_small/medium/large（按面积 <32²、32²–96²、>96²）。YOLOv5 训练日志里同时输出 P、R、mAP50、mAP50-95。VOC 早期用 11 点插值，后来改为全点积分。

**English short answer**
> mAP at 0.5 counts a detection correct if IoU is at least 0.5. COCO's main metric averages AP over IoU thresholds from 0.5 to 0.95, so it rewards precise localization. COCO also reports AP for small, medium and large objects.

**追问方向**：为什么 mAP@0.5 高但 mAP@0.5:0.95 低？（框不够准）

### Q16. 检测评估的实际注意点 ★★
**答案要点**
评估时置信度阈值要设得很低（如 0.001）以得到完整 PR 曲线；部署时则选定工作点（阈值）使 P/R 满足需求。需按场景分析：混淆矩阵、各类 AP、尺度分层 AP、漏检/误检样本可视化。mAP 不衡量速度、也不反映工作阈值下的实际表现，所以要同时报延迟、FPS、功耗。

**English short answer**
> For evaluation I use a very low confidence threshold to trace the full precision-recall curve, but in deployment I fix an operating threshold. mAP doesn't capture latency or the behavior at that threshold, so I also look at confusion matrices, per-class AP and the runtime numbers.

**追问方向**：量化前后 mAP 下降怎么分析？（见 06 章）

### Q17. 其他视觉指标 ★
**答案要点**
分割：mIoU、Dice；跟踪：MOTA、IDF1；姿态：OKS-AP；分类：Top-1/Top-5；回归（深度）：RMSE、δ<1.25。

**English short answer**
> Segmentation uses mean IoU or Dice, tracking uses MOTA and IDF1, keypoints use OKS-based AP, and classification uses top-1 and top-5 accuracy.

**追问方向**：mIoU 如何由混淆矩阵计算？

## 四、两阶段与一阶段检测器

### Q18. R-CNN → Fast R-CNN → Faster R-CNN 的演进 ★★★
**答案要点**
R-CNN：Selective Search 提 ~2000 个候选，每个裁剪后单独过 CNN，SVM 分类，极慢。Fast R-CNN：整图一次卷积，在特征图上对候选做 RoI Pooling，分类与回归联合训练。Faster R-CNN：用 RPN（Region Proposal Network）取代 Selective Search，proposal 与检测共享卷积特征，近似端到端。每一步都是在"共享计算、减少重复"。

**English short answer**
> R-CNN ran a CNN on each of thousands of region proposals separately, which was very slow. Fast R-CNN computes the feature map once and pools features for each region. Faster R-CNN replaces the external proposal method with a region proposal network sharing the same features, making the whole pipeline nearly end to end.

**追问方向**：RoI Pooling 与 RoI Align 的区别（Q20）。

### Q19. RPN 的结构与损失 ★★
**答案要点**
在共享特征图每个位置放 $k$ 个 anchor（3 尺度×3 比例=9），一个 $3\times3$ 卷积后分两支：$2k$ 个 objectness（前景/背景）和 $4k$ 个框偏移。训练时 anchor 与真值 IoU>0.7（或与某真值 IoU 最大）为正，<0.3 为负，其余忽略；每图采样 256 个 anchor，正负比约 1:1。损失 $=L_{cls}+\lambda L_{reg}$（Smooth L1，仅正样本）。RPN 输出经 NMS 后取 top-N proposal 送入第二阶段。

**English short answer**
> The RPN slides over the shared feature map, with several anchors per location, and predicts for each anchor an objectness score and box offsets. Anchors with high overlap are positives, low overlap are negatives, and it samples a balanced mini-batch. The top proposals after NMS go to the second stage.

**追问方向**：为何第二阶段还要再回归一次？

### Q20. RoI Pooling 与 RoI Align ★★
**答案要点**
RoI Pooling 把候选框坐标量化到整数网格再分块 max-pool，两次取整带来错位，对小目标和分割影响大。RoI Align 取消量化，用双线性插值在浮点坐标采样（每个 bin 内取若干采样点再平均/max），保留精确对齐，Mask R-CNN 采用。

**English short answer**
> RoI Pooling rounds the region coordinates to integer cells, which causes misalignment. RoI Align avoids any rounding and samples the feature map with bilinear interpolation, which is important for small objects and for mask prediction.

**追问方向**：双线性插值如何计算？

### Q21. Faster R-CNN 的损失与训练要点 ★★
**答案要点**
总损失 = RPN（分类+回归）+ Fast R-CNN 头（多类别交叉熵 + 类别相关 Smooth L1 回归）。训练可交替或近似联合。Smooth L1：$|x|<1$ 时 $0.5x^2$，否则 $|x|-0.5$。第二阶段采样 RoI：正（IoU≥0.5）约占 25%，负占 75%，每图 128 个。

**English short answer**
> The total loss has two parts: the RPN's objectness and box losses, and the detection head's classification and box regression losses. The regression uses smooth L1, which is quadratic near zero and linear elsewhere, so it's less sensitive to outliers than L2.

**追问方向**：为什么回归用 Smooth L1 不用 L2？

### Q22. SSD 的原理 ★★
**答案要点**
SSD（Single Shot MultiBox Detector）：在 VGG 骨干后加多个额外卷积层，在多个不同分辨率的特征图上都放默认框（default boxes，类似 anchor）并预测类别和偏移，大目标用深层小特征图，小目标用浅层大特征图。训练：匹配策略（每个真值匹配 IoU 最大的默认框，再把 IoU>0.5 的也设正），难负样本挖掘（hard negative mining）将负正比限制为 3:1，损失 = 分类（softmax CE）+ 定位（Smooth L1）。缺点：浅层特征语义弱，小目标差，这启发了 FPN。

**English short answer**
> SSD makes predictions from several feature maps of different resolutions, each with default boxes of various shapes, so it detects objects at multiple scales in one pass. Training uses hard negative mining to keep the negative-to-positive ratio at three to one. Its weakness is small objects, because shallow features are semantically weak, which motivated feature pyramids.

**追问方向**：难负样本挖掘与 Focal Loss 的关系？

### Q23. RetinaNet 与 Focal Loss ★★★
**答案要点**
一阶段检测的主要问题：约 $10^4$–$10^5$ 个候选里绝大多数是容易的背景负样本，累积梯度压倒少数前景。Focal Loss：
$$FL(p_t)=-\alpha_t(1-p_t)^\gamma\log p_t,\quad p_t=\begin{cases}p&y=1\\1-p&y=0\end{cases}$$
$\gamma$（常取 2）使已分类很好的样本（$p_t\to1$）损失被大幅降权。手算（教学示例）：$p_t=0.9$ 时调制因子 $(0.1)^2=0.01$，损失降到 CE 的 1%；$p_t=0.5$ 时因子 0.25。$\alpha_t$ 平衡类别权重。RetinaNet = ResNet + FPN + 两个子网（分类、回归）+ Focal Loss。

**English short answer**
> In one-stage detectors, easy background anchors vastly outnumber the objects and dominate the gradient. Focal loss multiplies cross-entropy by one minus p_t to the power gamma, so well-classified examples get almost no weight, and the training focuses on hard ones. RetinaNet combined this with an FPN backbone and matched two-stage accuracy.

**追问方向**：Focal Loss 对 objectness 的初始化偏置有什么要求？（先验概率 0.01 初始化偏置避免初期不稳）

### Q24. Anchor-free 检测：FCOS、CenterNet、YOLOX ★★★
**答案要点**
- CenterNet：把目标当作中心点，预测热图（heatmap，高斯核）、宽高、偏移，无需 NMS（局部极大值池化代替）；
- FCOS：逐像素预测到四边的距离 $(l,t,r,b)$ 和 centerness（离中心越近分越高，抑制低质量框），用 FPN 多层按尺度范围分配；
- YOLOX：解耦头（分类与回归分支分开）+ anchor-free + SimOTA 动态标签分配。
优点：少超参、不受 anchor 先验限制、泛化好；难点：正样本分配与大目标内多点歧义。

**English short answer**
> Anchor-free detectors predict directly from each location, without preset boxes. CenterNet treats objects as center points on a heatmap. FCOS predicts the distances to the four box edges plus a centerness score. YOLOX combines a decoupled head and dynamic label assignment. They remove anchor hyperparameters but need a careful assignment of positive samples.

**追问方向**：centerness 起什么作用？

### Q25. 标签分配（Label Assignment）：静态与动态 ★★
**答案要点**
静态：基于 IoU 阈值或几何位置（中心区域）固定规则；动态：根据当前预测质量分配，如 SimOTA（把分配视为最优传输，用分类+定位代价挑 top-k，$k$ 由 IoU 之和估算）、TOOD/TAL（任务对齐）。动态分配使正样本既分类好又定位准，减少分类分数高但框差的不对齐问题。

**English short answer**
> Static assignment uses fixed rules like an IoU threshold. Dynamic assignment, like SimOTA, picks positive samples per object based on the current cost of classification and localization, so the chosen samples are the ones the model already predicts well. This helps align classification confidence with box quality.

**追问方向**：为什么分类分数与定位质量错位是个问题？（NMS 会保留分高但框差的）

### Q26. DETR 与端到端检测 ★★
**答案要点**
DETR：CNN 骨干 + Transformer 编码解码器，用 $N$ 个可学习 object queries 并行输出 $N$ 个预测，训练时用匈牙利算法在预测与真值间做一对一匹配（代价含分类和 L1/GIoU 框损失），无 anchor 与 NMS。缺点：收敛慢（Deformable DETR 用稀疏采样加速）、小目标弱；后续 RT-DETR 面向实时。

**English short answer**
> DETR treats detection as set prediction. A transformer decoder takes a fixed number of learned queries and outputs one box per query, and a Hungarian matching loss assigns each ground truth to exactly one prediction, so no NMS is needed. It converges slowly and was improved by Deformable DETR and real-time variants.

**追问方向**：为什么一对一匹配让 NMS 不再需要？

## 五、YOLO 系列演进

### Q27. YOLOv1 到 YOLOv3 ★★
**答案要点**
v1（2016）：把图分成 $S\times S$ 网格，每格预测 $B$ 个框 + 类别，全图回归，速度快但定位粗、小目标和密集目标差、每格仅一个类别；损失为多项平方误差，宽高开根号以减弱大小框差异。v2：加 BN、anchor（k-means 聚类）、passthrough；v3：多尺度（三个尺度输出，FPN 式融合）、Darknet-53 残差骨干、类别用独立 sigmoid（多标签）、objectness 单独预测。

**English short answer**
> YOLOv1 divides the image into a grid and regresses boxes and classes in one pass, which was fast but coarse. YOLOv2 added batch norm and k-means anchors. YOLOv3 added multi-scale prediction with three output scales, a residual backbone, and independent sigmoid class predictions.

**追问方向**：v1 为什么对密集小目标差？（每格最多检出一类/两个框）

### Q28. YOLOv4 与 YOLOv5 的差别和"免费技巧 Bag of Freebies" ★★
**答案要点**
YOLOv4：CSPDarknet53、SPP、PANet、Mosaic、CIoU、DropBlock、Mish 激活等。Bag of Freebies：只增加训练成本不增推理成本的技巧（数据增强、CIoU、标签平滑、正则）；Bag of Specials：增加少量推理成本换精度（SPP、注意力、PAN）。YOLOv5（Ultralytics，PyTorch 实现）：工程化好，提供 n/s/m/l/x 尺寸，AutoAnchor、Mosaic、自适应图片缩放、EMA、SiLU、导出 ONNX/TensorRT 等。YOLOv5 无单独的论文（这一点面试可坦率说明：以官方代码仓库为准，具体细节以实际版本为准。本项目的做法是：采用 Ultralytics YOLOv5 官方仓库的 v6.x/v7.0 系列导出流程，模型尺寸取边缘端常用的 s 档（典型选择，教学示例，以实机为准））。

**English short answer**
> YOLOv4 collected many tricks: a CSP backbone, SPP, PANet, mosaic augmentation and CIoU loss. It separated training-only tricks, the bag of freebies, from small inference-cost additions, the bag of specials. YOLOv5 is an engineering-focused PyTorch implementation with multiple model sizes, auto-anchor, and easy export to ONNX and other formats.

**追问方向**：为什么 Mosaic 属于 freebie？

### Q29. YOLOv6/v7/v8 及后续的趋势 ★
**答案要点**
共同趋势：解耦头、anchor-free、更强的标签分配（TAL/SimOTA）、重参数化（RepVGG 思路：训练时多分支，推理时合并为单个 $3\times3$ 卷积）、更好的损失（分布焦点损失 DFL）、更适合部署的结构（YOLOv6/v7）。YOLOv8 为 anchor-free + 解耦头 + C2f 模块。具体指标以官方发布为准，面试时不要背数字。

**English short answer**
> Later YOLO versions moved to decoupled heads, anchor-free prediction, stronger label assignment, and re-parameterized convolutions, which merge training-time branches into a single conv for inference. I wouldn't quote exact benchmark numbers from memory.

**追问方向**：重参数化为什么能"免费"提速？

### Q30. 为什么 YOLO 适合边缘部署 ★★★
**答案要点**
结构规整（卷积、SiLU/ReLU、concat、上采样，算子大多被 NPU 支持）；一次前向；提供多规模模型；后处理简单；导出链路成熟（ONNX→RKNN/TensorRT）。注意：解码和 NMS 常不进 NPU，放在 CPU，需要考虑后处理耗时；SiLU 在部分 NPU 上不被原生支持或量化精度差，实践中会换成 ReLU/LeakyReLU 或让工具链处理。见 [06_模型部署与量化八股](./06_模型部署与量化八股.md)。

**English short answer**
> YOLO uses regular operators that NPUs support well, has a single forward pass, comes in several sizes, and its export path through ONNX to vendor toolchains is mature. Decoding and NMS usually run on the CPU, so I count their latency, and some activations like SiLU may need special handling in quantization.

**追问方向**：这和你在 RK3588 上的做法有什么对应？（见本章 "如何讲 P4"）

## 六、YOLOv5 细节（对应 P4）

> 下面是 YOLOv5 官方实现的通用结构，用来回答原理题；不代表你在项目里改过它们。你在 P4 里实际做的是"YOLOv5/RKNN INT8 推理链，把相机帧变成带置信度与时间戳的结构化观测"。

### Q31. YOLOv5 的整体结构 ★★★
**答案要点**
```text
输入 640x640x3
  -> Backbone (CSPDarknet): Focus/6x6 Conv stem -> Conv+C3 x4 stages -> SPPF
  -> Neck: FPN(自顶向下) + PAN(自底向上)
  -> Head: 3 个尺度 (stride 8/16/32), 每尺度 1x1 卷积输出 A*(5+C) 通道
  -> 后处理: 解码 -> 置信度过滤 -> NMS
```
Backbone 逐级下采样提取特征，C3 模块（CSP bottleneck）堆叠；SPPF 融合多尺度池化；Neck 融合高低层特征；Head 在 P3/P4/P5 输出。后期版本（v6.0+）用 $6\times6$ stride-2 卷积代替 Focus 切片以利于导出。

**English short answer**
> YOLOv5 has a CSPDarknet backbone with C3 blocks and an SPPF module at the end, a neck that fuses features with a top-down FPN path and a bottom-up PAN path, and three detection heads at strides 8, 16 and 32. After the network, decoding, confidence filtering and NMS produce the final boxes.

**追问方向**：Focus 为何后来被 6×6 卷积替代？

### Q32. CSP（Cross Stage Partial）结构 ★★★
**答案要点**
问题：深层网络梯度信息重复、计算量大。CSP 思路：把输入特征图按通道分成两部分：一部分走 bottleneck 堆叠（主分支），另一部分走捷径，最后在通道上 concat 再 $1\times1$ 融合。效果：减少重复梯度流、降低计算量与内存，提高学习能力。YOLOv5 的 C3 模块：两个 $1\times1$ 卷积分支，一支经过 $n$ 个 Bottleneck（$1\times1$→$3\times3$ + 残差），concat 后再 $1\times1$ 卷积。Backbone 中的 Bottleneck 有残差相加，Neck 中的 C3 可设 shortcut=False。

**English short answer**
> A CSP block splits the feature channels into two paths. One goes through a stack of bottleneck layers, the other skips them, and then they are concatenated and fused. This reduces duplicated gradient information and computation while keeping accuracy. YOLOv5's C3 module is exactly this pattern.

**追问方向**：C3 与 YOLOv8 的 C2f 有何不同？（C2f 把每个 bottleneck 的输出都拼接，梯度流更丰富）

### Q33. SPP 与 SPPF ★★
**答案要点**
SPP：对同一特征并行做不同核（5、9、13）的 max-pool 并 concat，扩大感受野、融合多尺度局部信息，不要求固定输入尺寸。SPPF：把并行改成串行三次 $5\times5$ max-pool（步长 1），输出拼接；两个 5×5 池化的感受野等价于 9×9，三个等价于 13×13，结果等价但更快。

**English short answer**
> SPP applies max pooling with several kernel sizes in parallel and concatenates the results to enlarge the receptive field. SPPF gets the same result by chaining three five-by-five poolings, because stacking them equals larger kernels, and it's faster.

**追问方向**：为什么池化 stride=1？（保持尺寸便于 concat）

### Q34. FPN 与 PAN ★★★
**答案要点**
FPN：自顶向下，深层语义强的小特征图上采样后与浅层相加/拼接，使浅层获得语义。PAN（Path Aggregation）：在 FPN 之后再加一条自底向上路径，把浅层的精确定位信息传回深层，缩短低层到高层的信息路径。YOLOv5 Neck = FPN + PAN，三个尺度融合后输出。关系：FPN 传"语义"，PAN 传"位置细节"。

**English short answer**
> FPN passes strong semantic information from deep, low-resolution layers down to shallow, high-resolution layers. PAN adds a bottom-up path that sends precise localization details from shallow layers back up to the deep layers. YOLOv5 uses both so each scale has semantics and fine position.

**追问方向**：BiFPN 做了什么改进？（加权融合、双向跨尺度连接）

### Q35. YOLOv5 的 Head 与输出张量解码 ★★★
**答案要点**
每个尺度一个 $1\times1$ 卷积，输出 $A(5+C)$ 通道，reshape 为 $(B,A,H,W,5+C)$。解码：
1. 取 sigmoid 得 $x,y,w,h,obj,cls$ 的激活值；
2. $b_x=(2\sigma(t_x)-0.5+c_x)\times stride$；$b_w=(2\sigma(t_w))^2\times p_w$（$p_w$ 为该尺度 anchor 宽，像素）；
3. 分数 = obj × cls；阈值过滤后 NMS。
这套解码在 RKNN 部署中通常放到 CPU 后处理（模型导出时可去掉解码部分，只导出到 head 的卷积输出），原因是 NPU 对 sigmoid、复杂 reshape/NMS 的支持和量化精度较差。

**English short answer**
> Each scale ends with a one-by-one conv that outputs, for every anchor, the box offsets, objectness and class scores. At decode time I apply sigmoid, convert center and size with the YOLOv5 formulas and multiply by the stride, then score is objectness times class probability, followed by thresholding and NMS. For edge deployment, this decoding is often done on the CPU after the NPU outputs the raw feature maps.

**追问方向**：把解码放进模型一起量化有何风险？（sigmoid/乘法放大量化误差，坐标精度下降）

### Q36. YOLOv5 的 anchor 匹配（正样本分配）★★★
**答案要点**
不是 IoU 匹配，而是**宽高比匹配 + 多格扩充**：(1) 对每个真值框与每个 anchor 计算宽高比 $r=\max(w_{gt}/w_a,\,w_a/w_{gt})$、$\max(h_{gt}/h_a,h_a/h_{gt})$，若最大值小于阈值 `anchor_t`（默认 4.0），该 anchor 为候选；(2) 找出真值中心所在格子，并根据中心在格内的偏移，再选取相邻的 2 个格子（上/下/左/右中靠近的两个），共最多 3 个格子对应的该 anchor 都作为正样本。这样一个真值可对应多至 9 个正样本（3 anchor × 3 格），增加正样本数，加速收敛；这也是解码中心偏移范围扩到 $[-0.5,1.5]$ 的原因。

**English short answer**
> YOLOv5 doesn't match by IoU. For each ground-truth box and anchor it checks the width and height ratio against a threshold, four by default. Matching anchors become candidates, and the assignment is extended to the two neighboring grid cells closest to the box center, so one object can have up to nine positive samples. That increases the number of positives and speeds up convergence.

**追问方向**：为什么要扩充邻近格子？与解码公式的关系？

### Q37. YOLOv5 的损失函数 ★★★
**答案要点**
$$L=\lambda_{box}L_{CIoU}+\lambda_{obj}L_{obj}+\lambda_{cls}L_{cls}$$
- 框：正样本的 $1-CIoU$；
- 置信度：BCE（二元交叉熵）作用于所有位置，目标为预测框与真值的 IoU（正样本）或 0（负样本）；三个尺度的 obj 损失加权不同（如 P3:P4:P5 = 4:1:0.4，默认超参，可在 hyp 文件查看），小尺度（高分辨率）格子多权重高；
- 类别：BCE with logits（每类独立，支持多标签），仅正样本。
三个 $\lambda$ 在超参文件中，默认值随版本变化，面试讲结构即可。

**English short answer**
> The loss has three parts: a CIoU box loss for positive samples, a binary cross-entropy objectness loss over all locations with the IoU as soft target for positives, and a binary cross-entropy class loss for positives with independent sigmoids per class. The objectness loss is weighted differently across the three scales.

**追问方向**：为什么类别用 BCE 而非 softmax？

### Q38. Mosaic 数据增强 ★★★
**答案要点**
把 4 张训练图随机缩放、裁剪后拼成一张大图，同时合并标注。好处：(1) 一次看到 4 张图的上下文，增加目标背景多样性；(2) 多数目标尺度被缩小，增加小目标比例；(3) 等效增大 batch（BN 统计受益）。训练末期（最后若干 epoch）通常关闭 Mosaic（`close_mosaic`），让分布回到真实图像。其他：随机仿射（平移缩放旋转剪切）、HSV 颜色扰动、左右翻转、MixUp（可选）、Copy-Paste。

**English short answer**
> Mosaic stitches four training images into one after random scaling and cropping. It exposes the model to more varied contexts and more small objects per image, and it effectively enlarges the batch for batch norm. It's typically turned off for the last epochs so the model finishes on realistic images.

**追问方向**：Mosaic 为什么对 mAP 提升明显但可能损害大目标完整性？

### Q39. 自适应缩放（Letterbox）与预处理一致性 ★★★
**答案要点**
保持长宽比缩放到不超过目标尺寸，再用灰色（114）填充到目标大小（推理时填充到 32 的倍数以减少无效计算）。后处理需把框坐标反变换回原图：$x_{orig}=(x-pad_x)/scale$。部署的重大陷阱：训练、导出模型、板端预处理（颜色顺序 RGB/BGR、归一化到 0–1 或均值方差、letterbox）必须一致，否则精度悄悄下降。量化校准数据也必须经过同样预处理。

**English short answer**
> Letterbox resizes the image keeping its aspect ratio and pads the rest with gray. After inference, box coordinates have to be mapped back by subtracting the padding and dividing by the scale. In deployment the preprocessing on the device, including channel order and normalization, must exactly match training, and the quantization calibration images must be preprocessed the same way.

**追问方向**：为什么非正方形输入也能运行？（卷积网络对尺寸不敏感，需为 stride 倍数）

### Q40. AutoAnchor、EMA、超参进化 ★
**答案要点**
AutoAnchor：训练前计算当前 anchor 对数据集的最佳可能召回（BPR），低于阈值则用 k-means + 遗传算法重新生成。EMA：维护权重的指数滑动平均 $\theta_{ema}\leftarrow d\,\theta_{ema}+(1-d)\theta$，评估和导出用 EMA 权重，更平滑。超参进化：用遗传算法变异超参并以 fitness（如 $0.1\,mAP_{50}+0.9\,mAP_{50:95}$）选优。

**English short answer**
> AutoAnchor checks how well the anchors fit the dataset and re-clusters them if needed. The model keeps an exponential moving average of its weights, which is used for evaluation and export. YOLOv5 also supports evolutionary hyperparameter search.

**追问方向**：EMA 的衰减系数为何随迭代逐步升高？

### Q41. YOLOv5 各规模模型与速度-精度权衡 ★★
**答案要点**
n/s/m/l/x 通过 `depth_multiple` 与 `width_multiple` 缩放层数与通道。边缘设备优先 n/s。输入分辨率（320/416/640）对速度影响近似平方。选型依据：目标最小尺寸、延迟预算、NPU 内存。具体数值（参数量、FLOPs、COCO mAP）以官方发布为准，这里不背。P4 的做法是：模型取 s 档，输入分辨率 640×640（典型取值，教学示例，以实机为准），类别数为园艺场景下的少量类别（典型 3–6 类，如病斑、叶片发黄、正常植株等）；mAP 与板端延迟不给具体数字，只说明评估办法：同一验证集比较 FP32 与 INT8 的 mAP，在板端统计预处理、NPU 前向、后处理 NMS 三段耗时。

**English short answer**
> The n, s, m, l and x variants scale depth and channel width. For edge devices the nano or small models are the usual choice. Input resolution affects latency roughly quadratically. In my project we use the small model at a 640 by 640 input, which is a typical choice, and I would measure latency per stage: preprocessing, the NPU forward pass, and NMS.
>
> 中文：n/s/m/l/x 通过深度与宽度缩放；边缘端常用 n 或 s；输入分辨率对延迟近似平方影响。本项目取 s 档、640×640 输入（典型选择），延迟按预处理、NPU 前向、NMS 三段分别测。

**追问方向**：如何选择输入分辨率？（由最小目标像素数决定）

## 七、数据与训练：增强、小目标、不平衡

### Q42. 常见数据增强及其适用边界 ★★★
**答案要点**
几何：翻转（注意文字、左右有语义的目标不适用）、缩放、裁剪、旋转、仿射、透视；颜色：亮度/对比度/饱和度/色调（HSV）、灰度、噪声、模糊；混合：Mixup、CutMix、Mosaic、Copy-Paste；遮挡：Random Erasing/Cutout。原则：增强应模拟真实部署中的变化（光照、遮挡、视角），不应改变标签语义。检测增强需同步变换框并裁掉越界部分。园艺场景下光照变化、叶片遮挡、背景杂乱是重点（属于合理推断，不是项目实测）。

**English short answer**
> Geometric augmentations like flips, scaling and crops, color jitter, and mixing methods like mosaic, mixup and copy-paste. The rule is that augmentation should mimic variation you expect at deployment, like lighting and occlusion, without changing the label. For detection, boxes must be transformed together with the image.

**追问方向**：哪些增强会破坏标签？（过度裁剪使目标消失）

### Q43. 小目标检测的难点与对策 ★★★
**答案要点**
难点：像素少、下采样后特征丢失、IoU 对小偏移极敏感（几像素偏差即大幅降低 IoU）、anchor 匹配困难、标注噪声相对大。对策：提高输入分辨率；使用 P2 层（stride 4）或更浅层特征；FPN/PAN 强化多尺度融合；切片推理（SAHI：大图切成重叠小块分别检测再合并）；Mosaic/Copy-Paste 增加小目标；调整 anchor；使用对小目标友好的损失（如 NWD、归一化 Wasserstein 距离）；增大分辨率前评估延迟。

**English short answer**
> Small objects have few pixels, they lose features after downsampling, and IoU is very sensitive to tiny offsets. I can raise the input resolution, add a higher-resolution detection layer, use stronger feature fusion, run sliced inference on tiles, and increase small-object samples with augmentation. Each of these costs latency, so I weigh it against the budget.

**追问方向**：切片推理的重叠区域如何合并？

### Q44. 检测中的类别不平衡与难例 ★★
**答案要点**
类内：前景-背景不平衡（Focal Loss、OHEM、负样本比例控制）；类间：长尾（重采样、类别平衡损失、Copy-Paste 稀有类）。难例挖掘：用训练后的模型在训练集/新数据上找 FP/FN，加入再训练（主动学习/数据闭环）。

**English short answer**
> Foreground-background imbalance is handled with focal loss or hard example mining, and long-tailed classes with resampling, class-balanced losses or copy-paste. A practical loop is to run the model on new data, collect false positives and misses, label them, and retrain.

**追问方向**：OHEM 是什么？

### Q45. 标注质量与数据集划分 ★★
**答案要点**
标注一致性（框松紧、遮挡目标规则）直接影响 mAP 上限；用多人交叉检查、可视化抽检。划分时同一场景/同一时间段的连续帧不能跨集（防泄漏，见 [01_机器学习八股](./01_机器学习八股.md) Q54）；验证集要覆盖部署环境的光照与背景。加入"负样本图"（没有目标的背景图）降低误检。

**English short answer**
> Annotation consistency sets a ceiling on the metrics, so I spot-check labels visually. I keep consecutive frames from the same scene in the same split to avoid leakage, make sure validation covers deployment lighting and backgrounds, and include background-only images to reduce false positives.

**追问方向**：如何估计标注噪声的影响？

### Q46. 域差异：训练数据与真实部署场景 ★★
**答案要点**
公开数据集训练的模型到真实环境（光照、相机、背景）会掉点。应对：在目标场景采集并标注少量数据微调；增强模拟；测试时用目标场景验证集；持续监控置信度分布。边缘端相机的曝光、白平衡、镜头畸变与训练图差异不可忽视。

**English short answer**
> A model trained on public data usually drops when moved to a real camera and environment because of lighting, backgrounds and camera differences. The fix is to collect and label a modest amount of data from the target setting, fine-tune, and validate on it, then keep monitoring the confidence distribution.

**追问方向**：如何在没有标签的部署数据上发现退化？

### Q47. 多目标跟踪（MOT）简述 ★
**答案要点**
Tracking-by-detection：每帧检测，再跨帧关联。SORT：卡尔曼滤波预测框位置 + 匈牙利算法按 IoU 匹配；DeepSORT 加外观特征（ReID）；ByteTrack 同时利用低分框关联以减少遮挡丢失。与状态估计的联系见 [03_卡尔曼滤波与EKF](../../02_基础知识/05_状态估计/03_卡尔曼滤波与EKF.md)。

**English short answer**
> Tracking by detection runs a detector on each frame and associates boxes across frames. SORT predicts motion with a Kalman filter and matches with the Hungarian algorithm using IoU. DeepSORT adds appearance features, and ByteTrack also uses low-confidence detections to recover occluded objects.

**追问方向**：匈牙利算法解决什么问题？

## 八、分割、特征金字塔与其他任务

### Q48. 语义分割：FCN、U-Net、DeepLab ★★
**答案要点**
FCN：全卷积，去掉全连接，转置卷积上采样，输出逐像素类别。U-Net：对称编码器-解码器 + 跳连拼接，小数据医学图像强。DeepLab：空洞卷积（保持分辨率扩大感受野）+ ASPP（多空洞率并行）+（早期）CRF 后处理。损失：逐像素交叉熵、Dice、Focal；指标 mIoU。

**English short answer**
> FCN replaced fully connected layers with convolutions and upsamples to a per-pixel prediction. U-Net adds skip connections between encoder and decoder to recover details. DeepLab uses dilated convolutions and atrous spatial pyramid pooling to keep resolution and capture multi-scale context. The usual metric is mean IoU.

**追问方向**：为什么分割需要保持高分辨率特征？

### Q49. 实例分割：Mask R-CNN 与 YOLO-seg ★★
**答案要点**
Mask R-CNN = Faster R-CNN + 并行的掩码分支（每个 RoI 预测 $K$ 个 $m\times m$ 二值掩码，只对真实类别的那个计算损失，解耦分类与掩码）+ RoI Align。YOLACT/YOLOv5-seg：预测一组原型掩码（prototype）和每个实例的系数，线性组合后裁剪得到实例掩码，速度快。

**English short answer**
> Mask R-CNN adds a mask branch to Faster R-CNN that predicts a binary mask per class for each region, using RoI Align for precise alignment. YOLACT-style models are faster: they predict a set of prototype masks and per-instance coefficients and combine them linearly.

**追问方向**：Mask R-CNN 为什么用 sigmoid 而非 softmax 预测掩码？

### Q50. 特征金字塔思想的总结 ★★
**答案要点**
问题：目标尺度跨度大，单一尺度特征无法兼顾语义与分辨率。图像金字塔（慢）→特征金字塔（SSD 直接用各层，语义弱）→FPN（自顶向下融合）→PANet（加自底向上）→NAS-FPN/BiFPN（自动/加权双向）。思想：低层定位细、高层语义强，要让各层都兼得。

**English short answer**
> Objects appear at many scales, and low-level features have good resolution but weak semantics, while high-level ones are the opposite. Feature pyramids fuse them: FPN adds a top-down path, PAN adds a bottom-up path, and BiFPN fuses bidirectionally with learned weights.

**追问方向**：为什么 FPN 用 $1\times1$ 横向连接？（统一通道数）

### Q51. 单目深度、关键点、位姿估计（简述）★
**答案要点**
关键点/姿态：自顶向下（先检测人再回归关键点）与自底向上（热图+关联）；热图回归比坐标直接回归更稳。深度估计：单目的尺度歧义，需要先验或融合 IMU/激光；与机器人感知的衔接见 [04_模型量化与边缘部署_RKNN](../../02_基础知识/07_感知与机器学习/04_模型量化与边缘部署_RKNN.md)。

**English short answer**
> Keypoint estimation is usually done by predicting heatmaps, either per detected person top-down or all keypoints then grouping bottom-up. Monocular depth has a scale ambiguity, so in robotics we often combine it with other sensors.

**追问方向**：为什么热图比直接回归坐标好？

### Q52. 视觉 Transformer 在检测中的位置 ★
**答案要点**
ViT/Swin 作为骨干替代 CNN，DETR 系做端到端。代价：全局注意力 $O(N^2)$ 内存，边缘 NPU 对其支持差，因此 YOLO 类 CNN 仍是边缘主流。ViT 细节见 [04_Transformer与大模型八股](./04_Transformer与大模型八股.md)。

**English short answer**
> Vision Transformers can serve as backbones or in DETR-style heads, but attention is quadratic in token count and edge NPUs support it poorly, so CNN-based YOLO models remain the usual edge choice.

**追问方向**：Swin 的窗口注意力解决了什么？

## 九、如何讲 P4 的视觉部分（面试话术）

CV 里 P4 的视觉 bullet 只有一句：**"built a YOLOv5/RKNN INT8 inference chain on RK3588, converting camera frames into structured observations with confidence and timestamps."** 因此回答原则：先讲你做的链路，再用上面的原理题支撑；没有依据的指标不要说。

**可以直说的（有 CV 依据）**
1. 在 RK3588 上，用 RKNN 工具链把 YOLOv5 模型转成 INT8，做边缘推理；
2. 输出不是裸框，而是"结构化观测"：类别、置信度、时间戳，供下游 Agent/规则使用；
3. 视觉结果与环境状态、用户命令一起汇入系统状态（traceable）。

**项目细节的具体做法（CV 未写明的部分按典型做法陈述，数值为典型/教学示例，以实机为准）**
- 检测目标：植株状态类目标（如病斑、叶片发黄、正常叶片等，典型 3–6 类）；数据以现场拍摄为主、可辅以公开数据集，规模典型为数百到数千张，并对现场图像做标注后微调。
- 模型与量化：s 档、640×640 输入；量化校准集典型取 100–500 张，来自现场光照与背景下的代表性帧，并覆盖各类别。
- 精度与延迟：量化前后用同一验证集比较 FP32 与 INT8 的 mAP，典型掉点在 1–2 个点内为可接受；板端延迟按预处理、NPU 前向、NMS 三段统计。本文不给具体实测数字。
- 阈值与误检：置信度阈值从常用默认（0.25）出发，NMS 阈值从 0.45 出发，在验证集上按“宁可多提醒、由下游复核”的取向调整；误检通过连续多帧一致确认、低置信度交给规则或人工复核来处理。

**英文答法模板**
> "On the RK3588 I converted a YOLOv5 model to INT8 with the RKNN toolkit and wrapped it into an inference service. Each frame is turned into a structured observation, with the class, a confidence score and a timestamp, so the downstream agent can reason on it and a rule-based fast path can react to extreme cases. I don't have the exact latency number in front of me, but I can explain how I would measure it and what dominates it: the NPU forward pass, the CPU post-processing with NMS, and the image preprocessing."
>
> 中文：在 RK3588 上用 RKNN 工具把 YOLOv5 转成 INT8 并封装为推理服务，每帧输出带类别、置信度、时间戳的结构化观测；我记不清精确延迟，但可以说明怎么测、主要耗时来自哪里。

**常见追问与诚实回答思路**
- "为什么选 YOLOv5 而不是更新的版本？"：当时的生态成熟、导出到 RKNN 的流程稳定、算子被 NPU 支持（这是合理的工程理由；若你当时有别的原因以你的为准）。
- "INT8 掉了多少点？"：若没记录，则说明"我没有保留精确数字"并讲如何评估：同一验证集比较 FP32/INT8 的 mAP，并检查校准集的代表性。
- "置信度有什么用？"：下游用它决定是走规则快路径、还是交给 Agent、还是要求人工确认——与 [07_Agent与RAG八股](./07_Agent与RAG八股.md) 的"提案-校验-执行-反馈"链对应。

## 本章要点速记
1. 一阶段快、两阶段准；一阶段的瓶颈是前景背景不平衡，Focal Loss 解决。
2. IoU → GIoU（外接框）→ DIoU（中心距）→ CIoU（长宽比）；YOLOv5 用 CIoU。
3. NMS：按分降序，删与最高分框 IoU 超阈值者；变体 Soft-NMS、DIoU-NMS。
4. AP = PR 曲线面积；mAP@0.5:0.95 平均 10 个 IoU 阈值。
5. YOLOv5：CSPDarknet(C3) + SPPF + FPN/PAN + 3 尺度 Head；匹配用宽高比阈值 4.0 + 邻近格扩充。
6. YOLOv5 解码：中心 $(2\sigma-0.5)$，宽高 $(2\sigma)^2\times$ anchor，分数 = obj × cls。
7. Mosaic 拼 4 图增加小目标与上下文，末期关闭；letterbox 与预处理一致性是部署关键。
8. 小目标：提高分辨率、P2 层、切片推理、增加小目标样本。
9. P4 里只说有依据的：YOLOv5 + RKNN INT8 + 结构化观测（类别、置信度、时间戳）。
