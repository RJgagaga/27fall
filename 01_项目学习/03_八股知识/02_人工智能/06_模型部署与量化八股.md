## 一、部署全景与性能基础

### Q1. 一个模型从训练到边缘部署的完整流程 ★★★
**答案要点**
```text
训练框架 (PyTorch) 
  -> 导出 (ONNX, 固定输入尺寸, 去掉训练专用节点)
  -> 图优化 (onnx-simplifier: 常量折叠, 去冗余)
  -> 推理引擎转换 (RKNN / TensorRT / ONNX Runtime)
       + 量化 (INT8: 校准集 -> scale/zero-point)
  -> 板端运行时 (预处理 -> NPU 推理 -> 后处理)
  -> 精度与延迟验证 (与 PC 端 FP32 对齐; 板端 profile)
  -> 集成进系统 (线程/队列/时间戳/监控)
```
关键认识：部署不是"导出就完事"，要保证三件事：**数值一致性**（板端输出≈训练端）、**性能达标**（延迟/吞吐/功耗）、**工程可靠**（异常处理、版本管理、可监控）。

**English short answer**
> The flow is: train in PyTorch, export to ONNX with a fixed input shape, simplify the graph, convert and quantize with the vendor toolchain, run on the device with pre- and post-processing, and then verify both accuracy against the FP32 reference and latency on the actual hardware. The tricky parts are numerical consistency and the non-model parts of the pipeline.

**追问方向**：哪一步最容易出问题？（算子不支持、预处理不一致、量化掉点）

### Q2. 延迟、吞吐与 FLOPs 的区别 ★★★
**答案要点**
延迟（latency）：单个请求从输入到输出的时间，实时控制/交互关心；吞吐（throughput）：单位时间处理的样本数（FPS），批处理关心。两者可矛盾：增大 batch 提升吞吐但增加单请求延迟。FLOPs/MACs 是理论计算量，不等于实际延迟，因为实际速度还取决于访存、算子并行度、内核实现、数据搬运。基准测试：预热若干次、多次测量取中位数与 P95/P99（尾延迟）、固定频率与温度、分段计时（预处理/推理/后处理）。

**English short answer**
> Latency is the time for one request, throughput is how many samples are processed per second. Batching raises throughput but also latency. FLOPs are only a theoretical count; actual speed depends on memory access and kernel implementations, so I benchmark on the real device with warm-up and report median and tail latency.

**追问方向**：为什么要看 P99？（实时系统最坏情况）

### Q3. 计算受限与访存受限（Roofline 模型）★★★
**答案要点**
算术强度 $I=\dfrac{\text{FLOPs}}{\text{访存字节}}$。可达性能 $P=\min(P_{peak},\ I\cdot BW)$。当 $I<P_{peak}/BW$（拐点）时受带宽限制（memory-bound），否则受算力限制（compute-bound）。例：大卷积通常 compute-bound；逐元素算子、BN、激活、小 batch 的全连接、LLM decode 阶段是 memory-bound。优化方向因此不同：memory-bound → 算子融合、降低精度减少字节、提高复用；compute-bound → 用 Tensor Core/NPU、低精度。
示例（教学示例）：带宽 25 GB/s、峰值 6 TOPS 的设备，拐点 $=6\times10^{12}/25\times10^9=240$ ops/byte，多数轻量网络层的强度低于此，受带宽限制，这就是为什么量化到 INT8（字节减半或四分之一）常能显著提速。

**English short answer**
> Arithmetic intensity is the number of operations per byte moved. Attainable performance is the minimum of the peak compute and intensity times memory bandwidth. Layers with low intensity, like elementwise ops or batch norm, are memory-bound, so fusion and lower precision help; layers with high intensity are compute-bound.

**追问方向**：为什么 depthwise 卷积在 NPU 上"理论 FLOPs 少却不快"？

### Q4. 常见边缘推理硬件 ★★
**答案要点**
CPU（ARM，NEON 指令）、GPU（Mali/Adreno/Jetson）、NPU（RK3588 内置 NPU，厂商宣称约 6 TOPS 的 INT8 算力，该数字来自厂商宣传，未核对）、DSP、FPGA。NPU 优势：能效比高、擅长卷积/矩阵 INT8；限制：算子支持有限、动态形状差、自定义算子难、与 CPU 之间有数据搬运开销。

**English short answer**
> Edge inference can run on the CPU, GPU, or a dedicated NPU. NPUs give high energy efficiency for INT8 convolutions and matrix multiplications, but they support a limited set of operators, don't like dynamic shapes, and incur data transfer costs to and from the CPU.

**追问方向**：RK3588 上哪些部分跑 CPU？（预处理、解码、NMS 通常）

### Q5. 为什么 FP32 不适合边缘，要降低精度 ★★
**答案要点**
减小模型体积（INT8 为 FP32 的 1/4）、降低访存带宽与功耗、利用低精度硬件单元提速。代价：量化误差、精度下降、可能需要校准或重训练。

**English short answer**
> Lower precision shrinks the model, reduces memory traffic and power, and lets the hardware use faster integer units. The price is quantization error, which we manage with calibration or quantization-aware training.

**追问方向**：INT8 相对 FP32 理论上带来多少倍压缩？

### Q6. 性能分析方法（Profiling）★★
**答案要点**
分段计时（采集、预处理、推理、后处理、传输）；逐层耗时（引擎提供的 profiler：TensorRT 的 trtexec --dumpProfile，RKNN 的性能评估接口，名称和参数以厂商文档为准）；系统层面看 CPU/NPU 利用率、频率、温度（热降频）、内存带宽；排除首次推理的初始化开销。典型发现：端到端瓶颈常在预处理（缩放、色彩转换）和后处理（NMS）而非 NPU 推理。

**English short answer**
> I time each stage separately — capture, preprocessing, inference, postprocessing — and use the engine's per-layer profiler. I also monitor utilization and temperature, since thermal throttling can change results. Often the bottleneck is preprocessing or NMS on the CPU rather than the network itself.

**追问方向**：如何用硬件加速预处理？（RGA、GPU、NEON）

### Q7. 精度、速度、体积的权衡与选型 ★★
**答案要点**
先定约束（实时延迟预算、功耗、内存、精度底线），再在 Pareto 前沿选模型规模、输入分辨率、量化方案。迭代：基线 FP32 精度 → 量化后精度 → 板端实测速度；每次只改一个变量。

**English short answer**
> I start from the constraints — latency budget, power, memory and the minimum accuracy — and then choose model size, input resolution and quantization on the Pareto frontier, changing one factor at a time and measuring on the target device.

**追问方向**：延迟预算怎么定？（由控制/任务周期反推）

## 二、ONNX 与导出

### Q8. ONNX 是什么，为什么需要它 ★★★
**答案要点**
ONNX（Open Neural Network Exchange）是一种开放的计算图格式：节点（算子）、张量、属性、opset 版本。作用：作为训练框架与各种推理引擎（ONNX Runtime、TensorRT、RKNN 工具链、OpenVINO 等）之间的中间表示，避免 N×M 适配。导出（PyTorch）：`torch.onnx.export(model, dummy_input, path, opset_version=..., input_names, output_names, dynamic_axes=...)`，通过 tracing 记录实际执行的算子；控制流依赖数据时 tracing 会"固化"分支，需注意。

**English short answer**
> ONNX is an open graph format with operators, tensors and a versioned operator set. It's the common intermediate representation between training frameworks and inference engines, so each framework doesn't need a separate converter for each runtime. PyTorch export traces the model with a dummy input, so data-dependent control flow can get frozen.

**追问方向**：tracing 与 scripting 的区别？

### Q9. 导出时的常见问题 ★★★
**答案要点**
(1) 不支持的算子或 opset 太低；(2) 动态形状：多数 NPU 工具链要求固定输入尺寸，需指定静态 shape；(3) tracing 固化 Python 条件判断/循环；(4) 训练专用层（Dropout、BN 训练模式）需 `model.eval()`；(5) 后处理层是否一起导出（解码、NMS 多数不建议导出到 NPU 图）；(6) 数值一致性校验：用同一输入对比 PyTorch 与 ONNX Runtime 输出，`np.testing.assert_allclose`（容差如 1e-4）；(7) 复杂算子（如 Focus/切片、`Resize` 的 `coordinate_transformation_mode` 不同导致对不齐）。

**English short answer**
> Typical export issues are unsupported operators or opset mismatch, dynamic shapes that the NPU toolchain doesn't accept, Python control flow frozen by tracing, forgetting eval mode, and subtle differences like how resize computes coordinates. After export I always compare the ONNX Runtime output against PyTorch on the same inputs.

**追问方向**：为什么要把 NMS 留在图外？

### Q10. onnx-simplifier 与图优化 ★★
**答案要点**
常量折叠（预先算好只依赖常量的子图）、消除冗余的 Reshape/Transpose/Identity、融合相邻算子、合并 BN 到 Conv。简化后的图更易被后端识别与优化，也减少不支持的"碎算子"。

**English short answer**
> A simplifier folds constants, removes redundant reshape, transpose and identity nodes, and merges patterns like batch norm into the preceding conv. The simpler graph is easier for the backend to optimize and more likely to map onto supported ops.

**追问方向**：Focus 切片结构为什么常被替换？

### Q11. ONNX Runtime 与其他推理引擎对比 ★★
**答案要点**
ONNX Runtime：跨平台，多个执行后端（CPU、CUDA、TensorRT、NNAPI 等）；TensorRT：NVIDIA GPU 极致优化；OpenVINO：Intel；NCNN/MNN/TFLite：移动端；RKNN：瑞芯微 NPU；各厂商工具链。选择：目标硬件决定。

**English short answer**
> ONNX Runtime is a portable engine with multiple execution providers. TensorRT is the best on NVIDIA GPUs. Mobile frameworks like NCNN, MNN and TFLite target phones, and vendor toolchains like RKNN target specific NPUs. The target hardware usually decides.

**追问方向**：为什么不同引擎对同一 ONNX 的支持度不同？

### Q12. 数值一致性验证的方法 ★★★
**答案要点**
用相同预处理的输入，比较输出：余弦相似度、最大绝对误差、相对误差；逐层对比（把中间层设为输出）定位首个偏差层；检测结果层面比较框与置信度的偏差、mAP。阈值：FP16 转换相似度应 >0.999，INT8 常见 >0.99 作为经验参考（经验值，视任务而定）。

**English short answer**
> I run the same preprocessed input through both models and compare outputs with cosine similarity and maximum error. If they diverge, I expose intermediate layers as outputs to find the first layer where they drift. Finally I compare end-task metrics like mAP, because small tensor errors may or may not matter.

**追问方向**：为什么 cosine 相似度高也可能检测结果变差？

## 三、推理引擎：TensorRT 与 RKNN

### Q13. TensorRT 的主要优化 ★★★
**答案要点**
(1) 层融合与算子融合（Conv+BN+ReLU 融合为一个 kernel，减少访存与 kernel launch）；(2) 精度校准（FP16/INT8，INT8 用校准器统计激活范围）；(3) kernel 自动选择（对目标 GPU 在多种实现里 benchmark，选最快）；(4) 内存复用与张量并行；(5) 动态张量显存管理；(6) 构建 engine 时离线完成，运行时加载序列化 engine。engine 绑定 GPU 型号与 TensorRT 版本，换设备需重建。

**English short answer**
> TensorRT fuses layers such as conv, batch norm and activation into one kernel, selects the fastest kernel for the target GPU by benchmarking, supports FP16 and INT8 with calibration, and optimizes memory reuse. The optimized engine is built offline and is specific to the GPU and TensorRT version.

**追问方向**：为什么 engine 不能跨设备？

### Q14. RKNN 工具链的典型流程 ★★★
**答案要点**
RKNN（Rockchip NPU）以 rknn-toolkit2（PC 端转换/仿真）+ 板端运行时（RKNPU 运行时库，C API 或 Python Lite）组成。典型步骤（通用做法，函数细节以官方文档为准）：
1. 在 PC 上加载 ONNX；
2. 配置：目标平台（如 rk3588）、输入均值/方差（归一化参数需与训练一致）、量化类型；
3. 构建：若量化，提供**校准数据集**（一批代表性图片路径列表）；
4. 导出 `.rknn` 文件；
5. 可在 PC 上用模拟器推理或做精度分析（逐层余弦相似度）；
6. 拷贝到板端，用运行时加载，输入图像→推理→得到输出张量→CPU 后处理。
```python
# 教学示例，非项目源码（接口以官方文档为准）
from rknn.api import RKNN
rknn = RKNN()
rknn.config(mean_values=[[0,0,0]], std_values=[[255,255,255]], target_platform='rk3588')
rknn.load_onnx(model='yolov5s.onnx')
rknn.build(do_quantization=True, dataset='calib_list.txt')
rknn.export_rknn('yolov5s_int8.rknn')
```
本项目的做法是：使用与 RK3588 匹配的 RKNN-Toolkit2 在 PC 端转换，校准集典型取 100–500 张现场代表性图像（教学示例，以实机为准）；量化后先对比整体检测结果，出现明显掉点再做逐层精度分析定位敏感层。

**English short answer**
> With the RKNN toolkit, I load the ONNX model on the PC, configure the target platform and the normalization parameters, provide a calibration dataset for INT8 quantization, build and export an RKNN file. Then on the board, the runtime loads it, I feed preprocessed images, get raw output tensors, and do decoding and NMS on the CPU. It's important to check accuracy against the floating-point model before trusting the quantized one.

**追问方向**：mean/std 配置错了会怎样？（输入分布错位，精度静默下降）

### Q15. 为什么 NPU 对算子和量化方式有限制 ★★
**答案要点**
NPU 为固定功能流水线，仅实现常见算子的整数核（Conv、Pool、ReLU、Add、Concat、Resize 等）；不支持或低效的算子会回退到 CPU，导致 NPU↔CPU 数据拷贝与同步，反而变慢。应对：查支持算子表，修改网络（如 SiLU→ReLU/LeakyReLU 的替换需要重训或微调评估）、把不支持部分放后处理、导出时去掉。

**English short answer**
> NPUs implement a fixed set of operators in hardware. An unsupported operator falls back to the CPU, which adds data transfers and sync, sometimes making things slower overall. So I check the supported operator list, adjust the network or move those parts into CPU post-processing.

**追问方向**：如何发现回退到 CPU 的算子？（工具链日志/性能分析）

### Q16. 运行时的零拷贝与内存管理 ★★
**答案要点**
减少 CPU↔NPU 之间的拷贝：使用与 NPU 共享的 DMA 缓冲（dma-buf / 零拷贝输入）、预分配输入输出缓冲、复用内存池。图像采集→色彩转换/缩放（可用 RGA 硬件加速）→NPU 输入这一链路上做零拷贝能显著降低延迟。

**English short answer**
> To cut latency I avoid copies between CPU and NPU memory by using shared DMA buffers, preallocating and reusing input and output buffers, and doing resize and color conversion with a hardware 2D accelerator when available.

**追问方向**：为什么拷贝开销不能忽略？

### Q17. 多线程流水线与异步推理 ★★★
**答案要点**
串行：采集→预处理→推理→后处理，总延迟是和。流水线：各阶段并行处理不同帧，吞吐提升到最慢阶段的速率，但单帧端到端延迟不降反略升。设计要点：有界队列（防止堆积）、丢帧策略（实时系统宁可丢旧帧用最新帧）、时间戳随帧传递（保证观测可追溯）、线程绑定核心与优先级。对机器人：控制/决策用的观测要带时间戳，使下游知道数据新鲜度（对应 P4 的"带置信度与时间戳的结构化观测"）。

**English short answer**
> A pipeline lets capture, preprocessing, inference and postprocessing run concurrently on different frames, so throughput is bounded by the slowest stage, though per-frame latency doesn't improve. I use bounded queues and drop stale frames, and I carry the capture timestamp along with each frame so downstream consumers know how fresh the observation is.

**追问方向**：队列满了该丢旧帧还是新帧？

### Q18. 模型版本管理、升级与回滚 ★★
**答案要点**
模型文件带版本号、校验和、训练数据/配置记录；预处理参数与模型一起版本化；灰度升级与回滚；板端启动自检（加载、跑一张标准图并比对输出）；记录推理日志（置信度分布）以监控漂移。

**English short answer**
> I version the model file together with its preprocessing parameters and a checksum, support rollback, and run a self-test on startup, such as inferring a reference image and comparing the output. Logging the confidence distribution helps detect drift in the field.

**追问方向**：自检图的输出比对容差如何设？

### Q19. 容错与降级 ★★
**答案要点**
模型加载失败、推理超时、输出 NaN、相机掉帧：设置看门狗与超时；降级策略（回退到规则路径、使用上一次有效观测但标记过期、通知上层）。这与 P4 中"规则快速路径处理极端状态"、P6 的安全执行链思想一致：AI 模块失效时系统仍然安全。

**English short answer**
> I put timeouts and a watchdog around inference, validate outputs for NaN or implausible values, and define a degraded mode, such as falling back to rules or marking the last observation stale. The system must stay safe when the AI component fails.

**追问方向**：如何判断一个观测"过期"？

## 四、量化原理

### Q20. 线性量化公式与推导（Affine Quantization）★★★
**答案要点**
把浮点 $x\in[x_{min},x_{max}]$ 映射到整数 $q\in[q_{min},q_{max}]$（INT8 非对称：$[-128,127]$ 或 UINT8 $[0,255]$）：
$$q=\mathrm{clip}\Big(\mathrm{round}\big(\tfrac{x}{S}\big)+Z,\ q_{min},\ q_{max}\Big),\qquad \hat x=S\,(q-Z)$$
推导 $S,Z$：要求 $x_{min}\mapsto q_{min}$，$x_{max}\mapsto q_{max}$：
$$S=\frac{x_{max}-x_{min}}{q_{max}-q_{min}},\qquad Z=\mathrm{round}\Big(q_{min}-\frac{x_{min}}{S}\Big)$$
量化误差：舍入误差上界 $S/2$，均匀分布时方差 $S^2/12$（所以范围越大、位宽越小误差越大）。
手算（教学示例）：$x\in[-1.0,\,3.0]$，UINT8 $[0,255]$：$S=4/255\approx0.01569$，$Z=\mathrm{round}(0-(-1.0)/0.01569)=\mathrm{round}(63.75)=64$。量化 $x=1.0$：$q=\mathrm{round}(1.0/0.01569)+64=\mathrm{round}(63.75)+64=64+64=128$；反量化 $\hat x=0.01569\times(128-64)=1.004$，误差约 0.004。0 被精确表示：$q=Z=64$（保证 padding、ReLU 的 0 无误差）。

**English short answer**
> Affine quantization maps a float to an integer with a scale and a zero point: q is round of x over S plus Z, clipped to the integer range. The scale is the float range divided by the integer range, and the zero point makes sure zero is represented exactly. The rounding error is at most half a scale step, so a wider range or fewer bits means more error.

**追问方向**：为什么要让 0 精确可表示？

### Q21. 对称量化与非对称量化 ★★★
**答案要点**
对称：$Z=0$，$S=\dfrac{\max(|x_{min}|,|x_{max}|)}{q_{max}}$（INT8 常用 $q\in[-127,127]$）。计算简单：整数乘法无需处理零点交叉项；适合权重（分布近似对称）。非对称：有 $Z$，能更好利用位宽覆盖偏斜分布（如 ReLU 后的激活全为非负，对称会浪费一半范围）；计算上矩阵乘多出零点修正项。常见组合：权重对称（常逐通道）、激活非对称（逐张量）。

**English short answer**
> Symmetric quantization uses a zero point of zero and a range symmetric around zero, which simplifies the integer arithmetic and suits weights. Asymmetric quantization adds a zero point to cover skewed distributions like post-ReLU activations without wasting half the range, at the cost of extra correction terms.

**追问方向**：INT8 对称为什么用 $[-127,127]$ 而不是 $-128$？

### Q22. 逐张量与逐通道量化（Per-tensor vs Per-channel）★★★
**答案要点**
逐张量：整层权重共用一个 $(S,Z)$；逐通道：每个输出通道独立 $S_c$。不同通道权重范围可差几十倍（尤其是深度可分离卷积、BN 折叠后），逐张量会被大范围通道拖累，使小范围通道分辨率不足。逐通道对权重精度大幅改善，且不增加推理开销（因为 $S_c$ 可吸收进输出的 requantize 缩放）。激活通常逐张量（逐通道激活会使整数矩阵乘复杂）。

**English short answer**
> Per-tensor quantization uses one scale for the whole weight tensor, while per-channel uses one scale per output channel. Different channels can have very different ranges, especially after folding batch norm or in depthwise convs, so per-channel keeps precision for the small ones. Activations are usually per-tensor.

**追问方向**：为什么激活不好逐通道？

### Q23. INT8 矩阵乘与重量化（Requantization）★★★
**答案要点**
设 $x=S_x(q_x-Z_x)$，$w=S_w(q_w-Z_w)$，输出 $y=S_y(q_y-Z_y)$。则
$$q_y=Z_y+\frac{S_xS_w}{S_y}\sum_k(q_{x,k}-Z_x)(q_{w,k}-Z_w)$$
累加在 INT32 中完成（防止溢出：INT8×INT8 = 16 位，累加数百项需 32 位），再乘一个组合缩放 $M=\frac{S_xS_w}{S_y}$ 并取整回 INT8。$M$ 是浮点数，硬件上用定点乘法 + 移位实现：$M\approx M_0\cdot2^{-n}$，$M_0$ 为 32 位整数。偏置也量化到 INT32，scale 取 $S_xS_w$。整条链路尽量保持整数域，避免来回反量化。

**English short answer**
> An INT8 layer multiplies the quantized inputs and weights, accumulates in INT32 to avoid overflow, adds an INT32 bias, and then requantizes by multiplying with the combined scale of input scale times weight scale over output scale. On hardware that multiplier is a fixed-point integer and a shift, so no floating point is needed.

**追问方向**：为什么累加必须用 INT32？

### Q24. 量化范围的选取：Min-Max、百分位、熵（KL）校准 ★★★
**答案要点**
激活范围需要用校准数据统计：
- Min-Max：直接用最小最大值，简单，但被离群点拉大范围，使大部分值分辨率变差；
- 百分位（如 99.99%）：裁剪极端离群值，牺牲少量饱和换取更好分辨率；
- 熵/KL 散度校准（TensorRT 采用）：搜索使量化后分布与原分布 KL 散度最小的截断阈值；
- MSE 最小化阈值。
本质是**截断误差（饱和）与舍入误差之间的折中**：范围小→舍入误差小但饱和多；范围大→舍入误差大。

**English short answer**
> Activation ranges are estimated on a calibration set. Min-max is simple but sensitive to outliers. Percentile clipping or KL-divergence-based calibration choose a smaller clipping threshold, trading a little saturation error for much finer resolution on the bulk of values. It's a tradeoff between clipping error and rounding error.

**追问方向**：校准集需要多大？应该怎么选？（几百张具有代表性的真实部署场景图片即可，经验做法；覆盖光照/类别/背景）

### Q25. 校准数据集的选择 ★★★
**答案要点**
应来自真实部署分布（同相机、同光照、同预处理），覆盖各类别与典型/边缘场景；数量一般几十到几百（经验，视工具链）；不能用测试集（防泄漏）；与训练集独立采样但分布一致。校准集偏差大会使激活范围估计错误，造成部署后掉点。用无目标的背景图过多会让检测头的分布失真。

**English short answer**
> The calibration set should come from the real deployment distribution, with the same camera and preprocessing, and cover the classes and conditions you care about. A few hundred representative images are usually enough. It shouldn't be the test set, and a biased set leads to wrong ranges and accuracy loss after deployment.

**追问方向**：校准集里目标太少会怎样？

### Q26. 量化粒度与位宽：INT8、INT4、FP16、BF16 ★★
**答案要点**
FP16：通常几乎无损、无需校准，体积减半；INT8：4 倍压缩，需校准，CNN 通常掉点很小；INT4 及以下：多用于 LLM 权重量化，需要更精细的方法（GPTQ/AWQ）。位宽 $b$ 对应量化噪声约每减少 1 bit 信噪比下降约 6 dB（$\mathrm{SQNR}\approx6.02b+1.76$ dB 的均匀量化经验公式）。

**English short answer**
> FP16 is usually nearly lossless, INT8 gives four times compression and needs calibration, and 4-bit is mostly used for LLM weights with specialized methods. Each bit removed costs roughly six decibels of quantization signal-to-noise ratio.

**追问方向**：为什么 INT8 对 CNN 友好但对 LLM 激活较难？

### Q27. 哪些层对量化敏感 ★★
**答案要点**
检测头的回归与 objectness 输出（数值范围跨度大、直接影响坐标）、第一层与最后一层、含 Softmax/Sigmoid/LayerNorm 的层、范围差异巨大的残差相加（Add 两端 scale 不同）、SiLU/Swish 等非线性。处理：这些层保留 FP16/FP32（混合精度量化）、把解码部分移出图、对敏感层用逐通道或更精细的校准、做 QAT。

**English short answer**
> The most sensitive parts are usually the first and last layers, detection head outputs with wide ranges, residual additions between tensors of different scales, and nonlinear layers like sigmoid or softmax. I can keep those in higher precision, move the decode out of the quantized graph, or use quantization-aware training.

**追问方向**：如何找出敏感层？（逐层量化消融、逐层余弦相似度）

### Q28. BN 折叠（Batch Norm Folding）★★★
**答案要点**
推理时 BN 是逐通道仿射变换。Conv 输出 $y=Wx+b$，BN：$\gamma\frac{y-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta$。合并后：
$$W'=W\cdot\frac{\gamma}{\sqrt{\sigma^2+\epsilon}},\qquad b'=\frac{\gamma(b-\mu)}{\sqrt{\sigma^2+\epsilon}}+\beta$$
（对每个输出通道缩放 $W$）。好处：消除 BN 的运算与访存；对量化：折叠后权重逐通道范围差异增大，这正是需要逐通道量化的原因。QAT 时需在训练图里模拟折叠，使训练时的量化与部署一致。

**English short answer**
> At inference, batch norm is a per-channel scale and shift, so it can be folded into the previous convolution by scaling its weights and adjusting the bias. That removes the layer entirely. It also makes the weight ranges differ more between channels, so per-channel quantization is important afterwards.

**追问方向**：Conv 之后是 BN 再 ReLU，融合后如何继续融合 ReLU？（量化 clip 直接实现 ReLU）

### Q29. 算子融合（Operator Fusion）★★★
**答案要点**
把多个相邻算子合成一个 kernel：Conv+BN+ReLU、Conv+Add+ReLU、逐元素运算链。收益：减少中间结果写回/读取内存（memory-bound 层受益最大）、减少 kernel 启动开销。量化中的融合：ReLU/ReLU6 可合并进量化的 clip；融合后的中间值不再量化，精度更好。限制：融合模式取决于后端支持；融合后调试逐层输出困难（中间张量不存在）。

**English short answer**
> Operator fusion combines adjacent operators, such as conv, batch norm and ReLU, into a single kernel so that intermediate tensors don't have to be written to and read from memory. It reduces memory traffic and launch overhead. In quantization, it also avoids quantizing intermediate values, which helps accuracy.

**追问方向**：融合会影响你做逐层精度对比吗？

### Q30. 量化误差的来源分析 ★★
**答案要点**
舍入误差、截断（饱和）误差、不同层误差累积与放大（残差、Concat 的 scale 不匹配）、离群值导致范围过大、校准分布与真实分布不一致、BN 折叠后通道差异、对输出极敏感的头部。诊断工具：逐层 SQNR / 余弦相似度，找出首个明显劣化的层。

**English short answer**
> Quantization error comes from rounding, clipping, accumulation across layers, outliers that inflate the range, and calibration data that doesn't match deployment. I diagnose it by comparing every layer's output against the floating-point version and finding where the similarity first drops.

**追问方向**：Concat 两路输入 scale 不同怎么办？（需要重量化到统一 scale）

### Q31. 量化与激活函数：SiLU/Sigmoid 的难点 ★★
**答案要点**
Sigmoid/SiLU 输出受限且非线性强，查表（LUT）实现于 INT8 时有精度损失；ReLU 天然友好。对边缘端，常把 SiLU 换成 ReLU/LeakyReLU 重新微调，或让 NPU 用查找表近似。YOLOv5 默认 SiLU，官方 repo 也提供了导出时替换 SiLU 的选项（通常是为了导出兼容；细节以代码为准）。

**English short answer**
> Smooth nonlinearities like SiLU and sigmoid are harder to implement accurately in integer arithmetic, usually via lookup tables. ReLU is hardware friendly, so on some NPUs people replace SiLU with ReLU and fine-tune, after checking the accuracy trade-off.

**追问方向**：替换激活后为什么必须微调或重训？

## 五、PTQ、QAT 与精度排查

### Q32. PTQ 与 QAT 的区别 ★★★
**答案要点**
| 维度 | PTQ（训练后量化） | QAT（量化感知训练） |
|---|---|---|
| 是否重训 | 否，只需校准集 | 是，微调若干 epoch |
| 成本 | 低、快 | 高，需训练数据与流程 |
| 精度 | 一般够用，激进量化（INT4/敏感模型）会掉点 | 更高，接近 FP32 |
| 使用时机 | 先试 | PTQ 掉点过多时 |
QAT 在前向中插入"伪量化"节点（量化→反量化），让网络权重适应量化噪声。

**English short answer**
> Post-training quantization only needs a small calibration set and no retraining, so it's fast and I try it first. Quantization-aware training inserts fake-quantization nodes into the training graph and fine-tunes the model so it learns to be robust to quantization noise. I use it when PTQ loses too much accuracy.

**追问方向**：PTQ 掉点超过阈值怎么办？先排查再决定是否 QAT（见 Q36）

### Q33. QAT 与直通估计器（STE）★★★
**答案要点**
伪量化 $\hat x=S\cdot(\mathrm{clip}(\mathrm{round}(x/S)+Z)-Z)$ 中 $\mathrm{round}$ 的导数几乎处处为 0，梯度无法回传。STE（Straight-Through Estimator）：反向传播时把 round 当作恒等映射，即
$$\frac{\partial\hat x}{\partial x}\approx\begin{cases}1&x\in[x_{min},x_{max}]\\0&\text{其他（被截断）}\end{cases}$$
$S$ 也可作为可学习参数（LSQ）。QAT 流程：从训练好的 FP32 权重出发 → 插入伪量化（权重+激活）→ 小学习率微调 → 冻结 BN/观测器 → 导出量化模型。

**English short answer**
> Rounding has zero gradient almost everywhere, so QAT uses the straight-through estimator: in the backward pass we treat the rounding as identity within the clipping range and zero outside. The forward pass simulates quantization so the weights adapt to it, and we typically fine-tune from a pretrained FP32 model with a small learning rate.

**追问方向**：STE 为何能工作？它引入了什么偏差？

### Q34. 权重量化与激活量化的区别 ★★
**答案要点**
权重：静态已知，可直接用其范围，常逐通道对称；激活：依赖输入，必须校准统计范围（静态量化）或在运行时动态计算范围（动态量化，更灵活但有开销）。仅权重量化（weight-only）减少存储与带宽，LLM 常用；权重+激活都量化才能用整数矩阵乘硬件加速。

**English short answer**
> Weights are known ahead of time and can be quantized directly, often per channel. Activations depend on the input, so their ranges come from calibration for static quantization, or are computed at runtime for dynamic quantization. Weight-only quantization saves memory and bandwidth, but integer compute needs both quantized.

**追问方向**：动态量化与静态量化各适合什么硬件？

### Q35. 混合精度量化与逐层精度分配 ★★
**答案要点**
对敏感层保持 FP16，其余 INT8。工具链通常支持指定层的精度。权衡：每个回退到浮点的层可能触发 NPU 与 CPU 数据转换，要综合延迟评估。

**English short answer**
> I keep sensitive layers in higher precision and quantize the rest. I check that the extra precision conversions don't cost more in latency than they gain in accuracy.

**追问方向**：如何自动搜索混合精度配置？

### Q36. 量化后掉点的排查流程 ★★★
**答案要点**
1. 先确认**非量化链路**一致：PyTorch FP32 → ONNX → 工具链 FP16/FP32 模式在板端/模拟器上的输出一致（排除预处理、mean/std、通道顺序、letterbox、导出错误）；
2. 再开 INT8，用同一批图计算 mAP 差值；
3. 检查校准集：数量、代表性、预处理一致；
4. 逐层余弦相似度/误差分析，找首个劣化层；
5. 对问题层：改回高精度、逐通道、换校准算法（KL/百分位）、调整激活范围；
6. 仍不行：QAT 或修改网络（替换难量化的激活、拆分输出头）；
7. 看后处理：置信度阈值、NMS 阈值可能需随量化重新标定。
关键：先排除"不是量化的问题"，因为多数"量化掉点"其实是预处理或配置错误。

**English short answer**
> First I verify that the non-quantized pipeline matches the PyTorch reference, because most accuracy problems come from preprocessing or configuration mismatches. Then I enable INT8, check the calibration set, compare layer-by-layer similarity to find where the drop begins, and fix that layer through higher precision, a different calibration method or per-channel quantization. If that's not enough, I use quantization-aware training.

**追问方向**：板端结果与 PC 模拟器结果不一致可能是什么原因？（驱动/版本差异、数据排布、舍入模式）

### Q37. 量化对检测任务的特殊影响 ★★
**答案要点**
检测头同时输出坐标（大范围）与置信度（0–1）和类别，共用一个 tensor scale 时，小数值（置信度）精度不足。常见处理：把三个尺度的输出分别量化，或将回归/分类分支分开，或导出时把后处理前的各分支拆成独立输出张量，使每个分支有自己的 scale。置信度分数被量化后分辨率降低，NMS 排序与阈值边界会受影响。

**English short answer**
> A detection head outputs coordinates with wide ranges together with confidence scores between zero and one. If they share a single scale, the small values lose resolution. So I give each output branch its own tensor and scale, and re-check the confidence threshold after quantization, since quantized scores are coarser.

**追问方向**：为什么置信度阈值要在量化后重新标定？

### Q38. 动态范围与离群值（尤其是 Transformer/LLM）★★
**答案要点**
LLM/Transformer 激活中少数通道存在极大离群值（系统性离群通道），使逐张量激活量化严重失真。方法：LLM.int8()（离群通道用 FP16 单独处理）、SmoothQuant（把激活的量化难度通过数学等价变换迁移到权重：$Y=(X\,\mathrm{diag}(s)^{-1})(\mathrm{diag}(s)W)$）、AWQ（保护显著权重通道）、GPTQ（逐层基于二阶信息的误差补偿）。属于近年方法，面试说出思想即可。

**English short answer**
> Transformer activations often have a few channels with huge outliers, which break per-tensor activation quantization. Approaches include handling outlier channels in higher precision, SmoothQuant which moves the difficulty from activations to weights with an equivalent scaling, and weight-only methods like GPTQ and AWQ.

**追问方向**：SmoothQuant 的数学等价性是什么？

### Q39. 量化的评估：不仅看 mAP ★★
**答案要点**
同时看：任务指标（mAP、召回/精度在工作阈值下）、置信度分布变化、速度与功耗、不同光照与场景下的稳定性、极端样本表现。对机器人，漏检与误检的代价不对称，应分别评估。

**English short answer**
> I evaluate the quantized model on the task metric, but also at the operating threshold, on difficult conditions, and in terms of latency and power. For robots, missed detections and false alarms have different costs, so I look at both.

**追问方向**：如何设定工作阈值？

## 六、剪枝、蒸馏、轻量化

### Q40. 剪枝：非结构化与结构化 ★★★
**答案要点**
非结构化：把小幅值权重置零（幅值剪枝），稀疏度高但需要稀疏硬件/库才能加速，通用硬件上往往不快；结构化：整个滤波器/通道/注意力头移除，直接得到更小的稠密网络，任意硬件都加速。流程：训练 → 评估重要性（L1 范数、BN 的 $\gamma$ 系数（network slimming）、梯度/Taylor 近似）→ 剪掉 → 微调恢复 → 迭代。注意残差连接要求相加两端通道一致。彩票假说（lottery ticket）：稠密网络中存在可单独训练到相近精度的稀疏子网络。

**English short answer**
> Unstructured pruning zeroes individual small weights and gives high sparsity, but needs sparse support to speed up. Structured pruning removes whole channels or filters, producing a smaller dense network that runs faster on any hardware. The usual loop is rank importance, prune, fine-tune and repeat.

**追问方向**：用 BN 的 $\gamma$ 衡量通道重要性的依据？

### Q41. 知识蒸馏 ★★★
**答案要点**
教师（大模型）的软标签带有类间相似性的"暗知识"。损失
$$L=(1-\lambda)\,CE(y,\mathrm{softmax}(z_s))+\lambda T^2\,KL\big(\mathrm{softmax}(z_t/T)\,\|\,\mathrm{softmax}(z_s/T)\big)$$
$T$ 为温度（软化分布），$T^2$ 用来保持梯度量级。扩展：中间特征蒸馏（匹配隐藏层）、注意力蒸馏、检测中蒸馏回归框与分类 logits。学生可以是更小的同族模型（YOLOv5l→s）。

**English short answer**
> In knowledge distillation, a small student is trained to match the softened output distribution of a large teacher, in addition to the true labels. The temperature softens the teacher's probabilities so that the relative similarities between classes are visible. It's also possible to distill intermediate features.

**追问方向**：蒸馏与量化可否组合？（可，先蒸馏小模型再量化；也可 QAT 中加蒸馏损失）

### Q42. 轻量化网络设计 ★★
**答案要点**
MobileNet（深度可分离卷积）、ShuffleNet（分组卷积+通道洗牌）、GhostNet、EfficientNet、RepVGG（训练多分支、推理合并成单分支）。设计准则（ShuffleNetV2）：输入输出通道相等时访存最少、避免过度分组、减少碎片化算子、减少逐元素操作——说明 FLOPs 不是唯一指标，实际硬件上看延迟。

**English short answer**
> Lightweight networks use depthwise separable or grouped convolutions to cut parameters and FLOPs. Re-parameterization trains with multiple branches but merges them into one conv for inference. But FLOPs aren't the only metric: memory access and fragmentation matter on real hardware, so I always measure latency on the target device.

**追问方向**：为什么 depthwise 卷积在某些 NPU 上效率低？

### Q43. 低秩分解与神经架构搜索（NAS）★
**答案要点**
低秩分解：把大矩阵/卷积核分解为小因子乘积（SVD、Tucker），与 LoRA 思想相通。NAS：自动搜索结构，常以实测延迟为约束（hardware-aware NAS）。

**English short answer**
> Low-rank factorization replaces a large weight matrix with the product of smaller ones. Neural architecture search automatically finds architectures, often with measured latency on the target hardware as a constraint.

**追问方向**：与 LoRA 的关系？

### Q44. 压缩手段的组合顺序 ★★
**答案要点**
常见顺序：选更小的主干/蒸馏 → 结构化剪枝并微调 → 量化（PTQ 或 QAT）→ 引擎级优化（融合）。越靠后越与硬件相关。每步都要在目标设备上回归测试，避免多种压缩误差累积不可控。

**English short answer**
> A typical order is to pick or distill a smaller architecture, prune structurally and fine-tune, then quantize, then apply engine-level optimizations. I re-test accuracy and latency on the device after each step to keep errors under control.

**追问方向**：为什么量化放最后？

## 七、边缘端系统优化

### Q45. 输入分辨率、batch 与帧率的选择 ★★
**答案要点**
实时视觉通常 batch=1（降低延迟）；分辨率由最小目标像素数与算力决定，延迟近似随像素数线性/平方增长；降低帧率或隔帧检测+跟踪/插值可节省算力。园艺等慢变化场景，不需要高帧率，可定时抽帧推理以省电（这是合理的工程选择，非项目实测数据）。

**English short answer**
> For real-time vision I use batch size one, choose the input resolution based on the smallest object I need to detect, and adjust the frame rate to the application. For slowly changing scenes, like plants, it's enough to run inference periodically, which saves power.

**追问方向**：事件触发推理 vs 周期推理？

### Q46. 预处理优化 ★★
**答案要点**
颜色空间转换（YUV/NV12→RGB）、缩放、letterbox、归一化：用硬件 2D 加速器（如 Rockchip RGA）、NEON、或把归一化（mean/std）融合进模型第一层（工具链配置）以免在 CPU 上浮点运算。保持与训练预处理逐像素一致（插值方式也会影响）。

**English short answer**
> I move color conversion and resizing to hardware accelerators if available, fold the mean and std normalization into the model, and make sure the preprocessing matches training exactly, including the interpolation method.

**追问方向**：插值方式不一致为什么会掉点？

### Q47. 后处理优化：解码与 NMS ★★★
**答案要点**
先按置信度阈值过滤，大幅减少候选再 NMS；使用 C/C++ 或 NEON 实现；按类别分组；限制每类最大保留数；对 NPU 输出的量化整型张量，**先过滤再反量化**（只对通过阈值的候选反量化），可省大量浮点运算。

**English short answer**
> I filter by confidence first so NMS only sees a handful of candidates, implement it in C++, and when the NPU gives quantized integer output, I compare against a quantized threshold and dequantize only the surviving candidates, which saves a lot of floating-point work.

**追问方向**：量化阈值怎样换算？$q_{thr}=\mathrm{round}(thr/S)+Z$

### Q48. 热、功耗与稳定性 ★★
**答案要点**
持续满载会引起温度升高与降频，性能不稳；基准测试要在稳态温度下测；限制帧率、使用中等频率档位；监控温度，必要时降级。电源（压降）与外设（相机、泵）共用供电时需注意干扰与电压跌落，嵌入式系统中常见（见 [08_嵌入式与通信](../../02_基础知识/08_嵌入式与通信/06_OpenHarmony_Hi3861_RK3588平台基础.md)）。

**English short answer**
> Sustained load can heat the board and trigger throttling, so I benchmark at steady-state temperature and limit the frame rate where possible. I also keep an eye on power supply stability when other peripherals share the supply.

**追问方向**：如何在报告中说明性能数据的测试条件？

### Q49. 异构系统分工：MCU + SoC ★★
**答案要点**
RK3588 级应用处理器跑视觉/Agent，MCU（如 Hi3861）跑实时灌溉控制，通过串口/网络通信；安全原则：实时、安全相关闭环放在 MCU 本地，AI 只给建议或受约束请求，不直接控制执行器。对应 P4："Hi3861 pump state machine with independent start/stop thresholds and manual-priority override" 与 AI 决策分层。详见 [P4 README](../../01_项目课程/P4_OpenHarmony智能园艺系统/README.md)。

**English short answer**
> The vision and agent workloads run on the application processor, while the safety-relevant real-time loop, like the pump state machine, runs locally on a microcontroller. The AI side only issues recommendations or constrained requests, so a failure of the AI part can't cause unsafe actuation.

**追问方向**：如果网络断了，灌溉系统的行为是什么？（本地状态机继续按阈值运行，手动优先）

### Q50. 推理服务的可观测性 ★
**答案要点**
记录每帧时间戳、延迟分段、置信度统计、异常计数；可回放（保存少量原始帧与输出）；便于线下复盘与回归测试。

**English short answer**
> I log per-frame timestamps, stage latencies, confidence statistics and error counts, and keep a few raw frames so I can replay and debug issues offline.

**追问方向**：日志的开销如何控制？

## 八、如何讲 P4 的部署部分

**CV 原文**："built a YOLOv5/RKNN INT8 inference chain on RK3588, converting camera frames into structured observations with confidence and timestamps."

**讲述结构（60 秒版）**
1. 目标：在端侧本地跑视觉，不依赖云端；
2. 链路：相机帧 → 预处理 → YOLOv5（RKNN INT8，跑在 RK3588 NPU）→ 解码+NMS（CPU）→ 带类别、置信度、时间戳的结构化观测；
3. 为什么 INT8：缩小模型、降低访存、利用 NPU 的整数算力；
4. 精度保障：用 FP32 做参考，对比量化后输出；
5. 与系统衔接：观测进入系统状态，供 Agent 与规则路径使用。

**英文口述范本**
> "On the RK3588 I built the edge vision chain. A YOLOv5 model is converted to INT8 with the RKNN toolkit and runs on the NPU, and a small post-processing step on the CPU decodes boxes and applies NMS. The output isn't just boxes: each observation carries a class, a confidence and a timestamp, so the agent and the rule-based fast path can decide how much to trust it. I verified the quantized model against the floating-point one before relying on it."
>
> 中文：在 RK3588 上用 RKNN 把 YOLOv5 转成 INT8 跑在 NPU 上，CPU 做解码和 NMS；输出带类别、置信度、时间戳，供 Agent 与规则快路径使用；上线前与浮点模型对比验证。

> 中文补充：最后一句表示量化模型上线前与浮点模型做过对比验证，这是本项目的标准做法。

**具体做法（典型取值，教学示例，以实机为准）**
- 校准集：典型 100–500 张，取自现场相机、覆盖不同光照与类别。
- 量化前后精度：同一验证集比较 FP32 与 INT8 的 mAP，典型掉点在 1–2 个点内为可接受；不报具体实测数字。
- 推理频率：灌溉场景变化缓慢，采用定时推理（典型数秒一帧）加事件触发，而不是连续满帧；延迟按预处理、NPU 前向、NMS 三段统计。
- 典型问题与处理：预处理不一致（均值/方差、BGR/RGB、letterbox 与训练不同）是最常见原因，统一配置后解决；个别算子或激活函数在 NPU 上不支持或量化敏感时，替换为支持的算子或对该层保留更高精度；输出头对量化敏感时在 CPU 侧做解码。

**诚实回答模板**
> "I won't quote a precise accuracy figure, but the way we checked was to compare outputs against the floating-point model on a held-out set of images, looking at the detection results rather than only the raw tensors."
>
> 中文：我不报具体精度数字，我们的检查方式是在留出图像集上对比浮点模型的输出，看检测结果而不仅是原始张量。

## 本章要点速记
1. 流程：PyTorch → ONNX（静态 shape、eval）→ 简化 → 厂商工具链（RKNN/TensorRT）→ 板端运行时 → 数值与性能验证。
2. 线性量化：$q=\mathrm{round}(x/S)+Z$；$S=(x_{max}-x_{min})/(q_{max}-q_{min})$；0 必须精确可表示。
3. 对称用于权重（逐通道），非对称用于激活（逐张量）；INT8 乘法在 INT32 累加，再按 $S_xS_w/S_y$ 重量化。
4. 校准：Min-Max / 百分位 / KL 是饱和误差与舍入误差的折中；校准集要代表部署分布。
5. PTQ 先试，掉点再 QAT（STE 把 round 当恒等）；BN 折叠使逐通道范围差异增大。
6. 掉点排查：先排除预处理/配置错误 → 逐层相似度定位 → 敏感层高精度 → QAT。
7. FLOPs ≠ 延迟；用 roofline 判断计算/访存受限；融合与低精度对访存受限层收益大。
8. 检测头输出分支分开量化；先过滤再反量化；NMS/解码放 CPU。
9. 安全设计：AI 失效时有本地规则/状态机兜底，观测带时间戳。

## 自测题
1. 已知 $x\in[-2,6]$，INT8 非对称量化 $[-128,127]$，求 $S$ 与 $Z$，并量化 $x=0$。（$S=8/255\approx0.03137$，$Z=\mathrm{round}(-128+2/0.03137)=\mathrm{round}(-128+63.75)=-64$；$x=0\Rightarrow q=-64$。）
2. 为什么 INT8 矩阵乘要用 INT32 累加？（INT8×INT8 乘积为 16 位，$K$ 项求和会溢出。）
3. 写出 BN 折叠公式。
4. 为什么量化后掉点第一步应先检查预处理和 mean/std？
5. 比较结构化与非结构化剪枝在通用硬件上的加速差异。
