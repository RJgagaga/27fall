## 一、总体架构与分层

### Q1. 导航系统通常怎么分层？每层职责？（Navigation stack layers）★★★
**答案要点**
```text
  目标点 -> [全局规划器] -> 全局路径(几何, 低频, 全局地图)
                              |
                              v
        传感器 -> [代价地图] -> [局部规划器/轨迹优化] -> 局部轨迹(带时间, 中频)
                              |
                              v
                       [轨迹跟踪控制器] -> 速度/转角 -> [底盘执行]
         定位(EKF/AMCL) 提供 map->odom->base_link 状态
```
- 全局规划：在静态/已知地图上求一条可行的几何路径，关注**可达与长度**；
- 局部规划：在局部代价地图（含新障碍）内，依据全局路径做**避障与动力学可行**的轨迹；
- 跟踪控制：把轨迹变成执行器命令，闭环抑制误差；
- 为什么分层：计算量（全局大地图低频，局部小窗口高频）、模块化、可替换、故障隔离。
- 对应 P5：Hybrid-A*（全局）→ TEB（局部）→ MPC（跟踪），底层由 EKF/AMCL 提供状态。
**English short answer**
I split navigation into layers: a global planner finds a feasible path on the whole map at low frequency, a local planner or trajectory optimiser makes a time-parameterised, obstacle-aware trajectory in a local costmap, and a tracking controller turns it into commands. This keeps the heavy search at low rate and the reactive part fast. In my project it was Hybrid-A*, TEB and MPC on top of EKF and AMCL localisation.
**追问方向**：为何不一个规划器全做；各层频率；层间接口与不一致（全局路径与局部轨迹）。

### Q2. 路径（path）、轨迹（trajectory）、控制指令的区别？（Path vs trajectory）★★★
**答案要点**
- 路径：几何曲线 $\{(x,y,\theta)\}$，无时间；
- 轨迹：路径 + 时间/速度剖面 $\{(x,y,\theta,v,\kappa,t)\}$，满足动力学约束（速度、加速度、曲率）；
- 控制指令：当前时刻的 $(v,\delta)$ 或 $(v,\omega)$。
- TEB 输出"带时间的位姿序列"，因此是轨迹；Hybrid-A* 输出带航向的路径，需要速度规划。
**English short answer**
A path is geometry only, a trajectory adds time and speed so that acceleration and curvature limits can be checked, and a command is just the current velocity and steering. TEB gives a time-parameterised trajectory, while Hybrid-A* gives a path that still needs a speed profile.
**追问方向**：速度规划怎么做；曲率限速。

### Q3. 规划器的完备性、最优性、复杂度怎么谈？（Completeness, optimality）★★
**答案要点**
- 完备：存在解则一定找到（A*、Dijkstra 完备；RRT 概率完备；Hybrid-A* 在离散化上**不完备**，不保证最优）；
- 最优：A*（可采纳启发）最优；RRT* 渐近最优；Hybrid-A* 不保证最优（连续状态只保留每格一个节点）；
- 复杂度：A* 最坏 $O(b^d)$，栅格上 $O(N\log N)$ 量级。
**English short answer**
A* with an admissible heuristic is complete and optimal on a grid. RRT is probabilistically complete, and RRT* is asymptotically optimal. Hybrid-A* trades completeness and optimality for kinematic feasibility, because each grid cell keeps just one continuous state.
**追问方向**：Hybrid-A* 为何不最优；如何改善。

### Q4. 栅格分辨率与精度怎么权衡？（Resolution trade-off）★★
**答案要点**
- 越细越精确、越慢（节点数 $\propto1/r^2$）；
- 车辆足迹相对格子太粗会导致窄通道"假堵塞"；
- 做法：规划用较粗网格 + 精确足迹碰撞检测（圆盘组或多边形）；跟踪用连续轨迹。
**English short answer**
A finer grid is more accurate but the node count grows quadratically. I plan on a moderate grid with a precise footprint collision check, so narrow passages are not falsely blocked.
**追问方向**：膨胀半径取法。

## 二、图搜索与重规划

### Q5. Dijkstra 算法原理与复杂度？（Dijkstra）★★★
**答案要点**
- 单源最短路，边权非负。维护 `dist` 与优先队列（按 `dist` 最小弹出）；弹出节点即最终最短；松弛邻居 `dist[v]=min(dist[v],dist[u]+w)`；
- 复杂度：二叉堆 $O((V+E)\log V)$；
- 栅格地图：8 邻接，对角代价 $\sqrt2$；
- 无方向性，向所有方向均匀扩展，故比 A* 慢。
- 手算（教学示例）：A-B 2，A-C 5，B-C 1，B-D 4，C-D 1。从 A 出发：dist(B)=2，dist(C)=min(5,2+1)=3，dist(D)=min(2+4,3+1)=4。
**English short answer**
Dijkstra repeatedly pops the node with the smallest known distance from a priority queue and relaxes its neighbours, and it works for non-negative weights. With a binary heap the complexity is V plus E times log V. It expands uniformly in all directions, so A* is usually faster for a single goal.
**追问方向**：负权怎么办（Bellman-Ford）；优先队列实现。

### Q6. A* 与 Dijkstra 的区别？启发函数条件？（A* and heuristics）★★★
**答案要点**
- $f(n)=g(n)+h(n)$：$g$ 起点到 $n$ 的实际代价，$h$ 到目标的估计；
- **可采纳**（admissible）：$h(n)\le h^*(n)$（永不高估）→ 最优；
- **一致**（consistent）：$h(n)\le c(n,n')+h(n')$ → 每个节点只需扩展一次（不用重开 closed 节点）；
- 常用启发：欧氏距离（任意方向）、对角距离/八向距离（栅格）：$h=\max(dx,dy)+(\sqrt2-1)\min(dx,dy)$、曼哈顿（四邻接）；
- $h=0$ → Dijkstra；$h$ 过大（加权 A*，$f=g+\epsilon h$）→ 更快但次优（至多 $\epsilon$ 倍）。
- 打破平局（tie-breaking）：略微放大 $h$ 或按 $h$ 排序，避免在等价路径上搜太多。
**English short answer**
A* orders nodes by cost so far plus an estimate to the goal. If the heuristic never overestimates, the path is optimal, and if it is also consistent, each node is expanded at most once. A zero heuristic gives Dijkstra, and inflating the heuristic gives faster but suboptimal weighted A*.
**追问方向**：对角距离启发；加权 A* 的界；开集/闭集实现。

### Q7. A* 的路径为什么"贴边、折线"？怎么改善？（Path quality）★★
**答案要点**
- 栅格只允许离散方向，路径有锯齿；会紧贴障碍；
- 改善：后处理平滑（简化拐点、样条、梯度下降平滑）、代价地图膨胀 + 障碍代价（远离障碍）、Theta*（任意角度，视线检查）、JPS（跳点搜索，加速）。
**English short answer**
Grid search yields jagged paths hugging obstacles. I fix that with inflated obstacle costs so the path keeps its distance, plus smoothing, or use any-angle planners like Theta*.
**追问方向**：Theta* 的视线检查；平滑后碰撞复检。

### Q8. D* Lite / LPA* 为什么适合动态环境？（D* Lite）★★
**答案要点**
- 反向搜索（从目标到起点），保存每个节点的 $g$ 与一步前瞻 $rhs$；地图变化时只更新受影响节点，**增量重规划**，复用旧搜索结果；
- 机器人移动后起点改变，用 $k_m$ 修正优先队列键值；
- 适用：未知/动态障碍的栅格导航（火星车）。
- 在 ROS 导航中，常见做法是简单地"周期性全局重规划"，D* Lite 提供更高效的替代。
**English short answer**
D* Lite searches backward from the goal and stores for each node both its cost and a one-step lookahead value. When the map changes, only inconsistent nodes are updated, so replanning reuses most of the earlier work. It is useful for dynamic obstacle environments, though many stacks just replan periodically.
**追问方向**：LPA* 与 D* Lite 的关系；$k_m$ 的作用。

### Q9. 周期重规划会带来什么问题？（Replanning issues）★★★
**答案要点**
- 路径抖动：相邻两次规划选择不同"同代价"路径 → 车辆左右摇摆；
- 对策：前一路径加偏置/继承（给旧路径附近代价折扣）；设定重规划触发条件（路径被堵、偏离、到期）；平滑；
- 计算：重规划应在独立线程，超时有回退。
**English short answer**
Replanning every cycle can flip between nearly equal paths and make the robot weave. I trigger replans only when needed, bias the new search towards the previous path, and run the planner in a separate thread with a timeout.
**追问方向**：路径振荡调试；滞回。

### Q10. 全局路径无解时怎么办？（No path）★★
**答案要点**
- 原因：目标在障碍/膨胀区内、地图未知区域、窄通道小于车宽；
- 处理：检查目标可达性（吸附最近可行点）、允许穿越未知区域（Nav2 `allow_unknown`）、降低膨胀、报告失败并触发恢复/重规划。
**English short answer**
If there is no path, I first check whether the goal is inside an inflated obstacle or an unknown area. I may allow planning through unknown space or snap the goal to the nearest free cell, and otherwise report failure and start recovery.
**追问方向**：目标吸附策略。

### Q11. 代价函数怎么设计？（Cost design）★★
**答案要点**
- 综合：路径长度 + 靠近障碍惩罚 + 转弯/曲率惩罚 + 倒车惩罚 + 换向惩罚；
- 车辆：转向变化代价避免频繁打方向；
- 注意：代价项量纲与权重需联动调，不要某项压倒。
**English short answer**
I combine path length with penalties for being close to obstacles, for curvature, for steering changes, and for reversing or switching direction. The weights need to be tuned together so that no single term dominates.
**追问方向**：权重调参依据。

### Q12. 最优路径 vs 安全路径？（Shortest vs safe）★★
**答案要点**
- 最短路径常贴边；工程更重视安全裕度 → 在代价地图中加入距离障碍的代价曲线，路径在中间走；
- 速度也与障碍距离相关（靠近则慢）。
**English short answer**
The shortest path tends to hug walls, which is risky for a real vehicle. I add a smooth cost around obstacles so the planner prefers a path with clearance, and I also slow down near obstacles.
**追问方向**：膨胀衰减系数。

### Q13. 图搜索与优化类规划的区别？（Search vs optimisation）★★
**答案要点**
- 搜索：离散化、全局、不依赖初值，但解质量受离散限制；
- 优化：连续、局部、依赖初值，解平滑且满足动力学；
- 组合：搜索给初值（拓扑），优化精修（Hybrid-A* + 优化，或 A* 路径 + TEB）。
**English short answer**
Search methods are global and independent of the initial guess but limited by discretisation. Optimisation methods are continuous and smooth but need a good initial guess and can get stuck in local minima. So the common pattern is a search to pick the route and an optimiser to refine it.
**追问方向**：TEB 的局部最优问题。

## 三、采样规划

### Q14. PRM 是什么？（Probabilistic roadmap）★★
**答案要点**
- 学习阶段：随机采样配置，保留无碰撞点，与近邻（k 近邻/半径内）用局部规划器连边（边无碰撞）；查询阶段：把起点终点连入路网，图搜索；
- 适合多次查询、高维、静态环境；
- 缺点：窄通道难采到；非完整约束难连边。
**English short answer**
PRM samples collision-free configurations, connects nearby ones with collision-free edges to form a roadmap, and answers queries by graph search. It is good for repeated queries in static, high-dimensional spaces, but narrow passages are hard to hit.
**追问方向**：采样策略；桥测试。

### Q15. RRT 的流程？（RRT）★★★
**答案要点**
1. 随机采样 $x_{rand}$（以小概率偏向目标，goal bias）；
2. 找树中最近节点 $x_{near}$；
3. 向 $x_{rand}$ 延伸一个步长得 $x_{new}$；
4. 若路径无碰撞，加入树；
5. 到达目标邻域则回溯。
- 特点：单查询、快速探索、**概率完备**、路径不最优且不平滑；适合高维/复杂约束。
**English short answer**
RRT grows a tree by sampling a random point, finding the nearest tree node, stepping towards the sample, and adding the new node if the segment is collision-free. It explores quickly and is probabilistically complete, but the paths are jagged and not optimal.
**追问方向**：goal bias；步长；Voronoi 偏置。

### Q16. RRT* 如何做到渐近最优？（RRT*）★★★
**答案要点**
- 新增两步：① **选父节点**（Choose Parent）：在 $x_{new}$ 的邻域半径内选使 cost-to-come 最小的父节点；② **重连**（Rewire）：若经 $x_{new}$ 能降低邻域节点 cost，则改父节点；
- 邻域半径 $r\propto(\log n/n)^{1/d}$；
- 渐近最优，代价：计算更多，收敛慢；变体：Informed RRT*（在椭圆内采样）、RRT-Connect（双向）。
**English short answer**
RRT* adds two steps: when inserting a node it chooses the best parent within a neighbourhood, and then it rewires neighbours through the new node if that lowers their cost. The path cost converges to the optimum as samples grow. Informed RRT* speeds that up by sampling inside an ellipse once a solution exists.
**追问方向**：为何半径随 n 缩小；Informed 椭圆。

### Q17. RRT 对车辆的非完整约束怎么处理？（Kinodynamic RRT）★★
**答案要点**
- 用车辆模型前向仿真（sample control）代替直线连接；或用 Dubins/RS 曲线作为连接；
- 距离度量需考虑航向；
- 实际车辆多用 Hybrid-A* 或 lattice，而不是纯 RRT。
**English short answer**
For a car-like robot, I extend the tree by forward simulating the vehicle model or by joining states with Dubins or Reeds-Shepp curves, so each edge is drivable. In practice Hybrid-A* is simpler for this case.
**追问方向**：距离度量；状态格。

### Q18. 搜索类（A*）与采样类（RRT）怎么选？（A* vs RRT）★★★
| | A*/Hybrid-A* | RRT/RRT* |
|---|---|---|
| 空间 | 低维离散 | 高维连续 |
| 最优性 | 离散最优 | 渐近最优（RRT*） |
| 一致性 | 同输入同输出 | 随机，结果不同 |
| 动力学约束 | Hybrid-A* 可处理 | 需 kinodynamic |
| 典型 | 2D 导航、泊车 | 机械臂规划、高维 |

**English short answer**
For low-dimensional navigation with a vehicle, a deterministic search like Hybrid-A* is predictable and easy to debug. For high-dimensional spaces such as arm planning, sampling-based methods like RRT scale better.
**追问方向**：可复现性；超时。

### Q19. 机械臂规划（MoveIt）里用什么？（Arm planning）★
**答案要点**
- MoveIt 通过 OMPL 采样规划（RRTConnect、PRM*），后用 TOTG/时间参数化；也可用 CHOMP/STOMP/TrajOpt 轨迹优化；
- 笛卡尔直线走 `computeCartesianPath`。
**English short answer**
MoveIt uses sampling-based planners from OMPL, such as RRTConnect, and then time-parameterises the path. Trajectory optimisers like CHOMP are used to smooth. Cartesian straight lines use a dedicated function.
**追问方向**：时间参数化。

## 四、车辆约束规划

### Q20. 车式（阿克曼）机器人的运动学约束是什么？（Car-like kinematics）★★★
**答案要点**
- 自行车模型：$\dot x=v\cos\psi,\ \dot y=v\sin\psi,\ \dot\psi=\frac{v}{L}\tan\delta$；
- **非完整约束**：不能横向直接移动，$\dot x\sin\psi-\dot y\cos\psi=0$；
- 最小转弯半径 $R_{min}=L/\tan\delta_{max}$；曲率 $\kappa=\tan\delta/L\le\kappa_{max}$；
- 手算（教学示例）：轴距 $L=0.5$ m，$\delta_{max}=30^\circ$：$R_{min}=0.5/\tan30^\circ=0.866$ m。
- 与差速：差速可原地转，阿克曼不行，所以规划必须考虑航向与曲率连续。
**English short answer**
A car-like robot cannot slide sideways, so its motion is non-holonomic. The yaw rate is speed over wheelbase times tan of the steering angle, and the minimum turning radius is the wheelbase over tan of the maximum steering angle. That is why a planner for it must include heading and curvature, not just position.
**追问方向**：后轴中心与前轴中心参考点；曲率连续性（clothoid）。

### Q21. Hybrid-A* 的核心思想？（Hybrid A*）★★★
**答案要点**
- 在 A* 框架里使用**连续状态** $(x,y,\psi)$，但每个离散格（3D：$x,y,\psi$ 离散）只保留一个代价最低的状态，兼顾连续可行性与搜索效率；
- 节点扩展：对一组离散转向角 $\delta\in\{-\delta_{max},\ldots,0,\ldots,\delta_{max}\}$ 和前进/后退，用运动学模型积分一小段弧长（如格子对角线长度）得到新状态；
- 代价 $g$：弧长 + 倒车惩罚 + 转向惩罚 + 转向变化惩罚 + 换向惩罚（+ 障碍代价）；
- 启发函数：取两个启发的**最大值**：① 非完整无障碍（Reeds-Shepp 距离，忽略障碍）；② 完整有障碍（2D A* 到目标的栅格距离，忽略运动学）；二者均可采纳，取 max 仍可采纳且更紧；
- 解析扩展（analytic expansion）：每隔若干步，尝试用 Reeds-Shepp 曲线直接连接当前节点与目标，若无碰撞则直接结束；
- 后处理：路径平滑（共轭梯度）。
- CV 对应：*incorporated vehicle heading and kinematic constraints into the search and generated feasible global paths under vehicle-footprint, minimum-turning-radius and obstacle-cost constraints*。
- 本项目的做法（典型取值，教学示例，以实机为准）：位置栅格取与代价地图同量级（几厘米到十几厘米），航向离散为约 5°–10° 一档（72 档左右）；转向角在 $[-\delta_{max},\delta_{max}]$ 内离散为 3–5 个；扩展步长略大于栅格对角线；对倒车加较大惩罚（可关闭，只在必要时使用），并对换向和转向变化加惩罚；启发函数取 Reeds-Shepp 非完整无障碍距离与 2D A* 有障碍距离的最大值；每隔若干次扩展尝试一次解析扩展；规划耗时在地图规模适中时通常为几十到几百毫秒量级（典型，以实机为准）。
**English short answer**
Hybrid-A* runs A* on continuous vehicle states but keeps only one state per cell of a discretised x, y, heading grid. Each expansion forward simulates the bicycle model with a few steering angles, forward or reverse. The heuristic is the maximum of a non-holonomic cost without obstacles and a holonomic cost with obstacles, and it periodically tries a Reeds-Shepp curve to the goal. The result is drivable but not guaranteed optimal.
**追问方向**：为什么取两个启发的最大；解析扩展作用；航向离散粒度的影响。

### Q22. Dubins 与 Reeds-Shepp 曲线是什么？（Dubins vs Reeds-Shepp）★★★
**答案要点**
- 都是在**最小转弯半径**约束下连接两个带航向位姿的最短曲线；由圆弧（C）与直线（S）组成；
- Dubins：只能前进，6 种字（LSL、LSR、RSL、RSR、RLR、LRL）；
- Reeds-Shepp：允许倒车，48 种字（含换向），最优路径可能含"尖点"（cusp）；
- 解析、计算快，可作为启发或解析扩展；但不考虑障碍。
**English short answer**
Both are shortest paths between two poses for a car with a minimum turning radius, built from circular arcs and straight segments. Dubins allows only forward motion, and Reeds-Shepp also allows reversing, so it needs cusps. They are closed-form, which makes them good for heuristics and direct connections.
**追问方向**：Dubins 为何不一定存在于所有目标；cusp 对控制的影响。

### Q23. 为什么 Hybrid-A* 的启发要用两个？（Two heuristics）★★★
**答案要点**
- 仅非完整无障碍（RS 距离）：忽略障碍，遇到大障碍时被误导（陷入死胡同后大量扩展）；
- 仅完整有障碍（2D A*）：忽略车辆约束，在需要大转弯/倒车场景（泊车）低估严重；
- 取 max：既考虑障碍绕行又考虑转弯，仍可采纳。
**English short answer**
The non-holonomic heuristic knows about turning limits but ignores obstacles, while the holonomic-with-obstacles heuristic knows about walls but ignores turning. Taking the maximum keeps it admissible and is much more informative than either alone.
**追问方向**：预计算 2D 代价图；计算量。

### Q24. 车辆足迹碰撞检测怎么做？（Footprint collision checking）★★★
**答案要点**
- 用多个圆覆盖车身（圆盘组），每个圆查距离场/代价地图，速度快；或用旋转矩形采样栅格；
- 内切圆与外接圆：中心代价 ≥ 内切半径代价 → 一定碰撞；外接圆代价为 0 → 一定安全；中间需要精确检查（足迹多边形）；
- 倒车、转弯时车尾外扫（swept area）要考虑；
- 与 P5 对应：*vehicle-footprint* 约束。
**English short answer**
I approximate the vehicle by a few discs and query a distance field for each, or rasterise the rotated footprint on the grid. If the centre cost exceeds the inscribed radius it is a certain collision, and if it is below the circumscribed radius it is safe, and only in between do I check the exact footprint.
**追问方向**：圆盘数量；转弯时的扫掠区域。

### Q25. Hybrid-A* 路径为什么要平滑？怎么做？（Path smoothing）★★
**答案要点**
- 搜索得到的路径由离散弧段组成，航向/曲率有小跳变；
- 平滑：目标=曲率、路径长度、远离障碍、平滑度的组合，梯度下降/共轭梯度/QP 优化；约束：曲率上限、不碰障碍；
- 倒车换向点（cusp）处要分段处理，段间速度为 0。
**English short answer**
The raw path has small kinks from discrete expansions. I smooth it by minimising a mix of curvature, length and obstacle terms under a curvature limit, and I treat reversing cusps as segment boundaries where the speed goes to zero.
**追问方向**：曲率连续；平滑后复检。

### Q26. Hybrid-A* 在哪些场景失败？（Failure cases）★★
**答案要点**
- 分辨率太粗导致窄通道找不到；
- 目标朝向严格而不可达；
- 搜索节点爆炸（大地图、复杂障碍）→ 超时；
- 路径不最优带来多余绕行；
- 对策：分层（粗到细）、限制搜索域、增大步长、解析扩展提前终止。
**English short answer**
It can fail in tight passages if the grid is coarse, or time out in huge maps. I mitigate by restricting the search region, using larger steps with analytic expansion, and tuning resolution.
**追问方向**：超时回退。

### Q27. 倒车与换向对路径的影响？（Reversing and cusps）★
**答案要点**
- 提高窄空间通过性，但需要停车换向、控制器在尖点处速度符号变化；
- 倒车惩罚+换向惩罚避免无谓往返；
- 跟踪控制器（Pure Pursuit/Stanley）需要对倒车分别处理。
**English short answer**
Reversing helps in tight spaces, but each cusp needs a full stop and the tracking controller must handle the sign change of speed. I penalise reversing and direction changes so the planner uses them only when needed.
**追问方向**：倒车跟踪的符号处理。

## 五、代价地图

### Q28. 代价地图（costmap）分哪几层？（Costmap layers）★★★
**答案要点**
- ROS costmap_2d / Nav2 costmap：
  - 静态层（static layer）：来自 SLAM 地图；
  - 障碍层（obstacle/voxel layer）：来自 LiDAR/深度相机的实时观测，标记+清除（raytrace）；
  - 膨胀层（inflation layer）：按距离给代价衰减；
  - 其他：社交层、限速区、禁行区（keepout）。
- 全局代价地图：大范围，低频更新；局部代价地图：滚动窗口（rolling window），高频更新，以机器人为中心。
- 代价值：0 自由、1–252 递减、253 内切（inscribed）、254 致命、255 未知。
**English short answer**
A costmap typically has a static layer from the map, an obstacle layer from live sensor data with marking and clearing, and an inflation layer that spreads cost around obstacles. The global costmap covers the whole map at a low rate, and the local costmap is a rolling window around the robot at a higher rate.
**追问方向**：raytrace 清除；动态障碍残影。

### Q29. 膨胀层怎么工作？参数怎么选？（Inflation）★★★
**答案要点**
- 代价随到障碍距离 $d$ 指数衰减：$cost=252\cdot e^{-k(d-r_{inscribed})}$（$d>r_{inscribed}$），$k$=`cost_scaling_factor`；`inflation_radius` 为影响范围；
- `inflation_radius` 太小：路径贴墙；太大：窄通道不可通行；
- 内切半径=机器人内切圆半径；膨胀与足迹要一致。
**English short answer**
Inflation spreads an exponentially decaying cost out to an inflation radius around obstacles. If the radius or decay is too small the robot hugs walls, and if it is too large narrow doors become impassable. The inscribed radius must match the robot's footprint.
**追问方向**：门洞通过；非圆足迹。

### Q30. 动态障碍与残影问题怎么处理？（Ghost obstacles）★★
**答案要点**
- 原因：障碍层只标记不清除，或雷达盲区；
- 对策：raytrace 清除自由空间、`obstacle_persistence`、观测源 `clearing` 开启、`expected_update_rate` 超时失效；
- 动态障碍预测可用速度估计+预测轨迹。
**English short answer**
Ghost obstacles remain because cells are marked but not cleared. I enable raytracing to clear free space and set timeouts on the observation source. For moving people I can add a velocity prediction.
**追问方向**：雷达高度/安装对障碍层的影响。

### Q31. 未知空间怎么处理？（Unknown space）★
**答案要点**
- 未知=255（或 `track_unknown_space`）；是否允许穿越取决于参数（Nav2 `allow_unknown`）；
- 探索任务以未知-自由边界为 frontier。
**English short answer**
Unknown cells can be treated as obstacles or as traversable, depending on the task. Exploration uses the boundary between known free space and unknown, called frontiers, as goals.
**追问方向**：frontier 探索。

### Q32. 全局与局部代价地图不一致会怎样？（Global-local mismatch）★★
**答案要点**
- 全局路径穿过局部检测到的新障碍 → 局部规划器偏离/卡住；
- 对策：局部规划区域内触发全局重规划；统一膨胀半径与足迹。
**English short answer**
If the local map sees a new obstacle that the global map does not, the global path can lead the local planner into a dead end. I keep footprints consistent and let the local planner report failure so the global planner replans.
**追问方向**：重规划触发。

## 六、局部规划

### Q33. DWA 的原理？（Dynamic Window Approach）★★★
**答案要点**
- 在速度空间 $(v,\omega)$ 采样，限制在**动态窗口**内（受电机加减速能力限制）：$v\in[v_c-a_{v}\Delta t,\ v_c+a_v\Delta t]$ 与最大速度、可制动距离（$v\le\sqrt{2\,d_{obs}\,a_{brk}}$）的交集；
- 对每个采样用恒定速度前向仿真（短时域）得轨迹，按目标函数打分：
$$G=\alpha\cdot heading+\beta\cdot dist+\gamma\cdot vel$$
  （朝向目标、离障碍距离、前进速度）；选分最高的 $(v,\omega)$；
- 优点：简单、实时、天然满足速度/加速度约束；缺点：只考虑圆弧轨迹（$v,\omega$ 常值）；短视；局部极小；对**阿克曼车辆**不一定可行（需限制曲率）；参数多。
**English short answer**
DWA samples forward and angular velocity pairs within a dynamic window limited by acceleration, simulates each for a short time, and scores them by heading to the goal, obstacle clearance and speed. It is simple and real-time, but it is short-sighted, only considers constant-curvature arcs, and is awkward for car-like robots with a minimum turning radius.
**追问方向**：窗口怎么算；打分权重；局部极小。

### Q34. TEB 的原理？（Timed Elastic Band）★★★
**答案要点**
- 把路径表示成**一串带时间间隔的位姿** $Q=\{x_i\}$、$\tau=\{\Delta T_i\}$（"弹性带"），通过**稀疏非线性最小二乘（g2o）**同时优化位姿与时间：
$$\min_{B}\ \sum_k\gamma_kf_k(B),\quad B=(x_1\ldots x_n,\Delta T_1\ldots\Delta T_{n-1})$$
- 各目标/约束（以罚函数实现）：
  - 路径跟随/到达目标；
  - 避障（与障碍的距离 > 最小距离）；
  - 速度/加速度上下限（用相邻位姿与时间差分）；
  - 时间最优（最小化总时间）；
  - **非完整运动学**（相邻位姿在同一圆弧：$\ \Delta d$ 与航向变化的几何约束）；
  - 最小转弯半径（car-like：`min_turning_radius`）。
- 过程：每个周期用全局路径初始化/更新带子，自动**增删位姿**以保持时间分辨率（`dt_ref`、`dt_hysteresis`），优化后取第一段速度/转角输出；
- 优点：平滑、时间最优、考虑动力学与车辆约束，支持 car-like（`cmd_angle_instead_rotvel`）；缺点：只局部最优（拓扑固定）、参数多、计算较重；需要并行拓扑候选（homotopy class planning）。
- CV 对应：*optimised time-parameterised local trajectories under global-path and local-costmap constraints, outputting continuous pose and curvature references to the controller as local obstacles change*。
- 本项目的做法（典型取值，教学示例，以实机为准）：`min_turning_radius` 设为不小于车辆实际最小转弯半径并留少量余量；`dt_ref` 取 0.3 s 左右、`dt_hysteresis` 取其约 10%；`weight_kinematics_nh` 取较大值以保证非完整约束、`weight_obstacle` 与 `weight_viapoint` 之间折中；规划频率约 10–20 Hz；是否开启同伦类（HCP）按场景决定，狭窄场景开启并限制候选数量以控制耗时。常见的震荡/卡死表现为门口来回摆、选错绕行侧，对应调法是提高障碍权重与 `min_obstacle_dist`、开启 HCP、降低最大速度与加速度、检查代价地图残影。
**English short answer**
TEB represents the local plan as a sequence of poses with time intervals between them, and optimises both with a sparse nonlinear least-squares solver. The objective includes following the global path, keeping away from obstacles, velocity and acceleration limits, minimum time, and non-holonomic and turning-radius constraints. It gives smooth, time-parameterised trajectories for car-like robots, but only locally optimal ones, so it can get stuck on the wrong side of an obstacle.
**追问方向**：g2o 图；拓扑等价类；car-like 的约束怎么写；调参。

### Q35. TEB 的非完整约束怎么建？（TEB kinematic constraint）★★
**答案要点**
- 约束让相邻位姿 $x_i,x_{i+1}$ 位于**同一圆弧**：设位置差向量 $d$ 与两个航向 $\psi_i,\psi_{i+1}$，要求 $(\cos\psi_i+\cos\psi_{i+1})\,d_y-(\sin\psi_i+\sin\psi_{i+1})\,d_x=0$；
- 此外加最小转弯半径约束：$\rho_i=\frac{\|d_i\|}{2|\sin(\Delta\psi_i/2)|}\ge R_{min}$ 的罚函数（car-like）；
- 速度由 $v_i=\|d_i\|/\Delta T_i$ 符号由前进/后退方向确定。
**English short answer**
TEB makes consecutive poses lie on one circular arc by penalising the cross product between the heading directions and the displacement. For car-like robots it also penalises turning radii smaller than the minimum, and velocities come from distance over time difference.
**追问方向**：圆弧约束的几何；倒车。

### Q36. TEB 为何会局部最优？怎么处理？（TEB local minima）★★★
**答案要点**
- 带子拓扑固定（从障碍的哪一侧绕）；障碍表现为排斥势，无法穿越；
- HCP（Homotopy Class Planning）：生成多个不同拓扑的候选（左绕/右绕），并行优化后选最优，代价是计算；
- 配合全局规划器提供好初值；
- 常见现象：在窄门口来回、原地打转、选择较长一侧。
**English short answer**
The band keeps its topology, so TEB cannot jump from one side of an obstacle to the other. Homotopy class planning generates several candidates, such as passing left and right, optimises them in parallel and picks the best. A good global path also reduces the problem.
**追问方向**：candidate 数；计算时间。

### Q37. TEB 与 DWA 比较？（TEB vs DWA）★★★
| | DWA | TEB |
|---|---|---|
| 搜索空间 | 速度采样 $(v,\omega)$ | 轨迹优化（位姿+时间） |
| 时域 | 短，恒速圆弧 | 较长，任意形状 |
| 运动学 | 差速自然；阿克曼需改造 | 支持 car-like 最小转弯半径 |
| 平滑性 | 一般 | 好 |
| 计算 | 低 | 中高 |
| 局部极小 | 有 | 有（HCP 缓解） |

**English short answer**
DWA picks the best constant velocity pair by sampling, so it is light but short-sighted. TEB optimises a whole trajectory including time, so it is smoother and supports car-like constraints, but costs more compute and has its own local-minimum issues. For a car-like robot, I chose TEB.
**追问方向**：为什么选 TEB 不选 DWA（答：阿克曼最小转弯半径与平滑性）。

### Q38. MPC 作为局部规划/跟踪有什么优势？（MPC for local planning）★★★
**答案要点**
- 显式处理速度/转角/转角速率约束；预测未来 N 步；代价函数可加入跟踪误差、平滑、避障（软约束或线性化半平面）；
- 与 TEB 的分工：TEB 负责给出避障的时间参数化参考轨迹（局部规划），MPC 负责**精确跟踪**并满足车辆执行器约束（P5："closing the loop from planned trajectory to vehicle motion on the real vehicle"）；
- 详见 [02 控制八股](./02_控制八股.md) Q27–Q32。
**English short answer**
MPC handles speed, steering and steering-rate limits explicitly and looks ahead along the reference. In my navigation stack, TEB produced an obstacle-aware time-parameterised trajectory, and MPC tracked it precisely within the actuator limits.
**追问方向**：两层是否冗余；MPC 里的避障；延迟。

### Q39. 局部规划器与跟踪控制器的接口应该是什么？（Interface between local planner and tracker）★★
**答案要点**
- 接口：带时间戳的参考轨迹点（位姿、速度、曲率）；控制器按当前时刻插值参考；
- 参考与状态必须在同一坐标系（odom）、同一时间基准；
- 轨迹刷新频率、过期检测（轨迹太旧→减速停车）。
**English short answer**
The local planner hands the controller a time-stamped sequence of poses, velocities and curvatures in the odom frame. The controller interpolates at the current time. If the trajectory is stale, it slows and stops.
**追问方向**：时间戳对齐；轨迹切换平滑。

### Q40. 速度规划与曲率限速怎么做？（Speed profile）★★
**答案要点**
- 横向加速度约束 $a_y=v^2\kappa\le a_{y,\max}$ → $v\le\sqrt{a_{y,\max}/\kappa}$；
- 纵向加减速：前向—后向扫描，保证 $v_{i+1}^2\le v_i^2+2a\,\Delta s$ 与 $v_i^2\le v_{i+1}^2+2d\,\Delta s$；
- 终点和尖点速度为 0。
- 例（教学示例）：$a_{y,\max}=1.0$ m/s²，半径 2 m（$\kappa=0.5$）：$v\le\sqrt{1/0.5}=1.41$ m/s。
**English short answer**
I cap speed by curvature using lateral acceleration, v less than the square root of the lateral limit over curvature, then run forward and backward passes to respect acceleration and deceleration limits. Speeds at the goal and at reversing cusps are zero.
**追问方向**：S 曲线；与障碍距离相关限速。

### Q41. 本地规划的局部极小和震荡如何排查？（Debugging local planner oscillation）★★★
**答案要点**
- 排查顺序：① 全局路径是否合理、是否在抖；② 局部代价地图是否有残影/噪声障碍；③ 定位是否跳变（map→odom）；④ 局部规划器权重（避障 vs 路径跟随）；⑤ 速度/加速度限制是否与底盘匹配；⑥ 控制延迟；
- 现象：门口来回摆、原地旋转、突然停下；
- 工具：可视化全局/局部路径、代价地图、TEB 的候选轨迹。
**English short answer**
I check in order: is the global path stable, does the local costmap contain noise or ghosts, is the localisation jumping, are the planner weights balanced, and do the speed limits match the real base. Visualising the paths and costmaps usually shows the cause quickly.
**追问方向**：典型案例（我们的排查方式）：车辆转弯后路径突然抖动，先看全局路径稳定，再看局部代价地图无残影，最后发现 map→odom 因 IMU、编码器与激光时间戳不一致而出现位姿跳变；统一时间戳与坐标系后恢复平滑。

### Q42. 为何局部规划要用 odom 坐标系？（Why plan in odom）★★
**答案要点**
- `map` 系下定位会跳变，局部规划/控制若用 `map` 位姿会让参考与状态瞬间错位；`odom` 系连续（见 [03 八股 Q30](./03_状态估计与SLAM八股.md)）。
**English short answer**
The map frame can jump when localisation corrects itself, which would make the reference and state suddenly inconsistent. The odom frame is continuous, so local planning and control are done there.
**追问方向**：全局路径如何转换到 odom。

## 七、轨迹跟踪

### Q43. Pure Pursuit 怎么工作？（Pure Pursuit）★★★
**答案要点**
- 在路径上找距离后轴 $L_d$（前视距离）的目标点，使车辆沿一段圆弧到达该点：
$$\delta=\arctan\!\left(\frac{2L\sin\alpha}{L_d}\right),\quad\kappa=\frac{2\sin\alpha}{L_d}$$
  $\alpha$ 是车体航向到前视点方向的夹角，$L$ 轴距。
- 前视距离 $L_d=k\,v+L_{min}$ 随速度增大；
- 推导：圆弧过后轴原点、与车体方向相切，到点 $(x_g,y_g)$ 的曲率为 $\kappa=2y_g/L_d^2$，其中 $y_g=L_d\sin\alpha$。
- 优点：简单、稳健；缺点：转弯时内切（cut corner）、$L_d$ 大时跟踪误差大、小时易振荡；不使用速度/横向误差的动态信息。
- 数值（教学示例）：$L=0.5$ m，$L_d=1.0$ m，$\alpha=20^\circ$：$\delta=\arctan(2\cdot0.5\cdot0.342/1.0)=\arctan(0.342)=18.9^\circ$。
**English short answer**
Pure Pursuit picks a look-ahead point on the path at a distance L_d ahead and steers along the circular arc that reaches it. The steering is arctangent of two times wheelbase times sine of the angle to the point, over L_d. A larger look-ahead is smoother but cuts corners, and a smaller one tracks closely but can oscillate.
**追问方向**：前视距离选取；弯道内切；倒车。

### Q44. Stanley 控制器？（Stanley）★★★
**答案要点**
- 以**前轴**为参考，转向角 = 航向误差 + 横向误差修正：
$$\delta=\psi_e+\arctan\!\left(\frac{k\,e_{ct}}{v}\right)$$
  $\psi_e$ 路径切线与车体航向差，$e_{ct}$ 前轴到最近路径点的横向偏差，$k$ 增益；低速加 $\epsilon$ 防除零：$\arctan(ke/(v+\epsilon))$。
- 性质：横向误差在直线情况下指数收敛（线性化 $\dot e=-\frac{k}{...}e$）；
- 缺点：路径曲率变化大/不连续时不平滑；对定位噪声敏感；低速调整。
**English short answer**
Stanley steers by the heading error plus an arctangent term of the cross-track error scaled by the speed. It references the front axle, converges exponentially to a straight path, and is sensitive to path discontinuities and noise. I add a small constant to the speed to avoid division by zero.
**追问方向**：收敛性；增益 $k$ 的选择；与 Pure Pursuit 比较。

### Q45. Pure Pursuit、Stanley、MPC 如何选？（Comparison）★★★
| | Pure Pursuit | Stanley | MPC |
|---|---|---|---|
| 参考点 | 后轴，前视点 | 前轴，最近点 | 参考轨迹窗口 |
| 模型 | 几何 | 几何/运动学 | 运动学（可动力学） |
| 约束 | 无 | 无 | 显式 |
| 速度适应 | 前视随速 | 反比速度 | 模型含速度 |
| 计算 | 极小 | 极小 | 高 |
| 适合 | 低速、简单路径 | 中高速、直线跟踪好 | 约束严格、需精度 |

**English short answer**
Pure Pursuit and Stanley are geometric and cheap, so they are great baselines. MPC costs more but handles constraints and uses preview of the reference, so it tracks better at curves. I chose MPC because I needed to respect the speed and steering limits on the real vehicle.
**追问方向**：为什么实车选择 MPC；与前两者的对比是方法层面的：Pure Pursuit 与 Stanley 在低速直线上够用，但无法显式处理速度与转向约束，所以实车最终用 MPC 闭环，这是基于原理的选择，而非逐项实测排名。

### Q46. 纵向和横向为什么可以解耦？（Longitudinal–lateral decoupling）★★★
**答案要点**
- 低速、小侧偏时，转向主要影响横向/航向，驱动/制动主要影响速度；运动学模型的耦合通过 $v$ 出现在横向方程里；
- 做法：横向控制器（PP/Stanley/MPC）输出转角，纵向控制器（速度 PID/PI + 前馈）跟踪速度剖面；速度由规划提供并受曲率限速；
- 局限：高速/大侧偏/大曲率时两者耦合（轮胎饱和，需耦合 MPC）；
- 实车：转弯时减速保证横向跟踪。
**English short answer**
At low speed I can treat steering and speed separately: a lateral controller sets the steering to follow the path, and a longitudinal controller tracks the speed profile, with the speed reduced in curves. At high speed or near tyre limits they are coupled and a joint controller is better.
**追问方向**：耦合表现；速度对横向增益的影响。

### Q47. 误差如何定义（横向、航向）？（Tracking error definitions）★★
**答案要点**
- 找路径上最近点（或按弧长投影）；横向误差 $e_y$ 在路径法向；航向误差 $e_\psi=\psi-\psi_{path}$ 并 wrap 到 $[-\pi,\pi]$；
- 最近点搜索要保持单调（避免跳回前段路径）；闭合/自交路径要用索引窗口；
- 倒车时车头方向与行驶方向反，误差定义需翻转。
**English short answer**
I project the vehicle onto the path to get the cross-track and heading errors, wrapping the angle difference. The closest-point search must be monotonic so it doesn't jump back on self-crossing paths, and reversing needs the error definition flipped.
**追问方向**：自交路径；起点附近。

### Q48. 跟踪时车辆出现"蛇行"怎么办？（Snaking）★★
**答案要点**
- 原因：前视距离太小、增益太大、转向延迟、定位噪声、转角量化；
- 对策：增大前视/减小增益；对转角限速和低通；补偿执行器延迟（预测状态）；
- 与 MPC：加转角变化率惩罚 $R_\Delta$。
**English short answer**
Snaking comes from a too-small look-ahead, too high gain, steering delay or noisy localisation. I increase the look-ahead or reduce gain, rate-limit the steering, compensate the delay by predicting the state, and in MPC penalise the steering rate.
**追问方向**：延迟测量。

### Q49. 横向控制器中延迟补偿怎么做？（Delay compensation）★★
**答案要点**
- 总延迟 = 感知 + 计算 + 通信 + 执行器；用车辆模型把状态向前预测 $\tau_d$：$\hat x(t+\tau_d)=x+f(x,u)\tau_d$，在预测状态上求控制；或把延迟加进 MPC 模型（状态扩展）。
- 需要测量延迟（时间戳/示波器）。
**English short answer**
I predict the vehicle state forward by the total latency using the model, and compute the control from the predicted state. In MPC, I can also augment the model with the delayed inputs. First I need to measure the latency.
**追问方向**：如何测。

### Q50. 到达目标的判定与停车？（Goal reaching and stopping）★★
**答案要点**
- 位置容差 $\epsilon_{xy}$、航向容差 $\epsilon_\psi$、速度接近 0；防止振荡到达（goal latch）；
- 停车：减速剖面 + 终点速度 0；差速可原地调头，阿克曼需要提前规划终点航向。
**English short answer**
I use tolerances on position, heading and speed, and latch the goal once reached to avoid dithering. For a car-like robot the final heading must be planned in advance since it cannot rotate in place.
**追问方向**：容差设定；到达后抖动。

## 八、恢复行为与工程问题

### Q51. 恢复行为（recovery behaviours）有哪些？（Recoveries）★★★
**答案要点**
- ROS move_base：清除代价地图 → 原地旋转（rotate recovery）→ 更激进清除 → 再旋转 → 放弃；Nav2：行为树（BT）里 `Spin`、`BackUp`、`Wait`、`ClearCostmap`、重规划；
- 车式机器人不能原地转：用 `BackUp`、重规划、换方向；
- 触发条件：局部规划失败、路径被阻塞、进展停滞（progress checker）、卡住（stuck detector）。
**English short answer**
Typical recoveries are clearing the costmaps, spinning in place, backing up, waiting, and replanning. For a car-like robot, spinning is not possible, so I use backing up and replanning. They are triggered by planner failure or by a progress checker that sees no movement.
**追问方向**：行为树；防止无限恢复。

### Q52. 机器人"卡死/震荡/撞墙"怎么系统排查？（Debug checklist）★★★
**答案要点**
1. 定位：`map→odom` 是否跳变、协方差；
2. 传感器：LiDAR 是否被遮挡、频率、时间戳；
3. 代价地图：膨胀、足迹、残影；
4. 规划：全局路径是否合理，规划频率，局部规划器是否报错；
5. 控制：命令是否被限幅、延迟、执行器是否响应；
6. 底层：电机方向、里程计符号、速度反馈。
- 用 rosbag/rviz 回放，隔离每层：先开环，再闭环。
**English short answer**
I debug layer by layer: localisation stability, sensor data and timestamps, costmaps, global path, local planner output, controller commands, and finally the actuators and odometry signs. Recording a bag and replaying it lets me isolate each layer.
**追问方向**：用什么工具；一次真实案例。

### Q53. 导航里的速度/加速度限制应该放在哪里？（Where to limit）★★
**答案要点**
- 规划层（轨迹满足动力学）；控制层（限幅/限速率）；底层（硬限制/故障保护）；三层互补，不能只靠一层；
- 限制值要与真实底盘能力一致，否则规划轨迹不可跟踪。
**English short answer**
I limit speeds and accelerations at the planner, the controller and the base, with the base as the hard safety layer. The planner limits must match what the base can really do, otherwise the trajectory is not trackable.
**追问方向**：不一致的后果。

### Q54. 全局路径与实际道路不一致（定位偏差）怎么办？（Localisation error vs map）★★
**答案要点**
- 定位偏差 → 车辆实际位置偏离，路径看似"穿墙"；根因通常在定位；监控协方差，不确定度大时减速或原地重定位。
**English short answer**
If the localisation is off, the path appears to cut through walls. I monitor the pose covariance and slow down or relocalise when it is large, since the root cause is nearly always the localisation.
**追问方向**：协方差阈值。

### Q55. 多机器人导航怎么避免冲突？（Multi-robot navigation）★
**答案要点**
- 集中调度（路径预约/时间窗，CBS、冲突搜索）、分布式避碰（ORCA/RVO 速度障碍法）、交通规则（单行道、优先级）；
- 通信延迟与一致性是难点（P6 的 M-DDS 协调）。
**English short answer**
Options are centralised scheduling with conflict-free paths, decentralised reciprocal collision avoidance like ORCA, and traffic rules. Communication latency and consistent shared state are the hard parts.
**追问方向**：死锁。

### Q56. 导航参数怎么整定顺序？（Tuning order）★★
**答案要点**
- 顺序：底盘模型与里程计 → 定位稳定 → 代价地图（足迹、膨胀）→ 全局规划 → 局部规划权重 → 控制器增益 → 速度提升；
- 每次改一项，保存日志；先低速再提高速度。
**English short answer**
I first get the odometry and localisation stable, then set the footprint and inflation in the costmaps, then the global planner, the local planner weights, and finally the controller, all at low speed, before increasing the speed.
**追问方向**：速度上限的约束来源。

### Q57. 车式机器人与差速机器人导航差别？（Ackermann vs differential）★★★
**答案要点**
- 差速：可原地转，规划可用圆形足迹+DWA，路径可含尖角；
- 阿克曼：最小转弯半径，必须用 Hybrid-A*/Reeds-Shepp/TEB car-like；倒车需换向；跟踪要限制转角及其变化率；
- 恢复行为不同（无原地旋转）。
**English short answer**
A differential robot can turn in place so planning is simpler. A car-like robot has a minimum turning radius, so I need kinematically feasible planning like Hybrid-A*, a car-like local planner, and recoveries that do not rely on spinning.
**追问方向**：窄通道通过。

### Q58. 导航中的传感器选择与安装？（Sensor placement）★
**答案要点**
- 2D LiDAR 高度决定能看到什么（桌腿、悬空物）；多传感器（深度相机、超声）补盲；
- 安装外参标定影响定位与障碍位置。
**English short answer**
The LiDAR height decides what it sees, so I add depth or ultrasonic sensors for obstacles outside its plane. The mounting extrinsics must be calibrated, otherwise obstacles and localisation are offset.
**追问方向**：外参标定方法。

## 九、本章要点速记

1. 分层：全局（几何、低频）→ 局部（带时间、避障、中频）→ 跟踪（高频）；定位在下。
2. A*：$f=g+h$，可采纳保证最优，一致保证单次扩展；D* Lite 增量重规划。
3. RRT 概率完备，RRT* 渐近最优（选父+重连）。
4. Hybrid-A*：连续状态+离散格去重；启发取 RS 与 2D A* 的最大；解析扩展用 Reeds-Shepp。
5. $R_{min}=L/\tan\delta_{max}$；Dubins 前进，Reeds-Shepp 含倒车。
6. 代价地图：静态+障碍+膨胀；全局大低频，局部滚动高频；足迹与膨胀要一致。
7. DWA 采样速度；TEB 优化位姿+时间，支持 car-like，局部最优需 HCP；MPC 精确跟踪。
8. Pure Pursuit：$\delta=\arctan(2L\sin\alpha/L_d)$；Stanley：$\psi_e+\arctan(ke/v)$。
9. 纵横向解耦：转角追路径、速度追剖面（曲率限速）。
10. 排查：定位 → 传感器 → 代价地图 → 规划 → 控制 → 底层。
