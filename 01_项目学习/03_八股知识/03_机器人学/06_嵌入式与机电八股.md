## 一、STM32 与外设

### Q1. STM32F4 与 H7 的差异？（F4 vs H7）★★★
**答案要点**
- F407：Cortex-M4F，最高 168 MHz，带 FPU，无数据 Cache；CAN 为经典 bxCAN（8 字节）；
- H7：Cortex-M7，数百 MHz 级（具体型号不同），带 L1 I/D-Cache、双精度 FPU（部分型号），多 SRAM 域（D1/D2/D3）和 **FDCAN**（支持 CAN FD，最大 64 字节数据、双速率）；
- 影响：H7 要关心 **Cache 一致性**（DMA 与 CPU 看到不同数据：用 `SCB_CleanDCache/InvalidateDCache` 或把 DMA 缓冲放在非缓存区/MPU 配置）、内存域对齐与 DMA 可访问性（某些 SRAM 域 DMA 访问受限）；
- 选型：F407 够用于云台/底盘多电机 PID；H7 适合更高控制频率、FDCAN、复杂算法（LQR+VMC）。
- 项目：P3：STM32F407/FreeRTOS+CAN；P7：STM32H7/FreeRTOS+FDCAN。
- 我们的做法（典型取值，以实机为准）：P3 用 F407 系列，主频 168 MHz，控制环 1 kHz 级；P7 用 H7 系列，主频数百 MHz，控制环 1 kHz 级；FDCAN 的仲裁段按 1 Mbps 级配置，数据段按需要提高。
**English short answer**
The F407 is a Cortex-M4F at up to 168 MHz with classic CAN. The H7 is a faster Cortex-M7 with caches and FDCAN, but you have to care about cache coherency with DMA and about which RAM domains the DMA can reach. I used the F407 for the RoboMaster hero, and an H7 with FDCAN for the wheel-legged robot, where the control loop is heavier.
**追问方向**：DMA 缓冲为何要对齐 32 字节；Cache 一致性 bug 的现象。

### Q2. STM32 的时钟树怎么理解？（Clock tree）★★★
**答案要点**
- 时钟源：HSI/HSE（外部晶振）、LSE；经 PLL 倍频得 SYSCLK；再分频出 AHB（HCLK）、APB1、APB2；定时器时钟在 APB 分频不为 1 时**自动 ×2**；
- 常见错误：晶振频率与代码 `HSE_VALUE` 不一致 → 所有波特率/定时全部偏移；APB 时钟超限；
- 外设波特率、定时器预分频、ADC 时钟、USB（需 48 MHz）都由时钟树决定。
- 计算示例（教学数值）：TIM 时钟 84 MHz，PSC=83，ARR=999 → 计数频率 1 MHz，周期 1 ms（1 kHz）。
**English short answer**
The clock comes from an oscillator through a PLL to the system clock, then through prescalers to the AHB and APB buses. Timer clocks double when the APB prescaler is not one. If the crystal value in the code is wrong, every baud rate and timer is off, so it is the first thing I check when everything is slightly wrong.
**追问方向**：时钟安全系统（CSS）；PLL 失锁。

### Q3. GPIO 的几种模式？（GPIO modes）★★
**答案要点**
- 输入（浮空/上拉/下拉）、通用输出（推挽/开漏）、复用功能（AF）、模拟；
- 开漏需要外部上拉（I2C、线与）；推挽驱动强；输出速度影响边沿与 EMI（不必要时用低速）；
- 按键消抖、悬空输入引入噪声。
**English short answer**
A pin can be an input with or without a pull, a push-pull or open-drain output, an alternate function for peripherals, or analog. Open-drain needs a pull-up and is used for I2C. I set the lowest output speed that works to reduce EMI.
**追问方向**：I2C 为何用开漏。

### Q4. 定时器（Timer）常见用法？（Timers）★★★
**答案要点**
- 基本定时（周期中断，控制环节拍）；PWM 输出（比较输出）；输入捕获（测脉宽/频率）；编码器模式（正交解码，TIMx_CNT 计数）；触发 ADC；
- 预装载（ARR 预装载使能）和影子寄存器：更新事件才生效，避免 PWM 毛刺；
- PWM 频率 $f=\dfrac{f_{clk}}{(PSC+1)(ARR+1)}$，占空比 $=CCR/(ARR+1)$。
- 中心对齐模式：电机三相 PWM 常用，开关纹波对称，便于 ADC 采样在中点。
**English short answer**
Timers give periodic interrupts for control loops, PWM outputs, input capture and hardware quadrature decoding for encoders, and they can trigger the ADC. The PWM frequency is the timer clock over prescaler times period, and the duty is the compare value over the period. Preload registers make updates take effect cleanly at the update event.
**追问方向**：编码器溢出处理；PWM 分辨率与频率折中。

### Q5. ADC 采样要注意什么？（ADC）★★
**答案要点**
- 采样时间与源阻抗；参考电压；分辨率 12 bit：电压 $V=\dfrac{N}{4095}V_{ref}$；
- 多通道扫描 + DMA；触发源用定时器保证同步；
- 噪声：硬件 RC、过采样、软件滤波；电机电流采样点要避开开关边沿（中心对齐 PWM 中点采样）。
**English short answer**
I choose the sampling time for the source impedance, trigger the conversions from a timer so they are synchronised, use DMA for multi-channel scans, and for motor currents sample at the middle of the PWM period to avoid switching noise.
**追问方向**：VREFINT 校准；过采样提高有效位数。

### Q6. UART/SPI/I2C 如何选？（Serial buses）★★
| | UART | SPI | I2C | CAN |
|---|---|---|---|---|
| 线数 | 2（异步） | 4+（同步） | 2（开漏，多主） | 2（差分） |
| 速度 | 115200 ~ Mbps | 数十 Mbps | 100k/400k/1M | 1 Mbps（FD 更高） |
| 拓扑 | 点对点 | 一主多从（片选） | 多主多从（地址） | 多主总线 |
| 典型 | 遥控接收、调试、上位机 | IMU、Flash | 小传感器 | 电机、车辆 |

- IMU 高速采样一般用 SPI + DMA；遥控器 SBUS/DBUS 用 UART（带反相/DMA 空闲中断）。
**English short answer**
UART is simple point-to-point, SPI is fast and used for IMUs, I2C is a two-wire bus for slow sensors, and CAN is a robust differential multi-master bus for motors. I use SPI with DMA for high-rate IMU reading and CAN for motor drives.
**追问方向**：I2C 总线挂死恢复；SPI 模式 CPOL/CPHA。

### Q7. UART 接收不定长数据怎么做？（UART variable-length RX）★★★
**答案要点**
- 方案：**DMA 循环/普通接收 + 空闲中断（IDLE）**：总线空闲一帧时间即触发，从 DMA 计数计算接收长度；环形缓冲区；
- 备选：逐字节中断 + 超时；帧头帧尾 + 校验（CRC）；
- 注意：数据帧解析在任务中，不在中断里做长处理；校验失败丢弃；丢失同步后重新找帧头。
**English short answer**
I use DMA reception with the idle-line interrupt, so I get an interrupt when the bus goes quiet, then compute the received length from the DMA counter. The parsing runs in a task, with a header and checksum to resynchronise after corruption.
**追问方向**：双缓冲；溢出处理。

### Q8. 存储：Flash、RAM、启动流程？（Memory and boot）★★
**答案要点**
- Flash：代码与常量，写入需擦除；RAM：栈、堆、全局变量；
- 启动：复位向量 → `Reset_Handler` → 初始化 `.data`/`.bss` → 系统时钟 → `main`；
- 链接脚本决定段位置；大数组放 RAM 域要考虑 DMA 可达；
- 参数存储：Flash 模拟 EEPROM（带校验与磨损）。
**English short answer**
After reset the startup code initialises the data and bss sections, configures the clock and calls main. Code and constants live in flash, and variables and stacks live in RAM, and the linker script places them. Parameters can be kept in flash with a checksum.
**追问方向**：栈大小确定；Bootloader。

### Q9. 内存对齐与字节序、结构体打包？（Alignment, endianness, packing）★★
**答案要点**
- ARM 小端；跨设备协议需统一字节序；`__attribute__((packed))` 避免填充但可能产生非对齐访问（M0 会 HardFault，M4/M7 一般可但慢）；
- 位域不可移植；协议编码用显式移位而不是直接 `memcpy` 结构体。
**English short answer**
ARM is little-endian, so for protocols I encode and decode fields explicitly with shifts instead of casting structs. Packed structs avoid padding but can cause unaligned access issues on some cores.
**追问方向**：CAN 电机反馈解析。

### Q10. `volatile` 的作用？（volatile）★★★
**答案要点**
- 告诉编译器变量可能被外部（中断/硬件）改变，禁止缓存到寄存器、禁止优化掉读写；
- 用于：外设寄存器、ISR 与主循环共享的标志；
- 不保证原子性和线程同步（需关中断/互斥/原子）。
**English short answer**
Volatile tells the compiler not to cache or optimise away accesses, because the value can change from an interrupt or hardware. It does not make accesses atomic or provide synchronisation.
**追问方向**：与 `atomic` 区别；多字节变量撕裂。

### Q11. 浮点运算在 MCU 上的问题？（Floating point on MCU）★★
**答案要点**
- 有 FPU（单精度）：`float` 快，`double` 软件模拟很慢；常量加 `f` 后缀；
- ISR 中使用 FPU 需保存 FPU 寄存器（FreeRTOS 需配置、懒惰压栈）；
- 数值：累加误差、积分长期漂移、除零/NaN 保护；
- 三角函数用 `sinf/cosf`，或查表/多项式近似。
**English short answer**
On an MCU with a single-precision FPU, I use float with the f suffix everywhere, since double falls back to slow software. Using the FPU inside interrupts needs context-saving support from the RTOS. I also protect against NaN and division by zero in the control path.
**追问方向**：控制环耗时测量。

### Q12. 低功耗与调试手段？（Debug tools）★
**答案要点**
- SWD/JTAG、断点、SWO/ITM 打印、逻辑分析仪/示波器、Ozone/SEGGER RTT、串口曲线工具；
- 控制调试：引脚翻转测中断耗时；DWT 周期计数器测函数耗时；
- HardFault 排查：看 CFSR/ HFSR/ 栈帧里的 PC/LR。
**English short answer**
I use SWD debugging, a logic analyser or oscilloscope, and toggle a pin around code to measure its execution time. For HardFaults, I read the fault status registers and the stacked PC.
**追问方向**：HardFault 常见原因。

## 二、中断与 DMA

### Q13. 中断是什么？NVIC 优先级怎么理解？（Interrupts and NVIC）★★★
**答案要点**
- 外设事件触发 CPU 暂停当前代码执行 ISR，返回后继续；
- Cortex-M NVIC：优先级数值**越小越高**；分组为抢占优先级 + 子优先级；高抢占可打断低抢占；
- **FreeRTOS 约束**：能调用 `FromISR` API 的中断，其优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`（即逻辑上不高于它）；高于此阈值的中断不能调用 RTOS API；
- ISR 原则：短、快、不阻塞，只设标志/发通知/拷贝数据，重活交给任务。
**English short answer**
An interrupt suspends the current code to run a handler. On Cortex-M a smaller priority number means a higher priority, and higher-preemption interrupts can interrupt lower ones. With FreeRTOS, interrupts that call the FromISR APIs must not be higher than the configured maximum syscall priority. Handlers should be short and just hand work over to tasks.
**追问方向**：优先级分组；ISR 里能不能 printf（不能）。

### Q14. 如何在 ISR 与任务之间传数据？（ISR-task communication）★★★
**答案要点**
- FreeRTOS：`xQueueSendFromISR`、`xTaskNotifyFromISR`（最轻量）、`xSemaphoreGiveFromISR`、流缓冲区；
- 使用 `portYIELD_FROM_ISR(xHigherPriorityTaskWoken)` 立即切换；
- 裸机：环形缓冲区 + 标志位，注意临界区与原子性；
- 避免：ISR 中动态内存分配、长时间持锁、浮点大量运算。
**English short answer**
I use task notifications or queues with the FromISR functions, and request a context switch at the end of the handler if a higher-priority task was woken. In bare-metal code I'd use a ring buffer with careful ownership of head and tail.
**追问方向**：任务通知 vs 信号量；队列满怎么办。

### Q15. 控制周期用定时器中断还是 RTOS 任务？（Control loop timing）★★★
**答案要点**
- 定时器中断：抖动最小，适合最内环（kHz）；缺点：占用中断时间、不能阻塞；
- RTOS 周期任务（`vTaskDelayUntil`）：结构清晰，抖动受调度影响；常用 1 kHz 以下的控制环；
- 折中：定时器中断发通知唤醒高优先级控制任务，既固定节拍又可用 RTOS 同步。
- 度量：记录最大执行时间与周期抖动；超时则报错。
**English short answer**
A timer interrupt gives the lowest jitter, but the work in it must stay tiny. A periodic RTOS task with vTaskDelayUntil is cleaner and good for loops up to about a kilohertz. A common compromise is a timer interrupt that notifies a high-priority control task. In every case, I measure the worst-case execution time.
**追问方向**：vTaskDelay vs vTaskDelayUntil；时间漂移。

### Q16. DMA 是什么？有哪些模式？（DMA）★★★
**答案要点**
- 不经 CPU 在外设与内存间搬运数据；模式：普通（一次）、循环（环形缓冲）；传输完成 / 半完成 / 错误中断；
- 典型用法：UART 接收、SPI 读 IMU、ADC 扫描、定时器 PWM 序列（如 WS2812）；
- 注意：缓冲区生命周期（不能是局部变量）；对齐；总线竞争；H7 的 Cache 一致性与内存域；
- 双缓冲 / 半满处理：处理上一半时，DMA 填另一半。
**English short answer**
DMA moves data between peripherals and memory without the CPU, in normal or circular mode, with half- and full-transfer interrupts. I use it for UART reception, SPI IMU reads and ADC scans. The buffer must stay valid, and on a Cortex-M7 I also manage the cache coherency.
**追问方向**：DMA 缓冲在栈上的 bug；传输完成后的处理。

### Q17. H7 上 DMA 与 Cache 的一致性问题怎么解决？（Cache coherency）★★★
**答案要点**
- 问题：CPU 通过 D-Cache 读到旧数据（DMA 写入内存），或 CPU 写入的数据还在 Cache 未写回，DMA 读到旧数据；
- 解决：① DMA 缓冲放入不可缓存区域（MPU 配置）；② 接收后 `SCB_InvalidateDCache_by_Addr`，发送前 `SCB_CleanDCache_by_Addr`（地址与大小需 32 字节对齐）；③ 使用 DTCM 之外的 DMA 可达 RAM（如 AXI SRAM/SRAM1-3 的特定域）；
- 现象：数据偶发错误、旧数据重复、仅在开启 Cache 后出现。
**English short answer**
With data cache enabled the CPU may read stale data that DMA has written, or DMA may read stale data the CPU has not flushed. I place DMA buffers in a non-cacheable region, or invalidate before reading and clean before sending, with 32-byte alignment. The symptom is random wrong or stale data that disappears when the cache is off.
**追问方向**：DTCM 不可被某些 DMA 访问。

### Q18. 临界区与原子操作？（Critical sections and atomics）★★
**答案要点**
- 关中断（`__disable_irq`）、FreeRTOS `taskENTER_CRITICAL`（会屏蔽到某优先级的中断）、互斥量（任务间）、LDREX/STREX 原子；
- 32 位对齐读写在 Cortex-M 上通常原子，但 64 位、结构体、`float` 对（如 x,y）不是；
- 共享数据：双缓冲/序列号（seqlock）读写无锁。
**English short answer**
For short shared-variable access I use a critical section or an atomic, and for longer sections a mutex. Reading a multi-word structure is not atomic, so I either lock or use a sequence number or double buffer.
**追问方向**：临界区时长对实时性的影响。

### Q19. 中断延迟与抖动来源？（Interrupt latency）★★
**答案要点**
- 来源：更高优先级中断、关中断区、Flash 等待状态、Cache miss、总线竞争；
- 优化：代码放 ITCM/RAM 执行、减少关中断区、合理优先级、缩短 ISR。
**English short answer**
Latency comes from higher-priority interrupts, long critical sections, flash wait states and cache misses. I keep critical sections short, set sensible priorities, and measure with a GPIO and a scope.
**追问方向**：如何测量。

### Q20. 回调函数里能做什么（HAL 库中断回调）？（HAL callbacks）★★
**答案要点**
- HAL 的 `HAL_xxx_RxCpltCallback` 在 ISR 上下文中；仍然遵守 ISR 规则；
- HAL 默认阻塞式 API 不要用于实时路径；
- 工程上常直接用 LL/寄存器或自写驱动以获得确定性。
**English short answer**
The HAL callbacks run in interrupt context, so the same short, non-blocking rules apply. I avoid the blocking HAL calls in real-time paths and sometimes use LL drivers for determinism.
**追问方向**：HAL vs LL。

## 三、CAN / FDCAN

### Q21. CAN 总线的基本特点？（CAN basics）★★★
**答案要点**
- 差分双线（CANH/CANL），两端 **120 Ω** 终端电阻（总线两端各一个，测得 CANH-CANL 约 60 Ω）；
- 多主、基于**非破坏性逐位仲裁**（ID 越小优先级越高，显性 0 压倒隐性 1）；
- 位填充（连续 5 个相同位插入反位）；CRC；ACK；错误帧；
- 经典 CAN：标准帧 11 位 ID / 扩展帧 29 位 ID，数据 ≤ 8 字节，最高 1 Mbps；CAN FD：数据最多 64 字节，数据段可更高速率（BRS）；
- 适合强干扰环境、实时、多节点。
**English short answer**
CAN is a differential multi-master bus with termination resistors at both ends, and arbitration is done bit by bit on the identifier, where a lower ID wins without destroying the frame. Classic CAN carries up to eight bytes at up to one megabit per second, and CAN FD allows up to sixty-four bytes with a faster data phase.
**追问方向**：为什么要终端电阻；显性隐性；仲裁为何不丢帧。

### Q22. CAN 帧结构？（CAN frame）★★
**答案要点**
- SOF、仲裁段（ID + RTR）、控制段（IDE、DLC）、数据段（0–8 字节；FD 至 64）、CRC、ACK、EOF、IFS；
- 数据帧 / 远程帧 / 错误帧 / 过载帧；
- RoboMaster 电机协议：反馈帧含转子机械角度（0–8191）、转速、电流、温度。
**English short answer**
A frame has the arbitration field with the ID, a control field with the length, the data, a CRC, an acknowledge slot and the end. There are also remote, error and overload frames. Motors typically report angle, speed, current and temperature in the data bytes.
**追问方向**：ACK 谁发。

### Q23. CAN 波特率与位时序怎么算？（Bit timing）★★★
**答案要点**
- 一个位 = SYNC_SEG(1 tq) + BS1(PROP+PHASE1) + BS2(PHASE2)，$t_{bit}=(1+BS1+BS2)\cdot t_q$，$t_q=\dfrac{Prescaler}{f_{CAN}}$；
- 采样点 $=\dfrac{1+BS1}{1+BS1+BS2}$，推荐 75–87.5%；SJW（再同步跳变宽度）处理时钟偏差；
- 计算示例（教学数值）：$f_{CAN}=42$ MHz，Prescaler=3 → $t_q=71.4$ ns；设 BS1=10，BS2=3 → 14 tq → $t_{bit}=1.0$ µs → 1 Mbps，采样点 $11/14=78.6\%$。
- 所有节点必须一致的波特率、相近的采样点。
**English short answer**
A bit is divided into time quanta: a sync segment, segment one and segment two. Baud rate is the CAN clock divided by prescaler times the total number of quanta. The sample point is the end of segment one divided by the total, typically around 75 to 87 percent. All nodes must agree on baud rate and a similar sample point.
**追问方向**：长线缆下采样点；FDCAN 的双速率配置（仲裁段/数据段）。

### Q24. CAN 的错误处理机制？（Error handling）★★★
**答案要点**
- 五种错误：位错误、填充错误、CRC 错误、格式错误、ACK 错误；
- 节点计数 TEC/REC：Error Active（<128）、Error Passive（≥128）、**Bus-Off**（TEC>255，停止收发，需恢复）；
- 工程：监控 Bus-Off 并自动恢复（`HAL_CAN_ResetError` / 自动 Bus-Off 恢复配置）；常见原因：终端电阻缺失、波特率不一致、线路干扰、接触不良、无其他节点应答；
- 单独上电无其他节点时会因 ACK 错误持续重发，不要误判。
**English short answer**
CAN detects bit, stuff, CRC, form and ACK errors, and each node keeps transmit and receive error counters. A node goes from error-active to error-passive and finally bus-off. I monitor bus-off and recover automatically. Typical causes are missing termination, baud rate mismatch, bad wiring or noise.
**追问方向**：如何排查总线挂死；示波器看差分波形。

### Q25. CAN 总线负载怎么估算？（Bus load）★★★
**答案要点**
- 标准帧 8 字节，约 $\approx 111$ 位（含位填充最坏约 130 位）；1 Mbps 下一帧约 111 µs（教学估算）；
- 负载 $=\dfrac{\sum_i f_i\cdot bits_i}{baud}$；
- 例（教学数值）：8 个电机各 1 kHz 发命令 + 1 kHz 反馈：约 $16\times1000\times111/10^6\approx1.78$ → **过载**（>100%）。实际需降频或拆分总线；经验上保持 < 70%。
- 对策：多路 CAN、提高波特率、使用 CAN FD、合并命令帧（RoboMaster 电机一帧 8 字节控制 4 个电机）。
- 本项目通常取：每条总线挂几个到十个左右电机节点，命令与反馈周期为 1 kHz 级；按上式估算后保持在 70% 以下，必要时拆分总线或合并命令帧（典型/教学示例，以实机为准）。
**English short answer**
A standard eight-byte frame is roughly 111 bits on the wire, so at one megabit that is about 111 microseconds. I sum the frame rates times frame bits and divide by the baud rate, and aim to stay under about seventy percent. If it is too high I split buses, merge commands, reduce rates, or move to CAN FD.
**追问方向**：为什么留余量；发送优先级对延迟的影响。

### Q26. CAN 电机控制的典型数据流？（Motor control over CAN）★★★
**答案要点**
- 主控周期发送控制帧（电流/力矩/位置，视协议），电机驱动器周期回传反馈（角度、速度、电流/力矩、温度、错误码）；
- 设计：① 同一时刻快照用于控制；② 反馈超时检测（如连续 N 个周期未收到 → 判定离线并输出零）；③ 指令限幅与单位换算（电流 ↔ 力矩：$\tau=K_t\cdot i$，含减速比 $N$：$\tau_{out}=NK_ti\eta$）；④ 编码器多圈累积（RoboMaster 电机角度 0–8191 回绕，需展开）；
- 接收：CAN 过滤器 + FIFO 中断，ISR 里只拷贝，任务里解析。
- 项目：P3（云台/发射/底盘多电机）、P7（FDCAN 驱动关节/轮毂电机）、P1（CAN 电机执行层）。
**English short answer**
The main controller sends control frames periodically and each motor replies with angle, speed, current and temperature. I take a consistent snapshot for the control loop, detect missing feedback with a timeout and output zero, limit commands, convert current to torque with the torque constant and gear ratio, and unwrap the encoder angle. In the receive interrupt I just copy, and parse in a task.
**追问方向**：角度回绕展开；多电机同步。

### Q27. CAN 过滤器怎么配置？（CAN filters）★★
**答案要点**
- 掩码模式：`(ID & mask) == (filterID & mask)` 才接收；列表模式：精确匹配；
- 作用：减轻 CPU 负担，只接收关心的电机反馈 ID；
- 多 FIFO 分配；FDCAN 的标准/扩展过滤器表、范围/双 ID/掩码。
**English short answer**
Filters decide which IDs are accepted into the receive FIFO, using a mask or an exact list. By accepting only the motor feedback IDs I need, the CPU is not interrupted by irrelevant traffic.
**追问方向**：FIFO 溢出。

### Q28. CAN FD / FDCAN 与经典 CAN 的差异？（CAN FD）★★★
**答案要点**
- 数据最多 64 字节；双速率（仲裁段较低速、数据段较高速，BRS 位）；CRC 更长（17/21 位）；
- STM32 H7 的 FDCAN 外设，使用消息 RAM（共享，需配置 FIFO/Tx buffer 个数与偏移）；
- 好处：更高带宽，更少帧数；
- 注意：总线所有节点需支持 FD（混合经典节点会产生错误帧）；收发器要支持 FD 速率；位时序要分别配置 Nominal/Data。
- 本项目 P7 的 CV 描述为 FDCAN 链路；实际通常把外设配置为兼容经典 CAN 的模式，速率取 1 Mbps 级，电机协议为 8 字节帧；若全总线节点均支持再启用 FD 与更高数据段速率（典型做法，以实机为准）。
**English short answer**
CAN FD allows up to sixty-four data bytes and can switch to a faster bit rate in the data phase. On the STM32 H7 the FDCAN peripheral uses a shared message RAM that must be configured. All nodes and transceivers on the bus must support FD if it is used, and the nominal and data phase timing are set separately.
**追问方向**：消息 RAM 配置错误现象；收发器选择。

### Q29. CAN 的实时性与发送延迟？（Latency）★★
**答案要点**
- 延迟 = 排队（仲裁失败）+ 传输 + 软件；高优先级（小 ID）延迟小；
- 控制类报文 ID 设小；使用 Tx 邮箱/FIFO 的优先级设置；
- 避免在控制周期内阻塞等待发送完成。
**English short answer**
The latency is arbitration waiting plus transmission time plus software overhead. I give control messages low IDs so they win arbitration, and I never block the control loop waiting for a frame to finish sending.
**追问方向**：邮箱满怎么办。

### Q30. CAN 与 RS485 / EtherCAT / UART 比较？（Bus choices）★
**答案要点**
- RS485：半双工、需自定协议；EtherCAT：高带宽硬实时同步，适合高端关节；CAN：成本低、可靠、广泛；
- 选择取决于节点数、周期、同步性、成本。
**English short answer**
RS485 is simple but needs a custom protocol, EtherCAT gives high bandwidth and tight synchronisation at a higher cost, and CAN is the cheap, robust middle ground used by most small robots.
**追问方向**：为何选 CAN。

## 四、FreeRTOS

### Q31. 为什么要用 RTOS？任务划分原则？（Why RTOS, task design）★★★
**答案要点**
- 多任务并发、确定的优先级调度、同步原语、软件模块化；
- 任务划分：按**周期和实时性**分——高优先级：控制环（1 kHz）、IMU 采样；中：通信（CAN/UART 解析）、状态估计；低：日志、LED、调试；
- 原则：优先级按**周期短者高**（rate monotonic 近似）；任务间用队列/通知传递数据；共享数据最少化；
- P3 的任务例（典型做法，非项目源码）：`gimbal_task`、`chassis_task`、`shoot_task`、`imu_task`、`referee/communication_task`。
- 本项目通常取：控制与 IMU 任务 1 kHz、最高优先级；CAN 通信与状态估计为中优先级；日志、指示灯最低；栈大小按任务复杂度取 256–1024 字（典型/教学示例，以实机为准）。
**English short answer**
An RTOS gives deterministic priority scheduling, synchronisation primitives and modularity. I split tasks by period and criticality: control and IMU tasks have the highest priority, communication and estimation are in the middle, and logging is lowest. Tasks exchange data through queues or notifications and share as little state as possible.
**追问方向**：为什么 IMU 任务优先级高；任务间数据一致性。

### Q32. FreeRTOS 调度机制？（Scheduler）★★★
**答案要点**
- 抢占式、优先级调度：最高优先级就绪任务运行；同优先级时间片轮转（`configUSE_TIME_SLICING`）；
- 任务状态：Running、Ready、Blocked、Suspended；
- 系统节拍 `configTICK_RATE_HZ`（常 1000）；`vTaskDelay` 相对延时，`vTaskDelayUntil` 绝对周期；
- 空闲任务回收资源、可钩子函数（Idle hook）。
**English short answer**
FreeRTOS uses preemptive fixed-priority scheduling: the highest-priority ready task runs, and equal priorities share time slices. Tasks are running, ready, blocked or suspended. The tick drives delays. For fixed-rate loops I use vTaskDelayUntil to avoid drift.
**追问方向**：时间片是否启用；tickless。

### Q33. 信号量、互斥量、队列、事件组、任务通知区别？（IPC primitives）★★★
| 机制 | 用途 | 特点 |
|---|---|---|
| 二值信号量 | ISR→任务事件同步 | 无所有权，无优先级继承 |
| 计数信号量 | 资源计数/事件计数 | |
| 互斥量（Mutex） | 保护共享资源 | **有所有权**，有**优先级继承**，不可在 ISR 使用 |
| 队列 | 传数据 | 拷贝语义，可阻塞 |
| 事件组 | 多事件组合等待 | 位标志，ISR 受限 |
| 任务通知 | 1:1 轻量通知 | 最快最省内存，替代二值信号量/计数 |

**English short answer**
Binary semaphores signal events, mutexes protect resources and provide priority inheritance, queues pass data, event groups wait on combinations of flags, and task notifications are the lightest one-to-one signal. A mutex cannot be used from an ISR.
**追问方向**：为什么用互斥量而不是二值信号量保护共享资源。

### Q34. 优先级反转怎么发生、怎么解？（Priority inversion）★★★
**答案要点**
- 低优先级 L 持锁，高优先级 H 等锁，中优先级 M 抢占 L → H 被 M 间接阻塞（无界）；
- 解法：**优先级继承**（FreeRTOS 互斥量实现：L 暂时提升到 H 的优先级）；优先级天花板；避免持锁时做长操作；减少共享；
- 二值信号量没有继承，不适合当锁。
**English short answer**
Priority inversion occurs when a low-priority task holds a lock needed by a high-priority task and a medium-priority task preempts the low one, so the high-priority task is blocked indirectly. Mutexes with priority inheritance fix this. I keep critical sections short and avoid sharing where I can.
**追问方向**：死锁与优先级反转的区别。

### Q35. 任务栈大小如何确定？栈溢出怎么检测？（Stack sizing and overflow）★★★
**答案要点**
- 栈中包含局部变量、调用链、上下文保存（含 FPU）；`uxTaskGetStackHighWaterMark` 查剩余最小栈；
- 开启 `configCHECK_FOR_STACK_OVERFLOW`（方法 1/2）和钩子；
- 现象：随机崩溃、HardFault、数据被改；避免大局部数组、递归、`printf` 浮点格式（栈大）。
**English short answer**
I check the stack high-water mark during testing and leave a margin, and enable the overflow check with a hook. Stack overflow shows up as random corruption or HardFaults. Large local arrays and printf with floats are common causes.
**追问方向**：堆 vs 栈；静态分配任务。

### Q36. 内存管理：动态 vs 静态分配？（Heap schemes）★★
**答案要点**
- heap_1 不释放、heap_2 简单、heap_4 合并碎片（常用）、heap_5 多块；
- 安全关键系统偏好**静态创建**（`xTaskCreateStatic` 等），避免运行时碎片；
- 控制路径禁止 `malloc`。
**English short answer**
For safety-critical control code I prefer static allocation of tasks and queues, and avoid malloc in the control path to prevent fragmentation and unpredictable timing. If I use the heap, heap_4 merges free blocks.
**追问方向**：碎片化现象。

### Q37. 死锁的条件与避免？（Deadlock）★★
**答案要点**
- 四条件：互斥、持有并等待、不可剥夺、循环等待；
- 避免：统一加锁顺序、超时获取、减少嵌套、用无锁队列。
**English short answer**
A deadlock needs mutual exclusion, hold-and-wait, no preemption and a cycle of waiting. I avoid it by fixed lock ordering, timeouts on take, and by not nesting locks.
**追问方向**：如何发现；看门狗。

### Q38. 临界区与调度锁？（Critical vs scheduler suspend）★
**答案要点**
- `taskENTER_CRITICAL`：关中断到某优先级，极短；`vTaskSuspendAll`：不切换任务但中断仍响应；
- 用于保护极短的共享数据修改。
**English short answer**
A critical section masks interrupts for a very short time, while suspending the scheduler only stops task switches. I use them for tiny, bounded operations.
**追问方向**：对实时性的影响。

### Q39. 软件定时器与硬件定时器？（Software timers）★
**答案要点**
- 软件定时器在 Timer Service 任务中执行回调，精度受 tick 与任务调度限制，回调不可阻塞；
- 控制环不要依赖软件定时器。
**English short answer**
Software timers run their callbacks in a timer service task, so their precision is limited by the tick and scheduling. I do not use them for control loops.
**追问方向**：定时器任务优先级。

### Q40. 如何分析任务执行时间与 CPU 占用？（Profiling）★★
**答案要点**
- `vTaskGetRunTimeStats`（需高分辨率计数器）；DWT 周期计数；GPIO + 示波器；Tracealyzer/SystemView；
- 关注：最坏执行时间（WCET）、周期抖动、CPU 余量。
**English short answer**
I use runtime statistics, the cycle counter and GPIO toggling to measure each task's worst-case time and the jitter of the control loop, and check I have enough margin.
**追问方向**：控制环超时处理。

## 五、电机、FOC、PWM

### Q41. 有刷直流电机的数学模型？（DC motor model）★★★
**答案要点**
- 电气：$V=Ri+L\dfrac{di}{dt}+K_e\omega$；机械：$J\dot\omega=K_ti-B\omega-\tau_L$；
- $K_t$（力矩常数，N·m/A）与 $K_e$（反电势常数，V·s/rad）在 SI 下数值相等；
- 稳态：$\omega=\dfrac{V-R i}{K_e}$；堵转电流 $I_{stall}=V/R$；
- 电流环最内（快），速度环、位置环依次外；电流 ≈ 力矩，使电流环成为"力矩源"。
- 例（教学数值）：$K_t=0.03$ N·m/A，减速比 19，效率按 1：输出力矩 $=0.03\times19\times i$；$i=5$ A → 2.85 N·m。
**English short answer**
A DC motor has an electrical equation with resistance, inductance and back-EMF, and a mechanical equation where torque is the torque constant times current. In SI units the torque constant and back-EMF constant are equal. The current loop makes the motor a torque source, and speed and position loops sit outside.
**追问方向**：堵转电流；电压饱和对速度上限的影响。

### Q42. BLDC 与 PMSM 的区别？（BLDC vs PMSM）★★★
**答案要点**
- 无刷直流 BLDC：梯形反电势，六步方波换相（霍尔），转矩脉动较大；
- 永磁同步 PMSM：正弦反电势，用 **FOC** 正弦驱动，转矩平滑、效率高、噪声小；
- 机器人关节电机多为 PMSM + FOC + 编码器。
**English short answer**
A BLDC motor has a trapezoidal back-EMF and is driven by six-step commutation with Hall sensors, which gives torque ripple. A PMSM has a sinusoidal back-EMF and uses field-oriented control for smooth torque. Most robot joint motors are PMSMs with FOC and an encoder.
**追问方向**：何时六步换相足够。

### Q43. FOC 的原理？（Field-oriented control）★★★
**答案要点**
- 目标：把三相交流电流变成像直流电机一样可独立控制"励磁"与"转矩"的两个直流量；
- 步骤：
  1. 采样两相电流 $i_a,i_b$（$i_c=-i_a-i_b$）；
  2. **Clarke 变换**（三相→两相静止 $\alpha\beta$）：$i_\alpha=i_a,\ i_\beta=\dfrac{i_a+2i_b}{\sqrt3}$；
  3. **Park 变换**（静止→旋转 $dq$，用电角度 $\theta_e$）：$i_d=i_\alpha\cos\theta_e+i_\beta\sin\theta_e,\ i_q=-i_\alpha\sin\theta_e+i_\beta\cos\theta_e$；
  4. $i_d$ 环（通常设 0，表面贴装 PMSM）与 $i_q$ 环（转矩）两个 PI 电流环，输出 $v_d,v_q$；
  5. 反 Park 得 $v_\alpha,v_\beta$，经 **SVPWM** 生成三相占空比；
- 转矩：$T=\tfrac32 p\,\psi_f i_q$（$p$ 极对数，$\psi_f$ 永磁磁链）；
- 关键：电角度 $\theta_e=p\theta_m$ + 零位校准（编码器对齐）；电流采样同步；死区补偿；
- 弱磁控制：高速时 $i_d<0$ 扩速。
**English short answer**
FOC transforms the three phase currents into a rotating frame aligned with the rotor using the Clarke and Park transforms, so torque and flux become two DC quantities, i_q and i_d. Two PI current loops control them, and the outputs are transformed back and turned into PWM by space-vector modulation. Torque is proportional to i_q, which is why the drive acts as a torque source.
**追问方向**：Clarke/Park 公式；电角度对齐；SVPWM；弱磁。

### Q44. SVPWM 是什么？比 SPWM 好在哪？（SVPWM）★★
**答案要点**
- 空间矢量调制：把电压矢量用相邻两个有效矢量 + 零矢量按时间合成；
- 直流母线电压利用率比 SPWM 高约 15%（线电压最大值 $V_{dc}/\sqrt3$ 相电压峰值）；
- 实现：扇区判断 + 作用时间计算；或注入三次谐波的等价方法。
**English short answer**
Space-vector modulation synthesises the reference voltage vector from the two adjacent active vectors and the zero vectors. It uses the DC bus about fifteen percent better than plain sinusoidal PWM.
**追问方向**：扇区判断。

### Q45. PWM 与死区？（PWM and dead time）★★★
**答案要点**
- 半桥上下管不能同时导通（直通短路）；死区时间：切换时先关一管，延时后再开另一管；
- 死区造成电压误差和电流畸变（低速明显），需补偿；
- PWM 频率：数 kHz–数十 kHz；越高电流纹波小但开关损耗大；需高于电流环带宽 10 倍以上，避开可听噪声（> 16 kHz）。
**English short answer**
The two switches of a half-bridge must never conduct together, so a dead time is inserted between switching one off and the other on. It distorts the output voltage, particularly at low speed, so good drives compensate for it. The PWM frequency trades current ripple against switching loss.
**追问方向**：直通后果；互补输出与刹车。

### Q46. 电流采样方式？（Current sensing）★★
**答案要点**
- 低侧采样电阻（+运放）、相线霍尔、母线单电阻（重构三相电流）；
- ADC 触发与 PWM 同步，中心对齐中点采样；
- 偏置校准（上电空载读取零点）；放大器饱和与共模范围。
**English short answer**
Currents are measured with shunt resistors and amplifiers or Hall sensors. The ADC is triggered in the middle of the PWM period to avoid switching noise, and the zero offset is calibrated at start-up.
**追问方向**：偏置校准。

### Q47. 速度/位置控制与电流环的带宽关系？（Loop bandwidth hierarchy）★★
**答案要点**
- 电流环带宽（kHz 级）≫ 速度环（百 Hz）≫ 位置环（十 Hz）；
- 上层认为电流环"瞬时"。若上位机直接发力矩（电流指令），环路延迟来自通信周期。
**English short answer**
The current loop is much faster than the speed loop, which is faster than the position loop, so the outer loops can treat the inner one as ideal. If the host sends torque commands, the communication period becomes the dominant delay.
**追问方向**：MIT 模式。

### Q48. 电机选型：力矩、速度、功率？（Motor sizing）★★
**答案要点**
- 需求：峰值/连续力矩、最高转速、负载惯量、占空比；
- 减速比 $N$ 使输出力矩 ×N、转速 ÷N，但反射惯量 ×N²，反向可驱动性变差；
- 热：连续电流受温升限制；峰值电流持续时间受限；
- 准直驱（低减速比）适合力控与腿足（透明度高）。
**English short answer**
I size the motor from the peak and continuous torque, top speed and thermal limits. A gear reduction multiplies torque but also reflects inertia by the square of the ratio and reduces back-drivability, which is why quasi-direct-drive motors are popular in legged robots.
**追问方向**：反射惯量计算。

### Q49. 堵转保护与过温保护？（Stall and thermal protection）★★
**答案要点**
- 电流限幅 + 时间窗（I²t）；温度读数超阈值降额或停止；
- 发射机构拨弹堵转：检测电流高且速度低 → 反转/停止（P3 的拨盘位置-速度双环要有堵转处理）；
- 状态机：正常 → 堵转 → 回退 → 重试。
**English short answer**
I limit current with a time window and reduce or cut output on over-temperature. For the feeder, a high current with low speed means a jam, so the logic backs off and retries.
**追问方向**：阈值设置依据。

### Q50. 减速器背隙与摩擦对控制的影响？（Backlash and friction）★★
**答案要点**
- 背隙导致换向死区与振荡；谐波/行星减速比摩擦与背隙不同；
- 对策：摩擦前馈、背隙补偿、双编码器、避免在零速反复穿越。
**English short answer**
Backlash creates a dead zone when the direction reverses and can cause oscillation. I use friction feedforward and avoid hunting around zero velocity.
**追问方向**：谐波减速器特性。

### Q51. 电机反电势与电压饱和如何限制速度？（Back-EMF and voltage limit）★★
**答案要点**
- 转速越高反电势越接近母线电压，电流环能提供的力矩下降（电压饱和）；
- 外特性：恒转矩区→恒功率区（弱磁）；
- 表现为：高速时力矩不足，PID 输出饱和 → 积分饱和（见 [02 控制八股](./02_控制八股.md)）。
**English short answer**
As speed rises the back-EMF approaches the bus voltage and the available torque drops, so at high speed the controller saturates. This appears as lack of torque at speed and can trigger integral windup.
**追问方向**：电池电压下降的影响。

### Q52. 多电机同步与相位（云台/底盘）？（Multi-motor sync）★
**答案要点**
- 同一控制周期内读取所有反馈、统一计算、统一下发；CAN 一次发 4 电机指令帧；
- 麦克纳姆轮四轮需协调，否则底盘走偏。
**English short answer**
I read all feedback, compute, and send all motor commands in the same control cycle. Four Mecanum wheels need coordinated commands, otherwise the chassis drifts sideways.
**追问方向**：延迟不一致的后果。

## 六、编码器与传感器

### Q53. 编码器类型？（Encoder types）★★★
| 类型 | 原理 | 特点 |
|---|---|---|
| 增量式（A/B/Z） | 光电/磁，输出脉冲 | 需回零，相对位置，四倍频 |
| 绝对式 | 单圈/多圈码盘 | 上电即知位置，多圈需电池/齿轮 |
| 磁编码器（AS5047 等） | 霍尔阵列 | 体积小，精度中等，易受磁干扰 |
| 旋转变压器 | 电磁 | 耐恶劣环境 |

- 正交解码：A、B 相差 90°，四倍频分辨率 $=4\times$线数；方向由相位先后判断；
- RoboMaster 电机：内置磁编码，一圈 8192 计数（0–8191），回绕需展开成多圈角度。
**English short answer**
Incremental encoders output quadrature pulses and give relative position, absolute encoders know the position at power-up, and magnetic encoders are small and common in robot joints. With quadrature decoding the resolution is four times the line count and the direction comes from the phase order.
**追问方向**：为何用 Z 相；多圈计数溢出。

### Q54. 速度估计方法？（Speed estimation）★★★
**答案要点**
- M 法（单位时间内脉冲数）：高速精度好；T 法（脉冲间隔计时）：低速好；M/T 法；
- 差分 + 低通；观测器（位置→速度）；
- 噪声/量化 → 速度环抖动（见 [03 八股](./03_状态估计与SLAM八股.md) Q56）。
**English short answer**
At high speed I count pulses over a fixed time, at low speed I time the interval between pulses, and a combination works across the range. A low-pass filter or an observer smooths the derivative.
**追问方向**：分辨率与速度噪声。

### Q55. 编码器角度回绕和多圈展开？（Angle unwrapping）★★★
**答案要点**
- 单圈 0–8191 回绕：若本次与上次差 $>4096$（半圈），则圈数 ∓1：
```c
// 教学示例，非项目源码
int32_t delta = (int32_t)raw - (int32_t)last;
if (delta >  4096) round_cnt--;
if (delta < -4096) round_cnt++;
total = round_cnt * 8192 + raw;   // 总位置 (counts)
last = raw;
```
- 采样周期内转动不能超过半圈，否则误判；
- 上电零位记录或保存。
**English short answer**
For a single-turn encoder that wraps, I compare the new reading to the previous one: a jump larger than half a revolution means a wrap, so I increment or decrement the turn counter. This only works if the shaft cannot move more than half a turn per sample.
**追问方向**：高速误判如何避免。

### Q56. IMU 的安装与校准？（IMU mounting and calibration）★★
**答案要点**
- 轴向与机体系对应，安装偏角会使重力投影错误；
- 零偏校准（静止平均）；温度补偿；加速度计六面校准；
- 振动：软安装/低通/采样频率。
**English short answer**
I align the IMU axes with the body frame and calibrate gyro bias at rest. Vibration isolation or low-pass filtering helps with the accelerometer. A wrong mounting offset appears as a constant tilt error.
**追问方向**：安装误差补偿。

### Q57. 传感器数据有效性检查？（Sensor validity）★★★
**答案要点**
- 范围检查、突变检查、超时、校验和/CRC、双传感器交叉校验；
- 无效数据 → 用上次有效值保持有限时间 → 超时降级（零输出/刹车）；
- P1/P7：状态不一致与有效性是故障定位重点。
**English short answer**
I check range, step changes, timeouts and checksums, and cross-check redundant sensors where available. Invalid data is held for a short time and then triggers a safe fallback.
**追问方向**：容错策略。

### Q58. 遥控器与裁判系统通信（RoboMaster）？（Remote control and referee）★★
**答案要点**
- 遥控器 DBUS（UART，100 kbps，8E1，反相），一帧 18 字节，DMA+空闲中断；
- 裁判系统串口协议：帧头 + CRC8 + 命令字 + CRC16；解析功率、热量、枪口速度、缓冲能量等；
- 用途：热量/功率限制与速度反馈（见 [07 专题](./07_轮腿_球形机器人_机械臂专题八股.md)）。
**English short answer**
The remote receiver uses a UART-based protocol, read with DMA and idle-line interrupts. The referee system sends framed packets with CRCs carrying power, heat and launcher speed, which my power and launcher logic uses.
**追问方向**：CRC 校验；断连处理。

## 七、电源、电池与功率

### Q59. 锂电池基本参数？（Battery basics）★★★
**答案要点**
- 单节标称 3.7 V（满电 4.2 V，截止约 3.0 V）；N 串（S）并联（P）；容量 Ah、能量 Wh = V×Ah；
- C 率：放电电流 = C × 容量；内阻导致大电流压降；低温内阻大；
- 保护：过充/过放/过流/短路（BMS）；
- 电量估计：开路电压曲线 + 库仑计数。
**English short answer**
A lithium cell is nominally 3.7 volts, full at 4.2, and shouldn't go below about 3.0. Series count sets voltage and parallel count sets capacity. Internal resistance causes voltage sag under high current, especially when cold, which matters for peak motor loads.
**追问方向**：电压跌落造成复位。

### Q60. 电机大电流时 MCU 复位怎么排查？（Brownout during motor surges）★★★
**答案要点**
- 原因：电池内阻 + 线阻 → 母线跌落；电源共地干扰；MCU 供电 LDO/DC-DC 输入下限；
- 对策：MCU 独立稳压、大电容缓冲、TVS/二极管、限流/软启动、星形接地、BOR 阈值设置、电机电流限幅；
- 诊断：示波器看 3.3V 与母线；日志里复位原因（RCC 复位标志）。
**English short answer**
Heavy motor current makes the battery voltage sag and can disturb the supply of the microcontroller. I give the MCU its own regulator with bulk capacitance, limit motor current, use a star ground, and check the reset flag and the supply on an oscilloscope.
**追问方向**：BOR；电源去耦。

### Q61. 底盘功率限制（RoboMaster）原理？（Chassis power limit）★★★
**答案要点**
- 规则：裁判系统限制底盘功率（W）与缓冲能量（J），超限扣血/断电；
- 功率模型（典型）：$P_{in}\approx\sum_i(\tau_i\omega_i+k_1\omega_i^2+k_2\tau_i^2)+P_0$（机械功率 + 铜损/电阻损 + 转速相关损耗 + 静态），系数由实验拟合；
- 控制：当预测功率 $>P_{max}$，按比例缩放电机力矩/速度目标（解二次方程求缩放系数）或在缓冲能量低时限速；
- 缓冲能量 PD：能量低 → 降低功率上限，避免透支；
- CV：*estimated power demand from real-time power and buffer-energy feedback and scaled wheel speeds*。
- 详见 [07 专题](./07_轮腿_球形机器人_机械臂专题八股.md)。
**English short answer**
The rules cap chassis power and give a buffer energy. I estimate the power demand with a model of mechanical power plus resistive and speed-dependent losses fitted from data, and when the prediction exceeds the limit I scale the wheel targets down, with the buffer energy lowering the allowed limit as it drains. The chassis stays controllable but within the rules.
**追问方向**：系数怎么拟合；缓冲能量控制。

### Q62. 稳压与去耦？（Regulation and decoupling）★★
**答案要点**
- LDO（低噪声、低效率，压差大发热）vs DC-DC（高效、有开关噪声）；
- 去耦电容就近放置于芯片电源脚（100 nF + 10 µF）；模拟电源单独滤波；
- 数字/模拟/功率地的单点连接。
**English short answer**
LDOs are quiet but waste power as heat, DC-DCs are efficient but noisy. I place decoupling capacitors next to the chip pins and keep analogue, digital and power grounds joined at a single point.
**追问方向**：ADC 精度受电源噪声影响。

### Q63. 电机反灌电压（再生）怎么处理？（Regeneration）★
**答案要点**
- 急减速时电机发电使母线电压上升，可能损坏驱动器/电池充电保护；
- 对策：泄放电阻/制动斩波、限制减速度、电池可吸收时优先回充。
**English short answer**
During hard braking the motors push energy back and raise the bus voltage. A brake resistor or limiting the deceleration protects the electronics.
**追问方向**：母线过压保护。

### Q64. 线束与连接器可靠性？（Wiring reliability）★
**答案要点**
- 接插件松动是最常见实机故障：加锁扣、应力释放；电源线径与压降；CAN 线双绞。
**English short answer**
Loose connectors are the most common hardware failure, so I use locking connectors and strain relief, size the power wires for the current, and use twisted pair for CAN.
**追问方向**：间歇性故障排查。

## 八、看门狗、故障安全与 EMC

### Q65. 看门狗（IWDG/WWDG）？（Watchdog）★★★
**答案要点**
- 独立看门狗 IWDG：独立低速时钟，超时不喂狗则复位，防程序跑飞；窗口看门狗 WWDG：必须在窗口内喂，防"过早喂"；
- 喂狗位置：在**确认各关键任务都正常**后统一喂（任务心跳标志位全置位），而不是在定时中断里无条件喂；
- 复位后读取复位原因，输出安全态。
**English short answer**
The independent watchdog resets the chip if software stops feeding it. I feed it only after every critical task has reported its heartbeat, not unconditionally from a timer interrupt, otherwise it would hide a stuck task. After a reset I check the reset flag and bring the actuators to a safe state.
**追问方向**：喂狗策略；调试时的暂停。

### Q66. 故障安全（fail-safe）设计原则？（Fail-safe design）★★★
**答案要点**
- 默认安全态：失去通信/传感器无效/超时 → 力矩归零或受控停车，而不是保持最后命令；
- 分层：硬件（过流/急停）→ 固件（限幅、超时、状态机）→ 软件（策略检查）；
- 启动序列：状态初始化（读取零位、检查传感器、使能顺序）、输出渐入（ramp）；
- 平衡机器人：跌倒检测（倾角超限 → 关闭驱动）、倒地恢复策略；
- 对应 P1：*state initialisation, output limiting and fall-recovery safeguards*。
- 我们的做法（典型设计，以实机为准）：跌倒判据为倾角超过设定上限并持续一小段时间，触发后关闭驱动输出；恢复流程为待机器人被扶起或回到安全姿态后重新初始化再使能；上电时先读取零位、检查传感器有效性，再按顺序使能并让输出渐入；保护包括力矩、电流、速度限幅与通信超时。
**English short answer**
My rule is that losing communication, invalid sensors or a timeout leads to a defined safe state, such as zero torque or a controlled stop, rather than holding the last command. I layer hardware protection, firmware limits and software checks, add a start-up sequence with state initialisation and output ramping, and for the balancing robot a fall detection with a recovery routine.
**追问方向**：谁来判断跌倒；恢复期间的安全。

### Q67. 上电与使能顺序？（Start-up sequencing）★★
**答案要点**
- 先通信和传感器自检 → 读取状态（零位、IMU 校准静止）→ 输出为零使能 → 缓慢提升（ramp）→ 进入闭环；
- 避免上电瞬间的跳变（编码器初值、积分初值、滤波器初值）。
**English short answer**
I first check communication and sensors, read the initial state, enable the drives with zero output, and ramp up into closed loop. Initialising integrators and filters from the actual state avoids a jump at start.
**追问方向**：无扰启动。

### Q68. EMC 与接地常识？（EMC and grounding）★★
**答案要点**
- 干扰源：电机 PWM 开关、继电器、电源开关；耦合：传导、辐射、共地阻抗；
- 措施：电源去耦、双绞/屏蔽线、差分通信、磁环、RC 吸收、TVS、远离大电流走线、接地分区单点连接、短而宽的回流路径；
- 现象：通信偶发错误、ADC 噪声、MCU 偶发复位/死机、编码器计数错误；
- 软件：CRC、重试、数字滤波。
**English short answer**
Motor switching and power supplies are the main noise sources. I use decoupling, twisted or shielded cables, differential links like CAN, ferrites and TVS diodes, short return paths and a careful ground layout. The symptoms are sporadic communication errors, noisy ADC readings or occasional resets, and I add CRCs and retries in software.
**追问方向**：共地噪声；屏蔽层接法。

### Q69. ESD 与接口保护？（ESD protection）★
**答案要点**
- TVS 二极管、串联电阻、磁珠；热插拔风险；带电插拔 CAN/USB 引起损坏。
**English short answer**
I protect interfaces with TVS diodes and series resistors, and I avoid hot-plugging if the design isn't made for it.
**追问方向**：USB ESD。

### Q70. 嵌入式日志与可观测性？（Logging）★★
**答案要点**
- 控制数据高速记录（RAM 环形缓冲 + 事后导出）、串口输出降频、关键事件（复位原因、故障码）存 Flash；
- 在线曲线工具调参；时间戳统一。
**English short answer**
I log control signals into a RAM ring buffer at full rate and export them afterwards, print only at a low rate, and store critical fault events in flash. Plotting tools make tuning much faster.
**追问方向**：日志对实时性的影响。

### Q71. OTA / Bootloader / 版本管理？（Firmware management）★
**答案要点**
- Bootloader + 双分区；参数与固件版本校验；回滚。
**English short answer**
A bootloader with two firmware slots and version checks allows safe updates and rollback.
**追问方向**：掉电保护。

### Q72. Hi3861（P4）水泵状态机怎么保证稳定？（Pump state machine on Hi3861）★★
**答案要点**
- 土壤湿度驱动的状态机：低于启动阈值 → 开泵；高于停止阈值 → 关泵；**两个独立阈值形成滞回**，避免在临界值附近频繁开关；
- 手动优先覆盖：用户命令优先于自动逻辑；
- 保护：最大连续运行时间、冷却间隔、传感器无效时的安全状态；
- 对应 CV：*soil-moisture-driven pump state machine on Hi3861 with independent start/stop thresholds and manual-priority override*。
- 本项目通常取：启动阈值低于停止阈值，两者间留出明确滞回区间；土壤湿度采样周期为秒级，并做简单滤波（滑动平均）；使用电容式或电阻式湿度传感器；设置最大连续运行时间与冷却间隔作为保护（典型/教学示例，以实机为准）。
**English short answer**
The pump turns on below a start threshold and off above a separate stop threshold, so there is hysteresis and no rapid cycling. A manual command overrides the automatic logic. I would add a maximum run time and a safe state if the sensor is invalid.
**追问方向**：滞回的作用；传感器漂移。

## 九、本章要点速记

1. 时钟树决定一切时序；APB 分频不为 1 时定时器时钟 ×2。
2. NVIC 数值越小优先级越高；FreeRTOS 的 `FromISR` 中断优先级不能高于阈值。
3. ISR 短小，通过通知/队列把重活交给任务；DMA + 空闲中断收不定长数据。
4. H7 的 DMA 要处理 Cache 一致性与内存域。
5. CAN：差分 + 120 Ω 终端 + 位仲裁 + Bus-Off 恢复；负载估算 < 70%；FDCAN 双速率。
6. FreeRTOS：抢占优先级调度；互斥量有优先级继承；监控栈水位；控制路径不 malloc。
7. 控制周期用定时器触发 + `vTaskDelayUntil`，监测抖动与 WCET。
8. FOC：Clarke → Park → $i_d/i_q$ PI → 反 Park → SVPWM；$T=\tfrac32p\psi_fi_q$。
9. 死区防直通；电流采样在 PWM 中点；高速时反电势限制力矩。
10. 看门狗要"检查完所有任务后再喂"；失联即安全态；功率限制按比例缩放。
