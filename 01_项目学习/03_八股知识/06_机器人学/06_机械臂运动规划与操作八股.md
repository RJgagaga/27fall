## 一、构型空间与运动学约束

### Q1 构型空间（C-space）是什么？为什么规划在其中进行？（Configuration space）
**优先级：★★★** · 对应基础知识：[采样规划_RRT_RRT星_PRM](../../02_基础知识/08_规划与导航/06_采样规划_RRT_RRT星_PRM.md)

**答案要点**
- 构型空间：描述机器人所有可能位形的参数空间，对 $n$ 轴机械臂是关节角 $\mathbf{q}\in\mathbb{R}^n$（受关节限位）；工作空间中的障碍物映射为 C-space 中的**障碍区域** $\mathcal{C}_{obs}$，自由空间 $\mathcal{C}_{free}=\mathcal{C}\setminus\mathcal{C}_{obs}$。
- 好处：把"有形状的机器人在工作空间中避障"化为"点在 C-space 中避障"，统一了规划算法；缺点：$\mathcal{C}_{obs}$ 的显式形状难以计算，只能通过**碰撞检测**黑盒查询某个 $\mathbf{q}$ 是否可行。
- 维度灾难：7 自由度臂的 C-space 为 7 维，栅格搜索不可行 → 采样 / 优化方法。
- 非欧几里得：旋转关节是圆周 $S^1$（角度环绕），距离度量需考虑周期；带基座移动时 $SE(2)\times\mathbb{R}^n$。

**English short answer**
The configuration space is the space of all robot configurations, for an arm the joint angles within limits. Workspace obstacles map to forbidden regions in it, so planning for a shaped robot becomes finding a path for a point. The obstacle region cannot be computed explicitly, so planners query a collision checker, and the dimension makes grid search infeasible for a seven-joint arm, hence sampling and optimization methods.

（译：构型空间是机器人所有位形的空间，对机械臂就是限位内的关节角；工作空间障碍映射为其中的禁区，使有形状机器人的规划变成点的路径寻找；障碍区域无法显式计算，规划器通过碰撞检测器查询，维度使得 7 轴臂无法用栅格搜索，所以采用采样和优化方法。）

**追问方向**：C-space 距离度量与周期关节；为什么不能显式构造 C-obstacle。

### Q2 机械臂的工作空间、可达空间与灵巧空间有何区别？（Workspace types）
**优先级：★★** · 对应基础知识：[正逆运动学与雅可比](../../02_基础知识/03_运动学与坐标变换/03_正逆运动学与雅可比.md)

**答案要点**
- **可达工作空间**：末端至少能以某种姿态到达的点集；**灵巧工作空间**：末端能以任意姿态到达的点集（子集）。受关节限位、连杆长度、自碰撞和奇异性约束。
- 实践：抓取规划前先判断目标是否在可达空间内；基座与物体相对位置（放置位置）决定 IK 成功率。可达图（reachability map）：离线对空间采样做 IK，统计每个位置可达姿态比例，用于选择基座位置/抓取方向。
- 7DoF 冗余臂的灵巧空间更大；6DoF 臂在边界附近姿态受限。
- 移动操作中联合基座与机械臂的可达性。

**English short answer**
The reachable workspace contains points the end effector can reach in some orientation, while the dexterous workspace contains points reachable in every orientation. Joint limits, link lengths, self-collision and singularities shape them. A reachability map built by sampling IK offline helps choose the base placement and grasp directions, and redundant arms have a larger dexterous region.

（译：可达工作空间是末端能以某种姿态到达的点集，灵巧工作空间是能以任意姿态到达的点集；关节限位、连杆长度、自碰撞和奇异性塑造它们；离线对 IK 采样构建的可达图有助于选择基座位置和抓取方向；冗余臂的灵巧区域更大。）

**追问方向**：可达图如何使用；基座选址的评价指标。

### Q3 规划中需要考虑哪些约束？（Constraints in arm planning）
**优先级：★★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- **运动学约束**：关节位置限位、速度、加速度、jerk 限制；自碰撞与环境碰撞；闭链/抓取物体约束。
- **任务约束**：末端姿态约束（端着水杯保持竖直、保持工具指向）、路径约束（沿直线、沿曲面擦拭）、关节/末端区域限制。
- **动力学约束**：力矩限制、负载（抓取物质量）、稳定性（防翻倒的底座）。
- **接触/力约束**：与环境接触时的力限幅。
- 处理：硬约束 → 采样时投影（约束流形）、拒绝；软约束 → 加入代价；MoveIt 的 `path_constraints`、方向/位置约束。
- 约束越多越易规划失败：投影采样（CBiRRT、基于 TSR）比拒绝采样高效。

**English short answer**
Planning must respect kinematic limits on position, velocity, acceleration and jerk, self and environment collisions, task constraints like keeping a cup upright or following a line, and dynamic or contact limits such as torque and force. Hard constraints are enforced by projecting samples onto the constraint manifold or rejecting them, and soft ones become costs. Rejection sampling struggles under tight constraints, so projection-based planners are preferred.

（译：规划必须遵守位置、速度、加速度、jerk 的运动学限制，自碰撞和环境碰撞，保持杯子竖直或沿直线等任务约束，以及力矩和接触力等动力学/接触限制；硬约束通过把样本投影到约束流形或拒绝来满足，软约束转为代价；约束紧时拒绝采样效率低，因此偏好基于投影的规划器。）

**追问方向**：方向约束下的采样；TSR（任务空间区域）是什么。

### Q4 数值逆运动学求解器：KDL、TRAC-IK、IKFast 怎么选？（IK solver choices）
**优先级：★★★** · 对应基础知识：[正逆运动学与雅可比](../../02_基础知识/03_运动学与坐标变换/03_正逆运动学与雅可比.md)

**答案要点**
- **KDL（牛顿–拉夫森伪逆）**：通用、简单，但易陷局部极小、对关节限位处理弱、成功率较低；**TRAC-IK**：并行运行 KDL 与带非线性优化（SQP）的求解器（含限位处理），成功率更高，ROS 常用；**IKFast**（OpenRAVE）：对给定机器人**生成解析解代码**，毫秒以下、返回所有解，但仅限满足条件的几何（如 6R 末端三轴相交——Pieper 准则）和 6DoF（7DoF 需离散化冗余参数）；**优化型 IK**（Mink / QP / Pink 类）：可加约束、多任务。
- 选择：6R 工业臂 → IKFast；7DoF/带限位 → TRAC-IK 或优化 IK；实时遥操作 → 微分 IK + 阻尼 + 限位 QP。
- 多解处理：肘上/下、腕翻转；选与当前关节最近的解，避免大范围切换；检查碰撞。
- 初值很重要：用当前关节角作为初值保证连续。

**English short answer**
KDL's Newton-Raphson pseudoinverse is simple but can get stuck and handles limits poorly, TRAC-IK runs KDL in parallel with an SQP solver that respects limits for a higher success rate, and IKFast generates closed-form solutions for a specific kinematic structure, extremely fast and returning all solutions but restricted to suitable geometries. Optimization-based IK handles constraints and multiple tasks. I seed with the current joints and choose the nearest solution to keep motion continuous.

（译：KDL 的牛顿–拉夫森伪逆简单但易陷入局部极小、对限位处理弱；TRAC-IK 并行运行 KDL 和遵守限位的 SQP 求解器，成功率更高；IKFast 为特定运动学结构生成闭式解，极快且返回所有解，但仅限合适的几何；基于优化的 IK 能处理约束和多任务；以当前关节角为初值并选择最近的解以保持运动连续。）

**追问方向**：Pieper 准则；多解之间的切换如何避免。

### Q5 笛卡尔直线路径规划与插值怎么做？（Cartesian path planning）
**优先级：★★★** · 对应基础知识：[机械臂轨迹生成_多项式_梯形速度_S曲线](../../02_基础知识/03_运动学与坐标变换/08_机械臂轨迹生成_多项式_梯形速度_S曲线.md)

**答案要点**
- 需求：末端沿直线 / 圆弧运动（插拔、涂胶、焊接、擦拭）。位置线性插值 $\mathbf{p}(s)=\mathbf{p}_0+s(\mathbf{p}_1-\mathbf{p}_0)$；姿态用 **SLERP** 球面插值 $\mathbf{q}(s)$；$s\in[0,1]$ 由速度曲线（梯形 / S 曲线）决定。
- 逐点 IK：把路径离散为密集路点，对每个路点求 IK（用上一点的解作初值）；MoveIt `computeCartesianPath`（返回成功比例 fraction，<1 表示中途失败）。
- 风险：路径穿过奇异点 / 超限 / 碰撞 → 部分失败；IK 解在相邻点之间跳变（多解切换）→ 检查关节速度；工作空间边界附近不可达。
- 对策：调整起点构型（选择肘部姿态）、冗余臂利用零空间、加阻尼、分段规划。
- 与关节空间规划对比：笛卡尔路径更可预测但可达性更差、可能触发奇异。

**English short answer**
For straight-line or arc motion, I interpolate position linearly and orientation with SLERP, parameterize by a velocity profile, and solve IK at each dense waypoint using the previous solution as the seed. MoveIt reports the fraction of the path achieved, because singularities, joint limits or collisions can interrupt it. Jumps between IK branches must be checked via joint velocities, and I fix this by choosing a better start configuration or using redundancy.

（译：直线或圆弧运动时位置线性插值、姿态用 SLERP 插值，按速度曲线参数化，并在每个密集路点用上一解作初值求 IK；MoveIt 返回已完成路径的比例，因为奇异、关节超限或碰撞会中断路径；需通过关节速度检查 IK 分支之间的跳变，并用更好的起始构型或冗余自由度解决。）

**追问方向**：SLERP 的公式；奇异点附近的笛卡尔速度处理。

### Q6 机械臂运动学标定为什么必要？怎么做？（Kinematic calibration）
**优先级：★★** · 对应基础知识：[DH参数_POE_旋量理论](../../02_基础知识/03_运动学与坐标变换/07_DH参数_POE_旋量理论.md)

**答案要点**
- 名义 DH/URDF 参数与真实几何有偏差（加工装配误差、零位误差、关节偏置），末端绝对定位误差可达毫米到厘米，重复定位精度远优于绝对精度。
- 标定：采集一批关节构型下末端实测位姿（激光跟踪仪、视觉标定板、探针接触球、约束平面）→ 优化运动学参数使预测与实测误差最小（Levenberg–Marquardt，辨识雅可比）；需要足够多样且可观的构型（激励）。
- 视觉场景：手眼标定 + 机器人本体标定；末端工具中心点（TCP）标定（多姿态指向同一点）。
- 验证：留出构型的位置误差、重复实验。
- 实务：重复定位好但绝对精度差的机器人，抓取依赖视觉闭环或示教点；换工具/重装后需重标 TCP。

**English short answer**
Nominal kinematic parameters differ from the real arm, so absolute positioning error can reach millimeters even though repeatability is excellent. I calibrate by measuring end-effector poses across diverse configurations with a tracker, camera or touch probe, then optimizing kinematic parameters to minimize prediction error. Tool center point calibration points the tool at a fixed point from several poses. I validate on held-out configurations.

（译：名义运动学参数与真实机械臂有差异，即使重复精度很好，绝对定位误差也可能达到毫米级；用跟踪仪、相机或接触探针在多样构型下测量末端位姿，再优化运动学参数使预测误差最小；TCP 标定通过多个姿态使工具指向同一固定点；在留出构型上验证。）

**追问方向**：绝对精度与重复精度的区别；TCP 标定的方程。

## 二、碰撞检测

### Q7 机械臂碰撞检测的模型与库（FCL、Bullet）？（Collision checking libraries）
**优先级：★★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 模型：机器人用连杆的**碰撞几何**（简化网格 / 凸包 / 基本体：球、胶囊、盒；比视觉网格粗得多以提速），环境用基本体、网格、八叉树 / 体素、点云。
- 流程：**宽相（broad phase）**用包围体层次（AABB 树、BVH）快速剔除不相交对 → **窄相（narrow phase）**对候选对做精确检测（GJK/EPA 求凸体距离与穿透深度；三角网格用 OBB-tree）。
- 库：**FCL**（Flexible Collision Library，MoveIt 默认）、**Bullet**、**Coal/HPP-FCL**（Pinocchio 使用）、PQP；MuJoCo 自带接触检测。
- 查询类型：布尔碰撞、**最小距离**、穿透深度、**碰撞对列表**。
- 精度与速度折中：几何越粗越快、越保守；膨胀安全边距。

**English short answer**
Robots use simplified collision geometry such as spheres, capsules and convex hulls, and environments use primitives, meshes, voxels or point clouds. A broad phase with bounding volume hierarchies discards distant pairs, then a narrow phase such as GJK computes exact distance or penetration for candidates. FCL is the default in MoveIt, with Bullet and HPP-FCL as alternatives. Coarser shapes are faster and more conservative, and I add a safety margin.

（译：机器人用球、胶囊、凸包等简化碰撞几何，环境用基本体、网格、体素或点云；宽相用包围体层次剔除远距离对，窄相用 GJK 等对候选对计算精确距离或穿透深度；FCL 是 MoveIt 默认库，Bullet 与 HPP-FCL 为替代；形状越粗越快也越保守，并加安全边距。）

**追问方向**：GJK 算法的思想；为什么碰撞几何要比视觉几何粗。

### Q8 自碰撞矩阵（ACM）是什么？（Allowed collision matrix）
**优先级：★★**

**答案要点**
- 机械臂相邻连杆在关节处几何上总是接触/重叠，不应判为碰撞；某些连杆对在整个关节范围内永不碰撞。**允许碰撞矩阵**记录哪些连杆对可以忽略检测，减少检测对数量、避免误报。
- 生成：MoveIt Setup Assistant 通过大量随机采样构型自动推断（默认碰撞、相邻、从不碰撞、总是碰撞四类），并允许手动修改。
- 运行时修改：抓取物体后把该物体与夹爪连杆设为允许碰撞（attached object），否则抓取后规划总是“碰撞”。
- 风险：误将可能碰撞的对设为允许 → 实际撞击；定期核查。
- 调试：规划失败提示 `START_STATE_IN_COLLISION` 时检查初始构型与 ACM、障碍物位置。

**English short answer**
Adjacent links always overlap at joints and some pairs can never collide, so an allowed collision matrix lists pairs to ignore, reducing checks and false positives. MoveIt's setup assistant infers it by sampling configurations. At run time a grasped object is attached to the gripper and its collisions with the fingers are allowed, otherwise planning always reports collision. Wrongly allowed pairs can cause real collisions, so I review it.

（译：相邻连杆在关节处总是重叠，有些连杆对永不碰撞，允许碰撞矩阵列出可忽略的对，减少检测次数和误报；MoveIt 设置助手通过采样构型推断它；运行时被抓取的物体附加到夹爪上并允许其与手指碰撞，否则规划总报碰撞；误允许的对可能造成真实碰撞，所以需复核。）

**追问方向**：attached object 的作用；START_STATE_IN_COLLISION 的常见成因。

### Q9 连续碰撞检测与离散检测的差异？（Continuous vs discrete collision checking）
**优先级：★★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 规划器通常只检查离散采样点（构型 / 边上间隔点）。若相邻点间距大于障碍物厚度，可能"穿过"薄障碍（隧穿）。
- 解决：①**边的检查分辨率**（沿边按步长 $\le\epsilon$ 采样，步长依据最大连杆速度和障碍尺寸）；②**连续碰撞检测（CCD）**：计算扫掠体积（swept volume）或使用 conservative advancement（用距离和速度上界推进到安全时间）保证两构型之间无碰撞；③障碍膨胀。
- 取舍：CCD 精确但慢；离散 + 足够密 + 膨胀是实用方案。
- 轨迹执行阶段：高速时执行轨迹的路点要比规划边更密，且控制器跟踪误差可能引起偏离 → 留安全裕度。
- 经验：MoveIt `longest_valid_segment_fraction` 参数控制边检查分辨率。

**English short answer**
Planners check discrete samples, so if consecutive configurations are farther apart than a thin obstacle's thickness, the motion can tunnel through it. I limit the edge check step based on link speed and obstacle size, or use continuous collision detection with swept volumes or conservative advancement, and I inflate obstacles. Execution tracking error can still deviate from the checked path, so I keep a safety margin.

（译：规划器检查的是离散样本，如果相邻构型间距大于薄障碍的厚度，运动可能穿过它；根据连杆速度和障碍尺寸限制边检查的步长，或用基于扫掠体积或保守推进的连续碰撞检测，并膨胀障碍；执行时的跟踪误差仍可能偏离已检查路径，所以要留安全裕度。）

**追问方向**：conservative advancement 的原理；轨迹执行误差的裕度怎么定。

### Q10 点云/八叉树障碍物在规划中的表示与代价？（Environment representation for planning）
**优先级：★★** · 对应基础知识：[建图表示_栅格_八叉树_NDT_TSDF_ESDF](../../02_基础知识/07_SLAM与建图/06_建图表示_栅格_八叉树_NDT_TSDF_ESDF.md)

**答案要点**
- 感知的环境以点云 / 深度图进入规划场景：**八叉树（OctoMap）**体素化（分辨率 1–5 cm），碰撞检测对体素盒；或直接对点云做球近似；或 **ESDF/TSDF**（nvblox）提供距离与梯度（用于 CHOMP/TrajOpt）。
- 问题：机器人自身点被当作障碍（需要**自身过滤 / 机器人遮罩**：根据当前关节状态把机器人模型点剔除）；噪声点造成"幽灵障碍"（滤波、体素置信度）；动态物体残影；夹持物体点云应并入机器人而非环境。
- 更新延迟与规划一致性：规划期间场景更新可能使计划失效 → 执行前再验证。
- 计算：体素分辨率越细检测越慢，常 3 cm 左右的折中；GPU 距离场（cuRobo）加速。
- 已知物体（桌面、箱子）用基本几何体代替点云更准更快。

**English short answer**
Perceived environments enter the planning scene as an octree of voxels at a few centimeters, as a point cloud approximated by spheres, or as an ESDF that gives distance and gradients for optimization planners. The robot's own points must be filtered out using its current joint state, noise and dynamic ghosts need filtering, and a grasped object should be attached to the robot. Known objects such as tables are better modeled as primitives for speed and accuracy.

（译：感知到的环境以几厘米分辨率的八叉树体素、用球近似的点云，或为优化规划器提供距离与梯度的 ESDF 进入规划场景；必须按当前关节状态滤除机器人自身的点，处理噪声和动态残影，被抓物体应附加到机器人；桌面等已知物体用基本几何体建模更快更准。）

**追问方向**：自身过滤的实现；ESDF 在规划中的优势。

### Q11 安全边距（膨胀）如何设置？过大或过小的后果？（Safety margin tuning）
**优先级：★★★** · 对应基础知识：[功能安全基础_急停_安全链_ISO13849与IEC61508](../../02_基础知识/13_系统工程与安全/02_功能安全基础_急停_安全链_ISO13849与IEC61508.md)

**答案要点**
- 来源：感知误差（深度噪声、标定误差）、模型误差（碰撞几何与真实不符）、执行跟踪误差、延迟，加上环境不确定性。边距 ≈ 这些误差上界之和（再留余量）。例（教学）：标定 3 mm + 深度噪声 5 mm + 跟踪误差 3 mm → 边距取 2 cm。
- 过小：规划结果在执行中擦碰；过大：狭窄空间（抽屉、货架）找不到解或绕远路，起始/目标状态本身“在碰撞中”。
- 策略：分层边距——远离障碍用大边距（安全），接近目标/抓取时减小或对目标物体放宽（允许接触）；规划使用较大边距，执行使用较小边距；对不同障碍类别（人、易碎品、静态结构）设不同边距。
- 验证：测量实际最小间距分布；调参依据日志。

**English short answer**
The margin should cover the sum of perception error, model error, tracking error and delay, with some reserve. Too small a margin causes scraping during execution, too large a margin makes narrow spaces unsolvable and puts start or goal states in collision. I use larger margins while moving through free space, relax them for the target object during approach and grasp, apply different values per obstacle class, and tune from measured clearances.

（译：边距应涵盖感知误差、模型误差、跟踪误差和延迟之和并留有余量；过小会在执行中擦碰，过大则使狭窄空间无解并使起点或目标处于碰撞状态；自由空间移动时用较大边距，接近和抓取目标物体时放宽，按障碍类别设不同值，并依据实测间距调参。）

**追问方向**：目标物体边距放宽如何实现；人体边距为何更大。

### Q12 RRT-Connect 为什么在机械臂规划中最常用？（RRT-Connect）
**优先级：★★★** · 对应基础知识：[采样规划_RRT_RRT星_PRM](../../02_基础知识/08_规划与导航/06_采样规划_RRT_RRT星_PRM.md)

**答案要点**
- 双向树：从起点和目标各长一棵树，交替扩展并**贪心地尝试连接**（一棵树的新节点向另一棵树的最近节点反复延伸直到被阻挡或连接成功）。收敛极快，高维空间中典型问题毫秒到秒级。
- 概率完备（有解则以概率 1 找到），但**不最优**、路径抖动，必须后处理（shortcut + 平滑）。
- 需要：目标是单个构型（需先做 IK 得到若干目标构型；目标区域可用多个 IK 解初始化多棵目标树）。
- 与 RRT*：RRT* 渐近最优但慢，机械臂常用 RRT-Connect 快速找解再优化；实时重规划时更适合。
- OMPL 默认（MoveIt 里 `RRTConnectkConfigDefault`）。

**English short answer**
RRT-Connect grows trees from both start and goal and repeatedly tries to connect them greedily, which finds paths in high-dimensional arm configuration spaces very quickly. It is probabilistically complete but not optimal and produces jerky paths, so shortcutting and smoothing follow. It needs concrete goal configurations from IK, and it is the default planner in MoveIt through OMPL.

（译：RRT-Connect 从起点和目标同时生长树并反复贪心尝试连接，在高维机械臂构型空间里能很快找到路径；概率完备但不最优且路径抖动，需要随后做捷径和平滑；需要由 IK 给出具体目标构型；它通过 OMPL 成为 MoveIt 的默认规划器。）

**追问方向**：为什么双向树更快；多目标构型如何处理。

### Q13 PRM 与 RRT 在机械臂中的取舍？（PRM vs RRT）
**优先级：★★** · 对应基础知识：[采样规划_RRT_RRT星_PRM](../../02_基础知识/08_规划与导航/06_采样规划_RRT_RRT星_PRM.md)

**答案要点**
- **PRM（概率路线图）**：预先在 C-space 采样并连接成图（构建阶段），查询时只做图搜索；适合**静态环境、多次查询**（工位固定的重复作业）；环境变化需重建/修复；窄通道（窄缝）采样困难（桥测试、高斯采样改进）。
- **RRT 类**：单次查询、无需预处理、适合变化环境；每次从头长树。
- 变体：**lazy PRM**（延迟碰撞检测）、PRM*、Experience-based（缓存历史路径复用，如 MoveIt 的 lightning/thunder）。
- 选择：工位固定、频繁重复 → PRM 或经验库；任务多变、障碍动态 → RRT-Connect；需要最优 → RRT* / 优化后处理。
- 离线预计算可结合学习的采样分布。

**English short answer**
PRM builds a roadmap of sampled configurations once and answers queries by graph search, which is efficient for static workcells with repeated tasks but needs repair when the environment changes and struggles in narrow passages. RRT-type planners need no preprocessing and suit changing scenes but start from scratch each query. Lazy PRM and experience-based planners reuse previous work, and I choose by how static the scene is.

（译：PRM 一次性构建采样构型路线图，查询时只做图搜索，适合重复作业的静态工位，但环境变化时需修复且在窄通道中困难；RRT 类规划器无需预处理，适合多变场景，但每次查询从头开始；lazy PRM 和基于经验的规划器复用既有成果，按场景的静态程度选择。）

**追问方向**：窄通道采样的改进；经验库的检索方法。

### Q14 RRT* 与 BIT*、FMT* 等渐近最优规划器的区别？（Asymptotically optimal planners）
**优先级：★★** · 对应基础知识：[采样规划_RRT_RRT星_PRM](../../02_基础知识/08_规划与导航/06_采样规划_RRT_RRT星_PRM.md)

**答案要点**
- **RRT***：在 RRT 上加入“近邻选父”与“重连（rewire）”，随着样本增多路径代价收敛到最优（渐近最优），但收敛慢，高维时代价高。
- **PRM***：连接半径随样本数缩放以保证渐近最优；**FMT***（Fast Marching Tree）：批量采样 + 动态规划式扩展，批量时效率高；**BIT***（批量信息树）：结合图搜索（A*）与采样，利用启发式只处理可能改进当前解的样本（Informed 采样椭圆区域），收敛更快；**Informed RRT***：找到首个解后只在椭球内采样。
- 机械臂实践：RRT-Connect 找可行解 → 用 BIT*/RRT* 在时间预算内改进，或直接用 shortcut / 优化后处理。
- 代价函数：路径长度、关节运动量、到障碍距离；"最优"取决于代价定义。

**English short answer**
RRT* adds nearest-neighbor parent selection and rewiring so the path cost converges to the optimum as samples grow, but slowly in high dimensions. FMT* and BIT* process batches of samples with dynamic-programming or A*-style search, and informed sampling restricts new samples to the ellipsoid that can improve the current solution. In practice I get a feasible path quickly and improve it within a time budget or with shortcutting and trajectory optimization.

（译：RRT* 通过近邻选父和重连使路径代价随样本增多收敛到最优，但在高维时较慢；FMT* 和 BIT* 对批量样本做类动态规划或 A* 式搜索，信息采样把新样本限制在能改进当前解的椭球内；实践中先快速得到可行路径，再在时间预算内改进或用捷径与轨迹优化后处理。）

**追问方向**：信息采样椭球的构造；RRT* 重连的代价。

### Q15 路径后处理：shortcut 与平滑怎么做？（Path shortcutting and smoothing）
**优先级：★★★** · 对应基础知识：[采样规划_RRT_RRT星_PRM](../../02_基础知识/08_规划与导航/06_采样规划_RRT_RRT星_PRM.md)

**答案要点**
- 采样规划的原始路径冗余且折线抖动。**Shortcut**：随机选路径上两点，若直线（C-space）无碰撞则替换中间部分；重复多次；也可配合"部分捷径"（沿各关节独立缩短）。**平滑**：对路点做样条拟合（B 样条 / 三次样条）后重新检查碰撞；或以优化方法最小化加速度 / jerk。
- 约束：每次修改必须重做碰撞检查；路点之间的插值要保持关节速度可行；平滑不能把路径推入障碍（先膨胀安全距离）。
- 随后做时间参数化，得到轨迹。
- 现象与调试：路径看起来绕大圈（采样路径未后处理）；平滑后碰撞（缺少复检）。
- 工程：MoveIt 的 `AddTimeOptimalParameterization`、`SimplifyPath`、`ShortcutPath` 适配器。

**English short answer**
Raw sampled paths are jagged and redundant. Shortcutting repeatedly picks two points and replaces the segment between them by a straight configuration-space line if it is collision-free, and smoothing fits splines or minimizes acceleration. Every modification must be re-checked for collisions, with margins so smoothing does not push into obstacles. Time parameterization follows to produce an executable trajectory.

（译：采样得到的原始路径抖动且冗余；捷径法反复选取路径上两点，若它们的构型空间直线无碰撞就替换其间部分，平滑则拟合样条或最小化加速度；每次修改都必须重新检查碰撞并留裕度以免平滑把路径推入障碍；随后进行时间参数化得到可执行轨迹。）

**追问方向**：shortcut 的迭代次数；平滑前后碰撞复检的实现。

### Q16 规划失败时如何系统排查？（Debugging planning failures）
**优先级：★★★** · 对应基础知识：[测试策略_仿真在环_硬件在环_回归](../../02_基础知识/13_系统工程与安全/04_测试策略_仿真在环_硬件在环_回归.md)

**答案要点**
- 先看错误码：`START_STATE_IN_COLLISION`（起始状态碰撞：机器人真实姿态已贴近障碍、ACM、点云包含机器人自身、attached object 未设置）；`GOAL_IN_COLLISION`（目标位姿在障碍内/IK 无解/超限）；`TIMED_OUT`（时间预算不足、路径极窄、约束过紧）；`NO_IK_SOLUTION`（目标不可达、奇异、关节限位）；`INVALID_MOTION_PLAN`（执行前场景变化）。
- 排查：①可视化规划场景（RViz Planning Scene）看障碍物是否合理；②单独测试 IK 是否有解；③关闭障碍或增大时间/尝试次数；④检查关节限位与起始状态是否在限内；⑤降低约束（去掉路径约束）看是否成功；⑥更换规划器/参数；⑦查看碰撞距离（找出冲突的连杆对）。
- 规划成功率统计：对随机目标重复规划，统计成功率、耗时、路径长度，定位系统性问题。
- 预防：给起点/目标留裕度，边距合理，必要时分阶段（先到过渡点）。

**English short answer**
I read the error code first: start in collision usually means the robot's real pose touches an obstacle or the allowed collision matrix or attached object is wrong, goal in collision or no IK solution means the target is unreachable, and a timeout suggests tight constraints or narrow passages. Then I visualize the planning scene, test IK separately, relax constraints, enlarge time budgets, check joint limits and inspect which link pair collides. Repeating planning on random goals gives success statistics that reveal systematic issues.

（译：先看错误码：起点碰撞通常意味着机器人真实姿态贴近障碍或允许碰撞矩阵、附加物体设置有误，目标碰撞或无 IK 解说明目标不可达，超时提示约束过紧或通道狭窄；然后可视化规划场景、单独测试 IK、放宽约束、增加时间预算、检查关节限位并查看是哪对连杆碰撞；对随机目标重复规划得到的成功率统计能暴露系统性问题。）

**追问方向**：如何定位冲突连杆对；成功率统计的实验设计。

### Q17 带姿态约束的规划（如端水杯）如何实现？（Orientation-constrained planning）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 约束为一个低维流形（如末端 z 轴保持竖直，容差 ±5°）。采样得到的构型一般不满足约束，需要**投影**到约束流形：对构型 $\mathbf{q}$ 迭代 $\mathbf{q}\leftarrow\mathbf{q}-\mathbf{J}^{+}\mathbf{e}(\mathbf{q})$ 直到约束误差小于容差（OMPL 的 `ProjectedStateSpace`）；边的连接也要在流形上逐步插值并投影。
- **TSR（任务空间区域）/ CBiRRT** 表示与采样；**约束优化型**（TrajOpt）直接把约束写进代价/约束；MoveIt 的 `path_constraints`（OrientationConstraint）较慢，常需增大规划时间。
- 注意：容差设置过小则采样几乎不满足，规划失败；起止状态本身须满足约束。
- 另一思路：先在无约束下规划，再用任务空间控制保持姿态（对局部偏差有效，大改动无效）。
- 应用：端液体、持刀具、装配时保持朝向。

**English short answer**
Orientation constraints define a low-dimensional manifold, so sampled configurations are projected onto it with iterations of the Jacobian pseudoinverse on the constraint error, and edges are interpolated and projected step by step, as in OMPL's projected state space or CBiRRT with task-space regions. Optimization planners can include the constraint directly. A tolerance that is too tight makes planning fail, and the start and goal must satisfy the constraint themselves.

（译：姿态约束定义了低维流形，采样构型通过对约束误差迭代雅可比伪逆投影到流形上，边也逐步插值并投影（如 OMPL 的投影状态空间或带任务空间区域的 CBiRRT）；优化型规划器可直接纳入约束；容差过紧会导致规划失败，起点和目标本身必须满足约束。）

**追问方向**：投影收敛判据；TSR 的定义。

### Q18 动态障碍与实时重规划在机械臂上怎么处理？（Replanning with moving obstacles）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 场景：人进入工作区、传送带上的物体、协作任务。
- 方法：①**快速全局重规划**（RRT-Connect 亚秒级，或 GPU 规划器 cuRobo 毫秒级）+ 滚动执行；②**局部反应式**：势场 / 速度分离 / 基于距离的速度缩放（见安全）；③**时空规划**（障碍物预测轨迹，在 $(\mathbf{q},t)$ 空间规划）；④轨迹优化的在线版（MPC 式，滚动时域，距离场惩罚）；⑤经验库复用。
- 关键：感知更新频率与延迟、障碍预测、规划时间预算 < 障碍变化时间；重规划与执行衔接（从当前执行状态出发、保持速度连续）。
- 降级：无法在时限内规划 → 减速/停止（保守）。

**English short answer**
For moving obstacles I combine fast replanning, for example sub-second RRT-Connect or GPU-based planners, with reactive layers such as distance-based speed scaling, and sometimes plan in space-time using predicted obstacle motion or run receding-horizon trajectory optimization with distance penalties. The planning time must be shorter than the scene changes, replans start from the current dynamic state with continuous velocity, and failure leads to slowing or stopping.

（译：对移动障碍，结合快速重规划（如亚秒级 RRT-Connect 或基于 GPU 的规划器）与基于距离的速度缩放等反应层，有时利用预测的障碍运动在时空中规划，或运行带距离惩罚的滚动时域轨迹优化；规划时间必须短于场景变化，重规划从当前动态状态出发并保持速度连续，失败则减速或停止。）

**追问方向**：速度连续的衔接做法；障碍预测的不确定性。

## 四、优化型轨迹规划

### Q19 CHOMP 的思想与特点？（CHOMP）
**优先级：★★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 协变哈密顿优化运动规划：把轨迹 $\xi$（离散路点序列）看作变量，最小化 $\mathcal{U}(\xi)=\mathcal{F}_{smooth}(\xi)+\lambda\mathcal{F}_{obs}(\xi)$：平滑项（速度/加速度平方积分）+ 障碍项（用 **ESDF / 距离场**在工作空间中沿机器人表面点积分的代价，距离越近代价越高，梯度推离障碍）。
- 用**协变梯度下降**（梯度乘以平滑度量逆）使更新保持轨迹平滑；通常从直线初值开始。
- 优点：产生平滑、远离障碍的轨迹；有梯度信息利用（比纯采样“更有方向”）；可并行。
- 缺点：局部最优（初值依赖，被障碍卡住）；需要距离场；硬约束（关节限位、碰撞为零）通过惩罚/投影近似，不保证无碰撞；常需后验碰撞检查。
- 使用：MoveIt 中作为规划器适配器，常用于对 RRT 结果平滑（"采样 + CHOMP"）。

**English short answer**
CHOMP treats the trajectory as a vector of waypoints and minimizes a smoothness cost plus an obstacle cost computed from a signed distance field over the robot's body points, using covariant gradient descent that preserves smoothness. It yields smooth, clearance-rich trajectories and exploits gradients, but it is a local method that depends on the initial guess and does not guarantee collision-free output, so it is often run after a sampling planner.

（译：CHOMP 把轨迹视为路点向量，最小化平滑代价加上由有符号距离场沿机器人表面点计算的障碍代价，使用保持平滑性的协变梯度下降；产生平滑且间隙充足的轨迹并利用梯度，但它是局部方法，依赖初值且不保证无碰撞，所以常在采样规划器之后运行。）

**追问方向**：协变梯度的含义；障碍代价函数的形状。

### Q20 TrajOpt 的序列凸规划（SCP）思路？（TrajOpt）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 把规划写成**带约束的非线性优化**：变量为各时间步的关节角 $\mathbf{q}_t$；目标最小化路径长度（或平方位移）；约束：碰撞距离 $d(\mathbf{q}_t)\ge d_{safe}$（用 **有符号距离 + 凸–凸碰撞线性化**得到可导近似）、关节限位、末端位姿约束。
- 求解：**序列凸规划**——每次迭代在当前解附近把非线性约束线性化，得到凸 QP，用信赖域限制步长，**惩罚法**把约束违反加入目标并逐步增大惩罚系数。**连续碰撞检测**（对相邻时间步之间的扫掠体积约束）保证两路点之间无碰撞。
- 优点：能严格处理碰撞约束（接近硬约束）、可加入多种代价/约束（末端路径、速度），初始轨迹可不可行；比 CHOMP 更强处理“初值在障碍里”的情形；缺点：局部极小、计算较重、需要凸体形状。
- 现代：cuRobo 等 GPU 实现并行多初值。

**English short answer**
TrajOpt poses planning as a constrained nonlinear program over waypoint joint angles, minimizing path length subject to signed-distance collision constraints, joint limits and task constraints. It solves it by sequential convex programming: linearize the constraints, solve a trust-region QP and increase penalty weights, with swept-volume continuous collision checking between waypoints. It handles collisions more rigorously than CHOMP and tolerates infeasible initial guesses, but remains local and costly.

（译：TrajOpt 把规划表述为对路点关节角的约束非线性规划，在有符号距离碰撞约束、关节限位和任务约束下最小化路径长度；用序列凸规划求解：线性化约束、解信赖域 QP 并逐步增大惩罚权重，并对相邻路点之间的扫掠体积做连续碰撞检查；比 CHOMP 更严格地处理碰撞并容忍不可行初值，但仍是局部方法且计算较重。）

**追问方向**：惩罚法的增大策略；凸–凸碰撞线性化。

### Q21 STOMP 与基于采样的随机优化轨迹规划？（STOMP）
**优先级：★★**

**答案要点**
- STOMP（随机轨迹优化）：对当前轨迹添加平滑噪声生成 $K$ 条扰动轨迹，计算每条的代价（碰撞、平滑、约束等任意可评估量，**无需梯度**），按代价概率加权平均更新轨迹（类似路径积分/MPPI）；迭代直至收敛。
- 优点：**无梯度**，可优化不可微代价（任意代价函数、接触、规则）；对噪声和局部极小有一定鲁棒；易并行。
- 缺点：需多次评估（采样数×迭代）；收敛慢于梯度法；平滑噪声设计很重要。
- 与 CEM/MPPI 的关系：同为零阶随机优化；机器人规划中可用于带复杂代价（如操作任务评分）。

**English short answer**
STOMP perturbs the current trajectory with smooth noise to create rollouts, evaluates each with arbitrary cost terms without gradients and updates the trajectory by a cost-weighted average, similar to path-integral methods such as MPPI. It can optimize non-differentiable costs and is easy to parallelize, but needs many evaluations and converges more slowly than gradient methods.

（译：STOMP 用平滑噪声扰动当前轨迹生成多条 rollout，无需梯度地用任意代价项评估每条，并按代价加权平均更新轨迹，类似 MPPI 等路径积分方法；能优化不可微代价且易并行，但需要大量评估，收敛慢于梯度法。）

**追问方向**：平滑噪声如何生成；与 CHOMP 的取舍。

### Q22 GPU 加速运动规划（cuRobo）带来了什么？（GPU-accelerated planning）
**优先级：★★**

**答案要点**
- 思想：把 FK、碰撞距离查询（球近似机器人 vs 距离场/网格）、轨迹优化的大量并行评估放到 GPU，**并行多种子**（数十到数百条候选）同时优化，最后选最优；规划时间降至毫秒–数十毫秒，使**实时重规划、反应式避障**可行。
- 特点：用球集合近似机器人碰撞几何；环境用 ESDF/TSDF（nvblox）或网格；IK 和轨迹生成统一；支持批量。
- 取舍：需要 NVIDIA GPU；近似几何保守；与现有 MoveIt 生态对接（有 MoveIt 插件）；结果仍是局部最优（多种子缓解）。
- 意义：规划不再是“慢速一次性”，可闭环运行于感知之上。
- 面试：知道“并行多种子轨迹优化 + 球近似碰撞 + 距离场”即可。

**English short answer**
GPU planners evaluate forward kinematics, collision distances against a distance field and trajectory costs for many seeds in parallel, bringing planning to milliseconds so replanning and reactive avoidance become feasible. They approximate the robot by spheres, take environments as ESDFs from sources like nvblox, and pick the best of many local optima. They require NVIDIA GPUs and conservative geometry, but turn planning from a slow step into a feedback-rate capability.

（译：GPU 规划器并行评估大量种子的正运动学、对距离场的碰撞距离和轨迹代价，使规划缩短到毫秒级，从而使重规划与反应式避障成为可能；它们用球近似机器人、以 nvblox 等生成的 ESDF 作为环境，并在众多局部最优中选最优；需要 NVIDIA GPU 且几何近似较保守，但使规划从慢速步骤变为反馈频率级的能力。）

**追问方向**：球近似的保守性；多种子策略的覆盖。

### Q23 采样规划与优化规划如何组合使用？（Hybrid planning strategies）
**优先级：★★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 采样法：**全局性、概率完备**，能绕过复杂障碍找到可行路径，但不平滑、不最优；优化法：**局部性、依赖初值**，产生平滑近优轨迹，处理复杂代价/约束方便。
- 常见组合：RRT-Connect（可行解）→ shortcut → **CHOMP / TrajOpt / 时间最优参数化**（优化）；或多初值优化 + 采样兜底（优化失败回退采样规划）。
- 实时系统：先用经验/缓存路径作为初值；失败时调用全局规划；执行层再做局部反应。
- 评价：成功率、耗时（P95）、轨迹质量（长度、jerk、间隙）、可重复性。
- 选择依据：环境复杂度、实时性、质量要求、是否有梯度/距离场。

**English short answer**
Sampling planners are global and probabilistically complete but yield jagged paths, whereas optimization planners are local and need good initial guesses but give smooth, near-optimal trajectories. A typical pipeline finds a feasible path with RRT-Connect, shortcuts it, then refines it with CHOMP, TrajOpt or time-optimal parameterization, falling back to sampling when optimization fails. I evaluate success rate, tail latency and trajectory quality.

（译：采样规划器全局、概率完备，但路径抖动；优化规划器局部、依赖好初值，但给出平滑近优轨迹；典型流水线先用 RRT-Connect 找可行路径，经捷径处理，再用 CHOMP、TrajOpt 或时间最优参数化精化，优化失败时回退到采样；评估成功率、尾延迟与轨迹质量。）

**追问方向**：优化失败回退的触发条件；轨迹质量的度量。

### Q24 规划代价函数设计：长度、平滑、间隙、关节限位怎么权衡？（Cost function design）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 常见项：**路径长度**（C-space 或末端空间）、**平滑**（速度 / 加速度 / jerk 平方）、**障碍间隙**（距离的倒数或指数惩罚）、**关节限位**（靠近限位惩罚）、**能耗/力矩**、**可操作度**（远离奇异：最大化 $w=\sqrt{\det JJ^\top}$）、任务特定（末端轨迹偏差）。
- 权重取舍：间隙权重大 → 绕远路，路径长；平滑权重大 → 轨迹圆滑但可能偏离最短；需要在不同场景下标定权重或做层次化优化（先满足硬约束，再优化次要目标）。
- 单位与量纲：不同项数值量级差异大，需要归一化。
- 调参方法：固定一组基准场景，改变权重观察指标（碰撞率、时间、jerk）；用帕累托思想选择。

**English short answer**
Typical terms include path length, smoothness of velocity, acceleration or jerk, obstacle clearance, joint limit proximity, energy and manipulability to stay away from singularities, plus task-specific terms. Heavy clearance weights cause detours and heavy smoothness weights move away from the shortest path, so I normalize terms and tune weights on benchmark scenes, or use a hierarchy of hard constraints first and secondary objectives afterwards.

（译：典型代价项有路径长度、速度/加速度/jerk 平滑度、障碍间隙、接近关节限位程度、能耗以及用于远离奇异的可操作度，再加任务特定项；间隙权重大会绕远路，平滑权重大会偏离最短路径，所以对各项归一化并在基准场景上调权重，或先满足硬约束再优化次要目标。）

**追问方向**：可操作度作为代价的梯度；层次优化的实现。

## 五、时间参数化与轨迹执行

### Q25 路径（path）与轨迹（trajectory）有什么区别？为什么要时间参数化？（Path vs trajectory）
**优先级：★★★** · 对应基础知识：[机械臂轨迹生成_多项式_梯形速度_S曲线](../../02_基础知识/03_运动学与坐标变换/08_机械臂轨迹生成_多项式_梯形速度_S曲线.md)

**答案要点**
- **路径**：C-space 中的几何曲线 $\mathbf{q}(s)$，$s\in[0,1]$，不含时间；**轨迹**：带时间的 $\mathbf{q}(t)$（含速度、加速度），可直接送控制器执行。
- **时间参数化**：选择 $s(t)$ 使轨迹满足速度、加速度、jerk 限制并尽量快（时间最优）。路径速度 $\dot s$ 受每个关节 $|\dot q_i|=|q_i'(s)\dot s|\le\dot q_{i,max}$ 限制。
- 方法：梯形速度曲线、S 曲线（限 jerk）、三次/五次多项式、**TOTG**（时间最优轨迹生成，沿路径用相平面法，MoveIt 的 `TimeOptimalTrajectoryGeneration`）、**TOPP-RA**（可达集方法）、**Ruckig**（在线实时 jerk 受限轨迹生成）。
- 常见错误：直接把规划路径喂给控制器 → 没有时间/速度，会"瞬移"；或速度过快超限被驱动器报警。

**English short answer**
A path is a geometric curve in configuration space without timing, while a trajectory assigns time so velocities and accelerations are defined and can be executed. Time parameterization chooses the speed along the path to satisfy joint velocity, acceleration and jerk limits while staying fast, with methods such as trapezoidal or S-curve profiles, time-optimal TOTG or TOPP-RA, and Ruckig for online generation. Sending a bare path to a controller would cause undefined motion.

（译：路径是构型空间中不含时间的几何曲线，轨迹则赋予时间，使速度与加速度有定义并可执行；时间参数化选择沿路径的速度，在满足关节速度、加速度、jerk 限制的同时尽量快，方法有梯形或 S 曲线、时间最优的 TOTG 或 TOPP-RA、用于在线生成的 Ruckig；把裸路径直接交给控制器会导致运动未定义。）

**追问方向**：TOTG 的相平面思想；为什么 jerk 限制重要。

### Q26 梯形速度曲线、S 曲线与五次多项式的区别？（Velocity profiles）
**优先级：★★★** · 对应基础知识：[机械臂轨迹生成_多项式_梯形速度_S曲线](../../02_基础知识/03_运动学与坐标变换/08_机械臂轨迹生成_多项式_梯形速度_S曲线.md)

**答案要点**
- **梯形速度**：加速（恒加速度）→ 匀速 → 减速，位置 $C^1$，加速度阶跃（jerk 无限大）→ 对机械冲击大、易激励谐振；时间最优（在速度/加速度限制下）。
- **S 曲线（7 段）**：加速度也线性变化（恒 jerk 段），加速度连续，更平稳，时间略长；工业机器人/数控常用。
- **五次多项式**：给定起止位置、速度、加速度（6 个边界条件）解出 5 次多项式，位置/速度/加速度连续，jerk 有限；简单，适合点到点关节运动；不保证满足速度极值约束（需检查）。
- 选择：要速度/加速度极限最优 → 梯形；要平稳 → S 曲线；软启停简单实现 → 五次多项式。
- 多关节同步：以最慢关节确定总时间，其他关节缩放，保证同时到达（直线路径在关节空间）。

**English short answer**
A trapezoidal profile accelerates at a constant rate, cruises and decelerates, which is time-optimal under limits but has discontinuous acceleration and thus infinite jerk. An S-curve limits jerk so acceleration is continuous, giving smoother motion at a slightly longer duration. A quintic polynomial meets position, velocity and acceleration boundary conditions with finite jerk, but extremes must be checked. For multiple joints I synchronize by scaling to the slowest joint.

（译：梯形曲线以恒定加速度加速、匀速、减速，在限制下时间最优，但加速度不连续因而 jerk 无穷大；S 曲线限制 jerk 使加速度连续，运动更平稳但略慢；五次多项式满足位置、速度、加速度边界条件且 jerk 有限，但需检查极值；多关节通过缩放到最慢关节实现同步。）

**追问方向**：五次多项式系数的求解；S 曲线七个阶段。

### Q27 Ruckig 与在线轨迹生成的价值？（Online trajectory generation）
**优先级：★★**

**答案要点**
- 问题：目标在运行时变化（视觉伺服、遥操作、传感器触发），需要从**任意当前状态**（位置、速度、加速度）实时生成到新目标的**时间最优、jerk 受限、状态连续**的轨迹，周期 1 ms 级。
- Ruckig：开源在线轨迹生成库，支持多自由度同步、位置/速度控制接口、中间路点、运动学限制（速度、加速度、jerk），计算时间微秒级。
- 好处：目标突变时平滑过渡（不会出现速度阶跃），统一遥操作与自主运动；替代手写梯形规划。
- 对比离线时间参数化（TOTG）：离线针对已知完整路径；在线针对"当前状态 → 目标状态"。
- 注意：与控制器的接口（发布位置/速度指令的周期与保持）、限幅与安全检查。

**English short answer**
When targets change at run time, as in visual servoing or teleoperation, an online generator computes a time-optimal, jerk-limited trajectory from the current position, velocity and acceleration to the new target within a control cycle. Ruckig does this for multiple degrees of freedom in microseconds, giving smooth transitions without velocity jumps. Offline time parameterization instead handles a known complete path.

（译：当视觉伺服或遥操作等使目标在运行时变化，在线生成器在一个控制周期内计算从当前位置、速度、加速度到新目标的时间最优且 jerk 受限的轨迹；Ruckig 以微秒级耗时完成多自由度计算，目标突变时过渡平滑、无速度跳变；离线时间参数化则处理已知的完整路径。）

**追问方向**：状态连续性的意义；Ruckig 与 MoveIt Servo 的结合。

### Q28 轨迹如何下发给控制器？ROS 2 的 JointTrajectoryController？（Trajectory execution interface）
**优先级：★★★** · 对应基础知识：[ros2_control与硬件接口实战](../../02_基础知识/12_机器人软件/14_ros2_control与硬件接口实战.md)

**答案要点**
- 轨迹消息 `trajectory_msgs/JointTrajectory`：一串 `JointTrajectoryPoint`（时间 `time_from_start`、位置、速度、加速度）；通过 `FollowJointTrajectory` Action（带目标容差、反馈、取消）发送。
- `joint_trajectory_controller`（ros2_control）：在 1 kHz 控制循环中对轨迹点按时间**插值**（样条：线性/三次/五次，取决于给定的速度/加速度）得到当前期望，再交给硬件接口的位置/速度/力矩命令；检查路径容差（偏差超限则中止）与目标容差。
- 要点：轨迹时间戳起点（`header.stamp` 为 0 表示立即开始）；点与点的时间间隔、速度一致性；插值阶数对应质量；硬件接口命令类型；`stop_trajectory_duration`、取消/抢占行为。
- 常见问题：轨迹被拒绝（关节名、顺序、限位）、跟踪误差大触发容差、起点与当前状态不一致导致跳变（需第一点 = 当前状态）。
- 分层：规划 → 时间参数化 → 轨迹控制器 → 低层电机控制（PID/阻抗/电流环）。

**English short answer**
A JointTrajectory message carries timed waypoints with positions, velocities and accelerations and is sent through the FollowJointTrajectory action, which supports tolerances, feedback and cancellation. The ros2_control joint trajectory controller interpolates the points in its real-time loop with linear, cubic or quintic splines, checks path and goal tolerances and passes the setpoint to the hardware interface. The first point must match the current state to avoid jumps, and joint names and limits must be consistent.

（译：JointTrajectory 消息携带带时间的路点（位置、速度、加速度），通过支持容差、反馈与取消的 FollowJointTrajectory Action 发送；ros2_control 的关节轨迹控制器在实时循环中用线性、三次或五次样条对路点插值、检查路径与目标容差并把设定值交给硬件接口；第一个点必须与当前状态一致以免跳变，关节名与限位必须一致。）

**追问方向**：路径容差与目标容差的区别；轨迹被抢占时的行为。

### Q29 MoveIt Servo 与实时遥操作的做法？（MoveIt Servo）
**优先级：★★**

**答案要点**
- 用途：**实时笛卡尔 / 关节速度控制**（手柄、空间鼠标、VR 遥操作、视觉伺服），不是完整规划。输入 `TwistStamped`（笛卡尔速度）或关节增量，内部用雅可比伪逆（带阻尼）转为关节速度，发布 `JointTrajectory`/速度指令。
- 安全特性：**奇异点附近减速**（根据条件数或最小奇异值缩放速度）、**关节限位减速**、**碰撞检测减速/停止**（基于距离）、加速度/jerk 限制、超时停止。
- 与规划的区别：不全局避障（只局部检测碰撞），可能陷入局部困境；适用于连续人机交互。
- P2 的对应：遥操作需要将操作者的运动映射为末端目标并求受约束逆解（微分 IK + 阻尼 + 限位），道理相通（项目使用 MuJoCo / Mink 的受约束逆解，具体实现以项目文档为准）。
- 参数：发布周期、速度缩放、奇异阈值（`lower_singularity_threshold`）、碰撞检查距离。

**English short answer**
MoveIt Servo converts Cartesian twist or joint jog commands into joint velocities through a damped Jacobian pseudoinverse and publishes them in real time, slowing near singularities, joint limits and collisions and enforcing acceleration limits and timeouts. It is local, not a global planner, and suits teleoperation and servoing. My teleoperation work shares the same ideas of constrained differential inverse kinematics with damping and limits.

（译：MoveIt Servo 通过带阻尼的雅可比伪逆把笛卡尔速度或关节微动指令转换为关节速度并实时发布，在接近奇异点、关节限位和碰撞时减速，并施加加速度限制与超时保护；它是局部方法而非全局规划器，适合遥操作与伺服；我的遥操作工作同样使用带阻尼和限位的受约束微分逆运动学思想。）

**追问方向**：奇异点减速的缩放函数；Servo 与规划结合的方式。

### Q30 轨迹跟踪误差与容差如何设置？（Tracking error and tolerances）
**优先级：★★★** · 对应基础知识：[数字控制与实时性](../../02_基础知识/05_控制理论/08_数字控制与实时性.md)

**答案要点**
- 来源：控制器带宽有限、动力学未建模、负载变化、摩擦、延迟、饱和。
- 容差：**路径容差**（执行中允许偏离期望轨迹的最大误差，超限中止，防止撞击/失控）、**目标容差**（到达终点的位置/速度容差与等待时间 `goal_time`）。取值 ≈ 正常跟踪误差的 2–3 倍，加碰撞边距的考虑。
- 改进：前馈（速度/加速度前馈、重力补偿）、提高控制带宽、减小轨迹加速度、负载补偿、减小延迟；监测跟踪误差曲线，误差随速度增大说明动态不足。
- 安全：误差过大时停止（保护），并记录原因。
- 与碰撞边距联动：路径容差应小于规划使用的安全边距。

**English short answer**
Tracking error arises from limited controller bandwidth, unmodeled dynamics, load, friction, delay and saturation. I set a path tolerance that aborts execution when the deviation exceeds about two to three times the normal error, keep it smaller than the collision safety margin, and define goal tolerances for position, velocity and settling time. Feedforward and gravity compensation, gentler accelerations and lower latency reduce the error, and I log it to diagnose dynamics limits.

（译：跟踪误差来自有限的控制器带宽、未建模动力学、负载、摩擦、延迟和饱和；设定路径容差，偏差超过正常误差的约 2～3 倍时中止执行，并使其小于碰撞安全边距，同时定义位置、速度与稳定时间的目标容差；前馈与重力补偿、更平缓的加速度和更低延迟可减小误差，并记录误差以诊断动力学极限。）

**追问方向**：为什么路径容差要小于安全边距；误差随速度增大的含义。

### Q31 机械臂急停、轨迹中止与恢复的处理？（Stopping and aborting trajectories）
**优先级：★★★** · 对应基础知识：[功能安全基础_急停_安全链_ISO13849与IEC61508](../../02_基础知识/13_系统工程与安全/02_功能安全基础_急停_安全链_ISO13849与IEC61508.md)

**答案要点**
- 停止类别（参考工业概念，具体定义以标准为准，未核对）：**急停**（切断驱动力，可能惯性滑行，需制动器）、**受控停止**（沿路径减速停下后再断电）、**保护停止**（安全监控触发）；协作臂常用受控停止 + 制动器。
- 软件中止：取消 Action → 控制器以受限减速度停止（`stop_trajectory`，保持当前位置），避免瞬间速度跳变；规划层收到失败后决定重试、退回安全位姿或请求人工。
- 恢复：确认故障清除（碰撞、过载、限位），从当前状态重新规划而不是回放旧轨迹；复位后需要人工确认再恢复（防止意外启动）。
- 看门狗：指令流中断（通信/上层崩溃）→ 控制器超时自动停止；抱闸（断电抱死）防坠落（垂直轴）。
- 记录：事件日志（触发源、位置、速度）用于复盘。

**English short answer**
A hardware emergency stop removes drive power and relies on brakes, whereas a controlled stop decelerates along the path first. In software, cancelling the trajectory makes the controller stop with a limited deceleration and hold the position. After a fault clears, I replan from the current state rather than replay the old trajectory, and restart only after confirmation. A watchdog stops the arm if commands cease, and brakes protect vertical axes at power loss.

（译：硬件急停切断驱动电源并依赖制动器，受控停止则先沿路径减速；软件中取消轨迹使控制器以受限减速度停下并保持位置；故障清除后从当前状态重新规划而不是回放旧轨迹，并在确认后才重启；指令中断时看门狗使机械臂停止，断电时抱闸保护垂直轴。）

**追问方向**：抱闸的作用；受控停止与急停的取舍。

### Q32 一个完整 pick-and-place 流水线包含哪些步骤？（Pick-and-place pipeline）
**优先级：★★★** · 对应基础知识：[行为树与任务规划_PDDL_有限状态机](../../02_基础知识/08_规划与导航/08_行为树与任务规划_PDDL_有限状态机.md)

**答案要点**
- ①**感知**：检测/分割目标、估计位姿或点云（含标定：手眼）；②**抓取规划**：生成候选抓取位姿并筛选（可达、无碰撞）；③**预抓取（pregrasp）**位姿：沿接近方向后退一段距离；④**运动规划**到预抓取位姿（避障）；⑤**笛卡尔直线接近**到抓取位姿；⑥**闭合夹爪**（力 / 位置控制，检测抓取成功：夹爪开度、电流、触觉）；⑦**附着物体**到规划场景（更新碰撞模型）；⑧**直线抬升**（retreat）；⑨**规划到放置位姿**（预放置→放置→打开夹爪→撤退）；⑩**回到安全位**。
- 每一步设置**检查点与失败处理**：感知失败重试/换视角，IK 失败换抓取候选，夹爪未抓到则重试，掉落则恢复。
- 实现：行为树/状态机编排；MoveIt Task Constructor 提供阶段化的任务建模。

**English short answer**
The pipeline is perception of the object, grasp candidate generation and filtering by reachability and collisions, a pregrasp pose, collision-free motion planning to it, a Cartesian approach, gripper closing with success detection, attaching the object to the planning scene, a Cartesian lift, planning to a pre-place pose, placing, releasing and retreating. Each stage has failure handling such as trying another grasp or viewpoint, and a behavior tree or MoveIt Task Constructor orchestrates the sequence.

（译：流水线依次为目标感知、按可达性和碰撞筛选抓取候选、预抓取位姿、到预抓取位姿的无碰撞运动规划、笛卡尔接近、闭合夹爪并检测抓取成功、将物体附加到规划场景、笛卡尔抬升、规划到预放置位姿、放置、释放和撤退；每个阶段都有失败处理（如换抓取或视角），并用行为树或 MoveIt Task Constructor 编排。）

**追问方向**：抓取成功的检测方法；Task Constructor 的阶段类型。

### Q33 为什么要有预抓取与撤退（approach/retreat）路径？（Approach and retreat motions）
**优先级：★★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 全局避障规划保证到达物体附近，但**最后几厘米**应沿夹爪闭合方向**直线**接近，避免夹爪侧面扫过物体或碰到周围物体；预抓取位姿 = 抓取位姿沿接近轴后退 $d$（如 5–10 cm，取决于夹爪尺寸与物体）。
- 抓取后也要沿安全方向**直线撤退/抬升**，避免刮擦周围物体；放置同理（预放置 → 放置 → 撤退）。
- 实现：接近/撤退段用笛卡尔直线规划（可降速），允许夹爪与目标物体的碰撞（ACM 设置），其余障碍仍检测。
- 失败：IK 在直线段上失败 → 换抓取方向/候选；奇异附近速度过大 → 降速。
- 抬升高度需考虑被抓物体尺寸并避开其他物体。

**English short answer**
Global planning brings the gripper near the object, but the last centimeters should follow a straight approach along the gripper axis from a pregrasp pose so the fingers do not sweep into the object or neighbors. After grasping, a straight retreat or lift avoids scraping, and placing uses the same pattern. These segments use Cartesian planning at reduced speed with collisions allowed only between the fingers and the target object.

（译：全局规划把夹爪带到物体附近，但最后几厘米应从预抓取位姿沿夹爪轴线直线接近，避免手指扫到物体或邻物；抓取后沿直线撤退或抬升以免刮擦，放置同理；这些段用降速的笛卡尔规划，只允许手指与目标物体之间的碰撞。）

**追问方向**：预抓取距离怎么定；撤退方向的选择准则。

### Q34 抓取成功如何判断？失败如何恢复？（Grasp verification and recovery）
**优先级：★★★** · 对应基础知识：[可靠性与故障诊断_FMEA_看门狗_降级策略](../../02_基础知识/13_系统工程与安全/03_可靠性与故障诊断_FMEA_看门狗_降级策略.md)

**答案要点**
- 检测手段：①夹爪开度（闭合后开度应落在物体宽度附近，而非完全闭合/保持全开）；②夹爪电流/力（平行夹爪）；③触觉传感器；④抬升后的**重量/力矩**变化（腕部力传感器）；⑤视觉确认（物体随夹爪移动）；⑥抬升后再次闭合检查滑移。
- 失败类型：未抓到（空抓）、抓偏、滑落（运输中）、物体被挤飞。
- 恢复：重新感知后重试（换候选或视角）、调整夹持力、降低加速度、放回原位后再试；重复失败 N 次后上报求助；记录失败原因（便于改进感知/抓取规划）。
- 状态机/行为树中明确“抓取验证”节点与重试上限，防止无限循环。
- 安全：夹持力限幅，避免夹坏物体；易碎物体用柔顺夹爪/力控。

**English short answer**
I verify a grasp from the gripper opening after closing, motor current or force, tactile data, the weight change seen by a wrist force sensor after lifting, or vision confirming the object moves with the gripper. On failure I re-perceive and retry with another candidate or viewpoint, adjust force and acceleration, or place the object back and report after a retry limit. The state machine has an explicit verification node with bounded retries, and grip force is limited.

（译：通过闭合后的夹爪开度、电机电流或力、触觉数据、抬升后腕部力传感器看到的重量变化，或视觉确认物体随夹爪移动来验证抓取；失败时重新感知并换候选或视角重试、调整夹持力和加速度，或放回物体并在重试上限后上报；状态机中有带重试上限的显式验证节点，并限制夹持力。）

**追问方向**：用腕部力传感器测重量的步骤；重试策略的上限设置。

### Q35 抓取候选的筛选与排序标准？（Grasp candidate ranking）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 过滤硬约束：IK 有解且无碰撞（夹爪网格与场景、预抓取和接近段无碰撞）、关节限位内、远离奇异（可操作度阈值）。
- 排序软指标：抓取质量得分（学习/解析）、**离当前构型近**（关节运动量小、避免多解切换）、接近方向偏好（从上方/侧面，适应货架）、可操作度大、与后续放置动作兼容（放置位姿可达）、稳定性（质心附近、避开易滑区域）、对感知误差的鲁棒性（大开口余量）。
- 多步前瞻：选择同时使抓取与放置都可行的组合（任务级可行性，TAMP 思想）。
- 实现：评分加权和；并行评估；保留 top-K 以便失败时回退。
- 统计与迭代：记录各指标与成功率关系，调整权重。

**English short answer**
I first filter candidates by hard constraints: inverse kinematics solution, collision-free gripper in the pregrasp, approach and grasp poses, joint limits and distance from singularities. I then rank by grasp quality, closeness to the current configuration, preferred approach direction, manipulability, compatibility with the subsequent place pose and tolerance to perception error, keeping top-K candidates to fall back on. Looking ahead to place feasibility avoids dead ends.

（译：先按硬约束过滤候选：有 IK 解、夹爪在预抓取/接近/抓取位姿无碰撞、关节限位以及远离奇异；再按抓取质量、与当前构型的接近程度、偏好的接近方向、可操作度、与后续放置位姿的兼容性和对感知误差的容忍度排序，并保留前 K 个候选以便回退；向前看放置可行性可避免死路。）

**追问方向**：任务级可行性检查的实现；评分权重的标定。

### Q36 任务与运动规划（TAMP）是什么？（Task and motion planning）
**优先级：★★** · 对应基础知识：[行为树与任务规划_PDDL_有限状态机](../../02_基础知识/08_规划与导航/08_行为树与任务规划_PDDL_有限状态机.md)

**答案要点**
- 长时程操作任务（整理桌面、装配、做饭）需要决定**做什么、顺序、用什么抓取**（符号任务规划，PDDL 等离散状态）以及**如何运动**（连续几何运动规划），二者耦合：符号上可行的动作序列在几何上可能不可行（如被遮挡需先移开障碍）。
- 方法：分层（先符号后几何，几何失败回溯/加约束反馈符号层，如 PDDLStream、FFRob）；交织（采样候选连续参数——抓取位姿、放置位姿——与符号搜索联合）；基于优化（Logic-Geometric Programming）；学习引导（启发式、技能）。
- 难点：组合爆炸 + 高维连续空间；几何失败的回溯代价；不确定性。
- 实践折中：行为树/状态机 + 预定义技能（带前置条件检查），或 LLM 规划 + 技能库 + 可行性检查（见 Agent 相关章节）。

**English short answer**
Long-horizon manipulation needs both symbolic decisions about which actions to take in what order and continuous motion planning for each, and the two are coupled because a symbolically valid action can be geometrically infeasible, for example when an obstacle blocks the object. Approaches layer a symbolic planner over a motion planner with feedback on failures, interleave sampling of continuous parameters with symbolic search, or optimize jointly. In practice behavior trees with skills and precondition checks are common.

（译：长时程操作既需要关于做哪些动作、什么顺序的符号决策，也需要每个动作的连续运动规划，二者相互耦合，因为符号上合法的动作在几何上可能不可行，如被障碍遮挡；方法有在运动规划器之上叠加带失败反馈的符号规划器、把连续参数采样与符号搜索交织或联合优化；实践中带技能和前置条件检查的行为树很常见。）

**追问方向**：PDDLStream 的思想；几何失败如何反馈给符号层。

### Q37 双臂协调操作的规划要点？（Dual-arm coordination）
**优先级：★★** · 对应基础知识：[闭链并联机构与五连杆运动学](../../02_基础知识/03_运动学与坐标变换/05_闭链并联机构与五连杆运动学.md)

**答案要点**
- 类型：**独立**双臂（各做各的，需避免互相碰撞）；**协调**（共同搬运/装配同一物体，形成闭链约束，物体位姿由两臂共同决定）；**主从**（一臂固定物体、一臂操作）。
- 规划：联合构型空间维度 = 两臂自由度之和（如 7+7=14）；独立任务可顺序规划（先一臂再另一臂把它视为障碍）或解耦规划（优先级规划、速度协调）；协调任务把相对位姿作为约束（闭链流形约束采样 / 投影）或以物体为中心的任务空间控制（物体雅可比 + 内力控制 / 对称阻抗）。
- 碰撞：臂间自碰撞检测加入；时间协调避免同时占用同一空间区域。
- 控制：协调搬运需**内力控制**（避免挤压或松脱）与同步性；位置误差差异会产生内力。
- 遥操作：两臂各自映射或共同映射；标定两臂基座相对位姿（精度决定协调质量）。

**English short answer**
Dual arms can work independently with mutual collision avoidance, in coordination on a shared object forming a closed kinematic chain, or in a master-slave arrangement. The joint configuration space is the sum of both arms' joints, so I either plan sequentially with priorities or treat the relative pose as a constraint, using projection sampling or object-centered task-space control with internal force regulation. The base-to-base calibration accuracy limits coordination quality.

（译：双臂可独立工作并互相避碰，可协调操作同一物体形成闭链，或采用主从方式；联合构型空间维度是两臂关节数之和，所以要么按优先级顺序规划，要么把相对位姿当约束，用投影采样或以物体为中心并带内力调节的任务空间控制；基座到基座的标定精度限制协调质量。）

**追问方向**：内力的定义与控制；两臂基座标定的方法。

### Q38 移动操作（底盘 + 机械臂）的规划难点？（Mobile manipulation）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 自由度冗余：底盘 $SE(2)$（差速/全向）+ 臂 $n$ 轴；同一末端位姿可有无穷多（底盘位置，臂构型）组合 → 需要**基座放置选择**（可达图、可操作度最大、离障碍远）。
- 流程：导航到操作位置（基座停靠）→ 停稳 → 精确定位（相对目标视觉伺服/重新感知）→ 固定基座执行臂操作；或**全身协调**（底盘与臂同时运动）以增大可达范围、减少停顿。
- 难点：底盘定位误差（厘米级）传导到末端 → 需要视觉闭环；底盘运动对臂的动态扰动；非完整约束；底盘与臂的控制时间尺度；坐标系（map/odom/base/arm_base）管理。
- 简化：停稳后再操作；末端目标在臂基座系下计算（观测相对而非绝对）。
- 差速底盘 + 双臂（P2）：遥操作时底盘速度指令与双臂末端映射的协调。

**English short answer**
A mobile manipulator has redundancy between base placement and arm configuration, so I choose the base pose from a reachability map and navigate there. Because base localization errors of centimeters transfer to the end effector, I re-perceive the target relative to the arm and use visual feedback. I often stop the base before manipulating, while whole-body coordination extends reach but adds non-holonomic constraints and dynamics coupling. Careful frame management between map, odom, base and arm is essential.

（译：移动操作臂的底盘位置与臂构型之间存在冗余，所以用可达图选择底盘位姿并导航过去；底盘厘米级的定位误差会传导到末端，因此重新感知目标相对臂的位置并使用视觉反馈；常先停稳底盘再操作，而全身协调可扩大可达范围但会带来非完整约束和动力学耦合；map、odom、base 与 arm 之间的坐标系管理至关重要。）

**追问方向**：基座放置的评价指标；全身控制的实现框架。

### Q40 协作机器人的安全监控原则（速度与分离、功率力限制）？（Collaborative safety principles）
**优先级：★★★** · 对应基础知识：[功能安全基础_急停_安全链_ISO13849与IEC61508](../../02_基础知识/13_系统工程与安全/02_功能安全基础_急停_安全链_ISO13849与IEC61508.md)

**答案要点**
- 常见协作模式（概念，具体条款与限值以 ISO 10218 / ISO/TS 15066 为准，未核对）：①**安全级监控停止**（人进入协作区时停止）；②**手引导**（人直接拖动，低速、使能装置）；③**速度与分离监控（SSM）**：人机距离越近，允许速度越低，距离小于保护距离时停止（保护距离 ≈ 人速度×反应时间 + 机器人停止距离 + 不确定性）；④**功率与力限制（PFL）**：限制接触力/压力在人体部位阈值内（需力传感与低惯量设计）。
- 实现：激光扫描仪/安全光幕/相机检测人；力矩传感器或电流估计检测碰撞；安全控制器（独立 PL/SIL 评级硬件）；速度缩放；碰撞反应策略（停止、退让、柔顺）。
- 风险评估：识别危险、采取措施、验证；末端工具与负载（尖锐物）是风险来源。
- 面试：能说出四种协作模式及其依赖（传感器、算法、硬件）。

**English short answer**
Collaborative modes include safety-rated monitored stop, hand guiding, speed and separation monitoring, where allowed speed decreases with human proximity and the robot stops inside a protective distance computed from human speed, reaction time and stopping distance, and power and force limiting that bounds contact force. They rely on certified sensors and safety controllers, collision detection from torque or current, and a documented risk assessment that includes the tool and payload.

（译：协作模式包括安全级监控停止、手引导、速度与分离监控（人越近允许速度越低，进入由人速度、反应时间和停止距离计算的保护距离时停止）以及限制接触力的功率与力限制；它们依赖认证传感器和安全控制器、基于力矩或电流的碰撞检测，以及包含工具与负载的书面风险评估。）

**追问方向**：保护距离的计算；功率与力限制对机械设计的要求。

### Q41 碰撞检测（基于电流/力矩）的原理与阈值？（Collision detection via torque/current）
**优先级：★★★** · 对应基础知识：[机器人动力学进阶_操作空间_接触_阻抗](../../02_基础知识/02_力学与动力学建模/05_机器人动力学进阶_操作空间_接触_阻抗.md)

**答案要点**
- 原理：用动力学模型预测所需关节力矩 $\boldsymbol\tau_{model}=\mathbf{M}\ddot{\mathbf{q}}+\mathbf{C}\dot{\mathbf{q}}+\mathbf{g}+\boldsymbol\tau_f$，与测得力矩（关节力矩传感器或电机电流×力矩常数）作差得到**外力残差** $\mathbf{r}=\boldsymbol\tau_{meas}-\boldsymbol\tau_{model}$；超过阈值 → 判为碰撞。**动量观测器**（Haddadin 等）用广义动量 $\mathbf{p}=\mathbf{M}\dot{\mathbf{q}}$ 避免用加速度。
- 阈值：太低 → 误报（模型误差、摩擦变化、负载变化、加速度噪声）；太高 → 灵敏度差。可随速度/加速度自适应，或设置多级（降速/停止）。
- 提升：摩擦与负载辨识、温度补偿、限制加速度；使用关节力矩传感器更好（谐波减速器背隙与摩擦影响电流法）。
- 反应：停止、反弹（反向柔顺）、切换到零力矩/柔顺模式。
- 工程：记录触发时刻与残差曲线，用于调阈值。

**English short answer**
I compare the measured joint torques, from torque sensors or motor current, with those predicted by the dynamic model to form an external residual, and flag a collision when it exceeds a threshold. Momentum observers avoid acceleration signals. Thresholds trade false alarms from friction, payload and model errors against sensitivity, and can adapt with speed. Identification of friction and payload helps, and the reaction may be a stop, retraction or compliant mode.

（译：用力矩传感器或电机电流测得的关节力矩与动力学模型预测值比较，形成外力残差，超过阈值即判为碰撞；动量观测器避免使用加速度信号；阈值在由摩擦、负载与模型误差造成的误报和灵敏度之间折衷，并可随速度自适应；辨识摩擦和负载有帮助，反应可以是停止、回退或柔顺模式。）

**追问方向**：动量观测器的原理；电流法与力矩传感器法的差异。

### Q42 负载（payload）与质心估计对规划/控制的影响？（Payload estimation）
**优先级：★★** · 对应基础知识：[机器人动力学进阶_操作空间_接触_阻抗](../../02_基础知识/02_力学与动力学建模/05_机器人动力学进阶_操作空间_接触_阻抗.md)

**答案要点**
- 抓取不同质量的物体改变机械臂动力学（重力项、惯性）；若重力补偿/计算力矩控制仍使用空载模型，会出现下垂、跟踪误差、碰撞检测误报或漏报。
- 估计：①静止抬起后利用**腕部六维力传感器**读数，在多个姿态下求解质量与质心（线性最小二乘，消除传感器偏置与重力方向）；②用关节力矩残差估计；③已知物体用预设参数。
- 更新：抓取后把质量/质心/惯量更新到控制器（重力补偿负载参数）和碰撞检测模型；放下后恢复。
- 影响规划：质量大时降低加速度限制；检查力矩/扭矩余量；防止超负载（驱动器保护）。
- 工程：负载参数错误是协作机器人误停的常见原因。

**English short answer**
A grasped object changes gravity and inertia terms, so keeping the empty-robot model causes sagging, tracking error and wrong collision detection. I estimate mass and center of mass by lifting the object and solving least squares from wrist force-torque readings across several poses, or from torque residuals, then update the controller and collision model and restore them after release. Heavier payloads also call for lower acceleration limits.

（译：被抓物体改变重力和惯性项，沿用空载模型会导致下垂、跟踪误差和碰撞检测错误；抬起物体后，在多个姿态下由腕部力/力矩读数通过最小二乘或由力矩残差估计质量与质心，然后更新控制器和碰撞模型，释放后恢复；较重负载还应降低加速度限制。）

**追问方向**：传感器偏置如何消除；多姿态最小二乘的构造。

### Q43 机械臂运动调试的实用工具与方法？（Debugging arm motion）
**优先级：★★★** · 对应基础知识：[日志_诊断_性能剖析_perf_tracing](../../02_基础知识/12_机器人软件/13_日志_诊断_性能剖析_perf_tracing.md)

**答案要点**
- 可视化：RViz（规划场景、轨迹预览、碰撞对象、TF）、规划路径的末端轨迹、关节曲线（`rqt_plot` / PlotJuggler：位置、速度、加速度、跟踪误差）。
- 分层定位：①感知（点云/位姿是否合理，标定）→ ②规划（场景正确？IK 有解？）→ ③轨迹（时间参数化后速度/加速度是否超限）→ ④控制（跟踪误差、容差中止）→ ⑤硬件（驱动器错误码、过流、编码器）。
- 手法：在仿真（Gazebo/MuJoCo/fake hardware）中先验证；低速、降低速度缩放因子在真机试跑；分段执行（只到预抓取点）；日志与 rosbag 回放；对比规划轨迹与实际轨迹。
- 常见现象：抖动（增益过高 / 噪声 / 轨迹插值）、突然加速（时间参数化/路点跳变）、规划成功但执行失败（容差/起点不一致）、末端偏差（标定）。
- 安全：真机首次运行用低速 + 急停就绪 + 工作空间清空。

**English short answer**
I visualize the planning scene, trajectory and TF in RViz and plot joint positions, velocities and tracking error. I localize problems by layer: perception and calibration, planning scene and IK, time-parameterized limits, controller tracking and tolerances, then drive errors. I validate in simulation first, run at low speed scaling on hardware with the emergency stop ready, execute in segments, and compare planned versus actual trajectories from logged bags.

（译：在 RViz 中可视化规划场景、轨迹和 TF，并绘制关节位置、速度与跟踪误差；按层定位问题：感知与标定、规划场景与 IK、时间参数化后的限制、控制器跟踪与容差、驱动器错误；先在仿真中验证，真机上以低速缩放运行并随时可急停，分段执行，并用记录的 bag 对比规划与实际轨迹。）

**追问方向**：如何判断抖动来源；低速首测的检查清单。

### Q44 遥操作中的映射、延迟与安全策略（对应 P2）？（Teleoperation mapping and safety）
**优先级：★★★** · 对应基础知识：[奇异性_阻尼最小二乘_零空间](../../02_基础知识/03_运动学与坐标变换/04_奇异性_阻尼最小二乘_零空间.md)

**答案要点**
- 映射：操作者手部/手柄位姿 → 机械臂末端目标位姿（相对映射：以按下“离合”时刻的位姿为基准计算增量，避免绝对坐标突变；缩放因子调节精细度）。姿态用四元数相对旋转。
- 逆解：微分 IK（雅可比阻尼伪逆）或 QP（Mink 风格：关节限位、速度限制、碰撞/自碰撞避免、奇异鲁棒、零空间偏好），把末端目标转化为关节指令；输出前限速限加速度。
- 延迟：VR/网络采集→处理→执行链路延迟，需测量并保持低且稳定；预测补偿有限；视频反馈延迟影响操作质量。
- 安全：死人开关/使能（松开即停）、工作空间边界、速度限幅、通信超时停止、起始同步（先对齐再使能，避免跳变）、模式切换时平滑、碰撞检测。
- 数据：遥操作同时记录示教数据（观测+动作），为模仿学习所用。
- 项目对应（按 CV）：P2 为双臂遥操作与差速底盘，使用 MuJoCo/Mink 受约束逆解；具体参数以项目文档为准。

**English short answer**
I map the operator's hand or controller pose to an end-effector target relatively, using the pose when the clutch is pressed as reference to avoid jumps and a scale factor for precision. A damped differential IK or a constrained QP converts targets to joint commands respecting limits, collisions and singularities, followed by speed and acceleration limits. I keep latency low and stable and include a deadman switch, workspace bounds, communication timeouts and synchronized engagement. The same system can record demonstrations for imitation learning.

（译：把操作者手或手柄位姿相对映射为末端目标，以按下离合时的位姿为基准避免跳变并用缩放因子提高精细度；用带阻尼的微分 IK 或受约束 QP 把目标转为满足限位、碰撞与奇异约束的关节指令，再做速度与加速度限幅；保持低而稳定的延迟，并配备死人开关、工作空间边界、通信超时和同步使能；同一系统还可记录示教数据用于模仿学习。）

**追问方向**：相对映射与绝对映射的取舍；延迟对操作者的影响。

### Q45 规划/操作系统的度量指标与回归测试？（Metrics and regression for manipulation）
**优先级：★★** · 对应基础知识：[测试策略_仿真在环_硬件在环_回归](../../02_基础知识/13_系统工程与安全/04_测试策略_仿真在环_硬件在环_回归.md)

**答案要点**
- 规划指标：**成功率**、规划时间（均值与 P95）、路径长度、关节总位移、最小间隙、轨迹 jerk/平滑度、执行时间。
- 操作指标：抓取成功率、完成时间、重试次数、失败类型分布、碰撞/超限事件、人工干预率。
- 评测方法：固定一组场景与目标（含困难情形）在仿真中大量运行（随机种子）；真机用标准化评测集与随机顺序；报告置信区间。
- 回归：每次修改规划参数/模型/版本后自动重跑基准，阈值内通过；失败案例固化为用例。

- 面试表述：用指标证明“改进有效”，而不是只展示一个成功案例。

**English short answer**
For planning I track success rate, planning time with tail percentiles, path length, minimum clearance and smoothness, and for manipulation grasp success, cycle time, retries, failure categories and interventions. I run fixed benchmark scenes with many random seeds in simulation and a randomized standardized set on hardware, with confidence intervals. Each change reruns the suite in CI against thresholds, and failure cases become permanent regression tests.

（译：规划方面跟踪成功率、含尾部分位数的规划时间、路径长度、最小间隙与平滑度，操作方面跟踪抓取成功率、周期时间、重试次数、失败类别和干预次数；在仿真中用大量随机种子运行固定的基准场景，真机上用随机化的标准评测集并报告置信区间；每次改动在 CI 中对阈值重跑套件，失败案例固化为永久回归测试。）

**追问方向**：如何选取代表性基准场景；P95 规划时间的意义。

### Q46 视觉引导抓取中手眼标定误差的影响与补偿？（Hand-eye error in vision-guided grasping）
**优先级：★★★** · 对应基础知识：[相机模型与标定](../../02_基础知识/09_感知与视觉/01_相机模型与标定.md)

**答案要点**
- 手眼外参的旋转误差 $\delta\theta$ 放大为目标处位置误差 $\approx\delta\theta\cdot d$（$d$ 为相机到目标距离）：例 0.5° 在 0.5 m 距离 ≈ 4.4 mm；平移误差直接叠加；加上机器人绝对定位误差、深度噪声，抓取偏差可达厘米。
- 补偿：①**近距重观测**（接近目标时用腕部相机在更近处再次估计位姿，误差更小）；②**视觉伺服**（闭环对准，抵消标定误差）；③标定质量提升（更多构型、离线精化、验证）；④夹爪的机械顺应性（锥形导向、软手指）；⑤接触检测（力传感）与力控插入；⑥手眼标定与机器人本体标定联合；⑦定期校验（已知标记点检验）。
- 诊断：把相机识别到的标定板位置与机械臂接触探测的位置对比，得到系统误差向量。
- 面试：展示误差预算意识。

**English short answer**
A rotation error in hand-eye calibration is multiplied by the distance to the target, so half a degree at half a meter is about 4 mm, and it adds to robot absolute accuracy and depth noise. I compensate by re-observing the target from a closer wrist camera view, using visual servoing, improving calibration, adding mechanical compliance such as chamfers or soft fingers, and force-based contact detection. Periodic validation against a known target exposes drift.

（译：手眼标定的旋转误差会乘以到目标的距离被放大，0.5 m 处半度约为 4 mm，并与机器人绝对精度和深度噪声叠加；通过用腕部相机在更近处重新观测目标、视觉伺服、改进标定、增加倒角或软手指等机械顺应性以及基于力的接触检测来补偿；定期对已知目标做验证可发现漂移。）

**追问方向**：误差预算的构成；如何测量系统性偏差。

### Q47 Pilz 工业运动规划器的 PTP、LIN、CIRC 是什么？（Pilz industrial motion planner）
**优先级：★★** · 对应基础知识：[机械臂运动规划_碰撞检测_MoveIt_CHOMP](../../02_基础知识/08_规划与导航/07_机械臂运动规划_碰撞检测_MoveIt_CHOMP.md)

**答案要点**
- 工业机器人编程常用的确定性运动指令：**PTP**（点到点，关节空间插值，各关节同步到达，末端轨迹不保证直线，速度最快）；**LIN**（笛卡尔直线，末端沿直线运动，姿态 SLERP）；**CIRC**（笛卡尔圆弧，经过辅助点或圆心）；**SEQUENCE**（带混合半径的连续路点序列，平滑过渡不停顿）。
- Pilz 规划器：基于解析的梯形速度/加速度曲线，生成**可预测、可重复**的轨迹，不使用随机采样；不做避障（需要用户保证路径无碰撞，或结合 OMPL 先到安全点）。
- 好处：行为确定、执行时间可预估，适合产线、涂胶、焊接、装配等重复作业；缺点：没有避障智能，环境变化需要重新示教/检查。
- 选择：自由空间大范围运动 → 采样规划器；接近/作业段 → LIN/PTP；工业重复任务 → Pilz。

**English short answer**
PTP moves joints in a synchronized way between points without guaranteeing a straight tool path, LIN moves the tool along a Cartesian straight line, CIRC along an arc, and SEQUENCE blends waypoints without stopping. The Pilz planner uses analytic velocity profiles to give deterministic, repeatable trajectories without sampling, but it does no obstacle avoidance. It fits repetitive industrial tasks, while sampling planners handle free-space motion in changing scenes.

（译：PTP 在点间同步移动关节而不保证末端直线，LIN 使工具沿笛卡尔直线运动，CIRC 沿圆弧运动，SEQUENCE 混合路点而不停顿；Pilz 规划器用解析速度曲线生成确定、可重复的轨迹，不采样也不避障；适合重复性工业任务，而多变场景的自由空间运动用采样规划器。）

**追问方向**：混合半径的作用；PTP 为何速度最快。

### Q48 MoveIt Task Constructor 如何组织多阶段操作任务？（MoveIt Task Constructor）
**优先级：★★** · 对应基础知识：[行为树与任务规划_PDDL_有限状态机](../../02_基础知识/08_规划与导航/08_行为树与任务规划_PDDL_有限状态机.md)

**答案要点**
- 把任务分解为**阶段（stage）**的层次结构：生成器（generator，如 `GeneratePose`、`GenerateGraspPose` 产生抓取候选）、传播器（propagator，如 `MoveRelative`、`MoveTo`、`ModifyPlanningScene`，把一个状态推进到下一个）、连接器（connector，`Connect` 把两个固定状态用规划连接）；容器：串行、并行（备选）、包装器。
- 工作方式：前后向传播解的“部分解”，求出整体可行的组合，并按代价排序；可在 RViz 中检视每个阶段的解，快速看哪一步失败。
- 优点：将抓取、预抓取、直线接近、闭合、附着物体（`ModifyPlanningScene` 允许碰撞/附着）、抬升、放置等组织成声明式流水线，失败时能指出阶段。
- 典型示例：pick-and-place 官方教程。
- 局限：规划耗时较长（枚举候选）；复杂分支逻辑仍需行为树等外层编排。

**English short answer**
Task Constructor models a manipulation task as a hierarchy of stages: generators produce candidates such as grasp poses, propagators advance a state by a motion or a planning scene change like attaching an object, and connectors plan between fixed states. It propagates partial solutions forwards and backwards, finds feasible combinations and ranks them by cost, and lets me inspect each stage in RViz to see where it fails. Complex branching logic still belongs in an outer behavior tree.

（译：Task Constructor 把操作任务建模为阶段的层次结构：生成器产生抓取位姿等候选，传播器通过运动或附着物体等规划场景改变推进状态，连接器在固定状态间规划；它前后向传播部分解、找出可行组合并按代价排序，并可在 RViz 中检查各阶段以定位失败；复杂分支逻辑仍应交给外层行为树。）

**追问方向**：Connect 阶段如何与规划器配合；与行为树的分工。

### Q49 冗余机械臂（7DoF）在规划中如何利用冗余？（Using redundancy in planning）
**优先级：★★** · 对应基础知识：[奇异性_阻尼最小二乘_零空间](../../02_基础知识/03_运动学与坐标变换/04_奇异性_阻尼最小二乘_零空间.md)

**答案要点**
- 7 轴臂对 6D 末端位姿有 1 维零空间（臂角/肘部旋转）：同一末端位姿有连续族关节解。
- 用法：①**避关节限位**（零空间中最大化到限位的距离）；②**避奇异**（最大化可操作度）；③**避障**（把肘部移出障碍）；④**多目标优先级**（任务空间主任务 + 零空间次任务：$\dot{\mathbf{q}}=\mathbf{J}^{+}\dot{\mathbf{x}}+(\mathbf{I}-\mathbf{J}^{+}\mathbf{J})\dot{\mathbf{q}}_0$，$\dot{\mathbf{q}}_0=-\nabla H$）；⑤规划时把臂角作为额外采样参数（IK 返回一族解，选无碰撞者）。
- 缺点：解空间大，IK 解不唯一，需选择策略（最近、最优代价）以保持连续；零空间运动可能造成不期望的肘部摆动。
- 实现：KDL 对 7 轴有数值解；TRAC-IK；解析冗余参数化（臂角）。

**English short answer**
A seven-joint arm has a one-dimensional null space for a six-dimensional end-effector pose, so I can move the elbow without changing the tool pose. I use it to stay away from joint limits and singularities, avoid obstacles, and run secondary objectives projected through the null-space projector, or treat the arm angle as an extra planning parameter. The challenge is selecting among the continuum of IK solutions consistently.

（译：七轴臂对六维末端位姿有一维零空间，可在不改变工具位姿的情况下移动肘部；用它来远离关节限位和奇异、避障，或通过零空间投影器执行次级目标，也可把臂角作为额外的规划参数；难点是在连续的 IK 解族中一致地做选择。）

**追问方向**：零空间投影的数学形式；臂角参数化。

### Q50 装配/插孔（peg-in-hole）的力控策略？（Insertion and assembly with force control）
**优先级：★★★** · 对应基础知识：[力控与阻抗_导纳_混合力位控制](../../02_基础知识/05_控制理论/12_力控与阻抗_导纳_混合力位控制.md)

**答案要点**
- 难点：孔轴间隙（亚毫米）远小于视觉与机器人绝对定位误差 → 纯位置控制易卡死/损坏。
- 策略：①**被动柔顺**：RCC 装置、倒角、软夹持；②**主动柔顺**：阻抗/导纳控制，插入方向低刚度、侧向柔顺；③**搜索**：接触后沿螺旋/随机路径微动，检测力矩/位置突变（掉入孔）；④**力引导对准**：读取侧向力矩推断偏差并修正；⑤**接触状态机**：接近 → 接触 → 搜索 → 对准 → 插入 → 验证（力曲线、深度）。
- 力限幅与速度限制，防止过载；最终位置到位判据（深度 + 力下降）。
- 学习型：模仿学习/RL 学插孔策略（需要力觉观测）；仿真训练 + 真机微调。
- 评估：成功率、插入时间、最大接触力。

**English short answer**
Clearances are sub-millimeter, smaller than vision and absolute accuracy errors, so position control alone jams. I combine passive compliance such as chamfers and compliant mounts with active impedance or admittance control that is soft laterally, run a contact state machine of approach, contact, search, align and insert, spiral or random search to find the hole, and use force limits and depth with force-drop checks to confirm success. Learned policies with force observations are an alternative.

（译：间隙为亚毫米，小于视觉与绝对定位误差，纯位置控制会卡死；结合倒角和柔顺安装等被动柔顺与侧向较软的主动阻抗/导纳控制，运行接近、接触、搜索、对准、插入的接触状态机，用螺旋或随机搜索找孔，并用力限幅及深度与力下降检查确认成功；带力觉观测的学习型策略是替代方案。）

**追问方向**：螺旋搜索的参数；如何由力矩推断偏差方向。

### Q51 擦拭/打磨等力位混合任务怎么控制？（Hybrid force/position tasks）
**优先级：★★** · 对应基础知识：[力控与阻抗_导纳_混合力位控制](../../02_基础知识/05_控制理论/12_力控与阻抗_导纳_混合力位控制.md)

**答案要点**
- 任务空间划分：沿接触面法向**控制力**（保持恒定压力），沿切向**控制位置/速度**（沿表面轨迹运动）。选择矩阵 $\mathbf{S}$ 区分力控与位置控方向（Raibert–Craig 混合力/位控制）。
- 实现：外环力控（PI/导纳）修正法向位置设定，内环位置控；或阻抗控制设置法向低刚度 + 力前馈；需要末端力传感器（腕部六维力）或电流估计的接触力。
- 要点：接触面法向估计（来自点云/力）、路径规划与表面跟随（贴合曲面）、速度限制、摩擦补偿、接触建立/脱离的过渡（避免冲击）。
- 稳定性：接触刚度高时力环带宽受限（过高增益引起接触弹跳）；加入阻尼与滤波。
- 评估：力跟踪误差、表面质量。

**English short answer**
For wiping or polishing I split the task space into the surface-normal direction, where force is controlled to a constant pressure, and the tangential directions, where position or velocity follows the surface path, using a selection matrix. An outer force loop adjusts the normal setpoint of an inner position loop, or an impedance controller with low normal stiffness and force feedforward is used. Contact transitions and the stiffness of the environment limit the achievable force-loop bandwidth.

（译：擦拭或打磨时用选择矩阵把任务空间划分为沿表面法向的力控（保持恒定压力）和切向的位置/速度控制（沿表面路径）；外环力控调整内环位置控的法向设定值，或使用法向低刚度加力前馈的阻抗控制；接触过渡和环境刚度限制力环可达带宽。）

**追问方向**：选择矩阵的构造；接触弹跳的成因。

### Q52 夹爪、吸盘与软体手：末端执行器怎么选？（End-effector selection）
**优先级：★★** · 对应基础知识：[电机_编码器_驱动与力矩控制](../../02_基础知识/11_嵌入式与通信/05_电机_编码器_驱动与力矩控制.md)

**答案要点**
- **平行夹爪**：结构简单、力控制明确，适合规则形状；需要考虑行程、夹持力、手指形状；电动夹爪可控力/位置，气动夹爪成本低但力控差。
- **多指灵巧手**：能做复杂抓取与手内操作，成本高、控制复杂。
- **真空吸盘**：适合光滑平整表面、纸箱、玻璃；对多孔/粗糙/不平表面失效；需要真空度监测；快速、易于 bin picking。
- **软体/柔顺手指、鳍条（Fin Ray）**：适应不规则/易碎物体，定位容差大。
- **磁吸、针式、专用工具**：特定场景。
- 选择依据：物体几何/重量/材质/表面、节拍、定位误差容忍、成本、是否需要触觉反馈、与相机视野的布置（避免遮挡）。
- 控制：夹持力限幅、抓取成功检测（开度/电流/真空压力）、快速换工具时的 TCP 与负载更新。

**English short answer**
Parallel grippers are simple with clear force control and suit regular shapes, multi-finger hands allow complex grasps at high cost, vacuum suction works on smooth flat surfaces but fails on porous or rough ones, and soft fingers tolerate irregular fragile objects and positioning errors. I choose by object geometry, weight and surface, cycle time, accuracy tolerance and cost, monitor grip success through opening, current or vacuum pressure, and update TCP and payload after a tool change.

（译：平行夹爪结构简单、力控清晰，适合规则形状；多指手可做复杂抓取但成本高；真空吸盘适合光滑平面，对多孔或粗糙表面失效；软体手指容忍不规则易碎物体和定位误差；按物体几何、重量与表面、节拍、精度容忍和成本选择，通过开度、电流或真空压力监测抓取成功，换工具后更新 TCP 与负载。）

**追问方向**：真空吸盘的吸力估算；电动与气动夹爪的差异。

### Q53 机械臂振动抑制：输入整形与轨迹平滑？（Vibration suppression）
**优先级：★★**

**答案要点**
- 柔性（谐波减速器、长臂、悬挂负载）使快速运动后残余振动。对策：①**限制 jerk**（S 曲线 / 五次多项式）降低激励；②**输入整形（input shaping）**：把指令与一组脉冲卷积（ZV、ZVD 整形器），使在系统固有频率 $f_n$ 处的振动相消（需知道 $f_n$ 与阻尼比 $\zeta$）；③陷波滤波器（见信号章节）；④**加速度前馈 + 主动阻尼**（反馈负载侧速度）；⑤降低速度/延长运动时间。
- 辨识：对机械臂施加扫频或冲击测量加速度，FFT 找谐振峰；谐振随负载/姿态变化（需自适应或鲁棒整形）。
- 取舍：整形引入延迟（半个振动周期量级）；对未建模频率鲁棒性（ZVD 更鲁棒）。
- 应用：高速分拣、长臂、末端载液体。

**English short answer**
Flexibility in gearboxes, long links or hanging payloads causes residual vibration after fast moves. I limit jerk with S-curves, apply input shaping, which convolves the command with impulses placed to cancel vibration at the known natural frequency, add notch filters or active damping, and reduce speed if needed. I identify the resonance from a sweep or impulse test, noting it changes with payload and pose, and accept that shaping adds a delay of about half the vibration period.

（译：减速器、长连杆或悬挂负载的柔性会使快速运动后产生残余振动；用 S 曲线限制 jerk，采用输入整形（把指令与按已知固有频率处振动相消放置的脉冲卷积），加陷波滤波器或主动阻尼，必要时降低速度；通过扫频或冲击测试辨识谐振，注意它随负载与姿态变化，整形会引入约半个振动周期的延迟。）

**追问方向**：ZV 整形器的脉冲幅值与时间；谐振随姿态变化的处理。

### Q54 传送带动态抓取（moving target pick）的关键点？（Picking from a moving conveyor）
**优先级：★★**

**答案要点**
- 流程：相机/编码器检测物体并估计其位置与传送带速度 → 预测**拦截点与拦截时间**（物体在 $t$ 时刻位置 $\mathbf{p}(t)=\mathbf{p}_0+\mathbf{v}\,(t-t_0)$）→ 规划机械臂在该时刻到达拦截点且**末端速度匹配传送带速度** → 抓取 → 抬升放置。
- 时间同步与延迟：相机采集时刻、处理延迟、传送带编码器计数需统一；预测补偿处理延迟（把物体位置外推到执行时刻）。
- 要点：传送带速度估计精度（编码器）、抓取窗口（接触时间）、加速度与 jerk 限制下能否赶上（可达性分析）、多物体调度（优先级、先近先抓）、柔顺夹爪容忍误差。
- 标定：相机–传送带–机械臂的坐标系（传送带方向与零点）。
- 失败：漏抓（来不及）、位置预测偏差；统计漏抓率调整速度。

**English short answer**
I detect the object, estimate its position and the belt speed from an encoder, predict an interception point and time by extrapolating over the measured latency, and plan an arm motion that arrives with the end-effector velocity matched to the belt. Timestamps for camera, processing and encoder must be unified, and feasibility depends on acceleration and jerk limits and the grasp window. Multiple objects require scheduling, and calibration relates the camera, belt and arm frames.

（译：检测物体，用编码器估计其位置与传送带速度，按测得的延迟外推预测拦截点与拦截时间，并规划使末端速度与传送带匹配的到达运动；相机、处理与编码器的时间戳须统一，可行性取决于加速度和 jerk 限制及抓取窗口；多个物体需要调度，标定需关联相机、传送带与机械臂坐标系。）

**追问方向**：延迟外推的公式；抓取窗口的计算。

### Q55 主动感知与次优视角（Next-Best-View）在操作中的用法？（Active perception for manipulation）
**优先级：★★**

**答案要点**
- 单视角感知有遮挡、深度缺失、位姿不确定；让机械臂（腕部相机）**主动移动相机**到信息量最大的视角，累积融合观测（TSDF/点云/占据概率）。
- NBV 选择：候选视点集（球面/圆弧采样），对每个候选评估**预期信息增益**（可见未知体素数、对目标位姿不确定性的减少、遮挡减少），并考虑可达性与移动代价；选最大效用/代价比的视点；循环直至不确定度低于阈值。
- 应用：杂乱场景抓取前观察目标、透明/反光物体多视角重建、测量未知物体尺寸。
- 工程：视角规划与碰撞规划结合；运动期间的相机运动模糊（停稳后采集）；时间预算（每次额外视角增加耗时）。
- 评估：重建完整度、抓取成功率提升 vs 额外时间。

**English short answer**
When a single view is occluded or uncertain, I move the wrist camera to informative viewpoints and fuse the observations. Candidate views are scored by expected information gain, such as newly visible unknown voxels or reduced pose uncertainty, divided by motion cost and filtered by reachability, repeating until uncertainty is low. It helps with clutter and transparent objects at the price of extra time, and I stop the arm before capturing to avoid blur.

（译：单视角被遮挡或不确定时，移动腕部相机到信息量大的视点并融合观测；候选视点按预期信息增益（如新可见的未知体素或位姿不确定性的降低）除以运动代价评分并经可达性过滤，重复直到不确定性足够低；有助于杂乱场景和透明物体，但需额外时间，采集前先让机械臂停稳以避免模糊。）

**追问方向**：信息增益的具体计算；视点候选的采样。

### Q56 放置（place）的稳定性与位姿选择？（Placing stability）
**优先级：★★**

**答案要点**
- 放置位姿需保证物体**稳定静止**：接触面为平面时，物体重心投影落在支撑多边形内；选择物体的稳定放置姿态集合（凸包的面朝下）。
- 约束：放置区域无碰撞、容纳物体尺寸；堆叠时承重与上层稳定；物体朝向有要求（标签朝上、开口朝上端液体）。
- 软着陆：接近速度减小；力/接触检测判断落到表面后释放（避免从高处丢下）；放置后撤退时避免带走物体（先松夹爪再缓慢上升）。
- 感知验证：放置前扫描目标区域是否空闲；放置后视觉检查位置/姿态。
- 规划：同抓取一样有预放置、放置、撤退段；放置位姿与抓取位姿的兼容性要在抓取选择时考虑。

**English short answer**
A stable placement needs the object's center of mass to project inside its support polygon on the chosen face, with the target region collision-free and large enough, and any orientation requirements met. I approach slowly, detect contact by force or position, release only after touching the surface, and retreat carefully so the object is not dragged. I check the target area before placing and verify afterward, and I choose grasps that make the placement pose reachable.

（译：稳定放置要求物体质心投影落在所选接触面的支撑多边形内，目标区域无碰撞且足够大并满足朝向要求；缓慢接近，通过力或位置检测接触，触碰表面后才释放，并小心撤退以免带走物体；放置前检查目标区域、放置后验证，并在选抓取时保证放置位姿可达。）

**追问方向**：支撑多边形的计算；堆叠稳定性判断。

### Q57 工具坐标系（TCP）与坐标系管理在操作中的注意点？（TCP and frame management）
**优先级：★★★** · 对应基础知识：[坐标系_旋转矩阵_齐次变换](../../02_基础知识/03_运动学与坐标变换/01_坐标系_旋转矩阵_齐次变换.md)

**答案要点**
- 关键坐标系：`world/map`、`base_link`（机械臂基座）、`flange/tool0`（法兰）、`tcp`（工具中心点，夹爪指尖中点/吸盘中心）、`camera`（腕部/外部）、物体坐标系。规划与控制的目标一般定义在 TCP。
- TCP 标定：多姿态指向同一固定点求解；换工具或夹爪后必须更新 URDF/控制器的 TCP；错误的 TCP 使接近方向、抓取点偏离。
- 抓取位姿定义在物体系，转换：${}^{b}\mathbf{T}_{tcp}={}^{b}\mathbf{T}_{obj}\,{}^{obj}\mathbf{T}_{grasp}$。手眼变换 ${}^{b}\mathbf{T}_{cam}$（眼在手外固定、眼在手上则 ${}^{b}\mathbf{T}_{flange}\cdot{}^{flange}\mathbf{T}_{cam}$）。
- 常见 bug：变换方向反、使用了法兰而不是 TCP、时间戳错配（手臂运动中相机观测对应另一时刻的臂姿）、单位（mm/m）。
- 调试：RViz 显示各坐标轴；已知点对准实验。

**English short answer**
Targets are defined at the tool center point, so I calibrate the TCP by pointing at a fixed spot from several poses and update it whenever the gripper changes. Grasp poses are defined in the object frame and composed through the object, base and hand-eye transforms; for a wrist camera the camera pose uses the current flange pose at the image timestamp. Common bugs are inverted transforms, using the flange instead of the TCP, time mismatches and unit errors.

（译：目标定义在工具中心点，所以通过多姿态指向同一固定点来标定 TCP，并在更换夹爪时更新；抓取位姿定义在物体系，经物体、基座与手眼变换复合得到；腕部相机的位姿需使用图像时间戳对应的法兰位姿；常见 bug 有变换方向反、用法兰代替 TCP、时间错配和单位错误。）

**追问方向**：TCP 标定的数学；眼在手上时的时间戳处理。

### Q58 示教再现（teach & playback）与规划式操作如何选择？（Teach-and-playback vs planning）
**优先级：★★**

**答案要点**
- **示教再现**：人工示教关键点（拖动或示教器），保存关节/位姿序列，重复执行（重复定位精度高）；优点：简单、可预测、无需感知；缺点：对物体位置变化不适应、换件需重新示教、没有避障。
- **规划式**：根据传感器信息和目标实时规划，适应环境变化；需要感知、标定、规划，复杂度高、可预测性较低。
- 混合：示教定义“工位、关键位姿与动作模板”，运行时用视觉修正偏差（物体位姿偏差补偿示教点，**示教点相对物体系表达**）；自由空间运动用规划，接近段用示教动作。
- 选择：夹具固定、节拍高、来料位置精确 → 示教再现；来料随机、多品种 → 规划 + 视觉。
- 数据：示教轨迹可作为模仿学习的数据来源。

**English short answer**
Teach-and-playback repeats recorded poses, which is simple, predictable and repeatable but cannot adapt to object variation or avoid obstacles. Planning-based manipulation adapts to sensing at the cost of complexity. A hybrid expresses taught waypoints relative to the object frame so vision can correct deviations, uses planning for free-space motion and taught motion templates for approach. I choose by how variable the parts and fixtures are.

（译：示教再现重复记录的位姿，简单、可预测、可重复，但不能适应物体变化或避障；规划式操作能适应传感信息但更复杂；混合方案把示教路点相对物体系表示以便视觉修正偏差，自由空间运动用规划，接近段用示教动作模板；按来料与夹具的变化程度选择。）

**追问方向**：示教点相对物体系的好处；视觉补偿的实现。

### Q59 仿真中的操作（MuJoCo/Isaac）与真机差异：接触、摩擦与标定？（Sim-to-real for manipulation）
**优先级：★★** · 对应基础知识：[仿真平台_Gazebo_Isaac_MuJoCo对比](../../02_基础知识/12_机器人软件/10_仿真平台_Gazebo_Isaac_MuJoCo对比.md)

**答案要点**
- 接触建模：仿真使用软接触/互补约束，参数（刚度、阻尼、摩擦系数、接触求解器迭代数）影响抓取与堆叠表现；真实摩擦与表面状态不可忽略；夹爪抓取在仿真中常过于“理想”。
- 差异来源：延迟、传感器噪声、控制器带宽与摩擦、标定误差、物体质量/质心不确定、视觉域差异。
- 缩小差距：系统辨识校准仿真参数（质量、摩擦、关节阻尼、增益）；域随机化（物体质量、摩擦、位姿、视觉）；在仿真中模拟传感器噪声与延迟；用真机数据微调；在真机上以低风险任务验证。
- 用途：仿真适合算法开发、回归测试、示教数据扩增、RL 训练；最终性能以真机为准。
- 工具：MuJoCo（接触精度与速度）、Isaac Sim/Lab（GPU 并行、渲染）、Gazebo（ROS 生态）。

**English short answer**
Simulators use soft or complementarity contact models whose stiffness, damping, friction and solver settings strongly affect grasping, and they often omit latency, sensor noise and calibration error. I calibrate parameters by system identification, apply domain randomization over mass, friction and poses, model noise and delay, and fine-tune with real data. Simulation is excellent for development and regression tests, but final performance is judged on hardware.

（译：仿真器使用软接触或互补约束接触模型，其刚度、阻尼、摩擦和求解器设置会强烈影响抓取，且常省略延迟、传感器噪声与标定误差；通过系统辨识校准参数、对质量、摩擦与位姿做域随机化、模拟噪声与延迟并用真机数据微调；仿真适合开发与回归测试，最终性能以真机为准。）

**追问方向**：MuJoCo 接触参数含义；域随机化的范围设定。

### Q60 感知到规划场景的同步与延迟问题？（Perception-to-planning latency）
**优先级：★★★** · 对应基础知识：[时间同步_坐标系一致性与数据有效性](../../02_基础知识/06_状态估计/06_时间同步_坐标系一致性与数据有效性.md)

**答案要点**
- 规划场景来自感知（点云/物体位姿），存在采集→处理→发布→场景更新的延迟（几十到几百毫秒）；机械臂运动时相机视角变化，若用不同时刻的关节状态变换点云，障碍物位置会错位。
- 对策：点云使用**采集时刻**的 TF（相机–机械臂臂姿对应图像时间戳）；运动中暂停更新或用滤波；规划前**停稳后重新采集**（静止场景快照）；对动态障碍使用预测；执行前**再验证**（规划结果对最新场景做一次碰撞检查）；`planning_scene` 的 diff 更新频率控制，避免场景抖动导致规划失败。
- 一致性：同一次规划使用同一份场景快照；规划耗时内场景变化 → 轨迹执行前复核。
- 过滤：机器人自身点云剔除、体素降采样、时间累积（多帧融合）与衰减（清除残影）。
- 记录：场景版本和时间戳随计划一起记录，便于复盘。

**English short answer**
Scene updates lag acquisition by tens to hundreds of milliseconds, and if points from a moving wrist camera are transformed with the wrong arm pose they land in the wrong place. I use TF at the acquisition timestamp, take a fresh snapshot when the arm is stationary, plan against one consistent scene version, and re-validate the plan against the latest scene before execution. Filtering removes the robot's own points, and decay clears ghosts.

（译：场景更新比采集滞后几十到几百毫秒，运动腕部相机的点若用错误的臂姿变换会落在错误位置；使用采集时间戳对应的 TF，在机械臂静止时重新采集快照，对同一份一致的场景版本规划，并在执行前对最新场景重新验证计划；滤波剔除机器人自身点云，衰减机制清除残影。）

**追问方向**：规划场景 diff 更新的作用；执行前复核的实现。

### Q61 关节限位在规划与 IK 中的处理策略？（Handling joint limits）
**优先级：★★** · 对应基础知识：[奇异性_阻尼最小二乘_零空间](../../02_基础知识/03_运动学与坐标变换/04_奇异性_阻尼最小二乘_零空间.md)

**答案要点**
- 硬限位：位置、速度、加速度、（力矩）必须满足；软限位（比硬限位内缩 1–5° 的安全带）用于规划，避免触碰机械/软件硬停止。
- IK：数值 IK 在每次迭代后**裁剪**到限位会破坏收敛，更好的是 QP 形式（把限位写成不等式约束，Mink/OSQP）或在限位附近用**关节限位避免项**（零空间中的势函数）；TRAC-IK 内置限位处理。
- 规划：采样时从限位范围内均匀采样；旋转关节可连续（±360° 以上）要处理角度环绕；轨迹时间参数化需缩放速度以满足限制。
- 多圈关节：连续旋转关节的目标选择最短路径（±π 环绕），避免走大圈；线缆缠绕限制（腕部）需限制总转角。
- 监控：接近限位的关节速度减小；记录限位触发事件。

**English short answer**
I distinguish hard limits from tighter soft limits used in planning. In IK, clipping after each Newton step harms convergence, so I express limits as constraints in a QP or add a null-space joint-limit avoidance term, and TRAC-IK handles limits internally. Planning samples within limits and time parameterization scales speed to satisfy velocity limits. For continuous joints I choose the shortest wrap-around target while respecting cable limits.

（译：区分硬限位与规划使用的更紧的软限位；IK 中每步牛顿迭代后裁剪会损害收敛，因此把限位写成 QP 约束或添加零空间关节限位避免项，TRAC-IK 内部处理限位；规划在限位内采样，时间参数化通过缩放速度满足速度限制；对连续关节选择最短环绕目标并遵守线缆限制。）

**追问方向**：为什么裁剪破坏收敛；连续关节与线缆缠绕的处理。

## 本章要点速记
1. 规划在构型空间进行，障碍区域靠碰撞检测黑盒查询；高维用采样（RRT-Connect 默认）或优化（CHOMP、TrajOpt）。
2. 碰撞检测：宽相（BVH）+ 窄相（GJK）；碰撞几何要简化；ACM 与 attached object 是常见配置坑；边检查分辨率防"隧穿"。
3. 采样路径不平滑，需 shortcut + 平滑 + 时间参数化；优化法依赖初值，常"采样 + 优化"组合。
4. 路径 ≠ 轨迹：时间参数化（梯形、S 曲线、TOTG、Ruckig）满足速度/加速度/jerk；控制器插值并检查容差。
5. 笛卡尔路径逐点 IK，可能中途失败（奇异、限位、分支跳变）；规划失败按错误码 + 场景可视化 + 单独测 IK 排查。
6. Pick-and-place：感知→抓取候选→预抓取→无碰撞规划→直线接近→闭合验证→附着→抬升→放置；每步有失败恢复。
7. 协作安全：SSM / PFL / 手引导 / 安全停止；碰撞检测靠力矩残差；负载参数要更新。
8. 手眼标定误差按距离放大，用近距重观测、视觉伺服和机械顺应补偿。
