# 行为面试：STAR 方法与 30 道常见问题

> **一句话定位**：行为面试问的是“你过去怎么做”，用来预测“你将来怎么做”。本章教你用 STAR 把七个项目变成可复用的故事库，并给出 30 道常见行为题的英文答案。

**本章学完你能……**

- 用 STAR 结构在 60–90 秒内讲完一个有细节、有反思的故事；
- 为七个项目（P1–P7）各准备 1–2 个 STAR 骨架，并知道哪些细节必须自己补全；
- 区分“真实事例型”回答与“假设型”回答，在没有合适经历的题目上不撒谎；
- 针对团队合作、冲突、失败、压力、领导力、时间管理、学习新东西等 30 个题目给出英文表述；
- 避开 STAR 的六个常见坑。

**前置知识**：已读 [面试形式、流程与评分维度](./01_面试形式_流程与评分维度.md) 的“行为面试”一节。事实依据：[CV 逐条拆解](../../00_申请画像/01_CV逐条拆解.md)；项目细节见各项目 README（如 [P1](../../01_项目课程/P1_AIRS球形机器人平衡控制/README.md)、[P7](../../01_项目课程/P7_可变腿长轮腿机器人/README.md)）。

## 1. STAR 方法详解

### 1.1 四个字母

| 字母 | 含义 | 用多少篇幅 | 要回答的问题 |
|---|---|---|---|
| **S**ituation | 情境 | 约 10% | 在什么背景下？一句话 |
| **T**ask | 任务 | 约 10% | 你要解决什么问题？你的职责 |
| **A**ction | 行动 | 约 55% | **你**具体做了什么、为什么这么做 |
| **R**esult | 结果 | 约 15% | 结果如何？你怎么知道的？ |
| （+）**R**eflection | 反思 | 约 10% | 学到什么？下次怎么做 |

> 行为面试的“灵魂”是 A（行动）与反思。很多人把时间花在 S 上，结果没时间讲自己做了什么。

### 1.2 时间分配（以 90 秒为例，约 200 英文词）

| 部分 | 句数 | 英文词（约） |
|---|---|---|
| S + T | 2 句 | 30–40 |
| A | 4–5 句 | 100–110 |
| R | 1–2 句 | 25–30 |
| Reflection | 1 句 | 15–20 |

### 1.3 “I”与“we”

- **团队背景用 “we”**（We were preparing for the competition…）；
- **你的行动用 “I”**（I built the angle–rate cascaded PID for the gimbal…）；
- **团队成绩说团队**（Our team reached the national final.）。

### 1.4 没有数字的“结果”怎么说

你的 CV 项目大多**没有给量化指标**（这是对的，不要编）。结果可以用**可验证的观察**表达：

| 类型 | 例子（均来自 CV 的措辞） |
|---|---|
| 达成目标 | The chassis maintained dynamic balance while both arms moved along fixed trajectories.（P1） |
| 对比验证 | I verified the effect by toggling the compensation under fixed arm trajectories.（P1） |
| 诊断 | I traced the anomalies to state inconsistency, torque limits and ground-contact transitions.（P7） |
| 系统闭环 | The vehicle could localise, plan around obstacles and follow the path on the real vehicle.（P5） |
| 团队成绩 | The robot competed in the 2025 national final and won third prize.（P3） |

> 若被追问“具体数字呢？”，用诚实模板：*“I don't have the exact figure in front of me, but the qualitative result was…”*。如果你确实记得，请 `【待你补全：具体数字，来自你的测试记录】` 补上。

### 1.5 STAR 的六个常见坑

| 坑 | 表现 | 修正 |
|---|---|---|
| 背景太长 | 前 40 秒都在讲背景 | S+T 压到两句 |
| 全是“我们” | 评委不知道你做了什么 | 在 A 里切换到 “I” |
| 没有结果 | 讲到做完就停 | 补一句验证或观察 |
| 没有反思 | 像汇报 | 加一句 “That taught me…” |
| 故事不真实 | 追问时露馅 | 只用有依据的事实 |
| 一个故事答所有问题 | 重复 | 用故事库分配表（第 4 节） |

### 1.6 英文衔接句库

| 位置 | 句型 | 中文 |
|---|---|---|
| S | “We were preparing for…” / “At that time, I was working on…” | 当时我们在准备…… / 那时我在做…… |
| T | “My job was to…” / “I was responsible for…” | 我的任务是…… / 我负责…… |
| A | “First, I… Then, I… Finally, I…” | 首先……然后……最后…… |
| A | “To find the cause, I…” | 为了找原因，我…… |
| A | “I decided to… because…” | 我决定……因为…… |
| R | “As a result, …” / “That let us…” | 结果…… / 这使我们能…… |
| R | “I checked it by…” | 我通过……验证 |
| Reflection | “What I learned is…” / “Next time, I would…” | 我学到的是…… / 下次我会…… |

## 2. 七个项目的 STAR 骨架（P1–P7）

> **使用规则**：下面的“已知事实”全部来自 CV/PS/推荐信；凡 `【待你补全】` 之处是面试官大概率追问、而 CV 里没有的细节——**你必须自己补全，或决定不说**。各项目的完整自查表见对应项目 README 的“实机细节自查表”。

### P1 AIRS 球形机器人（ballbot）

#### P1-A 用 LQR 分析解释增益与执行器饱和

| 要素 | 内容 |
|---|---|
| S | 在 AIRS 实习（Sep 2025 – Mar 2026），三全向轮球形机器人，上半身带双臂；手臂运动时质心不断移动 |
| T | 我负责平衡控制开发与上机调参；目标：手臂沿固定轨迹运动时底盘保持动态平衡 |
| A | ① 设计并部署级联 PID：位置外环给出有界姿态参考，姿态内环用 IMU 与轮速反馈，输出经运动学分配给三个轮子；② 随后“返回模型”：把系统建成线性化的四状态倒立摆，用 LQR 分析 position / velocity / tilt / tilt-rate 权重在稳定性与控制量之间的权衡；③ 把分析当作 PID 调参的模型参考，并用来诊断执行器饱和 |
| R | 底盘在手臂运动时保持动态平衡；LQR 分析被用来解释已部署控制器的增益、定位状态异常和饱和（推荐信语句） |
| 反思 | 先做能跑的，再用模型解释为什么能跑；线性模型有边界 |
| `【待你补全】` | ① 当时观察到的具体“饱和”现象（哪个电机/什么时候）；② 你如何把 LQR 的权重结论翻译成对 PID 的调整方向；③ 四个状态的单位与取值范围（若你记得） |

#### P1-B 质心前馈与“开关对比验证”

| 要素 | 内容 |
|---|---|
| S | 双臂运动时，手臂改变整机质心，对底盘平衡是持续扰动 |
| T | 估计质心偏移并补偿 |
| A | 用 URDF/Pinocchio 从手臂关节状态估计质心偏移；把 roll/pitch 方向的重力前馈加到平衡控制器；在固定手臂轨迹下开关补偿来验证效果 |
| R | 开关补偿对比，验证了前馈的作用（CV：*verified its effect by toggling compensation under fixed arm trajectories*） |
| 反思 | 前馈解决“可预测的扰动”，反馈解决“预测不到的”；对比实验要固定其他条件 |
| `【待你补全】` | 开启/关闭前后你观察到的具体差异（如摆动幅度的大致变化，不要编数字） |

#### P7-B 按腿长调度的 LQR + VMC

| 要素 | 内容 |
|---|---|
| S | 腿长变化使模型参数改变，固定增益不再合适 |
| T | 设计随腿长变化的控制 |
| A | 用 IMU、轮速、关节反馈构造机体俯仰与运动状态；按腿长调度 LQR 增益；把平衡与运动误差转换为轮毂与髋关节力矩；VMC 由闭链运动学计算虚拟腿长与姿态，用雅可比把支撑力与俯仰力矩映射到关节，并用腿长 PID 与力前馈配合伸缩 |

#### Q21 Tell me about something you taught yourself.

> “I taught myself the model-based side of balance control. // My degree is in Computer Science, / so I took Principles of Automatic Control and Modern Control Theory, / and then I applied them on real robots — / the cascaded PID on the ballbot, / and the gain-scheduled LQR on the wheel-legged robot. // I also taught myself the ROS and hardware side, / such as integrating ROS with CAN motor execution. // I learn best when I need something for a real problem.”

**中文**：我自学了平衡控制中基于模型的部分。我的专业是计算机科学，所以我修了自动控制原理与现代控制理论，然后在真实机器人上应用：球形机器人上的级联 PID，以及轮腿机器人上的增益调度 LQR。我也自学了 ROS 与硬件方面，比如把 ROS 与 CAN 电机执行集成。当我为真实问题需要某种东西时，学得最好。

> 依据：CV 的相关课程与 P1/P7。`【待你补全：这些课程是课堂学习还是自学为主，按实际说】`

#### Q22 Tell me about a time you received critical feedback.

> “Feedback on my debugging approach was useful. // [Situation: e.g., my mentor pointed out that I was changing several parameters at once.] // I realised I couldn't tell which change had helped. // Since then, I change one thing at a time and keep a log of what I changed. // It sounds simple, / but it made my tuning on the real robot much faster and safer.”

`【待你补全：真实的批评性反馈来源与内容。示意版本，如无请改为假设型："When I receive feedback, I..."】`

**中文**：关于调试方法的反馈很有用。【情境，例如导师指出我同时改了多个参数。】我意识到无法判断哪次改动有效。此后，我一次只改一项并记录改动。这听起来简单，但让我在真机上的调参快得多、安全得多。

#### Q23 How do you respond to feedback or being wrong?

> “I try to treat it as information. // When someone points out a problem with my approach, / I ask for the reason and check it against the data. // If they're right, / I change quickly and say so. // If I still disagree, / I show what I see and ask for their view. // Being wrong early on a robot is much cheaper than being wrong late, / so I'd rather hear it early.”

**中文**：我把它当作信息。当有人指出我的方法有问题，我问原因并对照数据检查。如果对方是对的，我迅速改变并承认。如果我仍有异议，我展示我看到的并问他们的看法。在机器人上，早点错比晚点错代价小得多，所以我宁愿早点听到。

### H 问题解决与决策

#### Q24 Tell me about the hardest technical problem you solved.

**推荐**：P1（饱和与增益解释）或 P7（异常追溯）。

> “The hardest was understanding why the ballbot's balance behaved the way it did, / beyond just making it work. // I had a cascaded PID that worked, / but when the arms moved, / I saw saturation and state anomalies I couldn't explain by tuning alone. // So I built a linearised four-state inverted-pendulum model, / and used LQR to see how the weights on the states / trade stability against control effort. // That gave me a reference for which direction the gains should move, / and it helped me find actuator saturation. // I also added a centre-of-mass feedforward from the arm joints, / and verified it by toggling it under the same arm trajectories.”

**中文**：最难的是理解球形机器人的平衡为什么这样表现，而不只是让它工作。我有一个能工作的级联 PID，但手臂运动时出现了仅靠调参无法解释的饱和与状态异常。于是我建立线性化四状态倒立摆模型，用 LQR 看各状态的权重如何在稳定性和控制量之间权衡。这给了增益该往哪个方向调的参考，也帮我发现执行器饱和。我还从手臂关节加了质心前馈，并在相同轨迹下开关补偿来验证。

> 这是你最可靠的"技术硬问题"故事，三点都有 CV/推荐信依据。

#### Q25 How do you debug a problem you've never seen before?

> “I follow a fixed order. // First, is the data right? / Timestamps, frames, signs, units. // Second, is the system within its limits? / Torque, speed, saturation. // Third, is the model assumption valid? // Only then I change the controller. // On the wheel-legged robot, / this order helped me trace balance anomalies to state inconsistency, / torque limits and ground-contact transitions, / rather than to the control law. // I also change one thing at a time, / and I keep the robot in a safe state while testing.”

**中文**：我遵循固定顺序。第一，数据对吗？时间戳、坐标系、符号、单位。第二，系统在其限制内吗？力矩、速度、饱和。第三，模型假设有效吗？之后才改控制器。在轮腿机器人上，这个顺序帮助我把平衡异常追溯到状态不一致、力矩限制和触地切换，而不是控制律。我也一次只改一处，并在测试时让机器人保持安全状态。

#### Q26 Tell me about a decision you made with incomplete information.

> “In the smart-gardening system, / I had to decide how much to trust the vision model. // I didn't have enough data to know its failure cases. // So I designed the system so that its output was a recommendation or a constrained request, / not a direct command, / and I kept a rule-based fast path for extreme states / and a local pump state machine with manual override on the device. // That way, / even if the model was wrong, / the physical behaviour stayed safe. // When I can't remove uncertainty, I design around it.”

**中文**：在智能园艺系统中，我要决定对视觉模型信任多少。我没有足够数据了解它的失败情形。所以我把系统设计成：输出是建议或受约束的请求，而不是直接命令，同时保留对极端状态的规则快速通道，以及设备端带手动覆盖的本地水泵状态机。这样即使模型错了，物理行为仍然安全。当我无法消除不确定性时，我围绕它来设计。

> 依据：CV P4（*rule-based fast path*, *structured recommendations or constrained requests*, *manual-priority override*）。“我没有足够数据了解失败情形”为合理自述，请确认。

### I 品格与自我认知

#### Q27 What are your strengths?

> “My main strength is connecting an algorithm to the system around it. // I think about where the data comes from, / what the limits are, / and what happens when something is abnormal. // For example, / I've worked from edge vision deployment to robot control to platform software, / so I can see how the pieces affect each other. // I'm also persistent in debugging: / I like to find the real cause rather than patching symptoms.”

**中文**：我的主要优势是把算法与其周围的系统连接起来。我会考虑数据来自哪里、有什么限制、异常时会发生什么。比如我做过从边缘视觉部署到机器人控制再到平台软件，所以能看到各部分如何相互影响。我也在调试上很坚持：喜欢找到真正原因而不是修补症状。

#### Q28 What is your biggest weakness?

> “My formal theory is less strong than my practical experience. // I've applied LQR, MPC and filters on real robots, / but I haven't had a formal course in optimisation or reinforcement learning, / and my machine-learning experience is mostly deployment. // I'm working on it by reviewing the mathematics behind each method I use, / and that's one reason I want to do a master's. // Another habit I've been improving is explaining my work clearly in English, / which I practise regularly.”

**中文**：我的正式理论不如实践经验强。我在真实机器人上应用过 LQR、MPC 和滤波器，但没有上过最优化或强化学习的正式课程，机器学习经验主要在部署。我正在通过复习每种用到的方法背后的数学来改进，这也是我想读硕士的原因之一。另一个我在改进的习惯是用英文清楚地解释工作，我会定期练习。

> 与 PS 一致。详细版本见 [05 弱项应对](./05_弱项与敏感问题应对.md)。

#### Q29 What accomplishment are you most proud of?

> “I'm proudest of the ballbot at AIRS. // The chassis maintained dynamic balance while both arms moved along fixed trajectories, / which is hard because the arms keep shifting the centre of mass. // What I like about it is that I didn't stop at 'it works': / I went back to a model to understand the gains, / added a centre-of-mass feedforward, / and added safeguards such as output limiting and fall recovery. // It was the first time I felt I'd moved from tuning to understanding.”

**中文**：我最自豪的是 AIRS 的球形机器人。手臂沿固定轨迹运动时，底盘保持了动态平衡，这很难，因为手臂不断改变质心。我喜欢的是我没有停在"能跑"：我回到模型理解增益，加入质心前馈，并加了输出限幅和跌倒恢复这样的保护。那是我第一次觉得自己从调参走向了理解。

> 如果面试官更偏竞赛，换成 RoboMaster：“Our team reached the national final and won third prize; I'm proud of the launcher loop…” 。

#### Q30 Tell me about a time when you had to make an ethical or safety-related decision.

> “In robot systems, safety decisions come up often. // At Kaihong, / the platform doesn't send a high-level task plan directly to a robot; / it passes through an action proposal, a policy check, / execution and state feedback. // I worked on that chain. // The decision I stand by is that a policy check must be a real gate: / if the check fails, the action doesn't execute, / even if that makes the system less convenient. // Similarly, on the ballbot, / I added output limits and fall-recovery safeguards / so that testing didn't put the hardware or people at risk.”

**中文**：在机器人系统中，安全决策经常出现。在深开鸿，平台不会把高层任务计划直接发给机器人，而是经过动作提议、策略检查、执行和状态反馈。我参与了这条链。我坚持的决定是：策略检查必须是真正的关卡——检查不通过，动作就不执行，即使这让系统不那么方便。同样，在球形机器人上，我加了输出限幅和跌倒恢复保护，使测试不会让硬件或人员面临风险。

> 依据：CV P6 与 P1。“策略检查必须是真正的关卡”表达的是设计原则，需保证你能解释该检查具体检查什么；保密相关细节不要展开。`【待你补全】`

## 5. 练习方法与自检

### 5.1 三步练习

1. **骨架扩写**：把第 2 节的骨架填满 `【待你补全】`，写成 6–8 句英文。
2. **计时朗读**：90 秒内读完，不超时；录音。
3. **追问演练**：让朋友在你讲完后追问“Why did you do it that way?”“What would you do differently?”“How do you know it worked?”，你回答。

### 5.2 自检表（每个故事）

| 检查项 | 是 / 否 |
|---|---|
| S+T 不超过两句 | |
| A 里有明确的 “I” | |
| R 里有可验证的观察（不是编造数字） | |
| 有一句反思 | |
| 所有事实有 CV/PS/推荐信依据 | |
| 所有 `【待你补全】` 已替换或删除 | |
| 90 秒内能说完 | |

### 5.3 “假设型”回答的使用边界

当你确实没有合适经历时，**可以用假设型**，格式是：

```text
“I don't have a dramatic example, but I can tell you how I'd approach it.”
→ 说原则 → 说步骤 → 说你在类似场景下的小例子（若有）
```

不要把假设型包装成真实事件。

## 本章要点速记

1. STAR = 情境 / 任务 / 行动 / 结果（+ 反思）；行动与反思占大头。
2. “we” 说背景与团队成绩，“I” 说你的行动。
3. 没有数字时用可验证的观察：“toggling compensation under fixed arm trajectories”。
4. 准备 6–8 个核心故事，一个故事回答多类问题。
5. 最强的真实故事：P1（LQR 分析与前馈）、P3（发射机构迭代）、P5（定位漂移根因）、P7（异常追溯）、P4（不完整信息下的决策）、P6（安全执行链）。
6. 冲突、批评性反馈等题若无真实事例，用假设型，诚实标注。
7. 所有 `【待你补全】` 必须在面试前替换或删除。

## 自测题

1. STAR 里哪一部分篇幅应最大？为什么？（要点：Action，因为评委要评估你本人的行为）
2. 你的 CV 没有量化指标，结果怎么说才不虚？（要点：用可验证的观察，如开关对比、追溯到原因、完成闭环）
3. 说出一个能回答至少四类行为题的核心故事，并列出题目。（要点：如 P1 的 LQR 分析：主动性、最难技术问题、自豪、自学）
4. 为什么在 Q14（领导力）里不要说 “I led the team”？（要点：CV 无此角色；说成 ownership）
5. 你被问到一个没有真实事例的冲突题，怎么答？（要点：诚实说明，转为假设型，讲原则与步骤）
