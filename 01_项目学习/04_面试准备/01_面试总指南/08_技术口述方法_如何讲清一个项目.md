# 技术口述方法：如何用英文讲清一个项目

> **一句话定位**：技术面试里，评委能不能听懂、信不信你，取决于你的**讲法**，而不仅是你的**做法**。本章给你一套可重复使用的口述方法：五段结构、三层深挖、画图口述、数字与不确定性的说法、把控制与规划数学讲给不同听众，并用 P7 的 LQR 示范“讲给教授”与“讲给 HR”两个版本。

**本章学完你能……**

- 用“问题 → 方法 → 为什么 → 验证 → 局限”五段结构，在 90 秒内讲清任何一个项目；
- 预测评委的三层追问（What / Why / What if），并为每个项目准备“深挖阶梯”；
- 边画边讲：知道每个项目该画什么图、怎么用英文指着图讲；
- 对数字与不确定性说得体：有数据时怎么说、没数据时怎么说、示例数值怎么标注；
- 把 LQR、MPC、EKF、Hybrid-A* 等数学内容翻译成非专业评委能听懂的英文；
- 同一个技术点，根据听众（教授 / 工程师 / HR / 招生官）调整深度。

**前置知识**：[面试形式](./01_面试形式_流程与评分维度.md)（追问三层模型）、[英文口语表达](./07_英文口语表达_技术词汇与句型.md)（句型与词汇）。技术背景：[LQR 最优控制](../../02_基础知识/05_控制理论/04_LQR最优控制.md)、[PID 控制全解](../../02_基础知识/05_控制理论/02_PID控制全解.md)。

## 1. 为什么需要“口述方法”

### 1.1 书面的“正确”≠口头的“清楚”

你读书、写代码时，信息是**可回看**的；面试里，信息是**一次性**的。听众只能线性听，容易丢失。口述的任务是：

1. **让听众在任何时刻都知道你讲到哪了**（结构信号）；
2. **每一句只承载一个信息**（短句）；
3. **重要的信息重复一次**（先说结论，最后再说一次）；
4. **用图和例子分担语言负担**。

### 1.2 常见口述失败

| 失败类型 | 表现 | 后果 |
|---|---|---|
| 倒叙 | 先讲细节，最后才说目的 | 评委不知道你在做什么 |
| 堆砌 | 一口气说出十个技术名词 | 评委抓不到重点，也无法追问 |
| 跳步 | 省略“为什么”，直接讲结果 | 看不出你是否理解 |
| 过载 | 数字、符号太多 | 听众放弃 |
| 缺局限 | 只讲好的 | 显得不成熟或不诚实 |

## 2. 五段结构：问题 → 方法 → 为什么 → 验证 → 局限

### 2.1 总览

```text
  ①问题 Problem     这个系统要解决什么？难点在哪？（1–2 句）
  ②方法 Method      我做了什么？（按步骤，3–4 句）
  ③为什么 Why       为什么选这个方法？为什么不选别的？（1–2 句）
  ④验证 Verification  怎么知道它有效？（1–2 句，不编数字）
  ⑤局限 Limits      它在哪里会失效？下一步怎么办？（1–2 句）
```

> **为什么要有第③和第⑤段**：评委对“你理解多深”的判断主要来自这两段。第③段显示你有**选择与权衡**；第⑤段显示你**诚实且成熟**。

### 2.2 每一段的英文句型

| 段 | 句型 | 中文 |
|---|---|---|
| ① | “The problem was how to… while…” | 问题是如何在……的同时…… |
| ① | “The difficulty is that…” | 难点在于…… |
| ② | “I built… in three steps. First… Second… Third…” | 我分三步搭建……首先……其次……再次…… |
| ② | “The controller takes… as input and outputs…” | 控制器以……为输入，输出…… |
| ③ | “I chose… because… An alternative would be…, but…” | 我选……因为……另一种选择是……但…… |
| ③ | “The reason is…” | 原因是…… |
| ④ | “I checked it by…” / “To verify it, I…” | 我通过……检验 / 为了验证，我…… |
| ④ | “What I observed was…” | 我观察到…… |
| ⑤ | “The limitation is… / It only holds when…” | 局限是…… / 只有当……时成立 |
| ⑤ | “If I had more time, I would…” | 如果有更多时间，我会…… |

### 2.3 完整示例：P1 平衡控制（90 秒，约 200 词）

**英文**

> **[Problem]** The problem was how to keep a ballbot balanced / while two arms move on top of it. // The arms keep shifting the centre of mass, / so the base has to compensate all the time. //
> **[Method]** I built it in three steps. // First, a cascaded PID controller: / the outer loop takes the position error and gives a bounded attitude reference, / the inner loop uses IMU and wheel-speed feedback, / and the output is distributed to the three wheels through the kinematics. // Second, I modelled the system as a linearised four-state inverted pendulum / and used LQR to study how the weights on the states / trade stability against control effort. // Third, I estimated the centre-of-mass offset from the arm joints with URDF and Pinocchio, / and fed it forward as gravity compensation in roll and pitch. //
> **[Why]** I used the LQR analysis as a reference for tuning, / because it told me which direction the gains should move, / and it helped me diagnose actuator saturation. //
> **[Verification]** I checked the feedforward by switching it on and off / under the same arm trajectories. // The chassis kept dynamic balance while both arms moved along fixed trajectories. //
> **[Limits]** The main limitation is that it's a linear model, / so it's only reliable near the upright equilibrium.

**中文译文**

【问题】问题是如何在双臂在上方运动时让球形机器人保持平衡。手臂不断改变质心，所以底盘需要持续补偿。【方法】我分三步做。第一，级联 PID：外环取位置误差给出有界的姿态参考，内环使用 IMU 和轮速反馈，输出通过运动学分配到三个轮子。第二，我把系统建模为线性化的四状态倒立摆，用 LQR 研究各状态权重如何在稳定性与控制量之间权衡。第三，我用 URDF 和 Pinocchio 从手臂关节估计质心偏移，并作为 roll 和 pitch 的重力补偿前馈。【为什么】我把 LQR 分析当作调参的参考，因为它告诉我增益该往哪个方向调，也帮我诊断执行器饱和。【验证】我在相同手臂轨迹下开关前馈来检验。手臂沿固定轨迹运动时，底盘保持了动态平衡。【局限】主要局限是线性模型，只在直立平衡点附近可靠。

**检查事实依据**：每个动作都来自 CV P1 与推荐信。“只在平衡点附近可靠”是线性化的一般局限，不是新的数据声明。

### 2.4 压缩与展开

| 时长 | 做法 |
|---|---|
| 30 秒 | ①+②（只说一句）+④ |
| 60 秒 | ①+②（两步）+③+④ |
| 90 秒 | 五段全有 |
| 3 分钟 | 五段 + 每段增加一个细节 + 一个失败/调试故事 |

## 3. 三层深挖框架与“深挖阶梯”

### 3.1 三层

| 层 | 问题形态 | 例子 | 评委在测什么 |
|---|---|---|---|
| **L1 What** | 你做了什么？用了什么？ | “What controller did you use on the ballbot?” | 真实性 |
| **L2 Why** | 为什么这样做？为什么不用别的？ | “Why cascaded PID rather than LQR?” | 理解与权衡 |
| **L3 What if / How do you know** | 条件变化会怎样？怎么证明？ | “What if the arms move faster? How do you know the feedforward helped?” | 深度与方法 |

### 3.2 回答的节奏

```text
  L1：1–2 句直接答 → 停（让评委决定是否深挖）
  L2：先说结论，再说理由；必要时说备选方案
  L3：先说假设，再说推理；说不知道时用“承认→推理→验证”模板
```

> **面试要点**：不要在 L1 就把 L2、L3 的内容全说完。**留钩子**：L1 答完后加一句 “I can explain why if you like.” 这样能让评委主动追问你准备好的内容。

### 3.3 “深挖阶梯”：为每个项目写好 L1–L3

以下为每个项目的**典型阶梯问题**与回答方向。具体答案见各项目 `99_英文面试口述与深挖问答.md`。**凡数值，一律以你自己的记录为准；CV 里没有的，不要编。**

| 项目 | L1 | L2 | L3 |
|---|---|---|---|
| **P1** 球形机器人 | 用了什么控制结构？ | 为什么级联？为什么外环输出要有界？LQR 在这里的作用？ | LQR 的 Q/R 权重怎么影响饱和？前馈开关实验的控制变量是什么？线性化在大倾角下失效怎么办？ |
| **P2** 遥操作 | VR 如何变成末端目标？ | 为什么用约束 IK？奇异点附近为什么速度会放大？ | 如果延迟变大怎么办？重力补偿的模型误差如何影响手感？ |
| **P3** RoboMaster | 云台怎么控制？ | 为什么发射机构从 PID 到变增益再到滑模？ | 滑模的抖振怎么处理？功率限制下缩放轮速有什么副作用？ |
| **P4** 智能园艺 | 视觉到灌溉的链路是什么？ | 为什么需要规则快速通道？为什么水泵状态机放在设备端？ | 误检怎么办？Agent 失效或断网时水泵怎样？INT8 量化带来什么精度风险？ |
| **P5** 自主导航 | 定位—规划—跟踪的链路？ | 为什么 Hybrid-A* + TEB + MPC？为什么 EKF/AMCL 同时用？ | 位姿跳变的根因？局部规划与 MPC 的曲率/速度接口一致性？ |
| **P6** 平台软件 | 统一能力模型是什么？ | 为什么需要策略检查？为什么统一时间戳与坐标系？ | 策略检查失败时怎样？提议、命令、物理执行三者如何区分？（保密边界内） |
| **P7** 轮腿 | 用了什么控制？ | 为什么增益调度？VMC 的作用？ | 腿长变化时 LQR 增益怎样插值？异常追溯的三类原因各举例？ |

### 3.4 L3 的通用回答模板

| 情形 | 模板 |
|---|---|
| “如果……会怎样？” | “I haven't tested that exactly. My expectation is…, because…, and I would check it by…” |
| “你怎么知道它有用？” | “I compared with and without…, under the same conditions. What I saw was…” |
| “为什么不用 X？” | “X would be a good option if…. In our case, …, so I chose…” |
| “这个方法的缺点？” | “The main weakness is…, which shows up when…” |
| “你会怎么改进？” | “Next I would try…, because it addresses…” |

## 4. 画图口述

### 4.1 为什么要画图

- 图把“多维信息”压成“二维信息”，听众更容易跟随；
- 画图时你有自然的停顿，不会因为一直说话而紧张；
- 评委通常喜欢“能画图的人”，因为这代表理解了结构。

> **前提**：线上面试要问对方是否允许使用共享白板或举纸；线下面试可以用白板或纸。问法：*“May I draw a quick diagram to explain this?”*（我可以画个简图来解释吗？）

### 4.2 七个项目各画什么

| 项目 | 图类型 | 要点 |
|---|---|---|
| P1 | 级联控制框图 | 外环（位置）→ 内环（姿态）→ 轮分配 → 机器人；IMU 与轮速反馈 |
| P2 | VR→末端→IK→关节→CAN 的数据流 | 约束与奇异点的位置 |
| P3 | 发射机构双环 | 摩擦轮速度环、拨弹位置—速度环、弹速反馈 |
| P4 | 系统分层图 | 相机→RK3588 推理→Agent 决策→执行层→Hi3861 状态机 |
| P5 | 导航链 | 传感器→定位→全局规划→局部规划→MPC→车辆 |
| P6 | 提议→检查→执行→反馈 链 | 四个方块 + 反馈箭头 |
| P7 | 轮腿示意 | 机身、腿（虚拟腿）、轮；输入（IMU、轮速、关节）与输出（轮毂、髋力矩） |

### 4.3 示例图（可在白板上画出来）

**P1 级联结构**

```text
   p_ref ──►(+)──► [Position loop] ──► θ_ref ──►(+)──► [Attitude loop] ──► u ──► [Kinematics] ──► 3 wheels
              ▲        (outer, bounded)            ▲        (inner)                                  │
              │                                    │                                                 ▼
              │                                    └──── IMU (tilt, rate) ◄─────────────── Robot (ballbot)
              └────────────── position / wheel speed ◄────────────────────────────────────────────┘
```

**P6 安全执行链**

```text
  Task plan ──► [Action proposal] ──► [Policy check] ──► [Execution] ──► Robot
                                           │ fail                          │
                                           ▼                               ▼
                                       (reject)               [State feedback] ──► back to planner
```

**P4 系统分层**

```text
  Camera ─► RK3588 (YOLOv5 / RKNN INT8) ─► observation (confidence + timestamp)
                                                │
         environment sensors ───────────────────┤
                                                ▼
                             Agent decision chain (LangGraph) + rule fast path
                                                │ recommendation / constrained request
                                                ▼
                         Execution layer ─► Hi3861 pump state machine (thresholds, manual priority)
```

### 4.4 边画边讲的句型

| 动作 | 英文 | 中文 |
|---|---|---|
| 开始 | “Let me sketch the structure.” | 我来画一下结构。 |
| 指向方块 | “This block is the outer loop. It gives the reference to this one.” | 这个方块是外环，把参考给这个方块。 |
| 指向箭头 | “The arrow shows feedback from the IMU.” | 箭头表示 IMU 的反馈。 |
| 强调 | “The key point is this connection.” | 关键是这个连接。 |
| 标注 | “I'll mark the limits here.” | 我在这里标上限幅。 |
| 对比 | “Without this block, the system would…” | 没有这个方块，系统会…… |
| 结束 | “So that's the overall structure. Would you like me to go deeper into any block?” | 这就是整体结构。您想让我深入哪一块？ |

### 4.5 画图的规则

1. **先画骨架，再加细节**：先画 3–5 个方块和箭头，再说每个方块。
2. **每个方块只写一个词**（Position / Attitude / Kinematics），不要写长句。
3. **用不同标记区分信号**：实线=命令，虚线=反馈。
4. **边画边说**：不要沉默地画 30 秒。
5. **最多一张图** 在一个回答里，除非面试官要求。

## 5. 数字与不确定性的说法

### 5.1 铁律

> **CV 和你的记录里没有的数字，不说。** 需要举例时，明确说 “as an illustration” 或 “just to make the idea concrete”。

### 5.2 三种情形

| 情形 | 说法 |
|---|---|
| 你有真实记录 | 直接说，并说明条件：“In that test, … was about … under …”。例如："In that test, the muzzle-velocity spread was about plus or minus 0.3 metres per second under continuous fire."（中文：在那次测试里，连发时弹速散布约为正负 0.3 米每秒。）|
| 你记得量级但不确定 | “I don't remember the exact value, but it was in the range of…” |
| 你没有 | “I didn't record that precisely, so I can describe the behaviour rather than a number.” |

### 5.3 示例数值的标注

教学时用的示例数字必须带标签，防止被当成真实结果：

> “To make it concrete, **suppose** the tilt is five degrees. **This is just an illustration, not a measurement from the robot.**”

**中文**：为了具体，假设倾角是五度。这只是示意，不是机器人的测量值。

### 5.4 定性描述的词汇

| 想表达 | 英文 |
|---|---|
| 明显更稳 | clearly more stable |
| 振荡减小 | the oscillation was reduced |
| 恢复更快 | it recovered faster |
| 不再饱和 | it no longer hit the torque limit |
| 偶尔失败 | it occasionally failed, mostly when… |
| 在某条件下有效 | it worked under…, but I haven't tested… |
| 无法判断 | I couldn't tell from the data |

### 5.5 说“不确定”而不丢分

不确定不等于弱。**被追问时，不确定 + 推理 + 如何验证** 是一个完整的科学回答。

> **Q**：What was the exact control frequency?
> **A (if you remember)**：“It ran at … hertz.” 例如："The balance loop ran at about one hundred hertz."（中文：平衡环大约运行在一百赫兹。）
> **A (if you don't)**：“I don't have the exact frequency in front of me. It was set by a timer task on the microcontroller, and it was fast enough relative to the dynamics of the pendulum. I can find the number in my records.”
> **中文**：我手头没有确切频率。它由微控制器上的定时任务设定，相对于倒立摆的动态足够快。我可以从记录里查出数字。

> 控制频率是面试官几乎必问的问题（P1、P3、P7）。请务必在各项目 README 的“实机细节自查表”里补全。

### 5.6 不确定性在项目里的三个来源（讲局限时用）

| 来源 | 例子 | 英文 |
|---|---|---|
| 模型 | 线性化、忽略摩擦 | model error |
| 传感 | IMU 漂移、噪声、时间不同步 | sensor noise and timing |
| 环境 | 地面接触切换、障碍变化 | environment changes |

## 6. 把控制 / 规划数学讲给不同听众

### 6.1 “三档深度”原则

同一个概念，准备三档：

| 档 | 听众 | 长度 | 特点 |
|---|---|---|---|
| **一句话档** | HR、招生官、非专业人士 | 1 句（15–25 词） | 日常类比，无符号 |
| **直觉档** | 工程师、跨领域教授 | 3–5 句 | 概念 + 为什么需要 |
| **技术档** | 本领域教授 | 5–8 句 | 公式、假设、局限 |

### 6.2 主要概念的三档讲法

#### PID

- **一句话**：*“It's a controller that looks at the current error, the accumulated past error, and how fast the error is changing, to decide how hard to push.”*
 → 它根据当前误差、累积的过去误差、误差变化快慢来决定用多大力。
- **直觉**：*“Proportional reacts to now, integral fixes the long-term offset, and derivative acts like a damper that stops overshoot.”*
- **技术**：*“It's a linear feedback law $u = K_p e + K_i \int e + K_d \dot e$; the practical issues are noise amplification in the derivative term and integral windup under saturation.”*

#### 级联控制（cascaded control）

- **一句话**：*“One controller decides where to go and gives a target to a faster controller that decides how to move.”*
- **直觉**：*“The inner loop handles fast dynamics such as tilt; the outer loop handles slower goals such as position. Separating them makes tuning easier.”*
- **技术**：*“Time-scale separation: the inner loop has higher bandwidth, and the outer loop treats it as approximately unity gain.”*

#### LQR

- **一句话**：*“It finds the best balance between keeping the robot near upright and not using too much motor effort.”*
- **直觉**：*“You tell it how much you care about each error, and how much you care about effort. It computes a feedback gain that is optimal for that trade-off.”*
- **技术**：*“For a linear system $\dot x = Ax + Bu$, it minimises $J = \int (x^TQx + u^TRu)dt$. The solution is $u = -Kx$ with $K = R^{-1}B^TP$, where P solves the algebraic Riccati equation.”*

#### 增益调度（gain scheduling）

- **一句话**：*“When the robot's shape changes, I switch to the controller settings that fit that shape.”*
- **直觉**：*“The robot behaves differently with a long leg and with a short leg, so one fixed gain isn't ideal. I keep a family of gains and pick or blend them by leg length.”*
- **技术**：*“Linearise at several leg lengths, compute an LQR gain at each, and interpolate $K(L)$ at run time.”* （这是**典型做法**；你的实现可以这样说：离线在若干个腿长点上求解 LQR，再对每个增益做三次多项式拟合，运行时按实时腿长计算增益）

#### MPC

- **一句话**：*“It plans a short sequence of future moves, applies the first one, then plans again.”*
- **直觉**：*“Like driving: you look a few seconds ahead, steer, and keep updating. And it respects limits such as maximum steering angle.”*
- **技术**：*“At each step, solve a finite-horizon optimisation with the vehicle's kinematic model and constraints on position, heading, speed and steering; apply the first control; repeat — a receding horizon.”*

#### EKF / 传感器融合

- **一句话**：*“It combines a prediction from motion with noisy measurements, and trusts each according to how reliable it is.”*
- **直觉**：*“If the wheel odometry drifts but the LiDAR is accurate, the filter leans on the LiDAR, and vice versa.”*
- **技术**：*“Linearise the motion and measurement models around the current estimate, propagate the covariance, and update with the Kalman gain.”*

#### AMCL

- **一句话**：*“It keeps many guesses of where the robot is and removes the ones that don't match the laser scan.”*
- **直觉**：*“Each guess is a 'particle'. Guesses that agree with the map and the laser survive.”*
- **技术**：*“Monte Carlo localisation: a particle filter with adaptive particle count, using the motion model for prediction and the laser likelihood for weighting.”*

#### Hybrid-A*

- **一句话**：*“It searches for a path that a car can actually drive, not just a path on a grid.”*
- **直觉**：*“It remembers the car's heading and turning limits while searching, so the path has no impossible turns.”*
- **技术**：*“A* over continuous states discretised into cells, with kinematically feasible motion primitives, under footprint and minimum-turning-radius constraints.”*

#### TEB

- **一句话**：*“It bends and times the path so the robot can follow it smoothly while dodging nearby obstacles.”*
- **直觉**：*“Think of the path as an elastic band that's pushed away by obstacles and pulled toward the goal.”*
- **技术**：*“Timed Elastic Band: a sparse graph optimisation over time-parameterised poses with objectives for path following, obstacle distance and kinodynamic limits.”*

#### 逆运动学与奇异点

- **一句话**：*“Given where the hand should be, work out how each joint should move; near some poses, tiny hand motions need huge joint motions.”*
- **直觉**：*“Like a fully stretched arm: to move the hand sideways a little, the joints have to swing wildly. That's a singularity.”*
- **技术**：*“The Jacobian loses rank at a singularity, so the inverse gives unbounded joint velocities; we add constraints or damping to keep the solution bounded.”*

#### VMC

- **一句话**：*“I imagine a virtual spring along the leg and convert the force I want into motor torques.”*
- **直觉**：*“Instead of controlling each joint, I control the leg as one object—its length and angle—and map the desired force through the mechanism.”*
- **技术**：*“Compute the virtual leg length and angle from closed-chain kinematics, then map the virtual force and torque to joint torques with the Jacobian transpose.”*

#### 量化（INT8）

- **一句话**：*“It shrinks the model by using small integers instead of decimal numbers, so it runs faster on small chips.”*
- **直觉**：*“You trade a little precision for speed and memory. A calibration set helps choose the scale.”*
- **技术**：*“Map float tensors to 8-bit integers with scale and zero-point, calibrated on a representative dataset; accuracy loss depends on the layer distribution.”*

## 7. 示例：把 P7 的 LQR 分别讲给教授与讲给 HR

### 7.1 先确认事实（P7 CV）

- 实验室可变腿长轮腿平台，**增益调度 LQR**：用 IMU、轮速和关节反馈构造机体俯仰与运动状态；**按腿长调度** LQR 增益；把平衡与运动误差转换为**轮毂与髋关节力矩**。
- 还有 VMC、腿长 PID 与力前馈；运行在 STM32H7/FreeRTOS/FDCAN 链路；**上机调参**。
- 机器人在腿长变化时保持机身平衡并跟踪速度指令。

> 以下描述与你的项目口径一致：增益来自离线计算（在腿长范围内取若干个离散点，求解 LQR 后做三次多项式拟合），再在机器人上微调 Q/R 和增益；状态向量是六维——位移、速度、腿摆角、摆角速度、机体俯仰角、俯仰角速度；控制周期在几毫秒量级。核对时若与你的真实实现有出入，以真实实现为准。

### 7.2 版本一：讲给教授（技术档，约 150 词，60–75 秒）

**英文**

> **[Problem]** The wheel-legged robot has to keep its body balanced and track a speed command / while its leg length changes. // Changing the leg length changes the inertia and the height of the centre of mass, / so the dynamics change with it. //
> **[Method]** I linearised the body as an inverted pendulum on wheels / around the upright equilibrium, / with states built from the IMU pitch, / the wheel speed and the joint feedback. // For each leg length, / the LQR gain minimises a quadratic cost on state error and control effort. // At run time the gain is scheduled by the leg length, / and the output is converted into wheel-hub torque and hip torque. //
> **[Why]** A single fixed gain tuned for one leg length / loses performance, or even stability, at another. // LQR gives a systematic way to trade tracking against effort for each length. //
> **[Verification]** I tuned and validated it on the robot, / and when I saw balance anomalies, / I traced them to state inconsistency, torque limits and ground-contact transitions, / rather than the gain itself. //
> **[Limits]** It's still based on a linear model, / so large disturbances or the moment the wheels touch the ground / are handled by other logic.

**中文译文**

【问题】轮腿机器人要在腿长变化时保持机身平衡并跟踪速度指令。腿长变化会改变惯量和质心高度，动力学也随之改变。【方法】我把机身线性化为轮子上的倒立摆，在直立平衡点附近，状态由 IMU 俯仰、轮速和关节反馈构造。对每个腿长，LQR 增益最小化状态误差与控制量的二次代价。运行时按腿长调度增益，输出转换为轮毂力矩和髋关节力矩。【为什么】针对某一腿长调好的固定增益，在另一个腿长上会损失性能甚至稳定性。LQR 提供了针对每个腿长权衡跟踪与控制量的系统方法。【验证】我在机器人上调参并验证；看到平衡异常时，我把它们追溯到状态不一致、力矩限制和触地切换，而不是增益本身。【局限】它仍基于线性模型，大扰动或轮子触地的瞬间由其他逻辑处理。

**为什么这样讲**

| 句子 | 用意 |
|---|---|
| “Changing the leg length changes the inertia…” | 给出“为什么需要调度”的物理原因 |
| “quadratic cost on state error and control effort” | 对教授给出准确的 LQR 描述 |
| “scheduled by the leg length” | CV 原话 |
| “rather than the gain itself” | 体现你的调试判断（CV：追溯到状态不一致、力矩限制、触地切换） |
| “handled by other logic” | 诚实的局限：线性模型在大扰动下失效，所以另有限幅与离地判据等逻辑来兜底 |

**教授可能的追问（L2/L3）与回答方向**

| 追问 | 回答方向 |
|---|---|
| Why LQR rather than PID? | LQR 处理多状态耦合并给出一致的权衡；PID 对单变量更直观；在本项目里 PID 用于腿长环（CV：leg-length PID）。 |
| How did you choose Q and R? | 说明方法（如先按各状态量纲归一化再调整）；具体取值的说法：状态量先按量纲归一化，位置和速度权重取小、倾角和倾角速率权重取大，R 取与力矩上限匹配的量级，再上机微调；不报精确数字。 |
| How do you schedule between lengths? | 插值或查表，我们的做法：对每个增益做三次多项式拟合，运行时按当前腿长求值。 |
| What about nonlinearity? | 线性化只在平衡点附近有效；大扰动时靠限幅与其他逻辑。 |
| What if the state estimate is wrong? | 引用 CV：状态不一致是异常的主要来源之一，所以先检查状态。 |

### 7.3 版本二：讲给 HR（一句话档 + 类比，约 100 词，40–50 秒）

**英文**

> “I worked on a robot with wheels on the ends of its legs, / a bit like a two-wheeled balancing scooter, / but the legs can get longer or shorter. // The challenge is that when the legs change length, / the robot balances differently, / just like balancing a long stick feels different from balancing a short one. // I used a method that automatically finds a good balance between / ‘stay upright’ and ‘don't use too much motor power’, / and I prepared a set of settings for different leg lengths. // I tested it on the real robot, / and it kept its body balanced while following speed commands / even as the legs changed length.”

**中文译文**

我做过一种腿末端有轮子的机器人，有点像双轮平衡车，但腿可以变长变短。挑战在于，腿的长度变化时，机器人的平衡方式也不同，就像平衡长棍和平衡短棍的感觉不同。我用了一种方法，自动找到“保持直立”和“别用太多电机功率”之间的好平衡，并为不同腿长准备了一组参数。我在真实机器人上测试，它在腿长变化时仍能保持机身平衡并跟随速度指令。

**为什么这样讲**

| 句子 | 用意 |
|---|---|
| “a bit like a two-wheeled balancing scooter” | 用日常物体建立画面 |
| “balancing a long stick feels different from a short one” | 类比解释“为什么腿长影响平衡”：只强调“不同”，不比较谁更难，避免被追问物理细节 |
| “automatically finds a good balance between ‘stay upright’ and ‘don't use too much motor power’” | 不出现 “LQR”，但保留其本质（权衡） |
| “a set of settings for different leg lengths” | 增益调度的外行说法 |
| “tested it on the real robot” | CV：on-robot tuning |

> 注意：不要说“长棍比短棍更难平衡”——物理上较长的摆动态更慢，人手往往更容易平衡。类比只用来说明“腿长不同，平衡方式不同”。

### 7.4 两个版本的对照

| 维度 | 教授版 | HR 版 |
|---|---|---|
| 术语 | linearised, equilibrium, quadratic cost, scheduled | 无术语，用类比 |
| 结构 | 五段齐全 | 问题 → 做法 → 结果（三段） |
| 数学 | 仅点到“quadratic cost” | 无 |
| 强调 | 权衡与局限 | 能做出可工作的东西，能解释给别人 |
| 长度 | 60–75 秒 | 40–50 秒 |
| 结尾 | “handled by other logic” | “kept balanced as legs changed” |

### 7.5 “三档切换”练习

让朋友随机说：“Explain it to a professor / a manager / a child.”，你在 30 秒内切换三个版本。这是最有效的口述训练。

## 8. 其他项目的五段示范

### 8.1 P5 导航链（60 秒版）

**英文**

> **[Problem]** The goal was autonomous navigation of a car-like robot on a real vehicle, / from knowing where it is to following a planned path. //
> **[Method]** I built the chain in four parts. // Localisation with an EKF and AMCL, / fusing IMU, wheel encoders and 2D LiDAR. // Global planning with Hybrid-A*, / which includes heading and kinematic constraints. // Local trajectory optimisation with TEB around obstacles. // And MPC tracking based on a car-like kinematic model. //
> **[Why]** A car-like robot can't turn on the spot, / so the planner must respect the turning radius and the footprint. //
> **[Verification]** The chain ran on the real vehicle, / from planned trajectory to vehicle motion. // One lesson was that the pose drift and jumps came from inconsistent timing, frames and motion direction, / not from the filter itself. //
> **[Limits]** The planners assume a mostly static environment.

**中文**：【问题】目标是车式机器人在真车上自主导航，从知道自己在哪到跟随规划路径。【方法】我分四部分搭建：用 EKF 与 AMCL 融合 IMU、轮式编码器、2D 激光做定位；用 Hybrid-A* 做含朝向与运动学约束的全局规划；用 TEB 围绕障碍优化局部轨迹；用基于车式运动学模型的 MPC 做跟踪。【为什么】车式机器人不能原地转向，所以规划器必须遵守转弯半径和车体轮廓。【验证】链路在真车上运行，从规划轨迹到车辆运动。一个教训是位姿漂移和跳变来自时间、坐标系和运动方向不一致，而不是滤波器本身。【局限】规划器假设环境基本静态。

> “planners assume a mostly static environment” 来自你 PS（AI 版）中“planners that assumed a largely static environment”的自述。

### 8.2 P4 园艺系统（60 秒版）

> **[Problem]** I wanted a plant-care system that goes from seeing to deciding to watering, / and stays safe if the AI part is wrong. //
> **[Method]** On an RK3588 board, / a YOLOv5 model quantised to INT8 turns camera frames into observations with a confidence and a timestamp. // A LangGraph decision chain combines those with environment data, / with a rule-based fast path for extreme states. // It sends a recommendation or a constrained request to the execution layer. // On a Hi3861 chip, / a pump state machine uses separate start and stop thresholds and a manual-priority override. //
> **[Why]** I kept the safety-critical pump logic on the device, / so a wrong model output can't directly cause bad behaviour. //
> **[Verification]** The loop closed from camera to pump through a web interface. //
> **[Limits]** It's a small personal project, / and I haven't evaluated the model across many conditions.

**中文**：【问题】我想做一个从看到、决定到浇水的植物照护系统，并且在 AI 部分出错时仍然安全。【方法】在 RK3588 上，INT8 量化的 YOLOv5 把相机帧变成带置信度和时间戳的观测；LangGraph 决策链把它们与环境数据结合，对极端状态有规则快速通道；向执行层发出建议或受约束请求；在 Hi3861 上，水泵状态机用独立启停阈值和手动优先覆盖。【为什么】我把安全关键的水泵逻辑放在设备端，使错误的模型输出不能直接导致坏行为。【验证】闭环从相机经 Web 交互到水泵。【局限】这是个小型个人项目，我没有在多种条件下评估模型。

> “I haven't evaluated the model across many conditions” 是诚实局限；实际情况是：我评估过模型在同一采集场景留出的验证集上的精度，但没有系统地跨很多光照和环境条件评估，所以这句局限是准确的。

## 9. 常见错误与修正

| 错误 | 症状 | 修正 |
|---|---|---|
| 不先说目的 | 评委在前 30 秒不知道你在做什么 | ① 问题 先行 |
| 术语堆砌 | “EKF, AMCL, TEB, MPC…” 连珠炮 | 一次只引入一个术语，并配一句解释 |
| 不分听众 | 对 HR 讲 Riccati 方程 | 用三档深度 |
| 只讲成功 | 没有局限和失败 | 加⑤，并给一个调试故事 |
| 把“我们”与“我”混在一起 | 评委无法判断你的贡献 | A 部分用 “I” |
| 数字编造 | 追问就破 | 不确定就说定性 |
| 沉默画图 | 画 30 秒不说话 | 边画边说 |
| 一直说，不留停顿 | 评委无法插入 | 每个意群后停半拍；每 60 秒问一次 “Does that make sense?” |
| 不会收尾 | 讲着讲着变小声 | 用 “That's the main idea.” 收束 |
| 答非所问 | 评委问 Why，你答 What | 先复述问题再答：“You're asking why…, right?” |

## 10. 练习方法

### 10.1 “3-2-1 压缩”练习

对同一个项目，依次讲：**3 分钟 → 2 分钟 → 1 分钟 → 30 秒**。每次压缩迫使你保留最重要的部分，并找到真正的核心。

### 10.2 “橡皮鸭”练习

对着一个物体（真的橡皮鸭也行）讲项目，**不许看笔记**。卡住的位置就是你需要补的位置。

### 10.3 “换听众”练习

同一个项目：讲给教授、讲给 HR、讲给 12 岁的孩子。记录你最难翻译的概念。

### 10.4 “追问机”练习

找朋友（或自己写好问题卡片）对每个项目连问三层：What → Why → What if。你必须在 10 秒内开口。

### 10.5 录音自检表

| 检查项 | 是 / 否 |
|---|---|
| 第一句话就说清了项目的目的 | |
| 方法部分有明确的顺序词（First / Second / Third） | |
| 有至少一句“为什么” | |
| 有至少一句验证 | |
| 有至少一句局限 | |
| 没有编造数字 | |
| 术语每次只引入一个并解释 | |
| 时长在目标范围内 | |
| 语速没有突然加快 | |

## 本章要点速记

1. 口述的核心是结构：问题 → 方法 → 为什么 → 验证 → 局限。
2. “为什么”与“局限”决定评委对你深度和诚实度的判断。
3. 三层追问 What / Why / What if；L1 答完留钩子，别一口气说完。
4. 能画图就画图，边画边说；一个回答最多一张图。
5. 数字：有记录就说，没记录就说定性；示例数值必须标注 “as an illustration”。
6. 同一个概念准备三档：一句话档、直觉档、技术档。
7. P7 的 LQR：教授版强调线性化、二次代价、调度；HR 版强调“在直立与省电之间自动找平衡 + 不同腿长不同参数”。
8. P1 里 LQR 是分析工具，P7 里 LQR 是部署的控制器，别混。
9. 练习：3-2-1 压缩、橡皮鸭、换听众、追问机。

## 自测题

1. 五段结构的五段分别是什么？哪两段最能体现深度与诚实？（要点：问题、方法、为什么、验证、局限；为什么与局限）
2. 面试官问 “What was the control frequency?”，你不记得，怎么答？（要点：诚实说没有在手；说明由定时任务设定、相对动态足够快；愿查记录；不编数字）
3. 用一句话向 HR 解释 LQR。（要点：找到“保持直立”与“少用电机力”的最佳平衡）
4. 你会用什么图来讲 P6？（要点：提议→策略检查→执行→状态反馈，带反馈箭头与拒绝分支）
5. 为什么 P7 的 HR 版类比要小心“长棍 vs 短棍”？（要点：物理上长摆动态更慢、不一定更难；只说“感觉不同”避免被抓住）
