# CV 逐句英文表述与三层追问

> **一句话定位**：面试官手里只有你的 CV。他会挑一个 bullet，念出来，然后问。本文档把 CV 的每一条 bullet（共 24 条项目 bullet + 学业/奖项 + 5 行 Skills）逐句拆开：先用口语英文把原句"翻译"成人话，再给出三层追问——第一层 **What did you do?**，第二层 **Why / How?**，第三层 **What if / limits?**——每层一个英文问题和回答要点。

**本章学完你能……**

- 看到 CV 任何一句，都能用 2–3 句口语英文解释它，而不是照读；
- 预判面试官会问的三层问题，并有"要点式"的回答骨架；
- 区分哪些细节是 CV 已有事实，哪些必须自己补全（`【待你补全】`）；
- 在细节记不清时，使用诚实的回答模板，而不是编造。

**前置知识**：[CV 逐条拆解](../../00_申请画像/01_CV逐条拆解.md)、[口径与事实基线](../../00_申请画像/04_口径与事实基线.md)。

## 0. 用法与诚实回答模板

### 0.1 每条 bullet 的结构

```text
CV 原句
  └─ 拆句：把一句话切成 2–4 个意群，逐个口语化
      └─ 口语解释（说给面试官听的 2–3 句）
          └─ 关键词（卡壳时的提词）
              ├─ L1  What did you do?    —— 你做了什么（事实层）
              ├─ L2  Why / How?          —— 为什么这样、怎么做（方法层）
              └─ L3  What if / limits?   —— 如果……会怎样、局限在哪（判断层）
```

> **注意**：回答要点中，凡来自 CV/PS/推荐信的写成句子；凡 CV 没有而面试官大概率追问的细节，只写 `【待你补全：…】`。补全后请同步登记到对应项目 README 的「实机细节自查表」。

### 0.2 诚实回答模板（只在你确实记不清时使用）

| 场景 | 英文模板 | 中文 |
|---|---|---|
| 记不清具体数值 | "I don't have the exact number in front of me, but the trend was ... and I can tell you how I measured it." | 我手边没有确切数字，但趋势是……我可以说说怎么测的 |
| 超出自己负责范围 | "That part was handled by a teammate, so I can only describe the interface I used. My part was ..." | 那部分是队友负责的，我只能讲我用到的接口；我负责的是…… |
| 理论没学透 | "I used it in practice and I understand the idea, but I haven't studied the full theory yet. Here's what I do know: ..." | 我实践中用过、懂思想，但完整理论还没学；我能讲的是…… |
| 需要时间想 | "Let me think for a second." / "That's a good question — let me structure my answer." | 让我想一下／好问题，我组织一下 |
| 没听清 | "Sorry, could you rephrase that? I want to make sure I answer the right question." | 能否换个说法？ |

## 2. P6 — Kaihong（Robotics Platform Intern，Jun 2026 – Present）

> 对应讲义：[P6 README](../../01_项目课程/P6_深开鸿M-Robots平台软件/README.md)；深挖问答：[P6 英文面试口述与深挖问答](../../01_项目课程/P6_深开鸿M-Robots平台软件/99_英文面试口述与深挖问答.md)。

### 2.1 Unified motion interface

> **CV**：*Unified motion interface: built a unified capability model for sensors, actuators and controllers using C++ on OpenHarmony and mapped ROS/ROS2 motion commands to low-level drivers, enabling motion-control code reuse across hardware.*

**拆句**：
1. "built a unified capability model for sensors, actuators and controllers" = 给三类东西一个统一的描述方式；
2. "using C++ on OpenHarmony" = 实现语言与平台；
3. "mapped ROS/ROS2 motion commands to low-level drivers" = ROS 世界的指令翻译成底层驱动能懂的调用；
4. "enabling motion-control code reuse across hardware" = 结果：同一份控制代码换硬件不用重写。

**口语解释**："Different robots have different sensors and motors, and every driver has its own interface. I made a common description — a capability model — in C++. Then ROS commands go through a mapping down to the drivers. So the motion-control code talks to capabilities, and I can reuse it on different hardware."
中文：不同机器人传感器和电机不同，驱动接口各异。我在 C++ 里做了统一描述（能力模型），ROS 指令通过映射下发到驱动；控制代码面向能力，因此能跨硬件复用。

- **关键词**：capability model / abstraction / driver mapping / reuse。
- **L1 What did you do?** — *"What exactly is a 'capability model'?"* 要点：对传感器、执行器、控制器的统一抽象——每个设备声明"能做什么/提供什么"；上层按能力调用；`【待你补全：能力模型的类/接口形式，如何表示速度控制/位置控制等】`。
- **L2 Why / How?** — *"Why map ROS commands instead of calling drivers directly?"* 要点：ROS/ROS2 是常用生态，运动控制代码已有大量以 ROS 消息为接口；映射层隔离差异，换硬件只改映射/驱动，不改控制逻辑；`【待你补全：映射的具体方式（话题/服务/适配器）】`。
- **L3 What if / limits?** — *"What if two robots' hardware capabilities don't match?"* 要点：能力模型需要能表达"不具备某能力"，上层先查能力再下发；不可抽象的差异（如极限、延迟）需额外参数；抽象有代价（多一层间接）；诚实讲局限。

### 2.2 Robot state management

> **CV**：*Robot state management: standardised timestamps, coordinate frames and validity checks across multi-source perception and actuator feedback, giving the motion-control and task layers a consistent, trusted robot state.*

**拆句**：1) 标准化时间戳、坐标系、有效性检查；2) 覆盖多源感知与执行器反馈；3) 给上层（运动控制层与任务层）一致且可信的状态。

**口语解释**："Data comes from many sources — perception and actuator feedback — with different timestamps and frames. I made them follow one standard: the same time convention, the same frame convention, and a validity check. So the layers above get a state they can trust."
中文：数据来自多个来源，时间戳和坐标系各异；我让它们遵循同一标准——统一时间约定、统一坐标约定和有效性检查；上层得到可信的状态。

- **关键词**：timestamp / frame / validity / trusted state。
- **L1** — *"What data did the state manager handle?"* 要点：多源感知与执行器反馈；统一后供运动控制与任务层使用；`【待你补全：具体有哪些状态量（位姿、速度、关节、电池等）】`。
- **L2** — *"Why is this needed? Give an example of what goes wrong without it."* 要点：P5 的位姿跳变来自时间/坐标系/方向不一致；P7 的平衡异常来自状态不一致；没有统一标准，每个使用者各自猜；见 [跨项目对比 Q32](./02_跨项目技术对比问答.md)。
- **L3** — *"What do you do when a source becomes invalid?"* 要点：标记无效而不是悄悄使用；上层选择保持、降速、停止；`【待你补全：你实现的超时/无效处理策略】`；局限：无效检测靠规则，不能发现"数值合理但错误"的故障。

### 2.3 Coordination and safe execution

> **CV**：*Coordination and safe execution: implemented device discovery, capability registration, state synchronisation and task dispatch over M-DDS, and gated task plans through an action-proposal, policy-check, execution and state-feedback chain.*

**拆句**：1) 基于 M-DDS 的四个协同功能：发现、注册、同步、派发；2) 任务计划被"闸门"：四阶段链。

**口语解释**："Over M-DDS, devices can find each other, register what they can do, share their state, and receive tasks. And a task plan can't just go to the robot: it's an action proposal, then a policy check, then execution, then state feedback. The chain is the gate."
中文：基于 M-DDS，设备能互相发现、注册能力、共享状态、接收任务；任务计划不能直发机器人，要经提案、策略检查、执行、状态反馈，链就是闸门。

- **关键词**：M-DDS / discovery / registration / dispatch / gate / policy check。
- **L1** — *"Walk me through what happens when a plan arrives."* 要点：先作为 action proposal；策略检查依据当前状态与规则判断是否允许；通过则执行；执行后状态反馈回来，供下一次决策使用；`【待你补全：每阶段的输入输出消息】`。
- **L2** — *"Why DDS for coordination?"* 要点：DDS 是以数据为中心的发布-订阅中间件，适合多设备发现与状态共享，ROS2 也基于 DDS；M-DDS 是平台的分布式实现。`【待你补全：M-DDS 与标准 DDS 的区别——仅凭内部了解，别猜】` 见 [DDS 基础](../../02_基础知识/09_机器人软件/05_DDS与分布式通信.md)。
- **L3** — *"Can the policy check itself become a bottleneck or a single point of failure?"* 要点：是，要保持简单、确定、快；失败时应默认"不放行"（fail-safe）；它不能替代设备端自己的底线（呼应 P4）；局限：规则覆盖不到的情形。

## 3. P2 — Future Power（Robotics Software Intern，Mar 2026 – May 2026）

> 对应讲义：[P2 README](../../01_项目课程/P2_未来动力双臂遥操作与差速底盘/README.md)；深挖问答：[P2 英文面试口述与深挖问答](../../01_项目课程/P2_未来动力双臂遥操作与差速底盘/99_英文面试口述与深挖问答.md)。

### 3.1 VR dual-arm teleoperation

> **CV**：*mapped VR controller motion to end-effector targets and solved constrained inverse kinematics with MuJoCo/Mink, achieving end-effector tracking while suppressing velocity amplification near singularities.*

**拆句**：1) VR 手柄运动 → 末端目标；2) 约束逆运动学（MuJoCo/Mink）；3) 达成：末端跟踪 + 抑制奇异点附近的速度放大。

**口语解释**："The operator moves a VR controller. I turn that motion into target poses for the robot's hands, then solve for joint angles with an IK solver that respects constraints. Near a singularity the joints would normally spin very fast; the solver keeps that under control."
中文：操作者移动手柄，我把运动变成机器人手的目标位姿，用带约束的 IK 求关节角；奇异点附近关节本会转得极快，求解器把它压住。

- **关键词**：relative pose mapping / constrained IK / Mink / singularity。
- **L1** — *"How did you map the controller to the robot?"* 要点：手柄运动映射为末端目标（常见做法是相对位姿映射：以按下时刻为基准）；`【待你补全：你们的映射方式——相对/绝对、缩放、坐标系】` 见 [相对位姿映射](../../01_项目课程/P2_未来动力双臂遥操作与差速底盘/02_VR遥操作的相对位姿映射.md)。
- **L2** — *"What does Mink do, and what's the idea of differential IK?"* 要点：Mink 是基于 MuJoCo 的微分逆运动学库，把 IK 写成带任务和约束的 QP，求关节速度；约束（关节限位、速度）直接在优化里处理；见 [MuJoCo 与 Mink 入门](../../01_项目课程/P2_未来动力双臂遥操作与差速底盘/03_MuJoCo与Mink入门.md)。
- **L3** — *"What if the target is unreachable?"* 要点：约束 IK 给出最接近的可行解，不会崩；跟踪误差代价；可在界面提示操作者；`【待你补全：不可达时你们的处理】`。

### 3.2 Leader–follower teaching

> **CV**：*built dual-arm dynamics from URDF/KDL, designed leader-arm gravity compensation and follower position–velocity tracking, enabling low-resistance hand-guided teaching with synchronous follower motion.*

**拆句**：1) URDF/KDL 建双臂动力学；2) leader 重力补偿；3) follower 位置-速度跟踪；4) 结果：手拖轻松，follower 同步。

**口语解释**："I loaded the robot's description from URDF and used KDL to compute the dynamics. On the leader arm, I compute the gravity torque and send it back so the arm feels weightless when a person moves it. The follower copies the leader's position and velocity."
中文：从 URDF 载入模型，用 KDL 算动力学；leader 臂算重力力矩并回送，使人推动时臂"没有重量"；follower 复现 leader 的位置和速度。

- **关键词**：URDF / KDL / gravity compensation / low-resistance / position–velocity tracking。
- **L1** — *"What exactly does gravity compensation compute?"* 要点：给定关节角，算出抵消重力所需的关节力矩 g(q)，作为前馈；KDL 提供；见 [重力补偿与 URDF/KDL](../../02_基础知识/03_坐标变换与运动学/06_机械臂动力学_重力补偿_URDF_KDL.md)。
- **L2** — *"Why is the model quality important for hand-guided teaching?"* 要点：质量/质心不准会过补偿（自己飘走）或欠补偿（沉重）；摩擦也影响手感；`【待你补全：模型参数的来源与调整】`。
- **L3** — *"What are the limits of this approach?"* 要点：只补重力，不补摩擦/惯性，快速运动仍有阻力感；follower 只是位置-速度跟踪，没有力反馈；模型误差；诚实讲。

### 3.3 Wheel-speed control

> **CV**：*mapped body velocity commands to wheel targets via differential-drive kinematics, closed the PID loop using encoder feedback and integrated wheel motion into odometry for teleoperated and autonomous modes.*

**拆句**：1) 车体速度 → 轮目标（差速运动学）；2) 编码器反馈闭环 PID；3) 轮运动 → 里程计；4) 用于遥操作与自主两种模式。

**口语解释**："A command like 'go forward at this speed and turn at this rate' becomes a target speed for the left and right wheels. A PID loop uses the encoder to hit those targets. And I integrate the wheel motion to estimate the robot's pose, which works for both teleoperation and autonomous modes."
中文：'以此速度前进、以此速率转向' 变成左右轮目标转速；PID 用编码器达成；并积分轮运动估计位姿，遥操作与自主模式都能用。

- **关键词**：differential drive / wheel PID / encoder / odometry。
- **L1** — *"Write the differential-drive equations."* 要点：$v_L = v - \omega b/2$，$v_R = v + \omega b/2$（$b$ 为轮距）；里程计反向求 $v,\omega$ 并积分位姿。见 [差速运动学](../../02_基础知识/02_力学与建模/04_差速_麦克纳姆_全向轮与车辆运动学.md)。
- **L2** — *"Why does odometry drift?"* 要点：打滑、轮径误差、编码器离散化、积分累积；因此自主模式需要其他传感器修正（P5 的 EKF/AMCL）；`【待你补全：P2 里程计是否与其他传感器融合】`。
- **L3** — *"What happens if one wheel saturates?"* 要点：两轮不再按比例，实际转向与指令偏离；可对速度指令整体缩放保持比例（与 P3 底盘功率缩放类似）；`【待你补全：你是否处理过】`。

## 4. P1 — AIRS（Robotics Software Intern，Sep 2025 – Mar 2026）

> 对应讲义：[P1 README](../../01_项目课程/P1_AIRS球形机器人平衡控制/README.md)；深挖问答：[P1 英文面试口述与深挖问答](../../01_项目课程/P1_AIRS球形机器人平衡控制/99_英文面试口述与深挖问答.md)。

### 4.1 Cascaded balance control

> **CV**：*designed and deployed a PID cascade using IMU and wheel-speed feedback, a position outer loop feeding bounded attitude references to the attitude inner loop and outputs allocated to three wheels via kinematics.*

**拆句**：1) 用 IMU 与轮速反馈；2) 位置外环 → 有界姿态参考 → 姿态内环；3) 输出经运动学分配到三轮。

**口语解释**："The inner loop keeps the body upright using the IMU. The outer loop watches position and wheel speed and asks the inner loop for a lean angle — but I bound that lean angle. The inner output is a body-level command, and the kinematics splits it among the three omni wheels."
中文：内环用 IMU 保持直立；外环看位置和轮速，向内环要倾角，并对倾角限界；内环输出是机体级指令，运动学把它拆给三个全向轮。

- **关键词**：outer position loop / inner attitude loop / bounded reference / allocation。
- **L1** — *"What are the inputs and outputs of each loop?"* 要点：外环：位置/速度误差 → 姿态参考；内环：姿态误差 → 机体指令；再经运动学分配；`【待你补全：各环采样频率与输出量纲（力矩/电流/速度）】`。
- **L2** — *"Why bound the attitude reference? And why three-wheel allocation?"* 要点：防止外环在大位置误差时要求危险倾角；三轮的全向运动学把机体指令映射成每个轮；见 [三轮运动学](../../01_项目课程/P1_AIRS球形机器人平衡控制/02_球形底盘几何与三轮运动学.md)。
- **L3** — *"What if the outer loop is too fast relative to the inner loop?"* 要点：两环耦合、振荡；经验是内环明显快于外环；`【待你补全：你如何确认带宽关系】`。

### 4.2 LQR modelling and analysis

> **CV**：*modelled the system as a linearised four-state inverted pendulum and used LQR to analyse the stability–control-effort trade-off of state weights, as a model reference for PID tuning and actuator-saturation diagnosis.*

**拆句**：1) 线性化四状态倒立摆；2) LQR 分析状态权重的稳定性-控制量权衡；3) 用途：PID 整定的模型参考、执行器饱和诊断。

中文：我写了简化模型（四状态倒立摆），对它跑 LQR，看对位置、速度、倾角、倾角速率赋不同权重时会怎样；它展示稳定性与电机用力之间的平衡；我用它做 PID 增益参考并理解饱和。

- **L1** — *"What are the four states and what does Q do?"* 要点：position、velocity、tilt、tilt rate；Q 的对角元素表示对各状态偏差的惩罚，R 惩罚控制量；见 [倒立摆建模与线性化](../../02_基础知识/02_力学与建模/03_倒立摆建模与线性化.md)、[LQR](../../02_基础知识/04_控制理论/04_LQR最优控制.md)。

- **L3** — *"What are the limits of the linearised model for your robot?"* 要点：只在平衡点附近有效；手臂运动与质心变化未包含（所以需要质心前馈）；全向轮摩擦、执行器饱和；诚实讲。

### 4.3 Centre-of-mass feedforward

> **CV**：*estimated CoM offset from arm joint states with URDF/Pinocchio, fed roll/pitch gravity feedforward into the balance controller and verified its effect by toggling compensation under fixed arm trajectories.*

**拆句**：1) 由臂关节状态，用 URDF/Pinocchio 估计质心偏移；2) 把 roll/pitch 重力前馈送入平衡控制器；3) 验证：固定轨迹下开关补偿。

**口语解释**："When the arms move, the robot's centre of mass moves, which pushes the body off balance. To check, I ran the same arm motion with the compensation on and off."
中文：臂动时质心移动，把机体推离平衡；用 Pinocchio 由臂关节角算质心位置，加入 roll/pitch 的重力力矩前馈；验证时同一臂运动开关补偿对比。

- **关键词**：CoM / Pinocchio / feedforward / toggle test。
- **L1** — *"How do you compute the CoM with Pinocchio?"* 要点：Pinocchio 载入 URDF，给定关节配置，按各连杆质量和质心计算整体质心（forward kinematics + 质量加权）；`【待你补全：你的具体调用/函数，质量参数来源】`。
- **L2** — *"Why is a toggle test a good verification?"* 要点：控制变量——相同轨迹，仅差一项；避免把其他变化误认为补偿效果；`【待你补全：你观察到的差异（语言描述，不编数字）】`。
- **L3** — *"What if the URDF masses are inaccurate?"* 要点：前馈量不准，可能过补偿或欠补偿；反馈环兜底；可通过开关实验与观察残差修正；局限：只补静态重力，不含动态加速度项。

### 4.4 Hardware safety loop

> **CV**：*integrated ROS state processing with CAN motor execution and implemented state initialisation, output limiting and fall-recovery safeguards, keeping the chassis balanced under arm motion.*

**拆句**：1) 集成 ROS 状态处理与 CAN 电机执行；2) 状态初始化、输出限幅、跌倒恢复保护；3) 结果：臂动下底盘平衡。

**口语解释**："I connected the ROS side, where states are processed, to the CAN side, where the motors are driven. And I added safety: a clean initial state at start-up, limits on what the controller can output, and safeguards for a fall."
中文：把处理状态的 ROS 侧与驱动电机的 CAN 侧连起来，并加了安全措施：启动时干净的初始状态、控制器输出限幅、跌倒保护。

### 5.3 On-robot tuning

- **L3** — *"What if the solver doesn't converge in time?"* 要点：沿用上一个解或安全减速；简化问题；`【待你补全：求解器与超时处理】`。

- **L2** — *"Why cascade?"* 要点：见跨项目对比 Q5；速率环提高响应、降低对象复杂度。
- **L3** — *"What limits the gimbal's tracking performance?"* 要点：电机饱和、摩擦、传感器延迟、视觉延迟；`【待你补全：你遇到的主要限制】`。

### 7.2 Launcher control loops

> **CV**：*built friction-wheel speed loops and a feeder position–velocity dual loop, iterating from PID through variable-gain PID to sliding-mode control with muzzle-velocity feedback for stable continuous firing.*

**拆句**：1) 摩擦轮速度环；2) 拨弹位置-速度双环；3) PID → 变增益 PID → 滑模，使用初速反馈；4) 目标：稳定连发。

**口语解释**："The friction wheels need a steady speed, and the feeder needs to move the projectile exactly one step. I started with PID, then made the gains vary, then moved to sliding-mode control, and used the muzzle velocity to check the result, so continuous firing stays stable."
中文：摩擦轮需要稳定转速，拨弹机构需要精确走一步；先 PID，再变增益，再滑模，并用初速检验，使连发稳定。

- **关键词**：friction wheel / feeder / variable-gain / sliding mode / muzzle velocity。
- **L1** — *"What do the two loops of the feeder do?"* 要点：位置环决定转到哪里，速度环让运动平滑；`【待你补全：拨弹逻辑，如卡弹处理】`。
- **L2** — *"Why did you iterate?"* 要点：每一步针对观察到的问题：负载变化导致转速下降/超调；`【待你补全：每次迭代的具体动机】`；见 [跨项目对比 Q8、Q14](./02_跨项目技术对比问答.md)。
- **L3** — *"What are the risks of sliding-mode control?"* 要点：抖振、对噪声敏感；需要软化切换；`【待你补全：你的处理】`。

### 7.3 Chassis power control

> **CV**：*allocated body velocity to four Mecanum wheels, estimated power demand from real-time power and buffer-energy feedback and scaled wheel speeds, keeping the chassis manoeuvrable under power limits.*

**拆句**：1) 车体速度 → 四麦轮；2) 用实时功率与缓冲能量反馈估计需求；3) 缩放轮速；4) 功率限制下保持机动。

**口语解释**："A Mecanum chassis can move in any direction by mixing the speeds of four wheels. The rules limit the power. I read the real-time power and the buffer energy, estimate how much power the command will need, and scale the wheel speeds down if needed, so we don't break the limit but can still move."
中文：麦轮底盘通过混合四个轮速能向任意方向运动；规则限制功率，我读取实时功率与缓冲能量，估计指令所需功率，必要时缩放轮速，不违反限制又仍能移动。

- **关键词**：Mecanum / buffer energy / power estimate / scale。
- **L1** — *"Write the Mecanum inverse kinematics."* 要点：轮速是 $v_x, v_y, \omega$ 的线性组合，符号取决于轮的安装方向；`【待你补全：你们的坐标定义与符号】`；见 [麦轮运动学](../../02_基础知识/02_力学与建模/04_差速_麦克纳姆_全向轮与车辆运动学.md)。
- **L2** — *"How do you estimate the power demand?"* 要点：功率与力矩×转速相关；用实时功率反馈校准模型；`【待你补全：估计公式、缩放策略】`。
- **L3** — *"What are the trade-offs when scaling wheel speeds?"* 要点：整体按比例缩放保持运动方向，但降低速度；不缩放则可能超功率受罚；`【待你补全：比赛规则下的后果】`。

中文：用 LangGraph 构建决策流程，输入环境读数与视觉事件；极端情形由简单规则立即触发；输出是结构化建议或受约束请求，而不是直接的硬件命令。

中文：在 Hi3861 上泵有状态；土壤够干时启动，湿到足够才停止（两个不同阈值），避免来回抖动；人手动控制时手动优先。

- **L2** — *"Why independent thresholds?"* 要点：滞回防止在阈值附近频繁启停（继电器寿命、水泵冲击）；ADC 噪声下更稳。

## 本章要点速记

1. 面试官念 CV 一句，你先"翻译成人话"（2–3 句），再进入三层追问。
2. L1 问事实，L2 问方法与理由，L3 问边界与失败；每层准备一个英文答案骨架。
3. P1 的 LQR 是分析，P7 的 LQR 是控制器；P2 的奇异是"抑制放大"；P4 的 agent 是"建议"；P6 是"闸门链"。
4. 凡 CV 没有的细节一律 `【待你补全】`，不要现场编；记不清用诚实模板。
5. 每个 bullet 都至少挂一个对应的项目文档链接，追问时可回到那里复习。

## 自测题

1. 不看文档，把 P3 三条 bullet 各用一句英文口语解释。
2. 选 P5 的任一 bullet，现场说出 L1–L3 的问题和你的回答要点。
3. 哪几条 bullet 里含有"验证方式"？分别是什么？（提示：P1 质心前馈、P2 真机验证、P5 真车闭环）
4. 在 Skills 里，哪些词你不能当作"深度掌握"来宣称？为什么？
5. 面试官问 "What was your own contribution in P7 compared to the lab?" 你怎么答？

**答案要点**：3. P1：开关补偿；P2：ROS2-CAN 链真机验证；P5：真车自主导航。4. 视你自评，诚实标注 MPC、滑模、LangGraph 等较浅项。5. 强调 CV 的 "responsible for balance control algorithms and on-robot tuning"，并区分实验室提供的平台与你的算法/整定。
