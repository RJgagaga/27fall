## 4. 硬性约束（所有后续工作都要遵守）

1. **以 CV 为准**。源码、旧文档、学习笔记、中文简历、系统表单与 CV 冲突时，一律按 CV 写；冲突点只记入各项目 README 的"口径备忘（仅自查）"，不进入正文叙述。
2. **P5、P6 的源码禁止参考**（`项目源码/智能车自主导航系统`、`项目源码/深开鸿`）。这两个项目只依据 CV、PS、推荐信、通用知识（P5 另可用学习笔记）。
3. **缺失源码就按 CV 写**，不纠结于源码。
4. **不得把无依据的数字当实测**（增益、频率、阈值、误差、成功率、帧率、延迟、功率上限等）。用户 2026-10 追加指示：不再保留任何待补占位，一律根据 CV 与项目写成具体内容（“本项目取值约…/我们的做法是…”），教学数值仍标“教学示例（非项目实测）”。
5. **面试英文**：所有面试表达用英文，英文后附中文译文；讲解正文用中文。
6. **事实口径**：排名 6 of 156（top 4%），均分 87.63，IELTS Academic 6.5。中文简历的 7/156、前 5% 和部分旧材料的 87.66 都是旧口径，不用。
7. **不碰** `05_学习笔记归档/`（用户的原始问答稿）和 `00_当前申请/`（申请材料）。
8. **P1 的 LQR 只是分析工具，部署的是级联 PID**；P7 才是部署增益调度 LQR。这是推荐信和 CV 共同支持的口径，最容易说混。

## 5. 仓库与 Git 约定

- 提交身份：沿用仓库历史里已有的作者（`git log --format='%an' | sort -u` 查看姓名；邮箱同理用 `%ae`，不要抄进文档），提交时 `git -c user.name="<姓名>" -c user.email="<邮箱>" commit ...`。
- 直接在 `main` 上提交并 `git push -u origin HEAD`。
- 会话里有一个 stop hook（`~/.claude/stop-hook-git-check.sh`），只要工作区有未提交或未跟踪的改动，就会提示"请提交并推送"。因此**每完成一批就提交推送**，不要攒到最后。
- 大文件、原始网页、超过 5 MB 的文件不要提交。
- 提交信息末尾附会话要求的署名行（若当前会话有要求）。
