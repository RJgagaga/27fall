# 04 重构任务 Prompt：申请画像与七个项目

> **一句话定位**：重构时分发给 8 个写作任务（profile、P1–P7）的原始 prompt。以后要**重写或大幅修改**某一部分时，可以把对应 prompt 稍作调整后重新使用；要**局部补充**请用 `待补充清单与补写Prompt.md` 里的 prompt。
> 与原始 prompt 相比的唯一改动：共用文件和旧文档的路径由临时目录改成了仓库内路径。

## 0. 使用方法

1. 开新会话，进入仓库 `RJgagaga/27fall`。
2. 先让会话读 `01_项目背景与原始需求.md`、`写作规范.md`、`CV事实基线.md`、`03_目录结构与文件职责.md`。
3. 贴 0.1 的**公共前缀**，再贴某个任务的 prompt。
4. 重写完成后跑 `工具/check_all.py`（见 `07_质量检查与工具.md`），再提交推送。
5. 重写前先看现有文件，决定是"整体重写"还是"在原文基础上加深"；加深请用补写 prompt，避免覆盖已核实的内容。

### 0.1 公共前缀（每个任务前都有）

```text
你是文档重构团队成员「<任务名>」。仓库根：/home/user/27fall 。先完整阅读三个共用文件（必须遵守）：
- 01_项目学习/06_维护说明/写作规范.md
- 01_项目学习/06_维护说明/CV事实基线.md
- 01_项目学习/06_维护说明/03_目录结构与文件职责.md （第2节为目录树，精确文件名用于交叉链接）

背景：用户在准备港澳硕士申请的英文面试。整个 01_项目学习 目录正在被多个并行 Agent 重写；你只写自己负责的文件，不要改别人的文件，不要运行 git commit/push。
```

### 0.2 重构时的运行方式（供复现）

- 用 `Agent` 工具并行启动 21 个 `general-purpose` 子任务，同时最多 20 个（超过会报并发上限，需等有任务完成再补发）。
- 后期向所有仍在运行的任务发过两类追加消息：①"用户要求加快进度，剩余文件每篇控制在 4000–6000 汉字"；②"立刻收尾，先写最缺的文件"。
- 先把共用规范写成 3 个文件（写作规范 / CV 事实基线 / 目录树）让所有任务读取，保证一致；旧文档先移到临时目录再重建新树。
- 所有任务写完后统一做链接检查、格式检查、口径一致性检查，再提交推送。
