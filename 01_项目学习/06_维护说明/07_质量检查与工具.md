# 07 质量检查、工具与工作流程

> **一句话定位**：每次补写或优化文档的标准流程，以及检查脚本怎么用、各项检查的标准是什么。

## 1. 标准工作流程（一个会话内）

```text
1. 读背景            01_项目背景与原始需求.md、写作规范.md、CV事实基线.md
2. 选任务            待补充清单与补写Prompt.md → 找到要补的文件和对应 prompt
3. 读现有内容        先完整读目标文件和同项目 README；不要覆盖已核实的内容
4. 查资料            CV事实基线 → 02_材料地图 → 学习笔记 → 源码（P5/P6 禁止）
5. 写                按写作规范的"八步讲解"；缺依据的细节写成具体设计取值，不留占位
6. 同步登记          新增的占位登记到该项目 README 的"## 实机细节自查表"；新增/删除文件要更新该项目 README 的阅读顺序
7. 自查              python -I 01_项目学习/06_维护说明/工具/check_all.py   （必须通过）
8. 提交推送          git add -A && git commit && git push -u origin HEAD   （main 分支）
```

> 如果同时开多个会话并行补写，每个会话只改自己负责的文件；最后由一个会话统一跑检查、解决冲突、提交。

## 2. 工具

| 脚本 | 作用 | 用法（仓库根目录） |
|---|---|---|
| `工具/check_all.py` | 全量检查：断链、代码围栏、`$$` 配对、`\[ \]` 公式定界、手机号/邮箱、项目 README 自查表标题 | `python -I 01_项目学习/06_维护说明/工具/check_all.py`，退出码 0 即通过 |
| `工具/gen_inventory.py` | 生成文件清单（标题、汉字数、英文词数、占位数），用于更新 `03_目录结构与文件职责.md` 第 5 节和 `待补充清单与补写Prompt.md` | `python -I 01_项目学习/06_维护说明/工具/gen_inventory.py > /tmp/inv.md` |
| `工具/fix_broken_links.py` | 把指向不存在文件的链接改成纯文字（图片链接改成文字说明）。**会直接改文件**，先 `git status` 确认干净再用；用在补写完成后收尾，不要在补写过程中跑 | 在 `01_项目学习/` 目录下运行 `python -I 06_维护说明/工具/fix_broken_links.py` |

> 用 `python -I`（隔离模式）运行，避免当前目录里的同名模块被误导入。

## 3. 检查标准

| 检查项 | 标准 | 说明 |
|---|---|---|
| 相对链接 | 目标文件必须存在 | 链接到尚未写的文件时，先写文件，或暂时写成纯文字并在 README 标"未写" |
| 代码围栏 | 每个文件 ``` 的数量为偶数 | 奇数会让后面的内容整段变成代码 |
| 公式 | `$$` 出现次数为偶数；不使用 `\[ … \]` | GitHub 渲染 `$…$` 与 `$$…$$`；矩阵用 `\begin{bmatrix}` |
| 隐私 | 不含手机号、邮箱 | 推荐人和本人联系方式不抄入学习文档 |
| 项目 README | 含精确标题 `## 实机细节自查表` | 其他文档用 `#实机细节自查表` 锚点链接它 |
| 口径 | 排名 6 of 156 / top 4%，均分 87.63 | 用 `grep -rnE '7/156|87\.66|前 ?5%'` 排查；`00_申请画像/04_口径与事实基线.md` 里讲旧口径的地方除外 |
| 事实 | 凡"我做了 X"必须有 CV/PS/推荐信/源码/笔记依据 | 其余用"典型做法 / typically"措辞 |
| 数值 | 没有依据的数字必须标"教学示例（非项目实测）"或"推算"并给算式 | 面试会追问的实机数字写成与自查表一致的具体取值 |
| 中英文 | 面试表达为英文，英文后附中文译文 | 讲解正文中文 |

人工抽查（脚本查不到的）：
1. 随机抽 3 个文件，在 GitHub 网页上打开，看公式和 mermaid 是否正常渲染（重构时没有逐一验证）。
2. 抽查英文答案是否口语化、是否过长；是否出现 CV 里没有的经历。
3. 抽查"本项目怎么用"一节是否写成了未经依据的事实。

## 4. 常见坑

1. **链接前缀**：从 `02_基础知识/xx/yy.md` 链项目是 `../../01_项目课程/…`（两个 `..`），不是三个。
2. **P1 的 LQR**：只能说"用 LQR 分析"，不能说"部署 LQR"。
3. **P7 与课程仓库**：课程是 ESP32-S3 / 四状态单输出；CV 是 STM32H7 / 六状态双输出。不要把课程细节当成用户项目的事实。
4. **P4 的 YOLO**：CV 是 YOLOv5；笔记里大量 YOLOv8 的格式 `(1, 4+nc, 8400)` 不能套用（v5 是 `5+nc`、25200 个预测）。
5. **P2 的 PID**：不要在没确认的情况下写"STM32 固件里有轮速 PID"。
6. **读码发现的隐患**不能说成用户的贡献。
7. **占位检查**：用 `grep -rnE '【待|【补全|\[FILL|待补' --include=*.md 01_项目学习` 确认零命中（排除 05_学习笔记归档、06_维护说明 自身的说明文字）。
8. **stop hook**：工作区有未提交的改动就会提示提交推送；每批改完就提交。
9. **文件名含中文**：不要转义，不要改名；改名要同步改所有链接（用脚本检查）。
10. **代码块里的 `\`**：本仓库没有"含反斜杠必须用 Write 工具"的限制，但写 LaTeX 时注意 Markdown 转义（`\\`、`_`、`*`）。

## 5. 更新文档规模统计

补写后更新三处数字：①`01_项目背景与原始需求.md` 第 6 节；②`待补充清单与补写Prompt.md` 的清单与第 8 节对照表；③`03_目录结构与文件职责.md` 第 5 节（重新生成清单）。
