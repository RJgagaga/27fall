# 写作规范（所有 Agent 必读）

## 0. 总目标
用户（赖咏怡，Yongyi Lai）正在准备港澳硕士申请的**英文面试**。目标：**只读你写的文档，就能学会全部项目、基础知识、八股，并能用英文应对各类面试**。因此：特别详细、具体、完整、有逻辑、排版好看；不是提纲，不是摘要，是教材级讲解。

## 1. 事实与诚实（最重要）
1. **以 CV 为准**（见 `CV事实基线.md`）。所有项目叙述从 CV 的 bullet 出发。源码、旧文档、学习笔记、中文简历若与 CV 冲突，一律按 CV 写；冲突点不要写进正文叙述，改记入该项目 README 末尾的「口径备忘（仅自查，面试按 CV 说）」。
2. **缺失源码就根据 CV + 通用工程知识写**，不要纠结于源码。P3、P4 的源码目录是空子模块；P1 的平衡控制源码缺失；P2 的 VR 目录为空；P7 仓库是公开课程代码；P5、P6 的源码**禁止参考**（只用 CV）。
3. **不得把无依据的数字当实测**：CV 和源码里没有的具体数值（增益、频率、阈值、误差、成功率、帧率、延迟、功率上限等）不要当作实测事实写。用户 2026-10 追加指示：不再使用任何待补占位，凡面试官可能追问而资料没有的细节，写成与 CV 一致、项目内前后一致的具体设计取值（“本项目取值约…/我们的做法是…”），并汇入该项目 README 的「实机细节自查表」；纯举例的数值标「教学示例（非项目实测）」。
4. 技术讲解可以合理推断"这类系统通常怎么做"，但要用"典型做法 / 常见实现"这类措辞，不能写成"你做了X"。凡写"你做了X"，必须能在 CV、PS、推荐信、源码或学习笔记中找到依据。
5. 面试英文答案用第一人称（I），只陈述有依据的事实；对没有依据的细节，答案里提供**诚实的回答模板**（如 "I don't have the exact figure in front of me, but ..." 的变体，仅用于用户确实记不清时），并鼓励用户补全。
6. 不写任何关于某人隐私的内容（电话、邮箱等不要抄进学习文档）。

## 2. 语言
- 讲解正文用**中文**；术语首次出现给英文：`卡尔曼滤波（Kalman filter）`。
- **所有面试表达用英文**：英文答案后附一行中文译文（或要点），便于核对。英文要自然口语化、适合"说"出来，句子不过长；避免背书感。
- 代码、公式变量、文件名、标识符用英文 ASCII。

## 3. 讲解方式（教材级）
每一个概念按这个顺序展开（可视内容合并，但不能缺逻辑）：
1. **它要解决什么问题**（现实对象/场景，一句话直觉）
2. **符号与单位**（每个字母是什么、单位、正方向）
3. **推导**（一步一步，不跳步；给出为什么这样做，而不是只给结论）
4. **完整手算例子**（数字小而干净，算每一步；教学数值标注"示例"）
5. **在本项目里怎么用**（链接到具体项目文档）
6. **常见错误 / 边界 / 故障现象**
7. **面试怎么问、怎么答**（至少 2–4 个英文问答，含追问方向）
8. **自测题**（5 道左右，附答案或要点）
基础文档和八股文档同样遵守，但项目无关的八股可用「问—答要点—英文速答」格式，每条要有实质内容，不是一句话。

## 4. 排版（GitHub Markdown）
- 标题层级：`#` 文档标题（仅一个）→ `##` 章 → `###` 节。章节用序号（一、二、…或 1. 2.）。
- 文档开头固定结构：一句话定位 → **本章学完你能……** 清单 → 前置知识（带链接）→ 目录（可选，长文必加）。
- 结尾固定：**本章要点速记**（5–10 条）→ 自测题 → 相关链接（上一章/下一章/相关项目）。
- 公式：行内 `$...$`，独立 `$$...$$`（GitHub 渲染 KaTeX）。避免使用 `\[ \]`。公式里的下划线、大括号要正确。矩阵用 `\begin{bmatrix}`。
- 图：优先用 ASCII 示意图放在 ```text 代码块里（对齐、不乱码），或简单的 ```mermaid（flowchart / sequenceDiagram，语法务必正确、节点文字不含特殊括号，否则不渲染）。不要用外部图片。
- 表格用于对比和速查；提示用引用块：`> **提示**`、`> **注意**`、`> **面试要点**`。
- 代码块标注语言（```c / ```cpp / ```python / ```text）。示例代码短小、可读、正确；明确"教学示例，非项目源码"。
- 每个文档**不得有空洞套话**；篇幅按内容需要，基础/项目文档一般 4000–12000 汉字等量，宁可多讲清楚一步。
- 不要输出"待续""略""同上"。每个文件必须完整。
