# 项目口述逐句精讲：把 CV 每条 bullet 拆成可替换的句型模板

> **一句话定位**：CV 的 bullet 是书面语，一句话里塞了 3–4 个名词短语和 2–3 个动词。口述时要把它拆成“主干句 + 细节句 + 因果句”，并且能随时替换其中的名词。本章对 CV 的 24 条项目 bullet 逐条做四件事：①原句；②拆句（意群）；③句型模板（带 `[ ]` 替换位）；④口语示范（英文 + 中文）。

**本章学完你能……**

- 看到任何一条 CV bullet，用 30 秒把它拆成口语的 3–4 句；
- 掌握“动词 + 对象 + using/with + 方法”这类 CV 句型的口语转换套路；
- 把同一个模板换词后用在不同项目，做到“一个模板，七个项目”；
- 在被追问时，沿着“拆句”里的意群逐个往下答，不会漏掉关键信息。

**前置知识**：[01_面试英语基础语法与句型](./01_面试英语基础语法与句型.md)（时态与被动）、[08_高频句型库](./08_高频句型库.md)、[07_项目术语英文说法](./07_项目术语英文说法.md)。

## 1. CV 句式的通用拆解套路（五步）

CV 里的 bullet 通常长这样：

```text
[主题标签]: [动词1] and [动词2] [对象] using [方法/工具], [结果分句 -ing].
```

口述时按下面五步拆：

| 步骤 | 做什么 | 例 |
|---|---|---|
| 1 | 去掉标签，找**主干动词 + 对象** | designed and deployed a PID cascade |
| 2 | 找出 **using / with / via** 引出的方法 | using IMU and wheel-speed feedback |
| 3 | 找出 **-ing 结果分句** | feeding bounded attitude references… |
| 4 | 把长句拆成 2–4 个短句，每句一个意群 | 见各条示范 |
| 5 | 补一句**为什么**（因果句）和一句**怎么验证** | The reference is bounded because… |

> **提示**：这五步也是面试官追问的顺序：做了什么 → 怎么做 → 为什么 → 怎么验证。

## 2. 通用模板库（12 个可替换骨架）

下面的骨架在 24 条 bullet 里反复出现，先掌握它们。

| # | 骨架 | 用途 | 示例 | 中文 |
|---|---|---|---|---|
| T1 | I designed and deployed [X] on [platform]. | 主干句 | I designed and deployed a PID cascade on the real robot. | 我在真机上设计并部署了 PID 级联。 |
| T2 | It uses [A] and [B] as feedback. | 方法 | It uses the IMU and the wheel speeds as feedback. | 它用 IMU 和轮速作反馈。 |
| T3 | [The outer loop] gives [the inner loop] [a bounded reference]. | 层级关系 | The position loop gives the attitude loop a bounded tilt reference. | 位置环给姿态环有界倾角参考。 |
| T4 | [X] is allocated / mapped / converted to [Y] through [Z]. | 转换关系 | The output is allocated to three wheels through the kinematics. | 输出通过运动学分配给三个轮子。 |
| T5 | I modelled [X] as [Y] and used [Z] to [purpose]. | 建模 | I modelled the robot as a four-state pendulum and used LQR to study the trade-off. | 我把机器人建成四状态倒立摆，用 LQR 研究权衡。 |
| T6 | The model served as a reference for [A] and [B]. | 模型用途 | The model served as a reference for tuning and saturation diagnosis. | 模型用作整定和饱和诊断的参照。 |
| T7 | I estimated [X] from [Y] and fed it into [Z]. | 估计+前馈 | I estimated the CoM offset from the joint states and fed it into the balance controller. | 我根据关节状态估计质心偏移并送入平衡控制器。 |
| T8 | I verified the effect by [method]. | 验证 | I verified the effect by toggling the compensation under a fixed trajectory. | 我通过固定轨迹下开关补偿验证效果。 |
| T9 | I traced [the problem] to [cause]. | 定位问题 | I traced the anomaly to state inconsistency. | 我把异常追溯到状态不一致。 |
| T10 | I implemented [A], [B] and [C] to keep [goal]. | 安全机制 | I implemented initialisation, output limiting and fall recovery to keep the chassis balanced. | 我实现了初始化、输出限幅和跌倒恢复来保持底盘平衡。 |
| T11 | I iterated from [A] to [B] to [C] with [feedback]. | 迭代 | I iterated from PID to variable-gain PID to sliding-mode control with muzzle-velocity feedback. | 我借助枪口初速反馈从 PID 迭代到变增益再到滑模。 |
| T12 | [Module] is gated through [chain]. | 把关链 | Every task plan is gated through a proposal, a policy check, execution and feedback. | 每个任务计划都经提案、策略校验、执行和回传把关。 |

## 3. P6 Kaihong（3 条）

### 3.1 Unified motion interface

**CV 原句**

> Unified motion interface: built a unified capability model for sensors, actuators and controllers using C++ on OpenHarmony and mapped ROS/ROS2 motion commands to low-level drivers, enabling motion-control code reuse across hardware.

**拆句（4 个意群）**

1. built a unified capability model（做了什么）
2. for sensors, actuators and controllers（对象范围）
3. using C++ on OpenHarmony（工具和平台）
4. mapped ROS/ROS2 commands to low-level drivers, enabling reuse（结果）

**句型模板**

> I built [a unified capability model] for [sensors, actuators and controllers] in [C++] on [OpenHarmony]. [ROS and ROS 2 commands] are mapped to [the low-level drivers]. As a result, [the same motion code can be reused across hardware].

**口语示范**

> I built a unified capability model in C++ on OpenHarmony. It describes sensors, actuators and controllers by what they can do, not by which device they are. ROS and ROS 2 motion commands are mapped to the low-level drivers, so the same motion-control code can run on different hardware.
>
> 中文：我在 OpenHarmony 上用 C++ 建了统一能力模型。它按“能做什么”而不是“是什么设备”来描述传感器、执行器和控制器。ROS 和 ROS 2 的运动命令被映射到底层驱动，所以同一份运动控制代码可以在不同硬件上运行。

**可替换词**：capability model → device abstraction layer；ROS/ROS 2 commands → task requests；low-level drivers → hardware adapters。

**追问准备**：Why a capability model? / How did you map the commands? / What is hard about reuse? — 回答参见 [P6 英文口述](../01_项目课程/P6_深开鸿M-Robots平台软件/99_英文面试口述与深挖问答.md)。

### 3.2 Robot state management

**CV 原句**

> Robot state management: standardised timestamps, coordinate frames and validity checks across multi-source perception and actuator feedback, giving the motion-control and task layers a consistent, trusted robot state.

**拆句**

1. standardised timestamps, frames and validity checks（做了什么）
2. across multi-source perception and actuator feedback（范围）
3. giving the motion-control and task layers a consistent, trusted state（目的）

**句型模板**

> I standardised [the timestamps, the coordinate frames and the validity checks] across [perception and actuator feedback]. This gives [the control layer and the task layer] [one consistent, trusted state].

**口语示范**

> Sensors and actuators report data with different clocks, frames and quality. I put the timestamps on one clock, expressed every measurement in a declared frame, and added validity checks so old or implausible data is marked invalid. The motion-control layer and the task layer then see one consistent robot state they can trust.
>
> 中文：传感器和执行器各自带着不同的时钟、坐标系和质量。我把时间戳统一到一个时钟，把每个测量表示在声明的坐标系里，并加入有效性检查，让过期或不合理的数据被标为无效。这样运动控制层和任务层看到的是一份一致、可信的机器人状态。

**可替换词**：validity checks → data-age check, range check；task layer → planner。

### 3.3 Coordination and safe execution

**CV 原句**

> Coordination and safe execution: implemented device discovery, capability registration, state synchronisation and task dispatch over M-DDS, and gated task plans through an action-proposal, policy-check, execution and state-feedback chain.

**拆句**

1. implemented discovery, registration, synchronisation, dispatch over M-DDS（协同）
2. gated task plans through a four-step chain（安全执行）

**句型模板**

> Over [M-DDS], I implemented [device discovery, capability registration, state synchronisation and task dispatch]. Every [task plan] is gated through [a proposal, a policy check, execution and state feedback].

**口语示范**

> Over M-DDS, I implemented four things: device discovery, capability registration, state synchronisation and task dispatch. On top of that, every task plan is gated through a chain. First it is only an action proposal. Then the policy layer checks it against the real state and limits. Only an accepted proposal reaches execution, and the result comes back as state feedback.
>
> 中文：我在 M-DDS 上实现了四件事：设备发现、能力注册、状态同步和任务分发。在此之上，每个任务计划都要经过一条链：先只是动作提案，再由策略层对照真实状态和限制检查，只有被接受的提案才会执行，结果以状态回传返回。

**为什么**：A plan can be wrong or out of date, so deciding and acting are separated.（计划可能错误或过期，所以决策和执行分离。）

## 4. P2 Future Power（3 条）

### 4.1 VR dual-arm teleoperation

**CV 原句**

> VR dual-arm teleoperation: mapped VR controller motion to end-effector targets and solved constrained inverse kinematics with MuJoCo/Mink, achieving end-effector tracking while suppressing velocity amplification near singularities.

**拆句**

1. mapped VR controller motion to end-effector targets（输入映射）
2. solved constrained IK with MuJoCo/Mink（求解）
3. tracking while suppressing velocity amplification near singularities（效果）

**句型模板**

> I mapped [the VR controller motion] to [end-effector targets] and solved [constrained inverse kinematics] with [MuJoCo and Mink]. Near [singularities], [damping] keeps [the joint velocities] bounded.

**口语示范**

> I mapped the motion of the VR controller to end-effector targets for the two arms. Then I solved a constrained inverse kinematics problem with MuJoCo and Mink, so the joint positions and velocities stay within their limits. Near a singularity, a plain inverse would give huge joint velocities, so I used damping to keep them bounded, at the cost of a small tracking error.
>
> 中文：我把 VR 手柄的运动映射成两条臂的末端目标，然后用 MuJoCo 和 Mink 求解带约束的逆运动学，使关节位置和速度保持在限位内。奇异点附近普通求逆会给出巨大关节速度，所以我用阻尼使它们有界，代价是小的跟踪误差。

**可替换词**：VR controller → operator's hand；MuJoCo/Mink → any differential IK solver。

### 4.2 Leader–follower teaching

**CV 原句**

> Leader–follower teaching: built dual-arm dynamics from URDF/KDL, designed leader-arm gravity compensation and follower position–velocity tracking, enabling low-resistance hand-guided teaching with synchronous follower motion.

**拆句**

1. built dual-arm dynamics from URDF/KDL（建模）
2. designed leader gravity compensation（主臂）
3. designed follower position–velocity tracking（从臂）
4. result: low-resistance teaching, synchronous motion（结果）

**句型模板**

> I built [the arm dynamics] from [the URDF] with [KDL]. On the leader arm, [gravity compensation] makes it [easy to move by hand]. The follower [tracks the leader] with [position and velocity terms].

**口语示范**

> I built the dual-arm dynamics from the URDF with KDL. For the leader arm, I added gravity compensation, so the operator can move it by hand with very little resistance. The follower tracks the leader with a position term and a velocity term, so the two arms move together. The load on the last joint is the least certain, so I compensate it slightly less.
>
> 中文：我用 KDL 从 URDF 构建双臂动力学。主臂加了重力补偿，操作者几乎无阻力地用手移动它。从臂用位置项和速度项跟踪主臂，两臂同步运动。最后一个关节的负载最不确定，所以我对它略微欠补偿。

### 4.3 Wheel-speed control

**CV 原句**

> Wheel-speed control: mapped body velocity commands to wheel targets via differential-drive kinematics, closed the PID loop using encoder feedback and integrated wheel motion into odometry for teleoperated and autonomous modes.

**拆句**

1. mapped body velocity to wheel targets（运动学）
2. closed the PID loop with encoder feedback（闭环）
3. integrated wheel motion into odometry（里程计）
4. for teleoperated and autonomous modes（场景）

**句型模板**

> I mapped [the body velocity command] to [the wheel speeds] with [differential-drive kinematics]. [Each wheel] has [a PID loop] using [encoder feedback]. The wheel motion is integrated into [odometry] for [both modes].

**口语示范**

> The base receives a body velocity command, linear and angular. Differential-drive kinematics turns it into a speed target for each wheel. A PID loop on the chassis board closes the loop with the encoder feedback. Finally, the wheel motion is integrated into odometry, which is used in both the teleoperated and the autonomous modes.
>
> 中文：底盘收到车体速度指令（线速度和角速度）。差速运动学把它变成每个轮子的速度目标。底盘板上的 PID 用编码器反馈闭环。最后，轮子的运动被积分成里程计，在遥操作和自主两种模式下都使用。

## 5. P1 AIRS（4 条）

### 5.1 Cascaded balance control

**CV 原句**

> Cascaded balance control: designed and deployed a PID cascade using IMU and wheel-speed feedback, a position outer loop feeding bounded attitude references to the attitude inner loop and outputs allocated to three wheels via kinematics.

**拆句**

1. designed and deployed a PID cascade（主干）
2. using IMU and wheel-speed feedback（反馈）
3. position outer loop → bounded attitude reference → inner loop（层级）
4. outputs allocated to three wheels via kinematics（执行）

**句型模板**

> T1 + T2 + T3 + T4：I designed and deployed [a PID cascade]. It uses [the IMU and the wheel speeds]. [The position loop] gives [the attitude loop] [a bounded reference], and the output is allocated to [three wheels].

**口语示范**

> I designed and deployed a PID cascade for balance. The feedback comes from the IMU and the wheel speeds. The slow outer loop controls the position and gives the fast inner loop a bounded tilt reference, so a large position error never asks the attitude loop for too much. The inner loop controls the attitude, and its output is allocated to the three wheels through the kinematics.
>
> 中文：我为平衡设计并部署了 PID 级联。反馈来自 IMU 和轮速。慢的外环控制位置，给快的内环一个有界倾角参考，所以大的位置误差不会让姿态环被要求过多。内环控制姿态，其输出通过运动学分配给三个轮子。

**因果句**：The reference is bounded because a large tilt command could make the robot fall.

### 5.2 LQR modelling and analysis

**CV 原句**

> LQR modelling and analysis: modelled the system as a linearised four-state inverted pendulum and used LQR to analyse the stability–control-effort trade-off of state weights, as a model reference for PID tuning and actuator-saturation diagnosis.

**拆句**

1. modelled the system as a linearised four-state pendulum（建模）
2. used LQR to analyse the weight trade-off（分析）
3. as a reference for PID tuning and saturation diagnosis（用途）

**句型模板**

> T5 + T6：I modelled [the system] as [a linearised four-state inverted pendulum] and used [LQR] to analyse [how the weights trade off stability against control effort]. The model served as a reference for [PID tuning] and [saturation diagnosis].

**口语示范**

> After the PID cascade was working, I went back to the model. I linearised the system as a four-state inverted pendulum: position, velocity, tilt and tilt rate. Then I used LQR to see how the state weights trade off stability against control effort. I did not deploy LQR on the robot. I used it as a reference to understand the deployed gains and to diagnose where the command was saturating.
>
> 中文：PID 级联跑通后，我回到模型。我把系统线性化为四状态倒立摆：位置、速度、倾角、倾角速率。然后用 LQR 看状态权重如何在稳定性与控制量之间取舍。我没有把 LQR 部署到机器人上，而是用它作参照来理解已部署的增益，并诊断指令在哪里饱和。

**诚实点**：LQR 只作参照，不要说成上机。

### 5.3 Centre-of-mass feedforward

**CV 原句**

> Centre-of-mass feedforward: estimated CoM offset from arm joint states with URDF/Pinocchio, fed roll/pitch gravity feedforward into the balance controller and verified its effect by toggling compensation under fixed arm trajectories.

**拆句**

1. estimated CoM offset from arm joint states with URDF/Pinocchio（估计）
2. fed roll/pitch gravity feedforward into the controller（前馈）
3. verified by toggling compensation under fixed trajectories（验证）

**句型模板**

> T7 + T8：I estimated [the centre-of-mass offset] from [the arm joint states] with [URDF and Pinocchio] and fed [a roll and pitch feedforward] into [the balance controller]. I verified it by [toggling the compensation under a fixed arm trajectory].

**口语示范**

> When the arms move, the centre of mass moves too, and the feedback alone has to fight that load. So I computed the centre-of-mass offset from the arm joint states, using the URDF and Pinocchio, and added a roll and pitch gravity feedforward to the balance controller. To check it, I ran the same fixed arm trajectory several times with the compensation off and on, and compared the tilt peak and the drift.
>
> 中文：手臂运动时质心也在移动，仅靠反馈就要去对抗这个负载。所以我用 URDF 和 Pinocchio 由手臂关节状态计算质心偏移，并给平衡控制器加了横滚和俯仰的重力前馈。验证时，我在相同的固定手臂轨迹下，补偿关与开各跑多次，比较倾角峰值和漂移。

### 5.4 Hardware safety loop

**CV 原句**

> Hardware safety loop: integrated ROS state processing with CAN motor execution and implemented state initialisation, output limiting and fall-recovery safeguards, keeping the chassis balanced under arm motion.

**拆句**

1. integrated ROS state processing with CAN motor execution（集成）
2. implemented initialisation, limiting, fall recovery（安全）
3. result: balanced under arm motion（结果）

**句型模板**

> T10：I integrated [ROS state processing] with [CAN motor execution]. I implemented [state initialisation], [output limiting] and [fall-recovery safeguards] to keep [the chassis balanced under arm motion].

**口语示范**

> I connected the ROS state processing to the CAN motor execution. For safety, I added three things. First, state initialisation: at enable, I measure the tilt bias while the robot is held still, and clear the integrator and the filters. Second, output limiting: the wheel command is limited as a whole and its rate of change is limited too. Third, fall recovery: if the tilt stays too large for several cycles, the output is set to zero and the controller locks in a fault state until a person re-enables it.
>
> 中文：我把 ROS 状态处理接到 CAN 电机执行上。为了安全，我加了三样：一是状态初始化，使能时在机器人被扶稳时测量倾角偏置，并清除积分器和滤波器；二是输出限幅，轮命令整体限幅并限制变化率；三是跌倒恢复，倾角连续数个周期过大时，输出置零并锁定为故障状态，直到有人重新使能。

## 6. P7 轮腿（3 条）

### 6.1 Gain-scheduled LQR

**CV 原句**

> Gain-scheduled LQR: built body-pitch and motion states from IMU, wheel-speed and joint feedback, scheduled LQR gains by leg length and converted balance and motion errors into wheel-hub and hip torques.

**拆句**

1. built pitch and motion states from IMU, wheel speed, joints（状态）
2. scheduled LQR gains by leg length（调度）
3. converted errors into wheel and hip torques（输出）

**句型模板**

> I built [the state] from [A, B and C]. I scheduled [the LQR gains] by [leg length]. The controller converts [the balance and motion errors] into [wheel-hub and hip torques].

**口语示范**

> The balance controller needs a clean state, so I built the body pitch and the motion states from three sources: the IMU, the wheel speeds and the joint feedback. Because the leg length changes the dynamics, I scheduled the LQR gains by leg length, with a polynomial fit. The controller then converts the balance and motion errors into wheel-hub torques and hip torques.
>
> 中文：平衡控制器需要干净的状态，所以我用 IMU、轮速和关节反馈三个来源构造机身俯仰和运动状态。因为腿长会改变动力学，我用多项式拟合按腿长调度 LQR 增益。控制器再把平衡和运动误差转化为轮毂力矩和髋关节力矩。

### 6.2 VMC torque control

**CV 原句**

> VMC torque control: computed virtual leg length and posture from closed-chain kinematics, mapped support force and pitch torque to joints via the Jacobian, and coordinated leg extension with leg-length PID and force feedforward.

**拆句**

1. computed virtual leg length and posture from closed-chain kinematics（运动学）
2. mapped support force and pitch torque to joints via Jacobian（力映射）
3. coordinated leg extension with PID and force feedforward（腿长）

**句型模板**

> I computed [the virtual leg length and angle] from [the closed-chain kinematics]. [The support force and the pitch torque] are mapped to [the joints] through [the Jacobian]. A [leg-length PID] with [force feedforward] holds [the commanded length].

**口语示范**

> The leg is a closed-chain linkage, so I first compute a virtual leg, with its length and angle, from the closed-chain kinematics. Then, virtual model control gives me a desired support force along the leg and a pitch torque, and I map them to the two joint torques through the Jacobian. For the leg length itself, a PID with a force feedforward holds the commanded height; the feedforward carries the body weight so the PID only corrects the error.
>
> 中文：腿是闭链连杆，所以我先由闭链运动学算出虚拟腿的长度和角度。然后 VMC 给出沿腿的期望支撑力和一个俯仰力矩，我通过雅可比把它们映射成两个关节力矩。腿长本身由带力前馈的 PID 保持；前馈承担机身重量，PID 只修正误差。

### 6.3 On-robot tuning

**CV 原句**

> On-robot tuning: integrated feedback and torque output on an STM32H7/FreeRTOS and FDCAN chain, traced balance anomalies to state inconsistency, torque limits and ground-contact transitions, and tuned parameters on the robot.

**拆句**

1. integrated feedback and torque output on STM32H7/FreeRTOS/FDCAN（集成）
2. traced anomalies to three causes（定位）
3. tuned parameters on the robot（整定）

**句型模板**

> T9：I integrated [feedback and torque output] on [an STM32H7 with FreeRTOS and FDCAN]. I traced [the balance anomalies] to [state inconsistency, torque limits and ground-contact transitions].

**口语示范**

> I ran the feedback and the torque output on an STM32H7 with FreeRTOS and FDCAN. On the robot I found three kinds of anomalies. First, state inconsistency: the IMU and joint data were not taken at the same time, and the robot crept slowly. Second, torque limits: a step in the speed command hit the limit, so I added a ramp. Third, ground-contact transitions: the wheel spun in the air at take-off, so I set the torque to zero when the support force dropped.
>
> 中文：我在 STM32H7（FreeRTOS、FDCAN）上运行反馈和力矩输出。真机上发现三类异常：一是状态不一致，IMU 与关节数据不同步，机器人缓慢爬行；二是力矩限制，速度指令阶跃撞上限制，所以加了斜坡；三是接地切换，离地时轮子空转，所以支撑力下降时把力矩置零。

## 7. P5 导航（4 条）

### 7.1 EKF/AMCL localisation

**CV 原句**

> EKF/AMCL localisation: fused IMU, wheel encoders and 2D LiDAR for map-based localisation, handled drift and pose jumps from inconsistent timing, frames and motion direction, and output a continuous vehicle state.

**拆句**

1. fused IMU, encoders, 2D LiDAR（融合）
2. handled drift and pose jumps from inconsistent timing, frames, direction（问题）
3. output a continuous vehicle state（结果）

**句型模板**

> I fused [A, B and C] for [map-based localisation]. The pose jumps came from [inconsistent timing, frames and motion direction], and I fixed them by [unifying them]. The output is [a continuous vehicle state].

**口语示范**

> I fused the IMU, the wheel encoders and the 2D LiDAR: an EKF gives a smooth local pose, and AMCL corrects its drift on a known map. The hard part was pose jumps when the car turned or reversed. They came from three inconsistencies: the LiDAR timestamp was taken at arrival, the reverse direction was lost in the speed message, and some static transforms were wrong. After I unified them, the vehicle state became continuous.
>
> 中文：我融合了 IMU、轮编码器和二维激光雷达：EKF 给出平滑的局部位姿，AMCL 在已知地图上纠正漂移。难点是车转弯或倒车时的位姿跳变，来自三种不一致：激光雷达时间戳取在到达时刻、速度消息里丢了倒车方向、部分静态变换有误。统一之后车辆状态变得连续。

### 7.2 Hybrid-A* global planning

**CV 原句**

> Hybrid-A* global planning: incorporated vehicle heading and kinematic constraints into the search and generated feasible global paths under vehicle-footprint, minimum-turning-radius and obstacle-cost constraints.

**拆句**

1. incorporated heading and kinematic constraints into the search（搜索）
2. generated feasible paths（结果）
3. under footprint, turning radius, obstacle cost（约束）

**句型模板**

> I used [Hybrid A*] so that [the search] respects [the heading and the kinematic constraints]. The planner takes into account [the footprint, the minimum turning radius and the obstacle cost].

**口语示范**

> A car cannot turn on the spot, so a plain grid A* path is not drivable. Hybrid A* searches over x, y and heading, and expands motion primitives such as left, straight and right. So the path respects the minimum turning radius, and the vehicle footprint and the obstacle cost are taken into account through the costmap. The result is a feasible global path that the real vehicle can follow.
>
> 中文：汽车不能原地转向，所以普通栅格 A* 的路径不可行驶。Hybrid A* 在 x、y 和航向上搜索，并展开左、直、右等运动基元，所以路径遵守最小转弯半径，车体轮廓和障碍代价通过代价地图被考虑。结果是真车能跟随的可行全局路径。

### 7.3 TEB local trajectory optimisation

**CV 原句**

> TEB local trajectory optimisation: optimised time-parameterised local trajectories under global-path and local-costmap constraints, outputting continuous pose and curvature references to the controller as local obstacles change.

**拆句**

1. optimised time-parameterised local trajectories（优化）
2. under global-path and local-costmap constraints（约束）
3. outputting continuous pose and curvature references（输出）
4. as local obstacles change（场景）

**句型模板**

> I used [TEB] to optimise [a time-parameterised trajectory] under [the global path and the local costmap]. It outputs [pose and curvature references] to [the controller] [as obstacles change].

**口语示范**

> The global path is only a geometric curve. TEB turns it into a trajectory with time, by optimising a sequence of poses and time intervals as an elastic band. The global path pulls the band along, and the local costmap pushes it away from obstacles. It outputs pose and curvature references to the controller, and it updates them continuously as obstacles change.
>
> 中文：全局路径只是几何曲线。TEB 把它变成带时间的轨迹：把位姿序列和时间间隔当弹性带来优化。全局路径把带子往前拉，局部代价地图把它从障碍物推开。它向控制器输出位姿和曲率参考，并随障碍物变化持续更新。

### 7.4 MPC trajectory tracking

**CV 原句**

> MPC trajectory tracking: based on a car-like kinematic model, solved receding-horizon control under position, heading, speed and steering constraints, closing the loop from planned trajectory to vehicle motion on the real vehicle.

**拆句**

1. based on a car-like kinematic model（模型）
2. solved receding-horizon control（方法）
3. under position, heading, speed, steering constraints（约束）
4. closing the loop on the real vehicle（结果）

**句型模板**

> T5：I built [an MPC] on [a car-like kinematic model]. At each step it solves [a constrained problem over a short horizon] and applies [the first input]. The constraints are [position, heading, speed and steering].

**口语示范**

> The MPC is based on a car-like kinematic model: the state is x, y, heading and speed, and the inputs are acceleration and steering angle. At every step it predicts the vehicle motion over a short horizon, solves a small constrained optimisation, and applies only the first input. The constraints cover the speed and the steering. This closes the loop from the planned trajectory to the real vehicle motion.
>
> 中文：MPC 基于车式运动学模型：状态是 x、y、航向和速度，输入是加速度和转向角。每一步它在短时域内预测车辆运动，求解小的带约束优化，只执行第一个输入。约束包含速度和转向。这就把规划轨迹到真车运动的回路闭合起来。

## 8. P3 RoboMaster（3 条）

### 8.1 Gimbal cascaded PID

**CV 原句**

> Gimbal cascaded PID: built pitch/yaw angle–rate cascaded PID using IMU/AHRS and motor feedback, converting remote-control and vision targets into continuous attitude commands for stable aiming and tracking.

**拆句**

1. built pitch/yaw angle–rate cascaded PID（主干）
2. using IMU/AHRS and motor feedback（反馈）
3. converting remote and vision targets into continuous commands（输入）
4. for stable aiming and tracking（目的）

**句型模板**

> I built [a cascaded PID] for [pitch and yaw]: [the outer loop controls the angle and the inner loop controls the angular rate]. The feedback is [IMU attitude and motor feedback]. [Remote and vision targets] are turned into [continuous attitude commands].

**口语示范**

> For the gimbal, I built a cascaded PID for pitch and yaw. The outer loop controls the angle and gives a target rate to the inner loop, which controls the angular rate and outputs the motor command. The feedback comes from the IMU attitude and the motor encoders. The targets from the remote controller and the vision system are turned into continuous attitude commands, so the aim is stable and the tracking is smooth.
>
> 中文：云台上我为俯仰和偏航做了串级 PID。外环控制角度并给内环一个目标角速度，内环控制角速度并输出电机指令。反馈来自 IMU 姿态和电机编码器。遥控和视觉的目标被转成连续的姿态指令，所以瞄准稳定、跟踪平滑。

### 8.2 Launcher control loops

**CV 原句**

> Launcher control loops: built friction-wheel speed loops and a feeder position–velocity dual loop, iterating from PID through variable-gain PID to sliding-mode control with muzzle-velocity feedback for stable continuous firing.

**拆句**

1. friction-wheel speed loops（摩擦轮）
2. feeder position–velocity dual loop（供弹）
3. iterating PID → variable-gain → sliding mode（迭代）
4. with muzzle-velocity feedback for stable continuous firing（目的）

**句型模板**

> T11：I built [friction-wheel speed loops] and [a feeder dual loop]. I iterated from [PID] to [variable-gain PID] to [sliding-mode control], with [muzzle-velocity feedback], for [stable continuous firing].

**口语示范**

> The launcher has two parts. The friction wheels have speed loops, and the feeder has a position and velocity dual loop. The challenge was continuous firing: each shot slows down the friction wheels, so the muzzle velocity was not consistent. I iterated from PID to variable-gain PID and then to sliding-mode control, which recovered the speed faster, and I used the muzzle-velocity feedback from the referee system to adjust the target speed in small steps.
>
> 中文：发射机构有两部分：摩擦轮的速度环，以及供弹的位置速度双环。难点是连发：每发都会让摩擦轮减速，枪口初速不一致。我从 PID 迭代到变增益 PID，再到恢复更快的滑模控制，并用裁判系统的枪口初速反馈小步调整目标转速。

### 8.3 Chassis power control

**CV 原句**

> Chassis power control: allocated body velocity to four Mecanum wheels, estimated power demand from real-time power and buffer-energy feedback and scaled wheel speeds, keeping the chassis manoeuvrable under power limits.

**拆句**

1. allocated body velocity to four Mecanum wheels（分配）
2. estimated power demand from power and buffer-energy feedback（估计）
3. scaled wheel speeds（缩放）
4. kept the chassis manoeuvrable under the limit（目的）

**句型模板**

> I allocated [the body velocity] to [four Mecanum wheels]. I estimated [the power demand] from [the real-time power and buffer-energy feedback] and scaled [the wheel speeds] to keep [the chassis manoeuvrable under the power limit].

**口语示范**

> The chassis has four Mecanum wheels, so I first allocate the body velocity command to the four wheel speeds. The referee system limits the chassis power, and exceeding it is penalised. So I estimate the power demand from the real-time power and the buffer energy, and scale all four wheel speeds by the same factor before the limit is hit. The scale goes down immediately but recovers slowly, so the chassis stays manoeuvrable without oscillating.
>
> 中文：底盘有四个麦克纳姆轮，所以我先把车体速度指令分配到四个轮速。裁判系统限制底盘功率，超限会受罚。所以我根据实时功率和缓冲能量估计功率需求，在触限前把四个轮速按同一系数缩放。系数下降立即生效，恢复则缓慢，这样底盘保持灵活又不振荡。

The chain captures a frame, pre-processes it with letterbox, runs the model, decodes the boxes with NMS, and turns them into a structured observation: the class, the confidence and a timestamp.

### 9.2 Agent decision chain

**CV 原句**

> Agent decision chain: built an environment and vision-event decision chain with LangGraph, with a rule-based fast path for extreme states, issuing structured recommendations or constrained requests to the execution layer.

**拆句**

1. built a decision chain with LangGraph（链路）
2. with a rule-based fast path for extreme states（快速通道）
3. issuing structured recommendations or constrained requests（输出）

**句型模板**

> I built [a decision chain] with [LangGraph] that combines [environment and vision events]. [Extreme states] take [a rule-based fast path]. The output is [a structured recommendation or a constrained request].

**口语示范**

> The decision chain is a LangGraph graph. It combines the environment state and the vision events. For extreme states, such as very dry soil, a rule-based fast path reacts at once without waiting for the language model. The model itself can only output a structured recommendation or a constrained request, and both go through a whitelist and a policy check before they reach the execution layer.
>
> 中文：决策链是一张 LangGraph 图，它结合环境状态和视觉事件。对于极端状态（如土壤过干），基于规则的快速通道立即响应，不等语言模型。模型本身只能输出结构化建议或受约束请求，二者在到达执行层之前都要通过白名单和策略校验。

### 9.3 Local irrigation control

**CV 原句**

> Local irrigation control: implemented a soil-moisture-driven pump state machine on Hi3861 with independent start/stop thresholds and manual-priority override for a stable local closed loop.

**拆句**

1. implemented a pump state machine on Hi3861（主干）
2. driven by soil moisture（输入）
3. independent start/stop thresholds（滞回）
4. manual-priority override（优先级）
5. for a stable local closed loop（目的）

**句型模板**

> I implemented [a pump state machine] on [the Hi3861], driven by [soil moisture]. It has [independent start and stop thresholds] and [a manual override that has priority].

**口语示范**

> The pump is controlled locally on the Hi3861, so irrigation works even when the network is down. It is a small state machine driven by the soil moisture. It has two separate thresholds, one to start and one to stop, and the gap between them prevents rapid switching. A manual command always has priority over the automatic mode. This gives a stable local closed loop.
>
> 中文：水泵在 Hi3861 上本地控制，所以即使网络断了灌溉也能工作。它是一个由土壤湿度驱动的小状态机，有两个分开的阈值（一个启动、一个停止），两者之间的间隙防止快速切换。手动命令始终优先于自动模式。这就形成了稳定的本地闭环。

### 9.4 System integration

**CV 原句**

> System integration: unified visual observations, environment state and user commands into a traceable system state, orchestrated decisions with a server-side agent and closed the loop through web interaction and device-side irrigation.

**拆句**

1. unified observations, state and commands into a traceable system state（统一）
2. orchestrated decisions with a server-side agent（编排）
3. closed the loop through web and device（闭环）

**句型模板**

> I unified [observations, environment state and user commands] into [one traceable system state]. [A server-side agent] orchestrates [the decisions], and the loop is closed through [the web interface] and [the device-side execution].

**口语示范**

> There are three kinds of input: visual observations, environment readings and user commands from the web page. I unified them into one traceable system state, so every decision is stored with the inputs that led to it. A server-side agent orchestrates the decisions, and the loop is closed: the web page shows the state, the user can intervene, and the device executes the irrigation and reports back.
>
> 中文：有三类输入：视觉观测、环境读数和网页上的用户命令。我把它们统一成一份可追溯的系统状态，所以每个决策都与引起它的输入一起存储。服务端智能体编排决策，并闭合回路：网页展示状态，用户可以介入，设备执行灌溉并回报。

## 本章要点速记

1. 拆句五步：主干 → 方法 → 结果分句 → 拆短句 → 加因果和验证。
2. 12 个通用骨架 T1–T12 覆盖 24 条 bullet 的绝大部分句型。
3. CV 的 “using / via / with” 对应口语里的 “It uses … / through … / with …”。
4. CV 的 “-ing 结果分句” 要拆成独立的一句，用 so / as a result 连接。
5. 过去时讲经历，现在时讲机制，被动讲转换关系（allocated / mapped / converted）。
6. P1 的 LQR 是“模型参照”，不是“已部署”；P3 的 3V3 是团队成绩。
7. P6 是在职项目，用现在进行时介绍；P4 的 LLM 只能建议。
8. 每条 bullet 都要准备一句“为什么”和一句“怎么验证”。

## 自测题

1. 用 T1–T4 把 P1 第 1 条说成 4 句话，不看本章。
2. 把 P5 第 3 条 “TEB local trajectory optimisation” 拆成 3 个意群，并各写一句口语。
3. P3 第 2 条里 “iterating from PID through variable-gain PID to sliding-mode control” 用哪个模板？（T11）
4. 为 P6 第 3 条写一句因果句，说明为什么要把“决策”和“执行”分开。
5. 用 T9 为 P7 写一句：你把哪类异常追溯到了哪个原因？
