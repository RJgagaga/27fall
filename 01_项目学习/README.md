## 1. 这套文档是什么、为什么这样组织

### 1.1 面试到底在考什么

港澳硕士（授课型）的面试，无论是真人技术问答还是 AI 自动视频面试（港城大东莞已有这种形式，见 [05_目标项目与面试画像总表](./00_申请画像/05_目标项目与面试画像总表.md)），其实在检验四件事：

| 面试官关心 | 他们的做法 | 你需要的准备 |
|---|---|---|
| 这个人是不是真做过 | 抓 CV 上一句话往下追问三层："你具体做了什么？为什么这样做？出问题怎么办？" | 项目课程：每个项目讲到"为什么""怎么验证""怎么出错" |
| 基础是否扎实 | 随手问一个概念（"LQR 的 Q、R 怎么选？""EKF 为什么要线性化？"） | 基础知识：能推导、能手算、能用英文解释 |
| 能否沟通 | 看你能不能用英文把复杂东西讲给非本方向的人听 | 面试准备：多版本自我介绍、口述方法、英文句型 |
| 是否适合这个专业 | "Why this programme? Why now? Future plan?" | 申请画像：PS 主线、各校定位 |

所以这套文档不是"项目总结"，而是**从面试官的追问方向倒推出来的学习材料**。

### 1.2 五大块的分工

```text
                    ┌──────────────────────────────┐
                    │  00_申请画像  (你是谁、材料怎么说) │
                    └──────────────┬───────────────┘
                                   │ 先看：口径与边界
        ┌──────────────────────────┼──────────────────────────┐
        ▼                          ▼                          ▼
 01_项目课程 (P1..P7)       02_基础知识 (数学→控制→…)     03_八股知识 (问答速查)
 把每个项目讲透               把项目背后的原理补牢          把通用题刷熟
        └──────────────────────────┼──────────────────────────┘
                                   ▼
                       04_面试准备 (英文表达与演练)
                                   ▲
                    05_学习笔记归档 (你自己的疑惑问答，原始素材)
```

- **00_申请画像**：锁定"事实边界"。CV 说了什么、PS 与推荐信承诺了什么、各校面试画像是什么。后面所有文档都服从这里。
- **01_项目课程**：七个项目各一个目录，每个目录有 README（项目全貌与「实机细节自查表」）、若干主题章节、以及 `99_英文面试口述与深挖问答.md`。
- **02_基础知识**：九个主题，从线性代数一直到 DDS。项目文档里遇到的"前置知识"都链到这里。
- **03_八股知识**：计算机基础、人工智能、机器人学三大类，"问—答要点—英文速答"格式，用于刷题。
- **04_面试准备**：总指南、各校画像、项目口述、模拟与冲刺。
- **05_学习笔记归档**：你和助手以前学习时的问答逐字稿，**只读，不改**。它们告诉写作者"你哪里不懂"，正式教材已经重写，不必再读原稿，除非想看当时的疑惑。

### 1.3 这套文档的诚实原则

面试官最容易识破的不是"不会"，而是"夸大"。因此：

1. 凡 CV 没写的实机数值（增益、频率、阈值、误差、成功率……），文档**不会替你编**。需要举例时使用「教学示例数值（非项目实测）」，并明确标注。
2. 面试官大概率会追问、但 CV 与源码里都没有的细节，用 `【待你补全：…】` 占位，并汇总到各项目 README 的「实机细节自查表」。你要做的是**翻自己的笔记、日志、仓库，把这些空填上**，填不上的就按 [04_口径与事实基线](./00_申请画像/04_口径与事实基线.md) 中的诚实策略回答。
3. 技术讲解会用"典型做法 / 常见实现"这类措辞，区分"这类系统通常怎么做"和"你做了什么"。

## 2. 怎么使用：五个动作

1. **先读画像**（约 2 小时）：[01_CV逐条拆解](./00_申请画像/01_CV逐条拆解.md) 是总地图；[02_PS与推荐信主线](./00_申请画像/02_PS与推荐信主线.md) 告诉你已经"对外承诺"过什么；[04_口径与事实基线](./00_申请画像/04_口径与事实基线.md) 是数字口径。
2. **按项目学**：进入某个 `01_项目课程/Px_*/README.md`，先读项目全貌，再按编号读章节，最后读 `99_英文面试口述与深挖问答.md`。
3. **遇到不懂的概念就跳基础**：项目章节顶部的"前置知识"都带链接，跳过去学，再回来。
4. **用八股查漏**：`03_八股知识` 当作题库，每天刷 10–20 条，用英文速答说出声。
5. **最后演练**：`04_面试准备` 的自我介绍、行为面试、模拟脚本、一周冲刺计划、当天检查清单。

> **提示**：每个项目 README 里有「实机细节自查表」。建议你把它打印出来或复制到笔记软件，逐项填空。这比多读十页教材更能提升面试表现。

## 3. 三条学习路线

## 5. 阅读顺序建议

```text
画像(2h) ──► 项目(逐个) ──► 基础(按需跳读) ──► 八股(每天10–20条) ──► 面试(演练)
  │            │               │                    │                  │
  口径边界      讲透项目         补原理               查漏                英文输出
```

具体推荐顺序（不赶时间的情况）：

1. **00_申请画像** 全部 5 篇。理由：先知道"对外说过什么"，才不会在学习时偏离。
2. **项目顺序**：P1 → P7 → P3 → P5 → P2 → P4 → P6。理由：P1/P7/P3 同属"控制主干"，概念复用度最高（PID、LQR、CAN、FreeRTOS）；P5 把"估计+规划+跟踪"串起来；P2 是机械臂方向；P4/P6 是"系统与 AI"层。这与 CV 的时间倒序不同，但学习顺序应当"由底层到上层"。
3. **基础知识**：不要从头读。按项目需要跳读，每章有"前置知识"。有空再按 [02_基础知识/00_总览与学习路线](./02_基础知识/00_总览与学习路线.md) 补全。
4. **八股**：与项目并行，每天固定 20 分钟。
5. **面试准备**：最后两周集中；但英文自我介绍应尽早开始练，因为口语需要时间。

## 6. 全套约定

### 6.1 以 CV 为准

英文通用 CV（`00_当前申请/03_通用证明材料/00_申请通用材料_跨学校复用/05_简历/英文通用简历/YongyiLaiCV.pdf`）是**唯一权威来源**。源码、旧文档、中文简历、学习笔记若与 CV 冲突，一律按 CV 写。冲突点不出现在正文叙述里，只在各项目 README 末尾的「口径备忘（仅自查，面试按 CV 说）」中记录。典型的口径要点（排名 6/156 top 4%、均分 87.63、IELTS 6.5）见 [04_口径与事实基线](./00_申请画像/04_口径与事实基线.md)。

### 6.2 `【待你补全】` 的含义

形如 `【待你补全：Kp、Ki、Kd 的数量级与整定顺序】` 的占位，表示：

- 这是面试官**很可能追问**的细节；
- CV 与现有材料里**没有**可靠数值或事实；
- 文档**拒绝替你编造**；
- 你需要自己翻笔记、日志、仓库、与同学确认后填上。

它们会汇总到各项目 README 的「实机细节自查表」。使用说明见 [04_口径与事实基线](./00_申请画像/04_口径与事实基线.md) 第八章。

### 6.3 「教学示例数值」不是实测

为了把公式讲清楚，文档里会出现带数字的手算例子（例如"设 $Q=\mathrm{diag}(1,1,10,1)$，$R=1$"）。凡这类数字，都会标注 **「教学示例数值（非项目实测）」**。它们只用于演示算法流程，**绝不能**当作你的项目数据在面试里说。

> **面试要点**：如果面试官问"你的 Q 是多少？"，不能回答教学示例里的数字，除非你自己真的用过。要么答出自己记得的量级和调法，要么用诚实模板。

### 6.4 "典型做法"与"你做了"

文档里出现"典型做法""常见实现"时，是在讲同类系统一般怎么做，**不代表你做了**。只有能在 CV、PS、推荐信、源码或学习笔记中找到依据的内容，才会写成"你做了 X"。

### 6.5 公式渲染

- 行内公式 `$...$`，独立公式 `$$...$$`，由 GitHub 的 KaTeX 渲染。
- 矩阵用 `\begin{bmatrix}...\end{bmatrix}`。
- 在 GitHub 网页、VS Code（安装 Markdown Preview Enhanced 或自带预览）、Typora 中均可正常显示。如果某个预览器不显示公式，换到 GitHub 网页看即可。
- 变量约定：状态 $x$、输入 $u$、输出 $y$、状态矩阵 $A$、输入矩阵 $B$；LQR 权重 $Q, R$；协方差 $P$，过程噪声 $Q_k$，测量噪声 $R_k$（在滤波章节会明示，避免与 LQR 的 $Q,R$ 混淆）。

### 6.6 图

全部使用 ASCII 示意图（放在 `text` 代码块里）或简单的 mermaid 流程图，不依赖外部图片。ASCII 图请用等宽字体查看。

### 6.7 语言

- 讲解正文中文，术语首次出现带英文，如"卡尔曼滤波（Kalman filter）"。
- **面试表达全部英文**，每段英文后附一行中文译文或要点。
- 代码、公式变量、文件名一律英文 ASCII。

### 6.8 隐私

学习文档中不保存电话、邮箱等个人联系方式。

## 7. 单篇文档的统一结构

基础与项目章节统一按下面的顺序讲，你读多了会形成"预期"，便于快速定位：

| 顺序 | 内容 |
|---|---|
| 1 | 它要解决什么问题（现实场景、一句话直觉） |
| 2 | 符号与单位（每个字母是什么、正方向） |
| 3 | 推导（一步一步，不跳步） |
| 4 | 完整手算例子（数字小而干净，标「示例」） |
| 5 | 在本项目里怎么用（链接到具体项目文档） |
| 6 | 常见错误、边界、故障现象 |
| 7 | 面试怎么问、怎么答（英文问答 + 追问方向） |
| 8 | 自测题（约 5 道，附答案或要点） |

文首固定：一句话定位 → 本章学完你能…… → 前置知识 → 目录；文末固定：本章要点速记 → 自测题 → 相关链接。

## 本章要点速记

1. 这套教材从"面试官的追问方向"倒推，不是项目总结。
2. 五大块：画像 → 项目 → 基础 → 八股 → 面试，笔记归档只读。
3. 当前日期距面试很近，默认走 7 天冲刺；有时间再升级到 30 天、60 天。
4. 以 CV 为准；冲突记在各项目 README 的「口径备忘」。

## 自测题

1. 你的面试官会从 CV 的一句话往下追问哪三层？（要点：做了什么；为什么这样做；出问题怎么办/怎么验证。）
2. `【待你补全】` 的占位出现时，你应该做什么？（要点：翻笔记和仓库填空；填不上就用诚实模板，不编数。）
3. 教学示例里的 $Q$ 矩阵能不能当作你项目的真实参数？为什么？（要点：不能，它只用于演示流程；面试说实际用过的量级与调法。）
4. 如果面试在 5 天后，你该选哪条路线？每天最少做什么？（要点：7 天冲刺；每天出声说英文，项目 90 秒口述为核心。）
5. 为什么建议先读 00_申请画像？（要点：先锁定对外口径、PS 与推荐信承诺，避免学习与面试说法冲突。）
